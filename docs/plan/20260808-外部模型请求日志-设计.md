# 外部模型请求日志设计

状态：已完成（2026-08-08）

对应[需求](../spec/20260808-外部模型请求日志-需求.md)和[任务](../tasks/20260808-外部模型请求日志-任务.md)。

## 1. 设计摘要

保留现有 Runtime 级 `llm_request` / `llm_response`，在共享 HTTP 边界新增：

```text
Runtime
  -> llm_request
  -> Provider.generate(messages, request_id=...)
     -> build actual provider payload
     -> post_json(..., request_id, provider, model)
        -> llm_http_request
        -> httpx POST
        -> llm_http_response | llm_http_error
     -> extract normalized output
  -> llm_response
```

成功路径四个事件共用一个 request ID。Provider 在校验密钥和消息后构造实际 payload，仅将已准备发送的 payload 交给 HTTP 层，因此日志不需要重建 `messages` 或 `input`。

## 2. 契约变更

Provider 内部契约增加必填关键字参数：

```python
async def generate(
    messages: Sequence[ChatMessage],
    *,
    request_id: str,
) -> ProviderResult: ...
```

`run_chat_messages()` 继续生成 request ID，先记录 `llm_request`，再将 ID 传给 Provider。HTTP Router、TUI 和 Session 签名不变。

共享 HTTP 函数增加关联上下文和可测时钟：

```python
async def post_json(
    url: str,
    api_key: str,
    payload: Mapping[str, Any],
    *,
    request_id: str,
    provider: str,
    model: str,
    clock: Callable[[], float] = time.monotonic,
) -> tuple[int, Any]: ...
```

`clock` 仅用于确定性测试，生产默认为单调时钟。不新增 ContextVar、全局当前 request ID 或依赖注入容器。

## 3. 日志数据模型

`app/observability/model_logging.py` 继续使用事件白名单。新增三个函数：

```python
log_model_http_request(..., request_body: Mapping[str, Any])
log_model_http_response(..., status_code: int, duration_ms: float, ...)
log_model_http_error(..., error_type: str, duration_ms: float)
```

### 3.1 请求事件

- `request_body` 直接使用 Provider 交给 `post_json()` 的 payload。
- DeepSeek 会完整保留 `model/messages/stream`。
- 阿里云会完整保留 `model/input`，无论 input 是 string 还是消息数组。
- `headers` 由日志函数用常量构造，而不接收 HTTP 层的真实 Header 对象：

```json
{
  "Accept": "application/json",
  "Content-Type": "application/json",
  "Authorization": "Bearer [REDACTED]"
}
```

这个结构保留调试价值，且从数据流上阻止 API Key 进入 Logger。

### 3.2 响应和失败事件

- 请求前读取一次 `clock()`。
- 收到任意 HTTP 响应后立即计算并记录 `llm_http_response`，再执行 401/403/其他状态映射和 JSON 解析。
- `httpx.TimeoutException` 映射为 `error_type=timeout`，其他 `httpx.RequestError` 映射为 `connection`。
- 耗时统一用 `round((clock() - started_at) * 1000, 2)` 转换为毫秒。
- 事件不接收 response body、异常或 request/response 对象。

## 4. 错误和日志失败语义

| 情况 | 事件 | 现有业务结果 |
| --- | --- | --- |
| 2xx + 有效文本 | request + http request + http response + response | 成功 |
| 2xx + 非法 JSON/无文本 | request + http request + http response | 现有 502 |
| 401/403 | request + http request + http response | 现有认证错误 |
| 其他非 2xx | request + http request + http response | 现有上游错误 |
| 超时/连接失败 | request + http request + http error | 现有 504/502 |
| 本地输入或 Provider 配置在 I/O 前失败 | 没有 http 事件 | 现有错误不变 |

日志 Handler 继续按现有策略将文件错误隔离。事件字段全部由内部固定数据构造，不向 Formatter 传递不可 JSON 序列化对象。

## 5. 测试设计

### 5.1 Formatter

- 四类事件的精确 key 集合、单行 UTF-8 JSON 和文件/stderr 一致性。
- 完整 `messages` 中的中文、换行、引号无损往返。
- 日志文本不包含假 API Key、原始响应标记或异常原文。

### 5.2 HTTP 边界

- MockTransport 捕获的实际 payload 与 `llm_http_request.request_body` 深度相等。
- 两个 Provider 分别覆盖单轮和多轮 `messages/input`。
- 可控 clock 验证 2xx、非 2xx、超时和连接失败耗时。
- 验证每条 HTTP 事件的 request ID/provider/model 与 Runtime 一致。

### 5.3 回归

- 更新所有假 Provider 的内部签名，不改测试原有行为断言。
- HTTP `/chat` 响应、TUI 历史/clear/取消、Session 回滚、日志转储全部通过。
- 所有外部调用继续使用 HTTPX MockTransport。

## 7. 风险与缓解

- **密钥泄漏**：日志函数自行构造脱敏 Header，不接收真实 Authorization；测试搜索假密钥。
- **对话重复与日志增长**：明确记录为用户已确认需求，保留 10 MiB/5 备份转储，README 警示。
- **观测改变业务**：事件在 I/O 边界旁路记录，不修改状态码映射、重试或超时。
- **签名迁移遗漏**：编译与全量测试覆盖 Provider 及所有 Fake。

## 8. 回滚

删除三类 HTTP 事件、恢复 Provider/`post_json` 签名即可回到现有日志。回滚不会删除已生成的历史日志文件。

## 9. 待确认设计决策

1. request ID 使用显式参数跨 Runtime → Provider → HTTP 传递。
2. 请求 Header 由 Logger 用固定安全值重建，不接触真实 Authorization。
3. `request_body` 与交给 HTTPX 的 payload 一致，完整包含 `messages/input`。
4. 外部 HTTP 耗时从创建客户端前起算，收到响应或网络异常时结束。
5. 非 2xx 只记录 http response，不另记 http error；原始响应体继续丢弃。
