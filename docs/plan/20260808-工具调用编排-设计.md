# 工具调用编排设计

状态：已完成（2026-08-08）

对应[需求](../spec/20260808-工具调用编排-需求.md)和[任务](../tasks/20260808-工具调用编排-任务.md)。

## 1. 设计摘要

在现有 Chat Runtime 和 Provider 之间引入有界工具循环，在仓库根目录增加独立 `tools/` Python 包。一次用户请求创建一个 Provider Turn；Turn 封装对应厂商的请求续接状态，Runtime 只处理 Provider 中立的模型步骤和工具结果。

```text
HTTP / TUI
    |
    v
run_chat_messages(messages, provider, registry)
    |
    +-> provider.create_turn(messages, definitions, request_id)
    |       |
    |       +-> DeepSeekTurn: assistant.tool_calls + role=tool
    |       |
    |       +-> AliyunTurn: function_call + function_call_output
    |
    +-> bounded loop
            |
            +-> turn.next() ---------------------> ModelStep
            |                                        |
            |                           final text <--+--> tool calls
            |                                                 |
            +<-- turn.next(tool results) <-- registry.execute-+
```

工具定义与执行不依赖 Provider；Provider Turn 不执行工具；Router、TUI 和 Session 继续只依赖 Runtime。

## 3. 中立契约

### 3.1 工具契约

```python
@dataclass(frozen=True)
class ToolDefinition:
    name: str
    description: str
    parameters: Mapping[str, object]

@dataclass(frozen=True)
class ToolCall:
    call_id: str
    name: str
    arguments_json: str

@dataclass(frozen=True)
class ToolResult:
    call_id: str
    output: str
    is_error: bool = False

class Tool(Protocol):
    definition: ToolDefinition
    async def invoke(self, arguments: Mapping[str, object]) -> object: ...
```

- 工具名使用两家协议的公共安全子集：`^[A-Za-z0-9_-]{1,64}$`。
- `parameters` 必须是顶层 `type=object` 的 JSON Schema；第一版 Registry 不实现通用 JSON Schema 引擎，Schema 用于指导模型，具体工具仍负责参数类型、必填项和额外字段校验。
- Handler 返回可 JSON 序列化对象，由 Registry 统一生成紧凑 UTF-8 JSON envelope。

成功结果：

```json
{"ok":true,"data":{"timezone":"Asia/Shanghai","datetime":"2026-08-08T12:00:00+08:00"}}
```

可恢复失败：

```json
{"ok":false,"error":{"code":"invalid_arguments","message":"Timezone is invalid"}}
```

错误 `code` 只允许 `invalid_arguments`、`unknown_tool`、`execution_failed`、`result_too_large`。内部异常不进入 `message`。

### 3.2 模型步骤与 Turn

```python
@dataclass(frozen=True)
class ModelStep:
    upstream_status: int
    output_text: str | None
    tool_calls: tuple[ToolCall, ...]

class LlmTurn(Protocol):
    async def next(
        self,
        tool_results: Sequence[ToolResult] = (),
    ) -> ModelStep: ...

class LlmProvider(Protocol):
    def create_turn(
        self,
        messages: Sequence[ChatMessage],
        tools: Sequence[ToolDefinition],
        *,
        request_id: str,
    ) -> LlmTurn: ...
```

`ModelStep` 允许中间文本和工具调用同时出现；只要存在 `tool_calls`，Runtime 就把该步视为中间步骤，不向 HTTP/TUI 输出其中的文本。没有工具调用时必须有非空 `output_text`，否则仍是非法上游响应。

Turn 对象仅存活于一次 `run_chat_messages()` 调用，持有 Provider 私有消息列表、待回传调用和 request ID。Runtime 不读取这些内部字段，也不持久化 Turn。

## 4. Runtime 工具循环

`run_chat_messages()` 保留输入校验、Provider 选择和一次 `llm_request`；随后创建 Turn 并调用新的 `run_tool_loop()`：

```python
turn = provider.create_turn(messages, registry.definitions, request_id=request_id)
results = ()

for step_number in range(1, MAX_MODEL_STEPS + 1):
    step = await turn.next(results)
    if not step.tool_calls:
        return require_final_text(step)
    if step_number == MAX_MODEL_STEPS:
        raise ToolLoopLimitError()
    if len(step.tool_calls) > MAX_TOOL_CALLS_PER_STEP:
        raise ToolLoopLimitError()
    results = await registry.execute_all(step.tool_calls)
```

固定边界：

- `MAX_MODEL_STEPS = 5`，首次模型请求计入。
- `MAX_TOOL_CALLS_PER_STEP = 4`。
- 第 5 步仍请求工具时，不执行这些工具，因为已无合法的下一模型步骤可消费结果。
- 工具按响应顺序逐个 `await`；任一 `CancelledError` 原样传播，不生成工具错误结果。
- 一个工具的可恢复失败不阻断同批其他工具，所有结果按调用顺序回传模型。
- 模型步数或调用数超限是终止性 `tool_limit`，不把错误交给模型继续修正。

Runtime 成功时只记录一次最终 `llm_response`。任何阶段失败都不产生该事件，现有 HTTP/TUI 安全错误映射继续生效。

## 5. Registry 与内置工具

### 5.1 注册

`ToolRegistry` 构造时复制并冻结工具顺序，通过名字建立只读查找表，并验证：

- 至少一个工具；名称合法且不重复。
- 描述为非空文本。
- 参数 Schema 是顶层 object。

`create_default_registry()` 只注册 `GetCurrentTimeTool`。Runtime 接受可选 Registry 便于测试；生产默认使用该工厂，不增加依赖注入容器或全局可变 Registry。

### 5.2 执行边界

对每个 `ToolCall` 依次执行：

1. 以 UTF-8 字节数校验 `arguments_json <= 8 KiB`；超限视为终止性循环错误，在 Registry 查找或 JSON 解析前停止。
2. 解析 JSON，并要求顶层为 object；失败产生 `invalid_arguments` 结果。
3. 按精确名称查找工具；未找到产生 `unknown_tool` 结果。
4. `await tool.invoke(arguments)`；工具声明的参数错误映射为 `invalid_arguments`，其他普通异常映射为 `execution_failed`。
5. 统一 JSON 序列化结果并校验 UTF-8 `<= 32 KiB`；超限替换为 `result_too_large`，绝不截断成可能无效的 JSON。

Registry 只捕获 `Exception`，不捕获取消等 `BaseException`。事件日志在执行前后旁路记录，日志失败不能改变工具结果。

### 5.3 `get_current_time`

定义：

```json
{
  "name": "get_current_time",
  "description": "获取指定 IANA 时区的当前日期和时间",
  "parameters": {
    "type": "object",
    "properties": {
      "timezone": {"type": "string", "description": "例如 Asia/Shanghai"}
    },
    "required": ["timezone"],
    "additionalProperties": false
  }
}
```

实现使用 `datetime.now(ZoneInfo(timezone))`，返回 `timezone` 与带 UTC offset 的 ISO 8601 `datetime`。缺少字段、空白、非字符串、未知时区或额外字段均返回统一参数错误。测试向工具注入可控的 aware UTC clock，不依赖机器当前时间。

## 6. Provider 适配

### 6.1 DeepSeek Turn

首次请求：

```json
{
  "model": "deepseek-v4-flash",
  "messages": [{"role":"user","content":"上海现在几点？"}],
  "tools": [{"type":"function","function":{"name":"...","description":"...","parameters":{}}}],
  "tool_choice": "auto",
  "stream": false
}
```

响应存在 `choices[0].message.tool_calls` 时：

- 校验每项 `id`、`type=function`、`function.name` 和字符串 `function.arguments`。
- 将完整、经过字段白名单重建的 assistant 消息保存到 Turn；保留 `content`、`reasoning_content` 和 `tool_calls`，以兼容 DeepSeek 思考模式的回传要求。
- `next(results)` 要求结果 call ID 与上一批调用一一对应且顺序一致，再追加 `role=tool`、`tool_call_id`、`content`。

若无工具调用，则从同一 message 的 `content` 提取最终文本。所有请求继续走共享 `post_json()`。

### 6.2 阿里云 Responses Turn

启用工具后，首次 `input` 统一使用消息数组，即使只有一条 user 消息，以便后续追加结构化 Function Call：

```json
{
  "model": "qwen3-max",
  "input": [{"role":"user","content":"上海现在几点？"}],
  "tools": [{"type":"function","name":"...","description":"...","parameters":{}}],
  "tool_choice": "auto"
}
```

响应从 `output` 中按原顺序提取所有 `type=function_call`，校验 `name`、字符串 `arguments` 和 `call_id`。Turn 保存按白名单重建的 `function_call` 项；收到结果后，对每个调用紧邻追加对应的 `function_call_output`。

无 Function Call 时继续按现有优先级提取 `output_text` 或 message 文本。工具模式不使用 `previous_response_id`、服务端存储或内置工具。

### 6.3 迁移策略

现有 `LlmProvider.generate()` 由 `create_turn()` 替代，不保留双路径：所有请求都经过同一 Turn 和循环，未触发工具时只有一次 HTTP 调用。Fake Provider 测试统一迁移到 Fake Turn，避免生产代码保留临时兼容分支。

`ProviderResult.raw_body` 不再作为 Runtime 所需契约；Provider 单步解析完成后只返回 `ModelStep`。若其他测试仍需验证原始 HTTP，可在 MockTransport 边界断言，不让原始响应跨入 Runtime。

## 7. 错误语义

| 情况 | 是否继续模型 | Runtime code | HTTP 建议 | TUI |
| --- | --- | --- | --- | --- |
| 非法 JSON 参数 | 是，作为工具错误结果 | - | 最终结果决定 | 最终结果决定 |
| 未知工具 | 是，作为工具错误结果 | - | 最终结果决定 | 最终结果决定 |
| 工具参数错误/普通异常 | 是，作为安全错误结果 | - | 最终结果决定 | 最终结果决定 |
| 工具结果过大 | 是，返回 `result_too_large` | - | 最终结果决定 | 最终结果决定 |
| 工具参数超过 8 KiB | 否 | `tool_limit` | 502 | 固定安全文案 |
| 每步调用数或模型步数超限 | 否 | `tool_limit` | 502 | 固定安全文案 |
| Provider 工具结构非法 | 否 | `invalid_response` | 502 | 现有上游响应错误 |
| 取消 | 否 | 原样传播 | 客户端取消 | 保持现有取消状态 |

工具可恢复错误对模型只暴露固定 code/message，不包含异常文本。`tool_limit` 增加到 `ChatErrorCode`，Router 映射复用 502，不改变成功契约。

## 8. 会话一致性

- `ChatSession.send()` 仍在整个 Runtime 调用成功后才构造 `assistant` 最终消息。
- 工具调用和结果只保存在 Turn 内，不进入 `ChatMessage`、`SessionStore` 或 `data/chat-session.json`。
- Runtime/Provider/工具失败、循环超限、取消或持久化失败均不更新内存历史。
- 下一用户轮次只向模型发送历史 user/assistant 最终文本；上一轮工具细节不会重放。

因此无需升级 `SESSION_SCHEMA_VERSION`，损坏历史处理与 `/clear` 行为不变。

## 9. 可观测性

单次成功工具调用的事件顺序示例：

```text
llm_request
llm_http_request        # model step 1
llm_http_response
llm_tool_call
llm_tool_result
llm_http_request        # model step 2，包含工具结果
llm_http_response
llm_response
```

新增白名单事件：

- `llm_tool_call`：`request_id`、`call_id`、`tool_name`、`arguments_chars`。
- `llm_tool_result`：`request_id`、`call_id`、`tool_name`、`status`（`success`/`error`）、`duration_ms`、`output_chars`。

字符数沿用现有模型日志口径；8/32 KiB 安全上限单独按 UTF-8 字节数判断。工具事件不记录完整参数、结果、异常对象或堆栈。实际回传模型的完整结果会出现在下一条现有 `llm_http_request.request_body`，继续受现有本地明文日志和转储策略约束。

一次用户请求的所有事件使用同一 request ID；各模型步骤不新增顶层 request ID。HTTP 事件顺序天然区分步骤，call ID 关联工具事件。

## 10. 性能与取消

- 未调用工具时只增加本地对象和一次循环判断，不增加外部请求。
- 每次工具调用至少可能新增一次模型 HTTP 请求，总延迟与费用随模型步骤线性增长；5 步上限是成本边界，不承诺延迟指标。
- 工具串行执行，行为确定且避免第一版引入并发资源竞争。
- Runtime、Turn 和 Registry 都不吞 `CancelledError`；TUI 现有 Worker 取消可中断正在等待的 HTTP 或工具 coroutine。
- 不增加重试、连接池生命周期、后台 Worker 或线程池。第一版工具必须原生 async 或只执行轻量标准库逻辑。

## 12. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 两家工具续接协议不同 | 高 | Provider Turn 独立持有协议状态，Mock 精确断言 JSON |
| DeepSeek 思考模式遗漏字段导致 400 | 高 | 保存并回传白名单内 `reasoning_content` 和完整 tool calls |
| 模型无限工具循环 | 高 | 5 个模型步骤、每步 4 调用，最后一步不执行无用工具 |
| 工具参数诱导任意执行 | 高 | 根目录白名单 Registry，无反射、eval、exec、动态 import |
| 工具异常或结果泄密 | 高 | 固定错误 envelope、32 KiB 边界、异常不进入日志或模型 |
| 完整结果进入现有 HTTP 日志 | 中 | 沿用已确认明文策略和转储；专用工具事件不重复内容 |
| 根包名 `tools` 与外部包冲突 | 中 | 从仓库根启动、无同名依赖、测试验证实际 import 来源 |
| 多步请求增加延迟与费用 | 中 | 固定步骤上限、无重试、日志可按 request ID 观察调用次数 |

## 13. 回滚

- 删除根目录 `tools/` 和 `app/runtime/tool_loop.py`。
- Provider 恢复单次 `generate()` 与原文本提取逻辑。
- Runtime 恢复一次 Provider 调用，移除 `tool_limit` 和工具事件。
- 会话 Schema 与公开 HTTP 契约未变化，无数据迁移或会话文件回滚。

回滚不会清理已生成的本地模型日志；其中可能保留历史工具结果，仍按现有轮转策略处理。

## 14. 待确认设计决策

1. 使用短生命周期 Provider Turn 隔离 DeepSeek 与阿里云续接状态，不让协议私有结构进入 Runtime。
2. 所有请求统一经过 Turn；不保留旧 `generate()` 双路径。
3. 阿里云启用工具后单轮 `input` 也统一使用消息数组，以支持后续追加 Function Call。
4. 工具成功和可恢复失败统一使用 JSON envelope；Registry 只做通用边界，工具自行做语义参数校验。
5. 第 5 个模型步骤再次请求工具时直接终止，不执行无法被后续步骤消费的调用。
6. 工具轨迹不进入会话文件；下一轮只携带最终 user/assistant 历史。
