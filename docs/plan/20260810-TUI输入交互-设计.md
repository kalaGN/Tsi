# TUI 输入交互设计

状态：已完成（2026-08-10）

对应[需求](../spec/20260810-TUI输入交互-需求.md)和[任务](../tasks/20260810-TUI输入交互-任务.md)。

## 1. 当前事实

- `ChatTuiApp` 的布局顺序是 transcript、prompt、现有状态栏、Footer。
- `run_status` 已有 `Ready/Thinking/Error`，但只在现有状态栏展示，不包含实时耗时。
- 单轮开始时间使用可注入的单调 `clock`，完成后通过 `_write_elapsed_time()` 写入最终耗时。
- `_request_generation` 已用于取消后阻止陈旧 Worker 写回。
- `ChatSession.messages` 可恢复完整成功的 user/assistant 轮次；失败和取消不持久化。
- `TextArea` 当前由高优先级 Enter/Esc App Binding 接管，没有 Up/Down App Binding。

已针对仓库固定的 Textual 8.2.8 验证：

- `App.set_interval(interval, callback, ...) -> Timer`。
- `Timer.stop()`、`pause()`、`resume()` 都是同步方法。
- `TextArea.load_text(text)` 替换内容，`TextArea.document.end` 返回文档末尾位置，
  `TextArea.move_cursor(location)` 可把光标移动到该位置。

## 2. 组件内状态


历史在构造阶段从注入或默认加载的 `ChatSession.messages` 提取所有 `ChatRole.USER` 内容。
这只是内存索引，不复制或修改 Session Store。

## 4. 活动 Timer 设计

### 4.1 启动

普通输入通过所有校验后：

1. `started_at = clock()`。
2. 增加请求代次并创建 Worker。
3. `_start_activity(started_at, generation)` 记录活动状态，立即渲染 `0.0 秒`。
4. 通过 `set_interval(0.1, callback, name="request-activity")` 创建本请求专属 Timer；callback 闭包捕获创建时的请求代次并传给 `_refresh_activity(generation)`。

初始渲染不再次调用 `clock()`，避免人为引入起始偏差，也让可控时钟测试稳定。

### 4.2 刷新

`_refresh_activity(generation)` 每次执行：

- 仅当回调捕获代次、活动代次和当前请求代次三者相等，且起始时间存在时更新。
- 使用 `max(0.0, clock() - started_at)` 防御测试时钟倒退。
- 循环推进 spinner frame。
- 更新为 `{frame} 思考中 · {elapsed:.1f} 秒 · Esc 取消`。

不读取 Provider、Worker 内部、reasoning、Token 或工具轨迹。

### 4.3 停止与并发安全

`_stop_activity(expected_generation: int | None = None)`：

1. 若指定代次且与活动代次不符则不操作，防止旧 Worker 清除新请求活动栏。
2. 对当前 Timer 调用同步 `stop()`。
3. 清空 Timer、起始时间、活动代次和 spinner index。
4. 将 `#activity-bar` 更新为空字符串。

调用路径：

- `_run_prompt()` 的匹配代次 `finally`：成功、已知错误和未知错误共用。
- `_cancel_active_request()`：递增请求代次前保存旧代次并停止对应 Timer，然后取消 Worker。
- `/quit` 和双 Esc 复用 `_cancel_active_request()`。

空闲时没有 Timer；不在 `on_mount()` 创建永久周期任务。

## 5. 历史输入设计

### 5.1 Binding

新增高优先级 App Binding：

```python
Binding("up", "previous_input", "Previous input", show=False, priority=True)
Binding("down", "next_input", "Next input", show=False, priority=True)
```

高优先级确保焦点位于 `TextArea` 时仍由历史动作处理；`show=False` 避免 Footer 过度拥挤，README 负责可发现性。

### 5.2 追加和重置

只有普通非空输入通过命令、活动请求和损坏历史等前置检查后，才在启动 Worker 前追加：

```python
self._input_history.append(input_text)
self._reset_history_navigation()
```

- 原始空格、中文和换行保留，不使用 `command` 的 strip 结果。
- 失败/取消仍保留在本进程历史；不会写入 Session。
- `/clear` 的 Session 清理成功后再清空列表和导航状态；清理异常时不修改历史。

### 5.3 Up/Down

`action_previous_input()`：

- 空列表时不操作。
- 首次浏览保存 `prompt.text` 到 `_history_draft`，索引设为最后一条。
- 已浏览时索引减一但不小于零。
- 通过 `_load_history_input()` 加载原文并移动光标到 `prompt.document.end`。

`action_next_input()`：

- 未浏览时不操作。
- 若还有更新记录，索引加一并加载。
- 若当前为最后一条，恢复草稿、将索引设为 `None` 并清空草稿。

边界不响铃、不循环、不写 transcript。召回内容的编辑不会覆盖历史列表。

## 6. 依赖与数据流

```text
Session user messages ──> ChatTuiApp._input_history
                               │
Up/Down Binding ───────────────┴──> TextArea.load_text + move_cursor(end)

submit ──> generation + started_at ──> Worker
                    │
                    └──> request Timer ──> activity-bar
                              │
success/error/cancel ─────────┴──> stop + clear
```

依赖仍是 `TUI -> Runtime`。Textual Timer 和 Widget 类型不越过 TUI 边界。

## 7. 测试设计

在 `tests/test_tui.py` 使用现有 headless Pilot：

### Timer

- 初始栏为空且位于 prompt 之前。
- 阻塞 Runner 启动后立即出现 `思考中`、`0.0 秒`、`Esc 取消`。
- 使用可变 `ManualClock` 推进时间并等待 interval，断言显示更新。
- 成功、`ChatRuntimeError`、未知异常、第一次 Esc 取消后栏为空且 `_activity_timer is None`。
- 吞掉取消的旧 Worker 不清除或重写新一代活动状态。

现有使用有限迭代器 Clock 的阻塞取消测试改为可变/可重复 Clock，避免 Timer tick 消耗预设值造成时序脆弱；不弱化原断言。

### History

- 空历史的 Up/Down no-op。
- 三条输入按 newest -> oldest 和 oldest -> newest 浏览，边界停留。
- 首次 Up 前草稿在 Down 越过最新项后恢复。
- 中文、多行、重复值原样召回，光标等于 `document.end`。
- Session 恢复只提取 user 消息。
- 超时/取消输入在当前进程可召回，但 Store 保持原有原子提交行为。
- `/clear` 成功清空历史；Store clear 失败时历史不变。

## 8. 性能、安全与可靠性

- 每个活动请求最多一个 100 ms Timer，单次 tick 为 O(1) 字符串更新；空闲成本为零。
- 历史导航为 O(1)，列表只引用已有/已发送字符串。本期不设条数上限，与现有无界 Session 保持一致并在文档标明。
- UI 不新增日志、网络、文件或密钥访问。
- 活动文本是应用固定文案，不插入 Provider 原始字段。
- Timer 停止和代次校验共同防止取消后泄漏、陈旧更新和跨请求清理。

## 9. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| Timer 与可注入 Clock 竞争 | 测试偶发耗尽或耗时倒退 | 初始显示不读时钟；阻塞测试使用可重复 ManualClock |
| 旧 Worker finally 清除新请求状态 | 新活动栏提前消失 | stop 接受 expected generation 并校验 |
| Up/Down 抢占多行光标移动 | 多行编辑习惯变化 | Spec 明确，Binding 高优先级，README 提示 |
| `/clear` 失败却清空内存历史 | 状态与 Session 不一致 | 仅在 Session clear 成功后清空历史 |
| 历史随长会话增长 | 内存增长 | 本期与 Session 同量级；未来限额需新决策 |
