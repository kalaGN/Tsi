# TUI 项目自修改设计

状态：已实现（2026-08-12）
创建日期：2026-08-11

对应已确认的[需求](../spec/20260811-TUI项目自修改-需求.md)。

## 1. 设计目标

在不改变 `/chat` 的前提下，为本地 TUI 建立一条可审计、可审批、可验证、可撤销的 Coding Agent
执行链。模型只能调用显式注册的 Workspace 工具；只读操作自动执行，任何文件写入都必须先由
宿主生成完整 Diff，并在 Textual Modal 中得到本地用户确认。

本设计优先保证：

1. 用户已有工作区内容不会被静默覆盖。
2. 模型不能把路径、命令或 Tool 参数变成越权执行入口。
3. TUI 与 HTTP 继续复用同一 Runtime，但使用不同 Registry 和 Tool Loop 策略。
4. 工具失败是模型可处理的结构化结果；取消和未知错误仍保持现有安全边界。
5. 不引入第三方依赖、后台服务、数据库或通用插件系统。

## 2. 当前事实

- `tools/contracts.py` 只有 Provider 中立定义、调用和结果，没有副作用等级或审批契约。
- `ToolRegistry.execute()` 在解析 JSON 后直接调用 `Tool.invoke()`，所有已注册工具都会自动执行。
- `run_tool_loop()` 固定最多 5 个模型步骤、每步 4 个调用，没有总调用数或审批上下文。
- `run_chat_messages()` 支持注入 Registry，但 `ChatSession` 没有保存或传递 Registry。
- TUI 的聊天请求运行在 Textual Worker 中；`App.push_screen_wait()` 可以安全地从该 Worker 等待 Modal 结果。
- Provider 适配器只序列化 Tool 的 `name/description/parameters`，因此宿主内部风险字段无需进入上游协议。
- Session 只提交最终 user/assistant，Provider Turn 内的工具调用不会写入会话文件。
- 模型 HTTP 请求日志保存完整续轮 Body，文件正文、Patch 参数和工具结果可能明文进入本地日志。
- 当前工作区已经在 `v0.1.0` 建立可恢复基线。

## 3. 总体架构

```text
python -m app.tui
  -> capture cwd once
  -> WorkspacePolicy(root)
  -> create_workspace_registry(policy, journal, command_runner)
  -> ChatTuiApp
       -> ChatSession(registry, WORKSPACE_LOOP_LIMITS)
       -> ChatSession.send(on_tool_approval=app callback)
       -> run_chat_messages(registry, limits, approval handler)
       -> run_tool_loop
            -> Provider Turn emits ToolCall
            -> ToolRegistry parses and validates
               -> read-only: invoke directly
               -> mutating: preview -> TUI Modal -> invoke or deny
            -> ToolResult returns to the same Provider Turn
       -> final assistant message persists

POST /chat
  -> run_chat
  -> create_default_registry(get_current_time only)
  -> DEFAULT_TOOL_LOOP_LIMITS(5 steps)
```

依赖方向保持为：

```text
TUI -> Session -> Runtime -> ToolLoop -> ToolRegistry -> Workspace Tools
HTTP -> Runtime -> ToolLoop -> ToolRegistry -> GetCurrentTimeTool
```

`tools/` 不导入 Textual、FastAPI、Runtime 或具体 Provider；审批通过异步中立回调反转到 TUI。

## 4. Tool 契约设计

### 4.1 风险与参数上限

在 `tools/contracts.py` 增加：

```python
class ToolEffect(str, Enum):
    READ_ONLY = "read_only"
    MUTATING = "mutating"


@dataclass(frozen=True)
class ToolDefinition:
    name: str
    description: str
    parameters: Mapping[str, object]
    effect: ToolEffect = ToolEffect.READ_ONLY
    max_argument_bytes: int = 8 * 1024
```

- 默认值保持 `get_current_time` 和 HTTP 行为不变。
- Registry 将 `max_argument_bytes` 限制在 `1..64 KiB`，防止 Tool 自行声明无界载荷。
- Provider 的阿里云/DeepSeek转换函数继续只发送前三个公开字段，并增加测试防止风险字段外泄。
- `apply_workspace_edits` 使用 64 KiB，其余工具继续使用 8 KiB。

### 4.2 审批请求

```python
@dataclass(frozen=True)
class ToolApprovalRequest:
    call_id: str
    tool_name: str
    title: str
    paths: tuple[str, ...]
    diff_text: str
    fingerprint: str


ToolApprovalHandler = Callable[[ToolApprovalRequest], Awaitable[bool]]
```

- `paths` 必须是已经验证的相对路径。
- `diff_text` 是有界完整 Diff；超过上限时写工具在审批前拒绝，不展示截断 Diff。
- `fingerprint` 对 Tool 名和规范化变更内容做 SHA-256，只用于同一请求内去重。
- 审批对象不包含绝对根目录、文件原始快照或可执行回调。

### 4.3 Mutating Tool 两阶段接口

保留现有 `Tool.invoke()`，另增加只供写工具实现的运行时可检查 Protocol：

```python
@runtime_checkable
class ApprovalTool(Tool, Protocol):
    async def preview(
        self,
        call_id: str,
        arguments: Mapping[str, object],
    ) -> ToolApprovalRequest:
        ...
```

Registry 初始化时验证：`MUTATING` Tool 必须实现 `ApprovalTool`；`READ_ONLY` Tool 不允许请求审批。

执行顺序固定为：

1. 校验 Tool 名、参数字节数和 JSON object。
2. 对写 Tool 调用 `preview()`；该方法只能读取和构造计划，不能改变磁盘。
3. 没有 Approval Handler 时返回 `approval_unavailable`。
4. 同一请求已拒绝过相同 fingerprint 时直接返回 `approval_denied`，不再次弹窗。
5. 等待 Handler；拒绝返回 `approval_denied`。
6. 确认后调用原 `invoke()`；Tool 必须重新执行路径、哈希和精确替换校验，消除审批期间的 TOCTOU。

### 4.4 安全错误

新增固定错误码，正文由 Registry 白名单映射：

```text
invalid_arguments
unknown_tool
execution_failed
result_too_large
approval_unavailable
approval_denied
protected_path
workspace_conflict
check_timeout
check_unavailable
```

Workspace Tool 通过只携带枚举码的 `ToolRejectedError` 报告预期失败；内部异常、绝对路径和正文不进入
ToolResult。`asyncio.CancelledError` 继续原样传播。

## 5. Tool Registry 与执行上下文

新增请求局部上下文：

```python
@dataclass
class ToolExecutionContext:
    approval_handler: ToolApprovalHandler | None = None
    denied_fingerprints: set[str] = field(default_factory=set)
```

- `run_tool_loop()` 每轮用户请求创建一个 Context，并传给 `registry.execute()`。
- Registry 本身仍是冻结注册表，可跨 TUI 多轮复用；审批拒绝集合不会跨请求泄漏。
- 多个 ToolCall 继续串行执行，避免同时弹出多个 Modal 或并发写同一 Workspace。
- 每个 Tool 事件继续使用 Provider request ID 和 call ID 记录。
- 增加 `llm_tool_approval` 日志，只记录 Tool 名、决定、文件数、Diff 字符数和耗时，不另存 Diff 正文。

## 6. Tool Loop 策略

把模块常量收敛为不可变策略：

```python
@dataclass(frozen=True)
class ToolLoopLimits:
    max_model_steps: int
    max_tool_calls_per_step: int
    max_total_tool_calls: int


DEFAULT_TOOL_LOOP_LIMITS = ToolLoopLimits(5, 4, 16)
WORKSPACE_TOOL_LOOP_LIMITS = ToolLoopLimits(41, 4, 40)
```

- HTTP 和未显式传参的调用使用 `DEFAULT_TOOL_LOOP_LIMITS`，保持第 5 步不执行无后续消费机会的 Tool。
- TUI `ChatSession` 使用 `WORKSPACE_LOOP_LIMITS`。
- TUI 为最多 40 次串行工具调用预留第 41 个模型步骤生成最终回答，兼容每步只返回一个工具调用的 Provider；工具调用硬上限仍为 40。
- 总调用数在执行前检查；达到任一边界都返回现有 `tool_limit`。
- 审批等待不增加模型步骤或 Tool 次数；确认后的实际执行计为该次 ToolCall。
- 不增加自动重试；检查失败作为 ToolResult 由模型决定是否继续。

## 7. Workspace Policy

新增 `tools/workspace.py`，由不可变 `WorkspacePolicy` 集中处理路径：

```python
@dataclass(frozen=True)
class WorkspacePolicy:
    root: Path

    def resolve_read_file(self, relative_path: str) -> Path: ...
    def resolve_read_directory(self, relative_path: str) -> Path: ...
    def resolve_write_file(self, relative_path: str, *, creating: bool) -> Path: ...
```

### 7.1 根目录和路径算法

- 启动时用 `Path.cwd().resolve(strict=True)` 捕获根目录，并确认是普通目录。
- 参数必须是非空相对路径；拒绝绝对路径、NUL、空组件和显式 `..`。
- 从根开始逐级 `lstat()`，任何现有组件是符号链接均拒绝。
- 解析结果再次用 `relative_to(root)` 验证包含关系。
- 读取目标必须是普通文件/目录；创建文件要求父目录已经存在且为非符号链接目录。
- 第一版不隐式创建目录，也不接受文件 URL、glob 作为写目标。

### 7.2 保护规则

禁止读写的顶层或生成路径：

```text
.env / .env.* / .git/ / .venv/ / data/ / logs/
__pycache__/ / .pytest_cache/
```

额外禁止写入：

```text
AGENTS.md
docs/rules/**
.gitignore
requirements.txt
tools/contracts.py
tools/registry.py
tools/workspace.py
tools/project_checks.py
tools/__init__.py
app/runtime/chat.py
app/runtime/session.py
app/runtime/tool_loop.py
app/tui/__main__.py
app/tui/approval.py
app/tui/application.py
app/tui/state.py
```

- `.env.example` 按已确认 Spec 也属于 `.env.*`，第一版不读取。
- 规则使用规范化相对路径组件匹配，不使用容易误判的字符串前缀。
- 保护集合是代码常量，不读取 Workspace 配置覆盖。

## 8. 只读 Workspace Tools

### 8.1 公共边界

- 单个可读文件最大 1 MiB；读取结果受 Registry 32 KiB ToolResult 上限约束。
- 路径和匹配结果按 Unicode 相对路径排序，分页 cursor 是非负整数偏移。
- cursor 超出当前结果集返回空页而不是异常。
- 所有文本严格 UTF-8；包含 NUL 或解码失败视为不可读文本。
- 输出只包含相对路径，不包含根目录绝对路径。

### 8.2 `list_workspace_files`

- 默认 path 为 `.`，depth 范围 `1..5`，每页最多 200 条。
- 使用标准库遍历，不跟随链接；遇到受保护目录直接剪枝。
- 输出 `path/type`，type 只可能为 `file` 或 `directory`。

### 8.3 `search_workspace_text`

- query 是长度 `1..256` 的字面量，不解释为正则。
- 可选 glob 使用 `PurePosixPath.match()`，只筛选已通过 Policy 的候选路径。
- 最多扫描 2,000 个、每个不超过 1 MiB 的允许文本文件；每页最多 100 个匹配。
- 单行输出截断到 500 字符并标明截断，避免单行耗尽结果预算。

### 8.4 `read_workspace_file`

- start_line 从 1 开始，max_lines 范围 `1..400`。
- 返回 `path/sha256/total_lines/start_line/end_line/content`。
- 保留原换行，不为展示重写内容；空文件返回空 content 和 0 行。

### 8.5 Git 只读工具

- `get_workspace_git_status` 固定执行 `git -c core.quotepath=false status --short --untracked-files=all`。
- `get_workspace_git_diff` 分别执行未暂存和 `--cached` Diff，并固定 `--no-ext-diff --no-color`。
- Git 使用 `asyncio.create_subprocess_exec`，`cwd=root`、`GIT_OPTIONAL_LOCKS=0`，不使用 Shell。
- 可执行文件在启动时通过 `shutil.which("git")` 固定；不存在或根目录非仓库返回 `check_unavailable`。
- stdout/stderr 有界，Git 错误只返回有限输出和退出码，不泄漏环境变量。

## 9. 写入、Journal 与撤销

### 9.1 Edit 数据

`apply_workspace_edits` 接受最多 10 个不同目标：

```json
{
  "edits": [
    {
      "mode": "replace",
      "path": "app/example.py",
      "expected_sha256": "...",
      "old_text": "old",
      "new_text": "new"
    },
    {
      "mode": "create",
      "path": "tests/test_example.py",
      "content": "..."
    }
  ]
}
```

- 同一路径不得在一个批次出现两次。
- replace 的 hash 必须匹配完整原始 bytes，old_text 必须非空且仅出现一次。
- create 的目标必须不存在，父目录必须已存在。
- 结果文件必须是 UTF-8 文本、无 NUL，单文件最大 256 KiB。
- 参数上限 64 KiB、完整 Diff 上限 64 KiB；超过即在审批前拒绝。

### 9.2 Preview

- 在进程内锁下读取所有原始 bytes，校验全部 Edit 后构造候选 bytes。
- 使用 `difflib.unified_diff()`，路径固定显示为 `a/<relative>` 与 `b/<relative>`。
- Preview 保存规范化 Edit、原始/候选 hash 和 Diff fingerprint，但不写磁盘。
- `invoke()` 不信任旧 Preview；确认后重新执行同样校验并要求 fingerprint 一致。

### 9.3 Commit 到磁盘

- 每个候选文件先写入同目录唯一临时文件，flush 并 `fsync()`。
- replace 保留原文件权限；create 使用普通文本文件权限。
- 所有临时文件准备完成后按稳定路径顺序 `os.replace()`。
- 每次替换后记录已应用项；后续失败时用内存原始 bytes 和同样原子流程恢复。
- 清理临时文件失败不改变主结果，但不把临时绝对路径返回模型。
- 批次成功后创建随机 `change_id`，Journal 保存有限原始 bytes、结果 hash、路径和反向 Diff。

### 9.4 Journal

- `WorkspaceChangeJournal` 只存在当前进程内，最多保留最近 10 个成功批次。
- 每个记录总快照最大 512 KiB；达到上限前拒绝新写入，不静默丢弃尚可撤销记录。
- 撤销只允许最近未撤销记录，避免跨批次依赖顺序被破坏。
- 撤销前要求每个当前目标 hash 等于记录的结果 hash；否则返回 `workspace_conflict`。
- 对 replace 恢复原 bytes；对 create 删除仅由该记录创建且 hash 未变化的文件。
- 撤销也先生成完整反向 Diff并走相同审批回调。

## 10. 项目检查

新增 `tools/project_checks.py`，`run_project_check` 只接受一个枚举 name：

| name | 固定 argv |
| --- | --- |
| `compile` | `.venv/bin/python -m compileall -q main.py app tools tests` |
| `test_all` | `.venv/bin/python -m pytest -q`，环境固定 `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` |
| `pip_check` | `.venv/bin/python -m pip check` |
| `diff_check` | `git diff --check` |

- `.venv/bin/python` 允许使用 Python 虚拟环境的标准符号链接；Tool 创建时解析并固定其真实普通可执行文件，执行前重新核对解析路径与设备/inode，链接被替换时返回 `check_unavailable`。
- 不接收额外 flags、路径、keyword、环境或工作目录参数。
- 每次最多运行一个检查，超时 120 秒，stdout+stderr 最多 32 KiB。
- 子进程环境从固定安全字段构造，明确移除 `DASHSCOPE_API_KEY`、`DEEPSEEK_API_KEY` 等密钥。
- 超时先 terminate，有限等待后 kill；取消同样清理子进程并传播取消。
- 正常非零退出返回 `{name, exit_code, duration_ms, output, truncated}`，`ok` 仍为 Tool 调用成功，便于模型读取失败细节。

## 11. TUI 审批界面

新增 `app/tui/approval.py`：

- `ToolApprovalScreen(ModalScreen[bool])` 使用 `SelectableRichLog` 展示纯文本 Diff。
- 显示标题、文件列表、应用按钮和拒绝按钮；拒绝按钮默认聚焦。
- `y`/应用按钮返回 `True`，`n`、`Esc`、拒绝按钮和 Screen 关闭返回 `False`。
- Modal 屏蔽主 Screen 的 Enter、上下历史和双 Esc 绑定。
- Diff 只展示，不解析 Markdown、不执行 ANSI/OSC 内容，并支持现有选择复制能力。

`ChatTuiApp` 增加：

```python
async def _approve_tool(self, request: ToolApprovalRequest) -> bool:
    self.run_status = RunStatus.AWAITING_APPROVAL
    approved = await self.push_screen_wait(ToolApprovalScreen(request))
    self.run_status = RunStatus.THINKING
    return approved
```

- `_run_prompt()` 已在 Textual Worker 中，符合 `push_screen_wait()` 的调用约束。
- `ChatRunner`、`ChatSession.send()`、`run_chat_messages()` 和 `run_tool_loop()` 增加可选审批回调。
- 审批期间活动栏显示“Awaiting approval · Esc 拒绝”，总耗时仍从用户发送时连续计算。
- Worker 取消时 Modal 被安全解除且没有写入；请求代次继续阻止陈旧输出。
- Status Bar 增加 `Workspace: enabled`，不显示绝对路径。

## 12. TUI 装配与 HTTP 隔离

`app/tui/__main__.py`：

1. 捕获并严格解析 `startup_directory`。
2. 读取同一目录 `AGENTS.md`。
3. 创建 `WorkspacePolicy`、Journal 和 Workspace Registry。
4. 通过 `_create_app()` 注入 Registry 与 `WORKSPACE_LOOP_LIMITS`。

`ChatSession` 构造和 `load()` 增加可选 `registry/loop_limits`，发送时透传；默认 `None` 保持现有测试、
直接调用和 HTTP 语义。`ChatTuiApp` 自建 Session 时使用注入值；测试仍可注入 fake runner/session。

HTTP 隔离以测试锁定：

- `create_default_registry()` 仍只包含 `get_current_time`。
- `app/application.py`、`app/routers/` 不导入任何 Workspace 模块。
- `/chat` Provider 请求的 tools 数组不出现 Workspace 名称。
- `/chat` 仍使用 5 步默认策略和原错误映射。

## 13. 状态、日志与持久化

- `RunStatus` 增加 `AWAITING_APPROVAL = "Awaiting approval"`。
- Tool Approval、Edit Preview 和 Journal 都是请求/进程内状态，不写入 Session JSON。
- 已确认并成功写入的文件在模型随后失败或用户取消时保留；TUI 显示中立错误，用户可新开一轮要求撤销。
- 若失败发生在 Tool 还未向模型返回 `change_id` 之前，TUI 在 transcript 额外显示本轮已应用的相对路径摘要，避免用户误以为零修改。
- 当前完整 Provider 请求日志策略不变；README 追加源码和 Diff 明文风险提示。
- `llm_tool_approval` 不记录 Diff 内容；根据 2026-08-11 用户追加要求，`llm_tool_call/result` 记录完整参数和结果正文，并继续使用 request ID/call ID 关联。

## 14. 异常映射

| 场景 | 结果 |
| --- | --- |
| 参数、路径或编码非法 | ToolResult `invalid_arguments` |
| 命中保护路径 | ToolResult `protected_path` |
| 哈希变化、替换不唯一、撤销后又被编辑 | ToolResult `workspace_conflict` |
| 用户拒绝/按 Esc | ToolResult `approval_denied` |
| TUI 外调用写 Tool | ToolResult `approval_unavailable` |
| 检查命令缺失 | ToolResult `check_unavailable` |
| 检查超时 | ToolResult `check_timeout` |
| 检查退出码非零 | 成功 ToolResult，data 中 `exit_code != 0` |
| 载荷、Diff 或输出超限 | 既有有界错误，不执行写入 |
| 取消 | 原样传播 `CancelledError`，清理 Modal/子进程/临时文件 |
| 未知内部异常 | ToolResult `execution_failed`，不泄漏详情 |

这些错误不增加 `/chat` HTTP 映射；它们只作为 ToolResult 供模型继续推理。Tool Loop 自身预算耗尽仍映射为
现有 `ChatErrorCode.TOOL_LIMIT`。

## 15. 并发与性能

- TUI 仍同时只有一个 Chat Worker，Workspace 写操作再使用一个 `asyncio.Lock` 保护 preview/apply/undo。
- 文件遍历、Git、检查和写盘属于本地 I/O；第一版不增加线程池、队列或后台 Worker。
- 目录遍历和纯文件 I/O 在当前轻量本地项目同步执行，但以文件数、文件大小和输出上限限制阻塞时间。
- Git 和项目检查使用异步子进程，避免阻塞 Textual event loop。
- 不声明未测量的响应时间；测试只验证上限、取消和不会无限读取。
- TUI 20 步/40 Tool 总预算显著高于当前对话，状态和文档明确可能增加 Token、耗时及模型费用。

## 16. 安全分析

### 16.1 Prompt Injection

源码和文档均视为模型上下文数据，文件中出现“执行命令”“忽略规则”等文本不能改变宿主 Tool 白名单、
保护路径或审批要求。安全决策只来自 Registry 和 WorkspacePolicy。

### 16.2 TOCTOU 与用户并行编辑

Preview 前和确认后各执行一次完整校验；replace 使用用户最近读取的 SHA-256，undo 使用结果 hash。
任一不一致都拒绝，不自动重读后覆盖。

### 16.3 命令注入

检查名映射固定 argv，禁止 `shell=True`、额外 flags、模型环境和自定义 cwd。Git path 使用独立 argv 元素和
`--` 分隔。

### 16.4 自我提升

第一版保护 AGENTS、Rules、依赖和 Workspace 安全实现；当前进程也不会热加载磁盘上的修改。
普通项目代码虽然可修改，但每个完整 Diff 都由本地用户确认。

### 16.5 信息泄漏

敏感目录禁止读取；ToolResult 不包含绝对路径或环境。允许源码仍会发送给所选外部 Provider，并进入当前本地
完整请求日志，这是已确认的显式风险，不在本期重构。

## 17. 测试设计

### 17.1 `tests/test_workspace_tools.py`

- 路径：正常、中文、绝对、`..`、NUL、符号链接、保护目录、非普通文件。
- 列举/搜索/读取：排序、分页、深度、glob、空文件、UTF-8、二进制、大小和结果边界。
- Git：临时仓库的 clean/tracked/untracked/staged、分页、非仓库、命令失败和无外部 diff。
- Edit：create/replace、多文件、hash、唯一替换、重复路径、大小、Diff、拒绝、TOCTOU、原子失败恢复。
- Journal：最近记录、顺序、创建文件撤销、修改冲突、上限和重复撤销。
- Check：固定 argv/env/cwd、成功、非零、超时、截断、缺失程序和取消清理。

### 17.2 `tests/test_tools.py` / `tests/test_tool_loop.py`

- 风险定义验证、per-tool 参数上限和风险字段不进入 Provider Schema。
- 只读不审批；写 Tool 无 Handler、批准、拒绝、重复拒绝和审批异常。
- 默认/Workspace 策略的模型步骤、每步调用和总调用边界。
- 审批日志不包含 Diff 或绝对路径；Tool 日志按用户追加要求记录完整参数和结果，因此可能包含允许读取的相对路径、源码或变更正文。

### 17.3 Runtime、Session、Provider 和 HTTP

- Registry、Limits 和审批 Handler 沿 `Session -> Chat -> ToolLoop` 传递。
- 写入成功后 Provider 能收到 `change_id` 并继续；工具轨迹不进入 Session。
- 两个 Provider 均能发送 Workspace Schema 和续接结果。
- `/chat` 默认 Registry 和 5 步策略回归，公开 JSON/错误不变。

### 17.4 TUI

- Modal 默认拒绝、按钮、y/n/Esc、Diff 纯文本和选择复制。
- 审批时 RunStatus、活动栏、输入锁、批准/拒绝后恢复。
- Worker 取消、Modal 关闭、陈旧回调和已应用变更失败摘要。
- 入口只捕获一次 cwd，正确注入 Workspace Registry 与策略。

## 19. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 模型覆盖用户新修改 | 高 | read hash、确认后重验、唯一替换 |
| 批次部分落盘 | 高 | 全量预校验、临时文件、稳定替换、失败恢复 |
| Prompt Injection 请求越权 | 高 | 宿主白名单、保护路径、每次写审批 |
| 检查参数命令注入 | 高 | 固定 argv、无 Shell、最小环境 |
| Modal/Worker 取消竞态 | 中 | Worker 内 wait、默认拒绝、请求代次、无批准不 invoke |
| 大仓库阻塞或输出爆炸 | 中 | 文件/扫描/结果/步骤/调用/时间上限与分页 |
| 20 步成本上升 | 中 | TUI 专属预算、总 Tool 上限、状态提示 |
| 本地日志保存源码 | 中 | 敏感路径拒绝、README 明示、日志策略不伪装为脱敏 |
| 撤销覆盖后续编辑 | 高 | 结果 hash 冲突即拒绝、仅 LIFO |

## 20. 回滚方案

代码发布前已存在 `v0.1.0` 基线。若该功能实现后出现问题：

1. 不改变任何 Session schema，因此旧版本可直接读取既有会话。
2. Workspace Journal 仅内存存在，退出 TUI 即丢弃，不需要数据迁移。
3. 移除 TUI Workspace Registry 注入后，Runtime 默认回到只读 `get_current_time`。
4. ToolDefinition 新字段有默认值，旧只读 Tool 无需迁移。
5. 可基于 `v0.1.0` 对比或回退功能代码；不会自动回滚用户已明确确认的项目文件修改。
