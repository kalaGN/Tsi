# 模型流式输出设计

状态：已完成（2026-08-11）  
创建日期：2026-08-11

对应[需求](../spec/20260811-模型流式输出-需求.md)。

## 1. 设计摘要

HTTP 与 TUI 继续共享 Chat Runtime。Provider 下方增加有界 SSE 读取边界，Provider
Turn 解析厂商事件并组装完整 `ModelStep`。Runtime 通过可选同步回调向 TUI 传递
Provider 中立的文本增量与撤销事件；HTTP 不注册回调，继续聚合返回。

```text
DeepSeek / Aliyun SSE
          |
          v
    shared post_sse
          |
          v
 Provider Turn parses + accumulates ModelStep
          |
          v
 tool loop -- delta/reset --> optional TUI observer
          |
          v
 Runtime logs one complete output and returns ChatResult
          |
          +--> HTTP: {"output_text": "complete"}
          |
          +--> Session: persist complete turn --> TUI final Markdown
```

不增加面向 HTTP 客户端的 SSE 路由，不引入 OpenAI SDK、SSE 库、后台队列或新
持久化结构。

## 2. 关键决策

### 2.1 回调不暴露 Provider 流对象

`LlmTurn.next()` 仍返回完整 `ModelStep`，但接受可选文本回调：

- Provider 私有流对象不会穿透 Runtime、Session 或 TUI。
- 工具循环仍基于完整步骤决定是否执行工具。
- HTTP 不注册回调即可自然聚合，不维护第二套 Runtime。
- 回调与 Provider 读取在同一事件循环，不引入线程或队列。

### 2.2 临时纯文本与最终 Markdown 分离

流式阶段只更新一个临时 `RichLog`，使用 `Text` 而非 Markdown。现有 100ms 活动
Timer 批量刷新累计内容，避免每个 Token 都触发完整重排。完成后清空临时区域，
复用 `_write_message("Assistant", text)` 一次性渲染最终 Markdown。

### 2.3 工具步骤撤销临时文本

Provider 在流结束前无法保证当前步骤没有工具调用。文本可先进入临时区域；若完整
步骤包含工具调用，Tool Loop 调用 `on_text_reset()`，再执行工具和下一模型步骤。
只有无工具调用的最终步骤进入 `ChatResult`、日志和 Session。

### 2.4 60 秒总体超时

在完整 `client.stream()` 生命周期外增加 Python 3.11 `asyncio.timeout(60)`，避免
持续心跳无限延长请求。HTTPX 仍保留 10 秒连接超时。超时继续映射为现有
`ProviderTimeoutError`。

## 3. 依赖方向

```text
app.tui.application
        |
        v
app.runtime.session -> app.runtime.chat -> app.runtime.tool_loop
                              |                    |
                              v                    v
                     services.llm.contracts <- LlmTurn
                              |
                  +-----------+-----------+
                  v                       v
          services.llm.deepseek   services.llm.aliyun
                  \                       /
                   +-> services.llm.http_client
```

- HTTP Client 处理认证 HTTP、SSE 帧、时限、大小限制和网络错误。
- Provider 只理解自身 JSON 事件与 Turn 私有续接状态。
- Tool Loop 只理解 `ModelStep`、文本观察器和 Registry。
- Runtime 继续负责完整日志和中立错误。
- TUI 不导入或判断 Provider 事件类型。

## 4. 中立契约

在 `app/services/llm/contracts.py` 增加：

```python
TextDeltaHandler = Callable[[str], None]
TextResetHandler = Callable[[], None]

class LlmTurn(Protocol):
    async def next(
        self,
        tool_results: Sequence[ToolResult] = (),
        *,
        on_text_delta: TextDeltaHandler | None = None,
    ) -> ModelStep: ...
```

`ModelStep`、`ChatResult`、`ChatMessage` 和 Session JSON schema 不变。

`run_tool_loop()`、`run_chat()`、`run_chat_messages()` 和 `ChatSession.send()` 增加可选
`on_text_delta`、`on_text_reset` 关键字参数，默认均为 `None`。每个模型步骤把
`on_text_delta` 传给 Turn；若步骤包含工具调用，在执行工具前调用一次 reset。

回调异常不应被映射成上游网络错误；TUI 回调只做内存追加或清空，不执行 I/O。

## 5. 共享 SSE HTTP 边界

### 5.1 接口

Provider 改用：

```python
SseDataHandler = Callable[[str], None]

async def post_sse(
    url: str,
    api_key: str,
    payload: Mapping[str, Any],
    *,
    request_id: str,
    provider: str,
    model: str,
    on_data: SseDataHandler,
) -> int: ...
```

函数在自己的 HTTPX 上下文内完整消费响应，逐事件交付按 SSE 规则拼接的 `data`
字符串，最后返回状态码，不把依赖已关闭连接的迭代器返回上层。

### 5.2 SSE 解码

- 使用 `response.aiter_bytes()` 与增量 UTF-8 decoder，支持中文跨网络 Chunk。
- 空行结束事件；兼容 `\n` 与 `\r\n`，同一事件多行 `data:` 以 `\n` 拼接。
- 忽略注释、`event:`、`id:`、`retry:`；Provider 以 JSON 的 `type` 为准。
- 空事件不回调；`data: [DONE]` 原样交给 Provider。
- 未闭合事件、非法 UTF-8 或非法字段编码抛 `ProviderInvalidResponseError`。

### 5.3 固定边界

```text
MAX_SSE_EVENT_BYTES = 64 KiB
MAX_STREAM_OUTPUT_BYTES = 1 MiB
MAX_STREAM_TOOL_ARGUMENT_BYTES = 8 KiB
TOTAL_TIMEOUT_SECONDS = 60
CONNECT_TIMEOUT_SECONDS = 10
```

Reader 限制单事件；Provider 限制完整文本和工具参数。超限作为非法响应或既有工具
载荷错误，不截断成成功内容。1 MiB 明显高于当前正常回答，仅防御异常无限流，
不作为业务容量承诺。

### 5.4 状态、日志与取消

1. 请求前记录现有 `llm_http_request`，Body 真实包含 `stream: true`。
2. 响应头后先映射 401/403 和其他非成功状态，不读取或记录错误体。
3. 成功流完整结束后记录一次 `llm_http_response`，duration 覆盖完整流。
4. 超时或连接失败记录现有 `llm_http_error`。
5. `CancelledError` 不转换、不记为网络失败；HTTPX 上下文负责关闭连接。
6. Provider 解析异常原样离开 `post_sse()`，不伪装成连接错误。

## 6. DeepSeek 解析

请求保留 Chat Completions 消息和工具结构，固定 `"stream": true`。

单个 Turn 步骤使用局部累加器：

- `content_fragments`：保存 `choices[0].delta.content`，非空时立即回调。
- `reasoning_fragments`：只用于工具续接消息，不回调、不日志、不持久化。
- `tool_call_builders[index]`：拼接 `id`、function name 和 arguments。
- `finish_reason`：保存已知完成原因。
- `done_received`：仅精确 `[DONE]` 置真。

空 `choices` 的 usage Chunk忽略；普通事件必须是 JSON object 且只处理 choice index 0。
结束时未收到 `[DONE]`、工具结构不完整或最终文本为空均为非法响应。存在工具调用时
保存完整 assistant tool message；否则标记 Turn 完成并返回最终文本。

## 7. 阿里云 Responses 解析

请求保留现有 `input` 和工具结构并增加 `"stream": true`：

- `response.output_text.delta`：追加非空 `delta` 并立即回调。
- `response.output_text.done`：保存完整文本用于一致性校验。
- `response.output_item.done`：提取完整 `function_call`。
- `response.function_call_arguments.delta/done`：若上游发送，按 item ID 组装参数。
- `response.completed`：必须存在，保存完整 Response 作为权威完成对象。
- reasoning、usage 和结构合法的非关键事件忽略。
- `response.failed`、`response.incomplete` 或非 completed 状态视为非法响应。

完成时用 `response.output` 校验工具调用；若没有参数 Delta，则使用完成对象的完整
调用。最终文本以 Delta 拼接为主，并与 done/completed 完整文本一致；完全没有文本
Delta 时允许从完成对象提取文本。

## 8. Runtime、工具与日志

```text
run_chat_messages
  -> log llm_request
  -> create Turn
  -> run_tool_loop(callbacks)
       -> Turn.next streams current step
       -> final: return ModelStep
       -> tools: reset -> execute -> next step
  -> validate final output
  -> log one complete llm_response
  -> ChatResult
```

- 不记录 Chunk、原始 SSE、reasoning 或部分文本。
- `llm_response.output_text` 仍是完整输出，字段白名单不变。
- 工具限制仍为 5 个模型步骤、每步最多 4 个工具调用。
- 任意失败不生成 `llm_response`。
- HTTP 不提供回调，仍完整消费同一流并返回现有结果。

## 9. Session 原子提交

`ChatSession.send()` 将回调透传给 Runtime，锁、取消检查、磁盘保存和内存提交顺序
保持不变：

```text
stream complete -> ChatResult -> cancellation check
                -> save complete user/assistant -> replace memory
```

流失败或取消发生在 `ChatResult` 之前，因此不会保存部分回答。若流完成但存储失败，
TUI 清空临时区域并显示存储错误，内存历史保持旧值。

## 10. TUI 展示

### 10.1 组件与刷新

在 transcript 和活动栏之间增加临时 `RichLog(id="stream-output")`。默认隐藏，首个
Delta 后显示，最高 8 行，纯文本 wrap 并自动滚动。

新增：

- `_stream_text`：当前步骤累计原文。
- `_stream_dirty`：是否有尚未绘制的内容。
- `_stream_generation`：所属请求代次。

回调只在请求代次匹配时追加或清空；现有活动 Timer 每 100ms 调用
`_flush_stream_output()`，以 `clear()` + `write(Text(buffer))` 合并刷新。

成功顺序：强制刷新最后增量 → 清空临时组件 → 最终 Markdown 写入 transcript →
最终耗时。工具 reset、失败、取消、退出和新请求均清空临时状态。请求代次保护同时
覆盖 append 与 reset，旧流不能污染或清除新请求。

### 10.2 Runner 契约

内部 `ChatRunner` 改为接收输入及两个可选回调。生产使用 `ChatSession.send()`；测试
Fake Runner 按新契约主动发送 Delta。它不是公开 API，不增加旧单参数 Fake Runner
兼容分支。

## 11. HTTP 契约

`app/routers/chat.py` 不使用 `StreamingResponse`，契约保持：

```json

200
{"output_text":"完整回答"}
```

HTTP 测试新增断言：Mock 上游 Body 是 `stream: true`，响应仍只有 `output_text`。

## 12. 测试设计

### SSE Reader

- 中文跨 Byte Chunk、LF/CRLF、多行 data、注释和空行。
- 事件/输出大小、非法 UTF-8、未闭合事件。
- 状态映射、连接异常、总体超时和取消。
- HTTP 日志只出现一次请求、完整响应或有限错误。

### Provider

- DeepSeek 文本、usage、reasoning、`[DONE]` 和工具参数跨 Chunk。
- 阿里云 delta/done/completed、工具完成对象和一致性校验。
- 缺少终止、非法 JSON、空回答、超限和完成后重复调用。

### Runtime、Session 与 TUI

- 回调顺序与最终文本一致，工具步骤触发 reset。
- HTTP 无回调仍聚合，日志只有一次完整输出。
- Session 失败或取消不提交半轮。
- TUI 首 Delta 显示、100ms 合并、完成 Markdown、工具 reset、取消和陈旧请求清理。
- 中文、多行与 Markdown 半成品流中保持纯文本。

## 14. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| UTF-8 跨 Chunk | 中文乱码 | 增量 decoder 与分块测试 |
| 工具参数跨事件 | 错误调用 | 按 index/item ID 组装并严格校验 |
| 工具步骤先出文本 | 残留中间内容 | Tool Loop reset |
| 心跳绕过读超时 | 请求无限占用 | 60 秒整体 timeout |
| 高频 Token 重排 | CPU 增长 | 100ms 合并纯文本刷新 |
| 取消后旧 Chunk 写回 | 污染新请求 | Worker + generation 双保护 |
| 部分输出落盘 | 会话损坏 | 仅完整 ChatResult 后保存 |
| 缺少结束事件 | 截断被当成功 | 强校验 `[DONE]` / completed |

## 15. 回滚

本次不修改数据格式。若流式协议不稳定，整体回滚该功能提交，Provider 恢复
`post_json()` 与 `stream: false`；`.env`、Session 和 HTTP 客户端无需迁移。不得保留
“部分 Provider 流式、部分 Runtime 非流式”的中间回滚状态。

## 17. 设计确认项

1. 接受 64 KiB 单 SSE 事件、1 MiB 单轮文本和 8 KiB 工具参数上限。
2. 接受 60 秒作为完整流读取的总体超时，而不是每个 Chunk 重新计时。
3. 接受临时区域最高 8 行、100ms 合并刷新，成功后再替换为 Markdown。
4. 接受内部 `ChatRunner` 测试契约升级，不保留旧 Fake Runner 兼容代码。

以上四项确认后生成任务清单并进入测试先行实施。
