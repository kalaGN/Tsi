# 系统提示词设计

状态：已完成（2026-08-11）
创建日期：2026-08-11

对应[需求](../spec/20260811-系统提示词-需求.md)。

## 1. Design Summary

新增一个标准库文件读取边界，把 TUI 启动目录直属 `AGENTS.md` 转换为可选系统提示词。
系统提示词经 TUI 装配到 `ChatSession`，每轮由 Runtime 在持久化历史之前添加唯一
`ChatRole.SYSTEM` 消息。Provider 继续统一把中立消息映射到厂商请求体，不需要新增厂商专属
配置或第二套调用路径。

```text
TUI startup cwd/AGENTS.md
          |
          v
load_system_prompt (UTF-8, <= 32 KiB)
          |
          v
ChatTuiApp -> ChatSession(system_prompt)
                         |
                         v
run_chat_messages(history, system_prompt)
                         |
                [system] + [user/assistant history] + [user]
                         |
               +---------+---------+
               v                   v
      Aliyun Responses      DeepSeek Chat
```

HTTP `/chat` 仍调用 `run_chat()`，不提供 `system_prompt`，因此不会读取或发送宿主机文件。

## 2. File Loading Boundary

新增 `app/runtime/system_prompt.py`：

```python
MAX_SYSTEM_PROMPT_BYTES = 32 * 1024

class SystemPromptLoadError(Exception): ...

def load_system_prompt(startup_directory: Path) -> str | None: ...
```

- 固定目标为 `startup_directory / "AGENTS.md"`。
- 文件不存在返回 `None`；空白正文返回 `None`。
- 以二进制方式最多读取 `limit + 1` 字节，在解码前阻止超限内容进入内存上下文。
- 严格 UTF-8 解码；目录、读取失败、非法编码或超限统一抛出不含路径和正文的安全错误。
- 返回非空文件原文，不 strip，保证发往模型的内容与文件完全一致。

启动入口先捕获 `Path.cwd()`，再读取一次。错误不让进程崩溃，而是传给 TUI 显示并阻止
普通模型请求；`/quit` 与 `/clear` 仍可使用。

## 3. Neutral Message Contract

`ChatRole` 增加 `SYSTEM`。统一验证规则改为：

1. 可选一条非空 system 消息，只能位于索引 0。
2. system 后必须存在奇数条对话消息。
3. 对话部分仍严格按 user/assistant 交替并以 user 结尾。
4. system 出现在其他位置、重复、空白或没有 user 请求均拒绝。

`run_chat_messages(..., system_prompt=None)` 在调用 Provider 前创建请求局部元组；不修改调用方
的历史对象。`run_chat()` 不暴露系统提示词参数，保护 HTTP 当前契约。

## 4. Session Isolation

`ChatSession` 构造与 `load()` 接受可选 `system_prompt`，但：

- `messages` 属性继续只返回 user/assistant 历史。
- `send()` 只把 `system_prompt` 传给 Runtime；成功提交仍基于原 `candidate_request`。
- `SessionStore` schema 和校验保持不变，system 角色写入或恢复仍被拒绝。
- `clear()` 只清消息和文件，不改变进程启动时加载的系统提示词。

增加只读 `system_prompt_loaded` 属性供 TUI 状态展示，不暴露正文。

## 5. TUI Behavior

`ChatTuiApp` 接收 `system_prompt` 和安全的 `system_prompt_error`：

- 自行创建 Session 时把提示词传入；测试注入 Session 时从 Session 状态派生是否已加载。
- 状态栏增加 `AGENTS: loaded|none|error`。
- 挂载时只显示读取错误，不展示正文或绝对路径。
- `/quit`、`/clear` 优先处理；其他输入在存在读取错误时直接报告错误，不启动 Worker、不记输入历史。

## 6. Logging and Security

- Runtime 的 `llm_request.input_text` 继续只记录当前最后一条 user 输入。
- 两家 Provider 的完整 `llm_http_request.request_body` 会真实包含 system 消息，符合现有日志契约。
- 不记录额外的系统提示词专用事件，不在状态栏或 transcript 回显正文。
- 不解析或执行 Markdown、命令、链接和工具描述；模型是否遵循提示词不构成代码级权限。

## 7. Risks and Rollback

- 风险：32 KiB 项目规则会增加每轮输入 Token；通过启动时固定上限控制。
- 风险：正文随完整请求日志明文落盘；README 明确警告不得放置敏感信息。
- 风险：文件启动后变化不会生效；状态栏明确只表示本次启动是否加载。
- 回滚：移除 loader、system role 与 Session 参数即可；Session schema 无迁移，已有历史不受影响。
