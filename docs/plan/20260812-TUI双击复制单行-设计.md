# TUI 双击复制单行设计

状态：已完成（2026-08-12）
创建日期：2026-08-12

对应已确认的[需求](../spec/20260812-TUI双击复制单行-需求.md)。

## 1. 方案

在 `SelectableRichLog` 增加默认关闭的 `copy_line_on_double_click` 构造参数，并处理 Textual
公开 `Click` 事件。`ChatTuiApp` 只为 `#transcript` 传入 `True`，因此 `#stream-output` 和审批
Diff 保持现有拖选复制语义。

双击时按以下顺序执行：

```text
Click(chain=2, button=1)
  -> event.get_content_offset(widget)
  -> line_index = scroll_offset.y + content_offset.y
  -> 校验当前渲染行存在且非空
  -> Screen selection 收敛为当前行
  -> app.copy_to_clipboard(line.text)
```

Textual `RichLog` 默认会在双击时全选整个组件。组件的公开 `on_click` Handler 在内置处理之后
执行，因此无论命中有效行还是空白，都要覆盖或清空默认全选结果，避免后续 `Ctrl/Cmd+C` 误复制
整个对话记录。

## 2. 边界

- 只响应左键双击，单击、三击和拖选沿用 Textual 现有行为。
- 点击边框、内边距、空行或行范围外时清除本次默认全选，但不改剪贴板。
- 复制 `Strip.text`，即 RichLog 的当前渲染行文字；不访问 Session 或 Markdown 原文。
- 使用 RichLog 纵向滚动偏移；横向滚动不改变“整行”定义。
- 不增加依赖、Toast、系统消息或剪贴板命令。

## 3. 测试

- 普通中文第二行双击只复制第二行，选区也只覆盖第二行。
- 设置滚动偏移后双击视口首行，复制对应的内容行。
- 双击空白不覆盖已有剪贴板且不留下全选。
- `#stream-output` 未启用该选项；现有拖选复制测试继续通过。

## 4. 风险与处理

| 风险 | 处理 |
| --- | --- |
| 双击坐标包含 border/padding | 使用 `get_content_offset()`，非内容区直接拒绝 |
| 滚动后复制错行 | 内容纵坐标加 `scroll_offset.y` |
| Textual 默认双击全选残留 | 有效行改为单行 Selection，无效位置清除 Selection |
| Markdown 源码意外复制 | 只读取 `self.lines[*].text` |
