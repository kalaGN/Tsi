# Tsi 助手项目命名设计

## 状态

已完成（2026-09-01）。

## 概述

在不改变目录、模块、启动命令和 HTTP 契约的前提下，把正式展示名称 `Tsi 助手` 接入 FastAPI 元数据、Textual TUI 和当前项目文档。改动只落在已有展示边界，不新增名称配置服务或环境变量。

## 当前事实

- README 一级标题为 `FastAPI Demo`。
- `ChatTuiApp.TITLE` 为 `FastAPI Agent TUI`，同时用于终端窗口标题和 `#title` 顶部组件。
- FastAPI 使用 `FastAPI()` 默认元数据，OpenAPI `info.title` 为框架默认值。
- Rules 索引和规则正文仍以 `FastAPI Demo` 指代当前项目。
- 历史 Spec 中保留旧名称和 `demo/` 目录示意，它们是历史记录而非当前展示入口。

## 架构决策

### 1. 在展示边界直接声明名称

```text
FastAPI(title="Tsi 助手") -> Swagger / OpenAPI info.title
ChatTuiApp.TITLE = "Tsi 助手" -> 终端窗口 + #title
README / AGENTS / Rules / Knowledge -> 当前项目说明
```

当前只有两个运行时展示消费者，不抽取共享 `branding.py`，避免为单一常量增加跨层依赖。

### 2. 保持运行标识不变

`demo/`、`main.py`、`app` 包、模块路径、环境变量、会话文件和日志路径均属于运行或存储标识，不因展示名称变化而重命名。

### 3. 历史文档不迁移

`docs/spec/`、`docs/plan/`、`docs/tasks/` 中本次变更之前的文件继续记录当时名称。只更新当前入口文档、索引中新增的本次变更状态，以及 Rules/Knowledge 的当前事实。

## 依赖关系

```text
名称契约测试
  ├─ FastAPI 元数据实现
  ├─ TUI 标题实现
  └─ 当前文档同步
         └─ 全量门禁与旧名称范围审计
```

运行时代码两条路径互相独立；文档同步依赖最终名称已经固定。为保持每一步可验证，先增加失败测试，再分别修改 HTTP 和 TUI。

## 测试方案

HTTP 测试：

```python
assert application_app.title == "Tsi 助手"
assert client.get("/openapi.json").json()["info"]["title"] == "Tsi 助手"
```

TUI 测试：

```python
assert app.TITLE == "Tsi 助手"
assert str(app.query_one("#title", Static).content) == "Tsi 助手"
```

完整门禁：

```bash
.venv/bin/python -m compileall -q main.py app tools tests
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -m pytest -q
.venv/bin/python -m pip check
git diff --check
```

## 异常、安全与性能

- 仅修改静态元数据和文档，不新增异常路径。
- 不读取环境变量，不涉及密钥、用户输入或日志正文。
- 名称设置在应用构造期完成，不增加请求热路径开销。
- OpenAPI 标题会变化，但路径、Schema、请求响应和状态码不变。

## 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 把展示改名误扩展为目录迁移 | 启动脚本和导入失效 | 明确禁止重命名目录、包和命令；差异审计 |
| 遗漏 TUI 或 Swagger | 用户看到名称不一致 | 两个运行时边界分别增加测试 |
| 批量替换污染历史文档 | 历史决策失真 | 只编辑当前文档白名单，不做全仓机械替换 |
| OpenAPI 元数据变化影响快照 | 文档消费者看到新标题 | 仅标题按明确需求变化，Schema 其余契约由既有测试保护 |

## 回滚

回退 `FastAPI(title=...)`、`ChatTuiApp.TITLE` 和当前文档文本即可；无数据迁移、配置迁移或兼容期。
