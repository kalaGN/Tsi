# Skill 系统设计

状态：已完成（2026-09-02）
创建日期：2026-09-02
对应需求：[Skill 系统需求](../spec/20260902-Skill系统-需求.md)

## 1. 设计目标

在不改变 HTTP `/chat`、Provider 协议和 Session schema 的前提下，为本地 TUI 增加与
Codex 共用 `.agents/skills/` 的 Skill 系统：启动时发现 Skill 元数据，按需加载说明和
资源，并在每次本地审批后执行 Skill 内的 Python 或 POSIX Shell 脚本。

第一版优先保证四件事：

1. Skill 包符合 Codex 使用的 Agent Skills 格式，不产生 Tsi 私有格式。
2. Catalog、说明和资源按需披露，不一次占满模型上下文。
3. 脚本只能由专用工具执行，不能演变为任意 Shell。
4. 明确承认第一版没有 OS 沙箱，用逐次审批、固定解释器、最小环境、超时和输出边界降低风险。

## 2. 当前架构约束

- TUI 在 `app/tui/__main__.py` 捕获一次启动目录，并据此加载直属 `AGENTS.md`、创建
  `WorkspacePolicy` 和 TUI 专属 Tool Registry。
- `app/runtime/chat.py` 把一条可选 system 消息、会话消息和 Registry definitions 交给
  Provider；工具由 `app/runtime/tool_loop.py` 串行执行。
- 根目录 `tools/` 定义 Provider 中立工具契约、Registry 和 Workspace 工具，不得反向依赖
  Runtime、Textual 或具体 Provider。
- 当前 `ToolApprovalRequest` 和 `ToolApprovalScreen` 只表达文件 Diff；脚本执行不能伪装成
  Diff，也不能复用写文件审批文案。
- TUI 已有请求级审批回调、`Awaiting approval` 状态、Esc 拒绝、工具日志和取消代次控制。
- HTTP 使用独立默认 Registry，只含 `get_current_time`，不得加载宿主 Skill。

## 3. 总体架构

```text
TUI 启动目录
  ├── AGENTS.md
  └── .agents/skills/*/SKILL.md + resources
               │
               v
        SkillCatalogLoader
        ├── PyYAML 安全解析
        ├── 路径/大小/符号链接校验
        └── 不可变 SkillCatalog 快照
               │
        ┌──────┴───────────────────────────┐
        v                                  v
compose_system_prompt              create_workspace_registry
AGENTS + Skill Catalog             + load_skill
        │                           + read_skill_resource
        │                           + run_skill_script
        └──────────────┬───────────────────┘
                       v
                 ChatSession / Runtime
                       │
                       v
               Provider Tool Calling
                       │
              run_skill_script preview
                       │
                       v
               ScriptApprovalScreen
                 reject / approve
                       │
                       v
              bounded subprocess_exec
```

依赖方向保持为：

```text
app.tui -> app.runtime.system_prompt -> tools.skills
app.tui -> tools.workspace -> tools.skills -> tools.contracts
app.runtime -> tools registry
tools -X-> app.runtime / app.tui / provider
```

Skill 的发现、快照和工具都放在根目录 `tools/skills.py`。这样 system prompt 与 Registry 共享
同一个不可变 Catalog，同时避免 `tools/` 反向依赖 `app/runtime/skills.py`。

## 4. 依赖与版本

在 `requirements.txt` 增加：

```text
PyYAML==6.0.3
```

选择依据：PyYAML 6.0.3 是设计时 PyPI 最新稳定版本，支持 Python 3.11。代码只使用
`SafeLoader` 派生类，不使用 `yaml.load()` 默认 Loader、`FullLoader` 或 `UnsafeLoader`。

自定义 `UniqueKeySafeLoader` 在构造 Mapping 前检测重复键；任意重复键、Python 对象标签或
非 Mapping Frontmatter 都返回统一 `SkillLoadError`，不泄露文件正文和绝对路径。

## 5. Skill Catalog 与快照模型

### 5.1 数据结构

`tools/skills.py` 定义不可变数据对象：

```python
@dataclass(frozen=True)
class SkillResourceSnapshot:
    path: str
    sha256: str
    content: bytes
    is_text: bool

@dataclass(frozen=True)
class SkillSnapshot:
    name: str
    description: str
    relative_entrypoint: str
    skill_root: Path
    skill_markdown: str
    resources: Mapping[str, SkillResourceSnapshot]

@dataclass(frozen=True)
class SkillCatalog:
    skills: Mapping[str, SkillSnapshot]
```

- 对外暴露的 Mapping 使用只读包装，避免工具运行期间被修改。
- `relative_entrypoint` 形如 `.agents/skills/example/SKILL.md`，可以安全进入 Catalog。
- `skill_root` 只在本地工具内部使用，不进入模型结果、TUI 错误或日志摘要。
- 资源保存启动时字节快照和 SHA-256；读取工具返回快照，执行工具则在审批前后比较磁盘哈希。

### 5.2 发现流程

1. 定位 `<startup_directory>/.agents/skills`。
2. 缺失或空目录返回空 Catalog，不注册 Skill 工具，也不生成空提示词区块。
3. 按目录名字典序枚举一层 Skill；拒绝根目录、Skill 目录和入口文件符号链接。
4. 有界读取 `SKILL.md`，拆分首部 `---` YAML 和 Markdown 正文。
5. 使用 `UniqueKeySafeLoader` 解析并验证 `name`、`description`；允许但不解释其他字段。
6. 遍历 Skill 根目录下除 `SKILL.md` 外的普通资源；拒绝任一路径节点符号链接，记录二进制
   资源但只允许文本资源进入模型。
7. 校验数量、单文件、单 Skill 总量和 Catalog 大小；任一失败使整批 Skill 不可用。
8. 返回一次启动进程内不变的 `SkillCatalog`。

`name` 与目录名必须完全一致。Codex 虽允许同名 Skill 同时出现，但 Tsi 第一版只有一个项目
来源；重复名称意味着目录或元数据不一致，按配置错误处理。

### 5.3 错误隔离

`SkillLoadError` 的用户消息固定为：

```text
Project skills are unavailable
```

TUI 启动消息显示该错误，但继续使用有效 `AGENTS.md`、现有 Workspace Registry 和会话。
不把绝对路径、YAML 异常、文件正文或底层 `OSError` 显示给用户或模型。

## 6. 渐进式上下文

### 6.1 Catalog 提示词

`app/runtime/system_prompt.py` 新增纯函数：

```python
compose_system_prompt(
    agents_prompt: str | None,
    skill_catalog_prompt: str | None,
) -> str | None
```

顺序固定为 `AGENTS.md`、分隔说明、Skill Catalog。Catalog 使用稳定 XML-like 文本并转义
名称、描述和路径：

```text
<available_skills>
  <skill>
    <name>example-skill</name>
    <description>...</description>
    <location>.agents/skills/example-skill/SKILL.md</location>
  </skill>
</available_skills>

任务与某个 Skill 描述匹配时，必须先调用 load_skill；需要支持文件时再调用
read_skill_resource。不得把 Skill 的 allowed-tools 当作权限。
```

两部分都为空时继续返回 `None`；Provider 仍最多收到一条首位 system 消息。

### 6.2 Skill 读取工具

`LoadSkillTool`：

- 参数：精确 `name`。
- 返回：完整 `SKILL.md` 启动快照和排序后的资源清单。
- 未知名称、额外参数或类型错误映射为 `invalid_arguments`。

`ReadSkillResourceTool`：

- 参数：精确 `name`、Skill 根目录相对 `path`。
- 只读取启动 Catalog 中存在的 UTF-8 文本资源。
- 绝对路径、空路径、`.`、`..`、未知路径和二进制资源均返回有限错误。
- 不重新读取磁盘，保证与启动时 Catalog 一致。

两者 `effect=READ_ONLY`，自动执行，不触发审批。

## 7. 脚本执行契约

### 7.1 Tool Definition

`RunSkillScriptTool` 的模型参数：

```json
{
  "type": "object",
  "properties": {
    "name": {"type": "string"},
    "path": {"type": "string"},
    "arguments": {
      "type": "array",
      "items": {"type": "string"},
      "maxItems": 32
    }
  },
  "required": ["name", "path", "arguments"],
  "additionalProperties": false
}
```

额外边界：单参数最多 2 KiB，参数 UTF-8 总量最多 8 KiB；路径必须位于该 Skill 的
`scripts/` 资源清单；只接受 `.py` 和 `.sh`。

三个 Skill 工具按自身内容边界使用 256 KiB 的序列化结果上限；其他工具继续使用 32 KiB
默认值。这样 32 KiB `SKILL.md`、64 KiB 文本资源及 32 KiB 脚本原始输出经过 JSON 转义后仍可
完整返回，不通过静默截断破坏快照语义。

### 7.2 解释器与命令

- `.py`：`[sys.executable, absolute_script_path, *arguments]`
- `.sh`：`[/bin/sh, absolute_script_path, *arguments]`
- 使用 `asyncio.create_subprocess_exec(*argv)`，绝不经过 Shell 字符串解析。
- `cwd` 固定为 Skill 根目录；不根据 shebang、更改后缀或模型输入选择解释器。

审批预览使用标准库 `shlex.join()` 仅做显示，实际执行继续使用原始 argv。展示内容包括风险
警告、Skill 名称、相对脚本、解释器、参数和“脚本可读取工作区、修改文件及访问网络”。

### 7.3 审批契约演进

保留现有 `ToolApprovalRequest` 作为文件 Diff 请求，新增：

```python
@dataclass(frozen=True)
class ScriptApprovalRequest:
    call_id: str
    tool_name: str
    title: str
    skill_name: str
    script_path: str
    command_text: str
    warning_text: str
    fingerprint: str
```

`ToolApprovalHandler` 和 `ApprovalTool.preview()` 接受二者的 Union。Registry 按具体类型执行
独立严格校验：

- 文件审批继续验证相对路径、完整 Diff 和 64 KiB 上限。
- 脚本审批验证 Skill/脚本相对标识、命令预览、固定警告、64 KiB 上限和 SHA-256 指纹。
- `ToolEffect` 增加 `EXECUTING`；`MUTATING` 与 `EXECUTING` 都必须实现 `ApprovalTool`。
- 文件 Diff 继续使用请求级拒绝指纹去重；脚本每次调用都重新弹窗，不缓存批准或拒绝。

`app/tui/approval.py` 保留 `ToolApprovalScreen` 统一入口，但根据请求类型渲染：

- Diff：文件列表、完整 Diff、“应用”。
- Script：高风险警告、命令预览、“执行”。

两种界面都以纯文本渲染，默认聚焦“拒绝”，`N`/Esc 拒绝，`Y` 明确同意。

### 7.4 TOCTOU 与执行

`preview()` 和 `invoke()` 都重新执行以下校验：

1. 目标仍是原 Skill 根目录内非符号链接普通文件。
2. 相对路径、文件大小和扩展名仍合法。
3. 当前文件 SHA-256 与启动快照一致。
4. `invoke()` 的参数摘要与获批指纹一致。

任一不一致返回 `workspace_conflict`，不启动进程。批准计划只在当前 Tool 实例内短暂保存，
执行或失败后立即删除。

### 7.5 子进程边界

- `start_new_session=True` 创建独立进程组。
- 固定环境仅包含安全 `PATH=/usr/bin:/bin:/usr/sbin:/sbin`、固定 UTF-8 locale 和当前请求
  专属临时目录 `TMPDIR`；不传 `HOME`、API Key、代理、Python 注入变量或完整父进程环境。
- stdin 使用 `DEVNULL`；stdout/stderr 使用 `PIPE`。
- 两个流并发分块读取并共享 32 KiB 预算；到达上限立即终止进程组，避免 `communicate()`
  在内存中无界积累。
- `asyncio.timeout(30)` 包住进程和读取任务；超时、输出超限、取消均先向进程组发送 TERM，
  短暂等待后发送 KILL，并回收所有 reader task。
- 正常或非零退出都返回 `{exit_code, stdout, stderr}`；非零退出不是宿主异常，模型可以根据
  stderr 修正参数。启动失败、超时、输出超限使用固定安全错误码。

第一版不阻止脚本主动读取 `.env`、修改工作区或访问网络。审批只表示用户接受本次命令风险，
不是沙箱证明。README 和审批界面必须明确这一点。

## 8. Registry 与启动装配

`create_workspace_registry(policy, journal=None, skill_catalog=None)`：

- 始终注册现有 9 个工具。
- Catalog 非空时追加 `load_skill`、`read_skill_resource`、`run_skill_script`。
- Catalog 为空或加载失败时不注册任何 Skill 工具。
- HTTP `create_default_registry()` 不接受 Catalog，工具集合保持不变。

TUI 启动顺序：

1. 捕获启动目录并加载 `.env`。
2. 独立加载 `AGENTS.md`。
3. 独立加载 Skill Catalog；失败只设置 `skills_error`。
4. 用有效 Catalog 生成 Catalog prompt，并与有效 AGENTS 正文组合。
5. 创建 WorkspacePolicy、Journal 和含 Skill 的 Registry。
6. 把 `skills_count`、`skills_error`、组合后的 system prompt 和 Registry 传给 `ChatTuiApp`。

`AGENTS.md` 非法继续按现状阻止发送；Skill 非法只禁用 Skill，不阻止普通请求。Workspace
创建失败时包括脚本在内的全部 Workspace/Skill 工具不可用，但 HTTP 和普通 TUI 对话仍可用。

## 9. 日志与会话

- Catalog、Skill 激活和脚本轨迹不写入 `data/chat-session.json`。
- `load_skill`、资源读取和脚本执行复用现有 `llm_tool_call` / `llm_tool_result`，共享 request ID。
- 现有日志会明文记录完整工具参数和结果，因此 Skill 正文、脚本参数、stdout 和 stderr 会进入
  `logs/model-calls.log`，并在下一次模型 HTTP 请求体中再次出现。
- 审批事件继续只记录工具名、是否批准、预览字符数和耗时；不新增绝对路径或命令正文日志。
- 脚本环境变量内容永不进入工具结果或审批日志；脚本自行输出的敏感内容无法自动识别，用户
  必须把 Skill 仓库视为信任边界。

## 10. 错误语义

新增固定工具错误分类：

| 分类 | 触发条件 | 返回正文 |
| --- | --- | --- |
| `script_timeout` | 超过 30 秒 | `Skill script timed out` |
| `script_output_too_large` | stdout/stderr 合计超限 | `Skill script output is too large` |
| `workspace_conflict` | 审批前后脚本变化 | 沿用现有安全正文 |
| `approval_denied` | 用户拒绝 | 沿用现有安全正文 |
| `execution_failed` | 解释器或进程启动失败 | 沿用现有安全正文 |

参数、未知 Skill、未知资源、非文本资源和不支持后缀统一使用 `invalid_arguments`，不向模型
泄露绝对路径、底层异常和操作系统信息。`CancelledError` 始终向上传播。

## 12. 实施顺序与检查点

```text
PyYAML + Catalog/资源快照
        ↓
只读 Skill 工具 + Catalog prompt
        ↓
通用审批 Union + TUI 两类渲染
        ↓
脚本执行器 + 进程生命周期
        ↓
TUI 启动装配 + 错误隔离
        ↓
文档、全量回归与安全复核
```

检查点一：Catalog 和只读工具完成后，全量测试必须保持通过，HTTP 工具列表不变。

检查点二：审批契约完成后，现有文件 Diff 审批测试必须全部保持通过，再接入子进程。

检查点三：脚本执行完成后，必须验证拒绝、超时、输出超限、取消和 TOCTOU，再接入 TUI。

检查点四：最终运行语法检查、全量测试、依赖检查和差异检查，并人工确认审批风险文案。

## 13. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| Skill 属于提示词注入入口 | 模型执行仓库内恶意流程 | 只加载受信仓库；Catalog 渐进披露；工具权限不由 Skill 扩大 |
| 脚本拥有宿主权限 | 读取秘密、改文件、联网 | 每次审批、明确警告、最小环境；第一版不宣称沙箱 |
| 参数命令注入 | 执行模型拼接命令 | 固定解释器、argv 数组、禁止 Shell 字符串 |
| stdout/stderr 无界 | 内存耗尽或日志膨胀 | 分块并发读取、共享预算、到限终止进程组 |
| 脚本派生后台进程 | 取消后残留 | 新进程组、TERM/KILL、回收 reader task |
| 审批后脚本被替换 | 执行未批准内容 | 启动快照哈希、preview/invoke 双重 revalidate |
| YAML 对象构造 | 加载时执行代码 | `SafeLoader` 派生类、拒绝危险标签和重复键 |
| Catalog 变化破坏 Prompt Cache | 增加请求成本 | 启动快照、字典序稳定、进程内不热加载 |

## 14. 回滚方案

- 删除 `tools/skills.py` 及对应测试。
- 恢复原 `ToolEffect`、审批请求、Registry 和 TUI Modal 契约。
- 从 `app/tui/__main__.py` 移除 Catalog 加载与装配。
- 从 `requirements.txt` 移除 `PyYAML`。
- 删除 Skill 文档说明；仓库中的 `.agents/skills/` 内容可保留供 Codex 使用，不影响 Tsi。
- 不涉及数据库、Session schema 或用户数据迁移。
