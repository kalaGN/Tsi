# TUI 美元符号引用技能设计

状态：已完成（2026-09-05）
创建日期：2026-09-05
对应需求：[`docs/spec/20260905-TUI美元符号引用技能-需求.md`](../spec/20260905-TUI美元符号引用技能-需求.md)

## 1. 现状

- `SkillRuntime` 持有当前已发布的不可变 `SkillCatalog`，每次发送生成系统提示词和 Registry 快照。
- 系统提示词目前只包含 Skill 名称、描述和入口；模型必须主动调用 `load_skill` 才能读取完整 `SKILL.md`。
- `CommandPalette` 已提供不抢占输入框焦点的候选交互，但只适用于整段以 `/` 开头的本地命令。
- `ChatSession` 的执行快照提供者当前不接收用户输入，因此无法按本轮 `$技能名` 选择 Skill。

## 2. 总体方案

```text
TextArea 原文 + 光标
       |
       v
SkillPalette -----> AvailableSkill 内存摘要
       | 选择后返回替换范围与完整名称
       v
TextArea.replace("$name ", start, end)
       |
       v
ChatSession.send(原始输入)
       |
       v
ExecutionSnapshotProvider(原始输入)
       |
       v
SkillRuntime 固定当前 Catalog
       |-- 解析最多 3 个有效引用
       |-- 组合 AGENTS + Catalog + 显式 SKILL.md
       `-- 创建绑定同一 Catalog 的 Registry
```

候选展示和请求执行都只使用 `SkillRuntime` 当前发布版本。UI 仅接触 `AvailableSkill` 摘要；完整正文只在 Runtime 生成请求快照时读取内存中的不可变 `SkillSnapshot`。

## 3. 组件职责

### 3.1 `app/tui/skill_palette.py`

- 定义当前光标引用片段和补全结果的不可变数据对象。
- 根据 TextArea 原文与 `(row, column)` 光标识别当前行内、位于输入开头或空白后的 `$前缀`。
- 基于传入的 `AvailableSkill` 元组按名称过滤候选，维护选择索引、关闭状态和纯文本展示。
- 返回精确的 TextArea `start/end` 位置及 `$完整名称 `，不直接修改输入框、不读取磁盘。

### 3.2 `app/tui/application.py`

- 在 `TextArea.Changed` 和 `TextArea.SelectionChanged` 时刷新技能候选。
- 审批界面优先级最高；其后按 CommandPalette、SkillPalette 顺序处理 Enter、Tab、Up、Down、Esc。
- 消费技能补全后调用 `TextArea.replace`，把光标置于插入文本末尾。
- 从 `SkillRuntime.available_skills()` 提供内存摘要；Runtime 缺失或错误时不展示候选。

### 3.3 `tools/skills.py`

- 使用固定正则解析完整 token：前方为输入起点或空白，格式为 `$<合法技能名>`，后方为输入终点或空白。
- 只保留 Catalog 中存在的名称并按首次出现去重；未知名称忽略。
- 超过 3 个有效不同引用时抛出固定 `SkillReferenceError`。
- 将选中 Skill 的名称、描述、入口、完整 `SKILL.md` 和资源路径索引编码为有界 JSON 数据段；不包含资源正文。

### 3.4 `app/runtime/skill_runtime.py`

- `snapshot(input_text: str | None = None)` 保持无参数启动调用兼容；有输入时组合显式 Skill 数据段。
- 引用解析和 Registry 创建使用方法开始时捕获的同一个 Catalog 局部变量，避免安装发布导致版本撕裂。
- 把引用过多转换为 `ChatRuntimeError(INVALID_INPUT)` 的稳定用户消息，不暴露正文或路径细节。

### 3.5 `app/runtime/session.py`

- `ExecutionSnapshotProvider` 契约改为接收当前原始 `input_text`。
- `send()` 在构造 Provider 消息前只调用一次快照提供者。
- 候选请求和持久化仍使用原始输入，不保存组合后的系统提示词或 Skill 正文。

## 4. 关键契约

```python
ExecutionSnapshotProvider = Callable[[str], ChatExecutionSnapshot]

def resolve_skill_references(
    input_text: str,
    catalog: SkillCatalog,
) -> tuple[SkillSnapshot, ...]: ...

def snapshot(self, input_text: str | None = None) -> ChatExecutionSnapshot: ...
```

旧的 `SkillRuntime.snapshot()` 无参数调用继续用于 TUI 启动时取得初始 Registry 和系统提示词。真正发送时 `ChatSession` 始终传入用户原文。

## 5. 数据与上下文

- Session schema 不变，仍是版本化 user/assistant JSON。
- `$技能名` 作为用户原文的一部分持久化，历史恢复后可见。
- 显式 Skill 数据只存在于当前 Provider 请求的 system 消息和既有模型请求日志；这一点与当前系统提示词明文日志策略一致。
- 最多 3 个 Skill，每个 `SKILL.md` 已受 32 KiB 限制，显式数据段再执行总字节上限检查，建议上限 128 KiB。

## 6. 异常与安全

| 场景 | 行为 |
| --- | --- |
| Catalog 不可用或为空 | 不显示候选，普通 `$文本` 照常发送 |
| 未知完整名称 | 作为普通文本，不加载 Skill |
| 超过 3 个有效 Skill | 不调用 Provider，TUI 展示固定输入错误 |
| 显式数据段超限 | 不调用 Provider，展示同一固定输入错误 |
| 安装在请求开始后完成 | 当前请求继续使用已捕获 Catalog，下一请求生效 |
| Skill 要求写文件或运行脚本 | 仍经过现有 Registry 和逐次审批 |

Skill 内容被标记为不可信项目数据。JSON 编码用于保留边界和特殊字符，但真正权限仍由工具白名单、Workspace Policy 和审批机制强制执行，不能依赖提示词自律。

## 7. 性能

- 候选只遍历最多 64 条内存摘要，不访问磁盘。
- 引用解析对单条输入做一次有界正则扫描；当前 Session 尚无输入长度上限，本变更不新增全历史扫描。
- 完整 Skill 拼装每次发送最多 3 份、128 KiB，不建立后台任务或文件监控。

## 8. 兼容与回滚

- 不含 `$有效技能名` 的请求生成与当前相同的系统提示词。
- `/` 命令候选和 `$` 技能候选由不同组件维护，触发条件互斥。
- HTTP `/chat` 不创建 `SkillRuntime`，无行为变化。
- 回滚时删除 SkillPalette 和显式引用拼装，并恢复无参数快照提供者契约；Session 数据无需迁移。

## 10. 已确认决策

- 执行快照提供者接收原始输入。
- 最多 3 个显式 Skill 的完整 `SKILL.md` 作为当前 system 上下文发送给模型。
