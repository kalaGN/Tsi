# TUI 职责拆分设计

## 本轮范围

用户确认按架构建议拆分。第一轮仅外置布局样式并组件化命令预览，保留消息渲染、历史、请求 Worker 和取消代次的现有实现。

## 职责与依赖

- `application.py` 负责应用组装、事件分发、命令执行和请求生命周期。
- `command_palette.py` 的 `CommandPalette` 继承 `Static`，维护候选、选择索引、已关闭输入和文本展示。接口为 `filter_input`、`move_selection`、`take_selection`、`dismiss` 及 `is_open`。
- 主应用在输入变化时传入原文和空闲状态，在方向键、Tab、Enter、Esc 时协调候选与原有交互。
- `styles/application.tcss` 与 `styles/approval.tcss` 分别由所属类通过 `CSS_PATH` 加载，路径相对于类所在模块，不依赖启动工作目录。
- Rich `Panel`、`Text` 样式保留在消息渲染代码；不机械转换为 TCSS。

## 第二轮：消息区域组件化

- `Transcript` 继承现有可复制消息组件，接收角色和原文，负责用户卡片、Assistant Markdown、系统纯文本以及 Rich 样式。
- `StreamOutput` 维护文本片段和待刷新标记，提供追加、批量绘制、重置接口。
- 主应用保留请求代次校验、Worker、取消和 Timer 调度；只把已验证回调交给组件，保持旧结果无法写回的边界。
- 组件继承既有选择行为并保留原 ID、布局与配置；现有测试无需修改。
- 验证沿用完整 pytest、compileall、pip check 和差异检查。

## 第三轮：输入历史与活动栏

- `InputHistory` 是纯 Python 状态对象，保存输入记录、导航索引和草稿；`previous`/`next` 返回待展示文本，`None` 表示保持当前输入。
- `append`、`clear` 自动重置导航；磁盘清理仍须由会话先完成，失败时保留历史。
- `ActivityBar` 负责动画帧与思考/审批文案，使用主应用传入的耗时；不创建 Timer 或独立时钟。
- 主应用只协调方向键优先级、输入框更新、请求 Timer、代次和取消，避免出现多个生命周期管理者。
- 现有测试的用户行为断言不变，仅将历史内部状态断言迁移到所属对象。
