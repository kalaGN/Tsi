# Token 消耗统计设计

状态：已完成（2026-09-06）
创建日期：2026-09-06

对应[需求](../spec/20260906-Token消耗统计-需求.md)。

## 1. 设计目标

在不改变 `/chat` 公开响应和现有会话 schema 的前提下，把 DeepSeek 与阿里云流式响应中的真实 usage 转换为统一契约，逐模型步骤记录日志，并由 Tool Loop 聚合为 TUI 可展示的单轮 Token 消耗。

核心原则：

- Provider 负责协议字段映射和单步骤校验。
- Tool Loop 负责跨模型步骤累计和逐步骤可观测性。
- Runtime 只返回统一结果，TUI 不读取 Provider 私有 JSON。
- 任一步骤 usage 缺失时，本轮总量不可用，不把部分值伪装成完整统计。

## 2. 现状与依赖关系

当前调用链：

```text
TUI / HTTP
    -> app.runtime.chat
        -> app.runtime.tool_loop
            -> LlmTurn.next()
                -> DeepSeek / Aliyun 流解析器
```

- `ModelStep` 只有状态、文本和工具调用。
- `run_tool_loop()` 返回最终 `ModelStep`，中间步骤只用于执行工具。
- `ChatResult` 只有文本、Provider 和模型。
- DeepSeek 流解析器允许空 `choices` Chunk，但直接忽略其中 usage。
- 阿里云流解析器保存 completed Response，却没有解析其中 usage。
- 所有模型步骤已共享同一 request ID，适合作为 Token 日志关联键。

新依赖关系保持单向：

```text
Provider 私有 usage
    -> contracts.TokenUsage
        -> ModelStep（单步骤）
            -> ToolLoopResult（全步骤聚合）
                -> ChatResult
                    -> TUI

ModelStep + step_number
    -> observability.llm_token_usage
```

## 3. 统一 Token 契约

在 `app/services/llm/contracts.py` 增加：

```python
@dataclass(frozen=True)
class TokenUsage:
    input_tokens: int
    output_tokens: int
    total_tokens: int

    def __post_init__(self) -> None:
        ...

    def __add__(self, other: "TokenUsage") -> "TokenUsage":
        ...
```

校验规则：

- 三个字段必须满足 `type(value) is int`，明确拒绝 Python 中属于 `int` 子类的 `bool`。
- 三个字段必须大于等于零。
- `total_tokens == input_tokens + output_tokens`。
- 加法逐字段求和并再次经过同一不变量校验。

`ModelStep` 增加带默认值的字段，保持现有三参数构造兼容：

```python
@dataclass(frozen=True)
class ModelStep:
    upstream_status: int
    output_text: str | None
    tool_calls: tuple[ToolCall, ...]
    token_usage: TokenUsage | None = None
```

`None` 只表示该上游步骤没有提供 usage，不表示零消耗。

## 4. Provider 解析

### 4.1 字段映射

| Provider | 输入字段 | 输出字段 | 总计字段 |
|---|---|---|---|
| DeepSeek Chat Completions | `prompt_tokens` | `completion_tokens` | `total_tokens` |
| 阿里云 Responses | `input_tokens` | `output_tokens` | `total_tokens` |

Provider 显式映射后构造 `TokenUsage`。值对象校验失败时转换为现有 `ProviderInvalidResponseError`，不把原始值或响应正文带到用户错误。

### 4.2 DeepSeek

请求 payload 固定增加：

```json
{"stream":true,"stream_options":{"include_usage":true}}
```

流状态增加 `_token_usage`：

1. 每个 JSON Chunk 先检查 `usage`。
2. `usage` 缺失或为 `null` 时不改变状态。
3. 非空 usage 映射三个字段，并且只允许出现一次。
4. `choices=[]` 时，只有合法的非空 usage 才作为 usage-only Chunk 接受；不再静默吞掉完全无内容的空 Chunk。
5. 文本、reasoning、工具调用和 finish reason 继续走现有逻辑。
6. `finish()` 返回消息、工具调用与单步骤 usage。

缺失 usage 不破坏合法文本或工具步骤，最终为 `None`；重复或非法 usage 属于结构错误。

### 4.3 阿里云

流状态在确认 completed Response 状态后读取可选 `usage`：

1. `usage` 缺失或为 `null` 时返回 `None`。
2. 非空 usage 映射 `input_tokens/output_tokens/total_tokens`。
3. 文本步骤和 function call 步骤使用同一解析路径。
4. `finish()` 返回工具调用、输出文本和单步骤 usage。

Provider Turn 把解析结果放入对应 `ModelStep.token_usage`。现有输出文本、工具参数和完成状态校验顺序保持不变。

## 5. Tool Loop 聚合

在 `app/runtime/tool_loop.py` 增加职责明确的结果对象：

```python
@dataclass(frozen=True)
class ToolLoopResult:
    output_text: str
    token_usage: TokenUsage | None
```

不复用最终 `ModelStep` 承载聚合值，因为 `ModelStep.token_usage` 固定表示单次上游调用，避免同一字段在 Provider 与 Runtime 表示不同统计范围。

聚合算法：

```text
aggregate = 0/0/0
usage_complete = True

每个 ModelStep：
  usage 存在 -> 立即记录步骤日志并加入 aggregate
  usage 缺失 -> usage_complete = False
  有工具调用 -> 执行并继续
  无工具调用 -> 返回文本，以及 aggregate（仅 usage_complete 为 True）
```

- 模型步骤从 1 编号，与现有循环上限一致。
- 日志发生在 `turn.next()` 成功返回后、工具调用限制判断前；即使该步骤随后因工具数量超限终止，已由上游计量的 Token 仍被记录。
- 后续步骤抛错不会撤销此前日志。
- 任一步骤缺失 usage 后，即使其他步骤都有值，最终聚合也为 `None`。
- 合法的零 Token usage 可累计，不能被布尔判断误判为缺失。

## 6. Runtime 与 HTTP 边界

`ChatResult` 增加默认字段：

```python
@dataclass(frozen=True)
class ChatResult:
    output_text: str
    provider: str
    model: str
    token_usage: TokenUsage | None = None
```

- `run_chat_messages()` 从 `ToolLoopResult` 读取输出和聚合 usage。
- `log_model_response` 继续只负责完整文本；Token 使用独立事件，避免一个事件混合不同生命周期。
- Router 仍显式构造 `ChatResponse(output_text=...)`，新增内部字段不会进入 OpenAPI 或 HTTP JSON。
- Fake Provider、Fake Runner 和现有位置参数构造因默认值保持兼容；新增测试使用显式 usage。

## 7. Token 日志

在模型日志白名单中增加：

```text
event: llm_token_usage
request_id
step_number
input_tokens
output_tokens
total_tokens
```

本地中文分块示例：

```text
事件：Token 消耗
请求ID：...
模型步骤：2
输入 Token：180
输出 Token：15
总 Token：195
```

stderr JSON 沿用相同字段。事件不包含正文、Provider 原始 usage、价格、API Key 或其他新增敏感数据。文件 Handler 错误继续旁路，不影响 Tool Loop。

## 8. TUI 展示

`ChatTuiApp` 增加小型私有方法格式化统一 usage，不让 Transcript 或状态栏持有业务状态：

```text
Assistant
...
耗时：3.42 秒
Token：输入 520 | 输出 95 | 合计 615
```

- 成功请求：在最终回答和耗时之后显示统计。
- usage 为 `None`：显示 `Token：不可用`，明确区别于零。
- Provider、工具或存储失败：保留现有错误与耗时，不显示不完整合计。
- 取消或陈旧 Worker 返回：不显示 Token。
- Token 行使用普通系统文本，可选择复制，但不进入会话消息、输入历史或模型上下文。
- 状态栏保持不变，不把“累计消耗”与“上下文占比”混在同一区域。

## 9. 异常、安全、性能与兼容

- usage 是不可信上游数据，必须在 Provider 边界验证类型、范围和求和关系。
- 不记录 Provider usage 扩展对象，避免未来新增高基数字段或意外正文进入日志。
- Token 数不用于授权、计费结算或请求阻断，只作为上游报告的可观测信息。
- 单步骤只增加固定次数的字段检查与整数加法，不增加网络请求；性能影响可忽略但由测试验证行为。
- DeepSeek 新增 `stream_options` 是唯一请求协议变化；阿里云请求体不变。
- `/chat`、Session schema、工具契约、日志脱敏和错误映射保持兼容。

## 10. 测试设计

- 契约：正常构造、零值、加法、负数、字符串、小数、布尔值和总数不一致。
- DeepSeek：请求参数、文本与工具 usage、usage-only Chunk、null、缺失、重复和非法值。
- 阿里云：文本与工具 completed usage、缺失、null 和非法值。
- Tool Loop：单步、多步骤累计、部分缺失、逐步日志，以及超限或后续失败时保留已知日志。
- Runtime：`ChatResult` 透传聚合 usage；原有默认值兼容。
- TUI：成功、不可用、失败、取消和陈旧结果的展示边界。
- HTTP：成功响应和 OpenAPI schema 不出现 usage。
- 全部 Provider 测试继续使用 MockTransport，不访问真实服务。

## 11. 实施顺序与检查点

```text
统一 TokenUsage 契约
    -> 两家 Provider 解析
        -> Tool Loop 聚合与逐步日志
            -> ChatResult 透传
                -> TUI 展示
                    -> HTTP 回归与文档同步
```

检查点：

1. 契约和 Provider 完成后，单模型步骤稳定产生统一 usage。
2. Tool Loop 和日志完成后，多步骤累计与部分失败可由纯 Runtime 测试验证。
3. TUI 完成后，假 Provider 端到端测试能看到准确文本且 HTTP 契约无变化。
4. 最终执行语法、全量测试、依赖和 Diff 门禁，并检查测试日志事件格式。

## 12. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| Provider 流式 usage 位置不同 | 错误忽略或重复累计 | 每家独立映射，只允许一个非空 usage，按官方结构回归 |
| 工具循环只统计最终步骤 | 明显低估消耗 | 聚合放在 Tool Loop，每一步立即累计和记录 |
| 某一步缺失 usage | 部分和被误认为完整总量 | 最终返回不可用，日志保留已知步骤 |
| 内部字段泄漏到 HTTP | 破坏公开契约 | Router 显式 DTO 和 OpenAPI 回归测试 |
| 现有位置参数构造受影响 | 无关回归范围扩大 | 新字段放末尾并提供 `None` 默认值 |
| Token 与上下文占比混淆 | 用户误判剩余窗口 | 只在 transcript 显示本轮 Token，状态栏不变 |

## 13. 回滚

- 删除 `TokenUsage`、`ToolLoopResult` 和新增日志事件。
- Provider 恢复忽略 usage，DeepSeek 移除 `stream_options`。
- `ChatResult` 恢复三个字段，TUI 删除 Token 行。
- 不需要迁移 Session、日志或外部数据；历史日志中的新增事件可作为普通文本保留。
