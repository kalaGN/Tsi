# TUI 安全 Git 写工具设计

状态：已完成（2026-09-08）

创建日期：2026-09-07

对应需求：[TUI 安全 Git 写工具需求](../spec/20260907-TUI安全Git写工具-需求.md)

## 1. 总体设计

Git 写能力作为 TUI Workspace 能力的独立纵向切片实现：

```text
SkillRuntime.snapshot
  -> create_intent_workspace_registry
     -> GitStageTool / GitCommitTool / GitPushTool
     -> git_write ToolGroup
  -> ToolRegistry 强制审批
  -> ToolApprovalScreen 展示 GitApprovalRequest
  -> GitCommandRunner 执行固定 argv
```

HTTP 继续使用 `create_default_registry()`，不会导入或注册 Git 写工具。

## 2. 中立审批契约

在 `tools/contracts.py` 增加 `GitApprovalRequest`，包含 call ID、工具名、标题、固定操作名、摘要、预览正文、固定警告、网络标记和指纹。

- `operation` 只允许 `stage`、`commit`、`push`。
- `summary` 和 `preview_text` 只包含相对路径、分支、脱敏远端和有界 Diff/提交列表。
- `warning_text` 必须等于宿主固定文案，不能由 Tool 自定义风险说明。
- Registry 在调用审批回调前验证字段、长度、枚举和 fingerprint。
- TUI 对 Git 请求显示“执行”按钮；Push 额外标记网络访问。

这样不滥用以文件 Diff 为核心的 `ToolApprovalRequest`，也不把 Git 命令伪装成 Skill 脚本。

## 3. GitCommandRunner

`tools/git.py` 内部定义可注入的异步 Runner，生产实现只接受由三个工具内部构造的 argv：

- 可执行文件通过 `shutil.which("git")` 定位，`cwd` 固定为 `WorkspacePolicy.root`。
- 禁止 `shell=True`，stdout/stderr 合并并按字节限制持续排空。
- 30 秒超时；取消或超时终止整个进程组。
- 最小环境只保留 PATH、LANG，并设置 `GIT_TERMINAL_PROMPT=0`、`GCM_INTERACTIVE=never`。
- 每次调用注入 `core.hooksPath=/dev/null`、`commit.gpgSign=false`、`core.pager=cat`、`color.ui=false`。
- Diff 命令始终使用 `--no-ext-diff --no-color`。
- 非零退出只转换为固定 Git 错误，不把原始 stderr 交给模型。

## 4. Stage 设计

- 使用 WorkspacePolicy 写路径规则，只接受 1 至 20 个存在的非符号链接普通文件。
- 拒绝重复、目录、删除、`.`、以 `-` 开头及 Git pathspec 魔法。
- 复制真实 Index 到系统临时目录，通过 `GIT_INDEX_FILE` 对临时 Index 执行 `git add` 并读取 cached diff。
- 预览指纹包含路径、真实 Index 哈希、目标文件内容/模式哈希和 Diff。
- 批准后完整重算；一致才对真实 Index 执行同一 `git add -- <paths>`。

## 5. Commit 设计

- 参数校验使用固定 type 集合和中文字符正则。
- 快照读取当前分支、HEAD、Index 哈希、staged name-only 和 staged Diff。
- detached HEAD、空 staged、过大或截断 Diff 均拒绝。
- 预览包含中文提交信息、当前分支、相对文件列表和 staged Diff。
- 批准后重算 fingerprint；一致才以关闭 hooks/GPG 的固定 argv 提交。
- 成功后用 `rev-parse --short=12 HEAD` 读取提交 ID，不解析 Git 自由文本。

## 6. Push 设计

- 无模型参数；从当前分支读取已经存在的上游。
- 上游拆成已配置 remote 与 branch；remote 名使用安全字符集。
- Push URL 只允许无凭据 HTTPS、`ssh://` 或 SCP-like SSH 地址，UI 只显示协议和主机。
- 用 `rev-list @{upstream}..HEAD` 生成待推送哈希，用有界 log 生成预览。
- fingerprint 包含 HEAD、上游全名、脱敏目标和提交哈希列表。
- 批准后重算快照；一致才执行 `git push --porcelain <remote> HEAD:refs/heads/<branch>`。
- 不传 force、tags、delete、set-upstream 或模型参数；原始 Push 输出不返回模型。

测试通过注入 Runner 验证 Push argv和响应，不连接互联网；Stage/Commit 使用临时真实仓库做集成验证。

## 7. 工具组装配

`ToolGroup` 增加 `GIT_WRITE = "git_write"`。Workspace Catalog 固定追加三个 Git 工具；`create_intent_workspace_registry` 仅在三项完整存在时发布：

```text
git_write -> git_stage, git_commit, git_push
```

模型如需分析状态，可在同一次激活中同时请求 `workspace_read` 和 `git_write`。

## 8. 错误语义

| 错误码 | 条件 |
|---|---|
| `git_unavailable` | Git 不存在、不是仓库或基础状态不可读 |
| `git_conflict` | 批准前后 HEAD、Index、文件或上游状态变化 |
| `git_nothing_to_stage` | 指定文件不会产生 staged 差异 |
| `git_nothing_to_commit` | 当前没有 staged 内容 |
| `git_no_upstream` | 当前分支没有既有上游 |
| `git_nothing_to_push` | HEAD 没有领先上游的提交 |
| `git_remote_unsafe` | Push URL 不属于允许的安全形状 |
| `git_failed` | 固定 Git 写命令执行失败 |

所有正文来自 Registry 固定映射。

## 9. 安全与恢复

- Stage 只改变 Index，不改变工作区文件；拒绝和预览均为零副作用。
- Commit 创建本地对象和移动当前分支；本期不自动撤销 Commit。
- Push 改变远端且不可由本项目可靠回滚，因此必须展示网络警告并逐次批准。
- 三个工具互不串联；一个调用成功后不会自动发起下一个调用。
- TUI 取消传播到子进程并终止进程组。
- 不读取 `.git` 正文作为模型数据；仅宿主内部对 Index 做哈希和临时复制。

## 10. 验证与回滚

- 单元测试覆盖参数、预览、审批、竞态、hooks、固定命令和安全结果。
- HTTP 测试确认不加载 Git 模块和工具。
- 全量执行项目既有四项门禁，不调用真实远端或模型。
- 从 Workspace Catalog 和 `git_write` 组移除三项工具即可停止暴露；已提交或推送状态不自动回滚。
