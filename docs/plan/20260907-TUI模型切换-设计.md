# TUI 模型切换设计

状态：已完成（2026-09-07）

## 1. 设计依据

- 已确认需求：[TUI 模型切换需求](../spec/20260907-TUI模型切换-需求.md)。
- 当前命令目录由 `app/tui/commands.py` 统一定义，`CommandPalette` 只处理未完成命令的预览与补全。
- `ChatSession` 在构造时固定一个可选 Provider；未显式传入时，每次 Runtime 调用才从环境创建 Provider。
- TUI 状态栏使用独立 `ChatRuntimeInfo` 快照，不能从 Session 反向读取密钥。
- HTTP `/chat` 继续通过现有 `create_provider()` 读取部署环境，本设计不修改 Router 或 HTTP 契约。

## 2. 总体方案

增加一个 TUI 专属 `ModelPalette`。完整 `/model` 由既有本地命令目录识别，主应用在空闲时打开由启动环境生成的安全候选快照。选择器只管理候选展示和键盘位置；Provider 创建仍由 `services.llm.factory` 完成，Session 只负责原子替换当前 Provider，主应用负责协调三者并刷新状态栏。

```text
环境变量
   │
   v
resolve_model_options() ──> tuple[ModelOption, ...]
                                  │
/model ──> ChatTuiApp ──> ModelPalette
                             │ Up/Down/Enter
                             v
                    selected ModelOption
                             │
             create_provider_for_model()
                             │
                             v
                   ChatSession.replace_provider()
                             │
                             v
                   runtime_info + StatusBar
```

候选中只包含安全字段，不包含 API Key。任何失败都发生在 Session 替换前，因此原 Provider 和会话保持不变。

## 3. 数据契约

在 `app/services/llm/contracts.py` 增加不可变值对象：

```python
@dataclass(frozen=True)
class ModelOption:
    provider: str
    model: str
    api_key_configured: bool
```

- `provider` 仅允许工厂支持的规范小写名称。
- `model` 是验证后的显示值和实际请求值。
- `api_key_configured` 只表示是否存在非空 Key，不携带 Key 内容。
- 候选身份使用 `(provider, model)`，不同供应商允许同名模型。

不把候选目录加入 Session schema；现有 `ChatRuntimeInfo` 继续表示当前实际选择，避免把“候选”和“当前状态”混为同一类型。

## 4. 模型目录解析

在 `app/services/llm/factory.py` 增加：

```python
def resolve_model_options(
    environ: Mapping[str, str] | None = None,
) -> tuple[ModelOption, ...]: ...

def create_provider_for_model(
    provider: str,
    model: str,
    environ: Mapping[str, str] | None = None,
) -> LlmProvider: ...
```

### 4.1 目录来源

固定按 `deepseek`、`aliyun` 顺序构建分组：

| Provider | Key | 当前模型 | 候选列表 | 默认模型 |
| --- | --- | --- | --- | --- |
| DeepSeek | `DEEPSEEK_API_KEY` | `DEEPSEEK_MODEL` | `DEEPSEEK_MODELS` | Provider 常量 |
| Aliyun | `DASHSCOPE_API_KEY` | `ALIYUN_MODEL` | `ALIYUN_MODELS` | Provider 常量 |

每组先保留 `*_MODELS` 中合法条目的原顺序，再依次补入合法的当前配置模型和默认模型，按模型名首次出现去重。未设置当前模型时，它等同默认模型。这样用户配置的列表优先展示，同时保证合法当前值和回退值可见。

### 4.2 校验与降级

- 以英文逗号切分列表，每项去除首尾空白。
- 拒绝空项、控制字符、内部英文逗号和超过 128 字符的条目；合法条目不改写大小写。
- 列表中的非法条目逐项忽略，不回显原值，不影响其他候选或 TUI 启动。
- 单个 `*_MODELS` 原始值最多读取 8 KiB；超限时整项忽略并只保留当前/默认候选，避免切分无界配置。
- 当前配置模型沿用现有 `_model_or_default` 语义；进入选择器前使用同一有界显示校验。若其异常，则只展示该 Provider 的其他合法候选和默认模型，现有启动错误行为不扩大到 HTTP。
- `create_provider_for_model` 再次校验供应商和模型，并从传入环境读取对应 Key；它不修改环境，也不联网。
- 现有 `resolve_provider_config()`、`create_provider()` 的签名和 HTTP 行为保持不变。

## 5. Session 切换边界

`ChatSession` 增加同步方法：

```python
def replace_provider(self, provider: LlmProvider) -> None: ...
```

- Provider 必须非空并满足现有中立契约。
- `_send_lock.locked()` 为真时拒绝替换，抛出安全 `ChatRuntimeError`；不等待、不取消当前发送。
- 校验完成后只替换 `_provider`，不触碰 `_messages`、`SessionStore`、系统提示词、Registry 或 Skill 快照。
- 后续 `send()` 在锁内读取替换后的 Provider，当前已开始的请求始终使用原 Provider。

主应用只在 `_active_worker is None` 时打开模型列表，Session 检查作为第二道并发保护。

## 6. ModelPalette

新增 `app/tui/model_palette.py`，采用与 `CommandPalette` 相同的 `Static + Rich Text` 方式：

- `open(options, current_provider, current_model)`：复制不可变候选快照，定位当前项；找不到时选中第一项。
- `is_open`：候选列表处于显示状态。
- `move_selection(offset)`：上下循环移动，可用和不可用项都可被查看。
- `take_selection()`：返回当前 `ModelOption` 并关闭；无候选时返回 `None`。
- `dismiss()`：关闭并丢弃当前快照。

展示格式保持纯文本，例如：

```text
  DeepSeek · deepseek-v4-flash  当前
› Aliyun  · qwen3-max           Key 缺失
```

选中项使用现有 `bold reverse` 风格；不可用原因只显示固定文案，不显示环境变量内容。组件不读取环境、不创建 Provider、不操作 Session，也不写消息。

在 `application.tcss` 增加 `#model-preview`，默认隐藏、高度自适应并设置有界最大高度；候选超过可视高度时由组件采用 Textual 可滚动容器，不能无限撑高输入区域。若实现中 `Static` 无法可靠滚动，则改用 Textual 内置可滚动组件，不引入依赖。

## 7. 命令与键盘状态机

`LocalCommand` 增加 `MODEL = "/model"`，描述为“切换模型供应商和模型”。既有 `parse_local_command()` 只识别完整命令，`suggest_local_commands()` 在输入 `/m` 时返回该候选。

主应用的优先级调整为：

| 按键 | 优先级 |
| --- | --- |
| Enter | 工具审批 → 已打开 ModelPalette 确认 → Command/Skill 补全 → 本地命令 → 普通发送 |
| Up/Down | CommandPalette → ModelPalette → SkillPalette → 输入历史 |
| Esc | 工具审批拒绝 → ModelPalette 关闭 → CommandPalette → SkillPalette → 清空输入/双击退出 |

执行完整 `/model` 时：

1. 确认当前无活动 Worker。
2. 清空输入框，但不追加输入历史。
3. 使用启动时解析的候选快照打开 `ModelPalette`，当前配置作为默认选中项。
4. 回车取得候选；若 Key 缺失，写固定 System 错误并保持原状态。
5. 先通过工厂创建完整 Provider，再调用 `session.replace_provider()`。
6. 两步均成功后才替换 `runtime_info`、刷新状态栏并写成功 System 消息。

如果 TUI 通过测试注入的裸 `chat_runner` 启动而没有 `ChatSession`，`/model` 显示“模型切换不可用”，不尝试修改 Runner。

## 8. 异常语义

| 场景 | 行为 |
| --- | --- |
| 候选目录无有效条目 | 由当前/默认模型补齐；仍为空时显示固定不可用消息 |
| 目标 Key 缺失 | 关闭列表，显示“目标模型的 API Key 未配置”，不替换 |
| Provider/模型校验失败 | 显示安全配置错误，不回显原始环境内容 |
| Session 正在发送 | 拒绝替换，保持列表打开前的配置 |
| Provider 创建出现未知异常 | 收敛为“模型切换失败”，不显示堆栈 |
| Esc 取消 | 只关闭列表，不触发输入清空、请求取消或退出计时 |

切换本身不写模型调用日志，因为没有外部调用；成功/失败仅显示 TUI System 消息。现有下一轮请求日志自然记录新的 Provider 和模型。

## 9. 安全与隐私

- `ModelOption` 和状态栏只携带布尔 Key 状态，禁止保存、打印或传递真实 Key。
- 环境模型目录视为不可信配置；在渲染和 Provider 创建前都做长度与控制字符校验。
- Rich 组件使用 `markup=False` 或构造 `Text`，模型名不能被解释为 markup。
- 不写 `.env`，不改变 `os.environ`，不把模型列表或选择结果发给上游。
- 不增加网络请求、Shell、动态 import、工具权限或第三方依赖。

## 10. 性能

- 目录只在 TUI 启动时解析一次，原始列表每项不超过 8 KiB，候选数量按每家最多 50 个限制，避免异常环境值造成无界 UI 和内存占用。
- 打开选择器只复制最多 100 个轻量不可变对象；上下移动只重绘列表，不访问磁盘或网络。
- 模型切换不增加正常模型请求的 Token 或网络往返。

## 11. 兼容性

- 不修改 HTTP Router、请求/响应模型、错误状态映射和部署级选择行为。
- 未设置 `DEEPSEEK_MODELS`、`ALIYUN_MODELS` 时仍能列出两家当前/默认模型。
- 现有 `/clear`、`/skills`、`/quit`、命令预览、Skill 补全、输入历史和双 Esc 行为保持不变。
- 会话 JSON schema 不变，旧会话可以直接恢复。

## 12. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 切换时请求仍在执行 | 一个会话内 Provider 状态竞态 | UI 空闲检查 + Session 锁状态二次检查 |
| 模型名包含终端控制字符 | 界面污染或欺骗 | 目录解析和创建前双重校验，纯文本渲染 |
| 历史跨模型不兼容 | 新模型回答质量下降 | 按已确认需求保留历史，并用 System 消息明确切换；用户可主动 `/clear` |
| Key 状态与创建时环境不一致 | 候选显示可用但切换失败 | 创建 Provider 后再次检查实际 `api_key_configured`，失败不替换 |
| 候选过多挤压布局 | 输入区不可用 | 每家 50 项上限和有界滚动区域 |

## 13. 回滚

- 删除 `ModelPalette`、`/model` 枚举项、目录解析与 Session 替换方法即可恢复启动时固定 Provider。
- 不涉及数据迁移、环境写入或 Session schema 变化，回滚后现有会话继续可读。
- 新增的 `*_MODELS` 环境变量由旧版本自然忽略。

## 14. 验证检查点

1. 工厂与数据契约：目录解析、Key 状态、显式 Provider 创建测试通过，HTTP 原测试无变化。
2. Session：发送前切换生效、发送中拒绝、历史与存储不变。
3. 选择器：候选显示、默认项、循环移动、确认与取消测试通过。
4. TUI：完整 `/model` 流程、状态栏、System 消息和所有既有键盘行为通过无头测试。
5. 文档：README、架构 Knowledge、环境变量说明与 Spec/Plan/Tasks 状态同步。
6. 全量门禁：语法、403 项以上全量测试、依赖和差异检查全部通过。

## 15. 待确认项

- 模型候选采用单层“供应商 · 模型”列表，而不是先选择供应商再选择模型。
- `DEEPSEEK_MODELS`、`ALIYUN_MODELS` 每家最多接受 50 个合法候选。
- 切换后继续携带原会话历史；模型不兼容时由用户显式执行 `/clear`。
