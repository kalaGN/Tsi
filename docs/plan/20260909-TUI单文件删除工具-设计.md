# TUI 单文件删除工具设计

## 1. 设计目标

在不扩大 HTTP 权限、不引入任意文件删除能力的前提下，为本地 TUI 增加 `delete_workspace_file`。该工具沿用现有 Workspace Policy、两阶段审批、变更 Journal 和 LIFO 撤销机制，只允许删除启动工作区内一个经过哈希确认的普通 UTF-8 文本文件。

## 2. 当前实现

当前 Workspace 写入链路位于 `tools/workspace.py`：

```text
模型 ToolCall
  -> GroupedToolRegistry 激活 workspace_write
  -> ToolRegistry 校验 MUTATING Tool 并请求审批
  -> ApprovalTool.preview() 生成 Diff 与 fingerprint
  -> TUI Modal 确认
  -> Tool.invoke() 重新规划并校验 fingerprint
  -> WorkspaceChangeJournal 记录变更
  -> undo_workspace_change 撤销最近变更
```

`_FileChange` 目前只表达“创建”和“替换”：`before` 可以为空，`after` 必须存在；`UndoWorkspaceChangeTool` 也假设执行后的目标一定存在。要支持删除并继续复用同一个 Journal，需要让执行后内容也可以为空，并让提交、冲突验证、回滚和撤销都识别三种状态。

HTTP Runtime 默认使用 `tools.create_default_registry()`，只注册无副作用工具；TUI 使用 `create_intent_workspace_registry()`。因此删除工具只加入 Workspace 工厂和 `workspace_write` 组，不修改默认 HTTP 注册表。

## 3. 核心数据模型

将内部变更快照扩展为：

```python
@dataclass(frozen=True)
class _FileChange:
    path: Path
    relative: str
    before: bytes | None
    after: bytes | None
    mode: int


@dataclass(frozen=True)
class WorkspaceChange:
    change_id: str
    files: tuple[_FileChange, ...]
    result_hashes: tuple[str | None, ...]
```

状态含义：

| `before` | `after` | 操作 |
|---|---|---|
| `None` | `bytes` | 创建 |
| `bytes` | `bytes` | 替换 |
| `bytes` | `None` | 删除 |
| `None` | `None` | 非法，永不构造 |

`result_hashes` 中的 `None` 表示变更完成后路径必须不存在。这样撤销删除前可以检测同名文件是否被用户重新创建，避免覆盖用户内容。

## 4. 工具契约

### 4.1 定义

```python
class DeleteWorkspaceFileTool:
    definition = ToolDefinition(
        "delete_workspace_file",
        "删除工作区内一个经哈希确认的普通文本文件；执行前必须审批",
        {
            "type": "object",
            "properties": {
                "path": {"type": "string"},
                "expected_sha256": {
                    "type": "string",
                    "pattern": "^[0-9a-f]{64}$",
                },
            },
            "required": ["path", "expected_sha256"],
            "additionalProperties": False,
        },
        effect=ToolEffect.MUTATING,
    )
```

### 4.2 预览

`preview()` 在工具自己的异步锁内完成：

1. 精确校验参数集合和 SHA-256 格式。
2. 调用 `WorkspacePolicy.resolve_write_file(path, creating=False)`，复用越界、符号链接和保护路径规则。
3. 使用现有 `_read_text(..., max_bytes=MAX_EDIT_FILE_BYTES)` 拒绝大文件、二进制和非 UTF-8 内容。
4. 比较当前摘要和 `expected_sha256`；不一致返回 `workspace_conflict`。
5. 构造 `before=原字节、after=None` 的单个 `_FileChange`。
6. 使用 `_diff(relative, before, None)` 生成删除 Diff；空文件也必须产生可审批预览，因此为空文件补充固定元数据行，而不是绕过审批。
7. Diff 超过 `MAX_DIFF_BYTES` 时返回 `invalid_arguments`，不展示截断内容。
8. 保存参数摘要对应的 fingerprint，并返回标题“删除文件”、单个相对路径和 Diff。

### 4.3 执行

`invoke()` 在同一工具锁内重新调用规划逻辑，并比较预览阶段 fingerprint。任何路径、类型、权限、正文或摘要变化都返回 `workspace_conflict`。

执行顺序：

1. `journal.ensure_capacity((change,))`，提前确认数量与快照容量。
2. 再次读取文件并校验原内容摘要。
3. 使用 `Path.unlink()` 删除已经验证的普通文件，不调用 Shell。
4. 构造 `result_hashes=(None,)` 并追加 Journal。
5. 如果 Journal 追加异常，使用原字节和权限原子恢复；若恢复失败，异常仍只映射为有限的 `execution_failed`，详细原因不得进入模型结果。

成功结果：

```json
{
  "change_id": "...",
  "path": "docs/obsolete.md",
  "deleted_sha256": "..."
}
```

## 5. 通用变更执行与撤销

### 5.1 提交和回滚

扩展现有私有帮助函数，不新增另一套文件事务实现：

- `_commit_changes()`：`after is None` 时，在统一复验后调用 `unlink()`。
- `_restore_changes()`：删除变更失败回滚时，以 `_write_new_file()` 恢复原文件，绝不覆盖竞态中出现的新文件。
- 所有写入 `bytes` 的分支增加显式保护，避免把 `None` 传给原子写函数。

虽然第一版删除工具每次只有一个文件，仍复用通用路径，以保证 Journal 行为和后续维护一致。

### 5.2 撤销规划

`UndoWorkspaceChangeTool._plan()` 按执行后状态验证：

- `result_hash` 为字符串：目标必须是允许写入的普通文件且摘要一致。
- `result_hash` 为 `None`：目标必须仍不存在且父目录链仍位于工作区、不是符号链接；若用户已创建同名文件则返回 `workspace_conflict`。

删除变更的撤销 Diff 为 `_diff(relative, None, before)`。

### 5.3 撤销执行

`_undo_files()` 对 `after is None` 的删除变更使用 `_write_new_file(path, before, mode)` 恢复原字节和原权限。若批次撤销中途失败，补偿逻辑重新还原到撤销前的“不存在”状态。

现有创建和替换的撤销行为保持不变。

## 6. 路径与安全策略

- 删除仍调用 `normalize(..., writing=True)`，所以现有 `PROTECTED_COMPONENTS`、`.env*`、`PROTECTED_WRITE_PATHS` 和 `docs/rules/**` 全部继续生效。
- 目标必须在预览和执行时都是普通文件；`resolve_write_file(..., creating=False)` 已拒绝目录、缺失目标和符号链接。
- 不接受多个路径、目录、glob、绝对路径或文件 URL。
- 删除工具必须由 `ToolRegistry` 识别为 `ApprovalTool`；没有审批处理器时返回 `approval_unavailable`。
- TUI 审批日志沿用 `llm_tool_approval`，只记录工具名、决定、文件数、Diff 字符数和耗时，不记录被删正文。
- 原规则“不得提供文件删除”调整为“除 `delete_workspace_file` 外不得提供删除；该工具必须满足单文件、文本、哈希、保护路径、逐次审批和可撤销约束”。

## 7. 注册与工具披露

`_create_workspace_tools()` 创建同一个 `DeleteWorkspaceFileTool(policy, active_journal)`，与编辑及撤销工具共享 Journal。

`workspace_write` 组顺序调整为：

```text
read tools
apply_workspace_edits
delete_workspace_file
run_project_check
undo_workspace_change
```

这样模型只有先激活写入意图后才接收删除 Schema。`create_default_registry()` 保持不变，确保 HTTP `/chat` 不开放删除。

`app/tui/workspace_changes.py` 的请求级变更追踪器同时识别删除结果中的单个 `path`。删除成功后记录对应 `change_id` 和相对路径，后续模型步骤失败时沿用现有提示；`undo_workspace_change` 成功后按同一 `change_id` 移除。追踪器不读取已删除正文，也不改变工具返回契约。

## 8. 异常映射

不新增错误码，复用现有固定分类：

| 场景 | 错误码 |
|---|---|
| 参数缺失、格式错误、目录、普通不可读文本、超出大小或 Diff 上限 | `invalid_arguments` |
| 受保护路径 | `protected_path` |
| 哈希不一致、审批后变化、撤销前同名路径重现、Journal 已满 | `workspace_conflict` |
| 无审批处理器 | `approval_unavailable` |
| 用户拒绝 | `approval_denied` |
| 未预期文件系统失败 | `execution_failed` |

任何 ToolResult 都不包含工作区绝对路径、文件正文、系统错误字符串或堆栈。

## 9. 测试设计

### 9.1 工具单元与集成测试

- 工厂注册数量、工具名及 `workspace_write` 激活后的定义顺序。
- 正常删除中文路径、中文内容，并检查审批删除 Diff、有限结果和 Journal。
- 成功删除后批准撤销，校验原字节和权限恢复。
- 空文本文件仍产生明确审批预览并可删除、撤销。
- 无审批、用户拒绝时文件不变。
- 缺少/多余参数、错误摘要格式、错误摘要、目标不存在、目录、二进制、超限文件拒绝。
- 绝对路径、`..`、符号链接、`.env*`、生成目录、保护文件和 `docs/rules/**` 拒绝。
- 审批回调期间修改、删除或替换目标时返回冲突。
- 删除后、撤销前重新创建同名文件时撤销返回冲突且不覆盖。
- 模拟删除失败、Journal 追加失败和恢复竞态，校验不产生错误成功状态。

### 9.2 回归测试

- 创建、替换及其撤销行为不变。
- `create_default_registry()` 仍只有默认只读工具。
- Provider Schema 序列化支持新增工具定义。
- TUI 审批 Modal 无需增加新请求类型。
- TUI 请求级变更追踪器记录删除路径，并在撤销后移除。

## 11. 风险与缓解

- **误删用户文件**：强制读取摘要、逐次 Diff 审批、执行前复验、保护路径和单文件上限。
- **审批竞态**：参数 fingerprint 加执行时重读；发生变化一律拒绝。
- **撤销覆盖新文件**：用“不存在”结果状态验证和 `_write_new_file()` 原子发布。
- **内部数据模型回归**：三态表、类型保护及现有创建/替换全量测试。
- **大文件占用内存**：沿用 256 KiB 编辑上限和 512 KiB Journal 上限。
- **工具 Schema Token 增长**：仅激活 `workspace_write` 后披露，不进入默认首步和 HTTP。

## 12. 性能

每次预览和执行最多各读取一个 256 KiB 文件并计算 SHA-256，复杂度为 O(n)。删除本身是单文件系统调用。没有网络、并发批量或新后台任务；无需新增性能基线。

## 13. 回滚

- 代码回滚：移除工具注册和三态分支，恢复旧规则描述。
- 数据回滚：工具执行成功后优先使用返回的 `change_id` 调用 `undo_workspace_change`；若进程已经结束，Journal 不持久化，只能通过 Git 或备份恢复。
- 不自动迁移或持久化 Journal，不修改现有会话文件格式。
