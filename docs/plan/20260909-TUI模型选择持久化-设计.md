# TUI 模型选择持久化设计

状态：已完成（2026-09-09）

## 1. 设计依据

- 已确认需求：[TUI 模型选择持久化需求](../spec/20260909-TUI模型选择持久化-需求.md)。
- 现有 `/model` 已通过 `resolve_model_options()` 获取启动候选快照，通过 `create_provider_for_model()` 创建 Provider，再由 `ChatSession.replace_provider()` 原子替换后续请求使用的实例。
- `app/tui/__main__.py` 是生产组合根；`ChatTuiApp` 当前装配默认 `SessionStore`、`ChatSession`、模型候选和状态栏快照，并支持测试依赖注入。
- HTTP 调用继续由 `app/runtime/chat.py` 中的 `create_provider()` 读取环境，不应读取任何 TUI 本地偏好。

## 2. 总体方案

新增一个与聊天会话独立的 `ModelSelectionStore`，只负责版本化 JSON 的安全读写。生产组合根显式创建 Store 并注入 `ChatTuiApp`；应用在创建默认 `ChatSession` 时读取最后选择并注入恢复后的 Provider，运行中 `/model` 切换成功后立即保存。

```text
                    TUI 启动
                       │
          resolve_model_options()  环境默认配置
                       │             │
                       v             v
ModelSelectionStore.load() ──> 恢复策略 ──> 当前 ModelOption
                                      │
                            create_provider_for_model()
                                      │
                                      v
                         ChatSession.load(provider=...)
                                      │
                                      v
                         runtime_info + StatusBar

/model 确认 ──> 创建 Provider ──> replace_provider()
                                      │ 成功
                                      v
                         ModelSelectionStore.save()
```

保存发生在 Session 替换成功之后。保存失败不会回滚当前 Provider，只产生安全提示；这保证模型切换的即时结果与用户操作一致。

## 3. 持久化模型

新增 `app/runtime/model_selection_store.py`：

```python
@dataclass(frozen=True)
class ModelSelection:
    provider: str
    model: str


class ModelSelectionStore:
    def load(self) -> ModelSelection | None: ...
    def save(self, selection: ModelSelection) -> None: ...
```

默认路径为项目根目录 `data/model-selection.json`，与 `chat-session.json` 同目录但不同文件。Schema 固定为：

```json
{"version":1,"provider":"deepseek","model":"deepseek-v4-flash"}
```

### 3.1 读取约束

- 文件缺失返回 `None`，不是错误。
- 使用 `lstat()` 检查目标必须是普通文件且不是符号链接。
- 文件最大 4 KiB；读取前检查大小，读取时再次使用有界字节数，避免竞态导致无界读取。
- 只接受 UTF-8、JSON object、精确版本 `1`、字符串 `provider/model`；额外字段拒绝，避免错误配置被静默忽略。
- Provider 只允许 `deepseek`、`aliyun`；模型名复用公共模型名校验，避免存储契约与模型工厂出现两套规则。
- 任意无效状态抛出 `ModelSelectionStoreError("Unable to load saved model selection")`，不携带路径、正文或底层异常。

### 3.2 写入约束

- 先验证 `ModelSelection` 的类型、Provider 和模型名。
- 父目录以 `0700` 创建；同目录使用 `tempfile.mkstemp()`，临时文件设为 `0600`。
- 写入紧凑 UTF-8 JSON 和换行，`flush + fsync` 后用 `os.replace()` 原子发布；发布后显式 `chmod(0600)`，修复既有目标权限。
- 失败时关闭描述符并清理临时文件，抛出 `ModelSelectionStoreError("Unable to save model selection")`。
- 不提供 `clear()`；`/clear` 和 `/memory clear` 无法误删模型选择。

## 4. 公共模型名校验

现有 `factory._validated_model_name()` 已被目录解析和 Provider 创建共同使用，但它是私有函数。为避免 Store 复制长度、逗号和控制字符规则，将其提升为公开、纯函数 `validate_model_name(value) -> str | None`，原调用点统一复用。

该函数不读取环境、不创建 Provider，也不包含密钥。此调整只改变模块内公开命名，不修改 HTTP 契约。

## 5. TUI 装配与依赖注入

生产 `_create_app()` 和 `ChatTuiApp.__init__()` 增加参数：

```python
model_selection_store: ModelSelectionStore | None = None
```

装配规则：

1. `app/tui/__main__.py` 明确创建默认 `ModelSelectionStore()`；`ChatTuiApp` 自身不会在参数缺失时隐式访问磁盘。
2. 仅当应用使用默认 `ChatSession`（没有注入 `chat_runner` 或 `chat_session`）且 Store 已注入时尝试启动恢复；显式 Session 配合 Store只验证后续切换保存，不覆盖调用方 Provider。
3. 测试或宿主可显式注入临时 Store；未注入 Store 的裸 Runner 和现有单元测试不访问真实 `data/`。
4. 先解析 `_model_options`，再读取 Store；只有 `(provider, model)` 与候选精确匹配且 `api_key_configured=True` 时才创建恢复 Provider。
5. 恢复成功后，以 Provider 的真实 `name/model/api_key_configured` 构造 `ChatRuntimeInfo`，并把同一 Provider 注入 `ChatSession.load(..., provider=provider)`；状态栏与请求不会出现分叉。
6. 文件不存在时维持当前逻辑：状态栏来自 `get_chat_runtime_info()`，Session 首次请求按环境创建 Provider。
7. 文件无效、候选移除、Key 缺失或 Provider 创建失败时，保留环境默认逻辑并记录一条有限启动警告。

启动警告只说明“已忽略无法恢复的模型选择，当前使用环境默认模型”，不把应用置为 `ERROR`，也不阻止发送。警告通过 `on_mount()` 写为 System 消息；它不进入 Session。

## 6. 切换与保存顺序

调整 `_switch_model()`：

1. 校验候选 Key。
2. 创建完整 Provider。
3. `ChatSession.replace_provider(provider)`。
4. 更新 `runtime_info`、状态栏和就绪状态。
5. 若 Store 可用，保存 `ModelSelection(provider.name, provider.model)`。
6. 保存成功显示现有“已切换模型”消息；保存失败仍显示切换成功，并追加“模型已切换，但无法保存启动选择”。

不在 Provider 创建失败、Key 缺失或 Session 替换失败时写文件，因此磁盘始终表示最近一次真正生效的选择。

## 7. 错误语义

| 场景 | 当前 Provider | 启动/界面行为 | 磁盘行为 |
| --- | --- | --- | --- |
| 偏好文件缺失 | 环境默认 | 不提示 | 不创建文件 |
| 偏好合法且可用 | 保存模型 | 正常启动 | 不重写 |
| JSON/版本/类型非法 | 环境默认 | System 警告 | 保留原文件 |
| 保存模型已移出候选 | 环境默认 | System 警告 | 保留原文件 |
| 对应 Key 缺失 | 环境默认 | System 警告 | 保留原文件 |
| 恢复 Provider 创建失败 | 环境默认 | System 警告 | 保留原文件 |
| 运行中切换失败 | 原模型 | 现有错误 | 不写入 |
| 切换成功、保存失败 | 新模型 | 成功 + 保存警告 | 保留旧文件或不存在 |

无效文件不自动删除或覆盖；用户之后成功切换时，合法状态可原子替换该文件。

## 8. 安全与隐私

- 偏好只包含供应商和模型标识，不包含 API Key、Base URL、环境变量、工作区路径或聊天信息。
- 读取时拒绝符号链接和非普通文件；写入只操作固定应用数据路径，不接受用户或模型传入路径。
- 模型名在磁盘解析、候选匹配和 Provider 创建三层验证。
- 错误消息固定且脱敏，底层异常只保留在异常链中，不进入 TUI、模型请求或会话文件。
- 不新增工具、不扩大模型权限，也不让外部模型读写偏好文件。

## 9. 性能与可靠性

- 启动最多读取一个 4 KiB 文件并线性扫描至多 100 个候选，开销可忽略。
- 只有用户确认模型切换时写一次小文件，正常聊天请求不增加磁盘 I/O、Token 或网络往返。
- 立即保存比退出钩子可靠：双 Esc、终端关闭和进程崩溃不会丢失此前已完成的选择。
- 原子替换避免部分 JSON；临时文件与目标同目录，确保替换位于同一文件系统。

## 10. 测试设计

### 10.1 Store

- 缺失文件返回 `None`，合法中英文安全模型名读写一致。
- 保存后 JSON 字段精确、权限为 `0600`，连续保存覆盖为最后值。
- 拒绝符号链接、目录、超限、非 UTF-8、损坏 JSON、额外字段、错误版本、Provider、模型类型和非法模型名。
- 模拟创建目录、写入、`fsync`、替换失败，检查有限错误和临时文件清理。

### 10.2 TUI

- 合法保存项恢复到状态栏、ModelPalette 当前项和 `ChatSession` Provider；下一次发送使用恢复模型。
- 文件缺失继续使用环境默认；无效文件、目录移除和 Key 缺失均回退并显示非阻断警告。
- `/model` 成功后 Store 收到真实 Provider 选择；失败切换不保存。
- Store 保存失败时 Provider、状态栏和下一次请求仍使用新模型，并显示保存警告。
- `/clear`、`/memory clear` 后偏好文件仍存在。
- 注入裸 `chat_runner` 且未注入 Store 时不访问生产偏好文件。

### 10.3 回归

- HTTP `create_provider()` 和 `/chat` 不读取偏好。
- 模型候选、命令、会话恢复、记忆摘要、工具循环和流式输出行为不变。
- 全部测试使用 `tmp_path`、假 Store 或假 Provider，不访问真实 API。

## 12. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 状态栏已恢复但 Session 仍用环境 Provider | 展示与真实请求不一致 | 创建一次 Provider，并同时注入 Session 和 RuntimeInfo |
| 测试读取开发者真实偏好 | 测试污染或不稳定 | 默认 Store 只在生产默认 Session 路径启用，测试显式注入临时 Store |
| 环境模型目录更新 | 保存项已不可用 | 启动重新匹配候选并回退，不盲目创建 |
| Key 被移除 | 启动后首个请求失败 | 恢复前检查候选 Key，回退并提示 |
| 保存失败导致误认为已持久化 | 下次启动回到旧模型 | 当前切换不回滚，立即显示单独警告 |
| 损坏文件被自动覆盖 | 故障证据丢失 | 启动只读保留，成功人工切换后才覆盖 |

## 13. 回滚

- 代码回滚后旧版本自然忽略 `data/model-selection.json`，HTTP 和会话文件不受影响。
- 删除 Store 接入和保存调用即可恢复“每次启动按 `.env`”行为，无数据迁移。
- 偏好文件可保留供重新启用；如需删除应由用户明确操作，本功能不自动清理。
