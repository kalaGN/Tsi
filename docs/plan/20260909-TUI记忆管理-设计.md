# TUI 记忆管理设计

状态：已完成（2026-09-09）

对应需求：[TUI 记忆管理需求](../spec/20260909-TUI记忆管理-需求.md)

## 1. 架构

新增 `app/runtime/memory.py` 承担纯状态与策略：Token 估算、压缩计划、长期偏好提取、记忆提示构造。`ChatSession` 负责编排一次发送事务，`SessionStore` 只负责 v1/v2 解码和原子持久化。

```text
ChatSession.send
  -> 读取请求级 Skill/工具快照
  -> MemoryManager.prepare（估算、必要时摘要/淘汰）
  -> run_chat_messages（摘要 + 偏好 + 最近轮次）
  -> 成功后一次保存完整 Transcript + 新记忆状态
```

## 2. 关键决策

### 2.1 完整历史与模型上下文分离

`messages` 永久保留完整成功轮次；`summarized_message_count` 只决定从哪里开始构造模型上下文。这样压缩不会让重启后的界面丢失旧对话。

### 2.2 本地预算

估算器每条消息增加固定结构开销，ASCII 按约 4 字符/Token，非 ASCII 按 1 字符/Token。它仅用于安全预算，不能表示计费 Token。策略固定 70% 触发、50% 目标、最近 6 轮保护，并为回复和协议结构预留固定 Token。

### 2.3 模型摘要

摘要器使用当前 Session Provider 发起无工具、非流式内部请求。输入包含旧摘要与本次被压缩的完整轮次，输出只作为新的摘要文本。内部请求失败时返回无摘要的确定性淘汰结果，业务请求继续。

### 2.4 事务边界

压缩、偏好提取和业务回答先形成候选状态。只有业务 Provider 完成且 v2 文件保存成功，内存状态才整体替换；失败或取消不提交任何候选记忆。

### 2.5 长期偏好

偏好提取采用确定性显式语句规则，不为每轮额外调用模型。正文标准化、敏感关键词拒绝、SHA-256 派生 ID、UTC 更新时间，并以最近更新顺序限制为 50 条。

## 3. 兼容迁移

- v1 解码为仅含旧消息的空记忆状态。
- v2 严格验证边界、角色交替和偏好字段。
- 读取不主动改盘；下一次成功发送、清理或偏好变更再原子写 v2。
- `SessionStore.load()` 保留消息元组兼容入口，新增 `load_state()`/`save_state()` 供新 Session 使用。

## 4. TUI 命令

- `/memory`：展示已保存偏好编号和正文；空时显示明确提示。
- `/memory clear`：原子清除偏好，不清除对话和摘要。
- `/clear`：清除 Transcript 与摘要，但保留偏好；偏好非空时保留 v2 文件。

## 5. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 摘要调用增加成本或失败 | 只在阈值触发；不提供工具；失败走确定性淘汰 |
| 摘要内容注入指令 | 以低优先级记忆区包装，明确不能覆盖当前请求和项目规则 |
| 估算与真实 tokenizer 偏差 | 提前触发并预留输出预算；超长当前输入在本地阻断 |
| v1 文件迁移损坏 | 严格解码、延迟写回、保留现有损坏文件处理 |
| 完整 Transcript 无限占磁盘 | 本期不删除历史；后续多会话/归档单独设计 |
