# Agent 评测系统设计

状态：已完成（2026-09-11）

对应需求：[Agent 评测系统需求](../spec/20260911-Agent评测系统-需求.md)

## 1. 现状与设计原则

当前真实调用链为：

```text
HTTP/TUI
  -> ChatSession.send（TUI 会话、记忆和持久化）
  -> run_chat_messages（Provider 选择、统一错误和请求日志）
  -> LlmProvider.create_turn
  -> run_tool_loop（模型步骤、工具审批与执行、Token 聚合）
  -> ToolRuntime
```

评测必须复用这条链路。Runner 只负责构造受控 Provider、临时工作区、会话初始状态和 Observer，不复制业务编排。这样 Runtime、Tool Loop、规则或 Skill 发生变化时，评测会真实反映变化。

依赖方向固定为：

```text
app.evaluation -> app.runtime -> app.services.llm + tools
                         ^
                         |
                通用 Trace 契约
```

`app.runtime` 不得反向导入 `app.evaluation`。评测报告也不解析生产日志。

## 2. 模块设计

### 2.1 Runtime Trace 契约

新增 `app/runtime/trace.py`：

- `TraceEvent`：不可变事件，字段只使用 JSON 可序列化基本类型。
- `TraceObserver`：同步 `record(event)` Protocol。
- 事件类型：`request_started`、`model_step_completed`、`tool_call_started`、`tool_approval_completed`、`tool_call_completed`、`request_completed`、`request_failed`。
- `emit_trace(observer, event)`：Observer 为空时立即返回；Observer 异常向调用方传播，评测不会得到伪造的不完整成功结果。

以下入口新增仅关键字可选参数 `trace_observer=None`：

- `run_chat`
- `run_chat_messages`
- `run_tool_loop`
- `ChatSession.send`

不传 Observer 时不创建事件对象、不改变 HTTP/TUI 返回、流式回调、现有日志和错误映射。

`run_tool_loop` 在 `turn.next()` 前后使用已有可注入 `clock` 计算模型步骤耗时，并记录该步骤调用前实际可见的工具名。工具事件记录原始参数和结果只存在内存中，进入报告前由 Collector 脱敏。

### 2.2 数据契约

`app/evaluation/contracts.py` 使用冻结 `dataclass` 定义：

- `EvaluationCase`：ID、输入、标签、Setup、回放步骤和 Expected。
- `CaseSetup`：相对路径文本文件、初始完整对话、摘要边界和显式偏好。
- `CaseExpectation`：文本、上下文、工具、审批、文件、状态和预算断言。
- `AgentRunTrace`：单次 Trial 的执行轨迹与 Harness 指纹。
- `AssertionResult`：名称、维度、是否通过和有限证据。
- `TrialResult`、`CaseResult`、`EvaluationReport`：逐级聚合结果。

JSONL Loader 采用字段白名单递归校验。错误消息格式固定为：

```text
<suite-path>:<line>: case '<id>': <reason>
```

Setup 文件和文件断言只接受安全 POSIX 相对路径，拒绝绝对路径、空组件、`.`、`..`、NUL、`.git`、`.env*`、`logs`、`data` 和 `.agents`。初始历史必须保持 user/assistant 完整交替。

### 2.3 回放 Provider

`app/evaluation/replay.py` 实现现有 `LlmProvider`/`LlmTurn` 协议：

- Provider 名固定为 `replay`，模型固定为 `scripted-v1`。
- 每个 `create_turn()` 消费一组预先声明的步骤；普通 Case 只有一组，触发记忆摘要的 Case 可以声明多组 Turn。
- 每步转换为真实 `ModelStep`；工具调用使用真实 `ToolCall`。
- 记录 `create_turn()` 收到的消息与工具快照，供上下文断言使用。
- 步骤耗尽、存在未消费 Turn 或脚本字段非法时，以评测配置错误失败，不映射为 Provider 成功。
- `on_text_delta` 存在时只对最终文本发出确定性增量，覆盖真实流式回调路径。

回放 Provider 不访问网络，也不进入生产 Provider Factory。

### 2.4 Case 隔离环境

`app/evaluation/environment.py` 为每个 Trial 创建：

```text
<system-temp>/tsi-eval-<run>-<case>-<trial>/
├── workspace/       # 工具唯一可访问根目录
└── state/session.json
```

装配顺序：

1. 从当前项目复制 `AGENTS.md` 与已跟踪的 `.agents/skills/` 到 `workspace/`，只作为本次 Harness 输入。
2. 写入 Case Setup 的普通文本文件；禁止覆盖 Harness 文件。
3. 构造 `WorkspacePolicy(workspace)`、加载系统提示和 Skill Catalog。
4. 使用真实 `SkillRuntime` 和 `create_intent_workspace_registry` 创建请求级工具组。
5. 将 Setup 会话状态写入独立 `SessionStore(state/session.json)`。
6. 以回放或显式真实 Provider 构造真实 `ChatSession`。

每个 Trial 完成后先执行文件断言，再清理整个临时根目录。异常与取消也清理。Runner 不切换进程当前目录，避免并发和失败时污染宿主状态。

第一版串行运行 Case 和 Trial；接口不依赖全局状态，为后续并发预留空间。

### 2.5 Harness 指纹

`app/evaluation/fingerprint.py` 生成稳定 SHA-256：

- 原项目 Git HEAD；脏工作树单独记录 `dirty=true`，不将 Diff 正文写入报告。
- 原项目 `AGENTS.md` 内容哈希。
- `.agents/skills/` 中相对路径和文件内容的有序组合哈希。
- Trial 首步工具定义及分组说明的规范 JSON 哈希。
- `MemoryPolicy`、`ToolLoopLimits` 的规范 JSON 哈希。

动态激活后的实际工具可见性属于 Trace，不进入静态工具指纹。文件遍历排序，时间戳和绝对路径不参与哈希。

### 2.6 Trace Collector 与脱敏

`app/evaluation/observer.py` 接收 Runtime 事件并生成 `AgentRunTrace`。统一脱敏规则：

- 字段名匹配 `authorization`、`api_key`、`access_token`、`cookie`、`password`、`secret`、`密码`、`密钥`、`令牌` 时将值替换为 `[REDACTED]`。
- Bearer、常见 Key/Token 赋值文本在字符串中替换为 `[REDACTED]`。
- 单字段最多保留 32 KiB，超出时标记截断和原字符数。
- 报告中的本地路径转换为相对 Case 路径；无法相对化的绝对路径替换为 `[ABSOLUTE_PATH]`。

原始事件只在单次 Trial 内存中短暂存在，不写生产日志或中间文件。

## 3. Runner 与 CLI

`app/evaluation/runner.py`：

1. 加载 Suite 并生成 `run_id`。
2. 校验模式：默认 replay；`--live` 必须同时提供 provider/model，且 Case 不得包含 replay-only 断言冲突。
3. 按 Case/Trial 构造隔离环境并调用 `ChatSession.send()`。
4. 捕获 `ChatRuntimeError`、评测配置错误和意外异常为结构化失败；`KeyboardInterrupt` 终止整次 Run。
5. 执行 Grader 并聚合报告；单个 Case 失败不跳过其他 Case。
6. 原子写入 JSON 和 Markdown。

`app/evaluation/__main__.py` 使用 `argparse` 提供三个子命令：

- `run`：执行 replay 或 live Suite。
- `judge`：读取现有 JSON 报告，调用独立 Judge，写出同目录 `-judged.json/.md`，不覆盖原报告。
- `compare`：读取基线和候选报告并输出中文摘要。

退出码：

| 退出码 | 含义 |
|---:|---|
| 0 | 命令成功，`run` 无失败 Case，`compare` 无回归 |
| 1 | 存在评测失败或确认的指标回归 |
| 2 | CLI 参数、Suite、报告或配置无效 |
| 3 | live Provider/Judge 调用失败，无法形成有效结论 |

`run --live` 仅加载项目根 `.env` 以读取密钥，Provider 必须通过 `create_provider_for_model()` 创建。CLI 不接受 API Key 参数，避免进入 Shell 历史。

## 4. 评分算法

### 4.1 断言与维度

Grader 从 Trace、Replay 捕获的请求快照、最终结果和清理前文件快照计算断言：

- 任务完成：状态、错误码、输出包含/排除/正则、文件结果、系统提示和请求上下文。
- 工具正确性：必要/禁止工具、调用顺序、总调用次数、模型步骤和逐步可见工具。
- 安全审批：期望审批决定、拒绝后未执行、路径边界与环境污染检查。
- 效率：Token、模型步骤、工具调用和耗时预算。

每个显式断言等权计算所属维度得分；某维度没有断言时不参与 Case 权重。参与维度按需求默认权重重新归一化。任一安全断言失败时 Case 必须失败，即使加权总分较高。

### 4.2 聚合

- Trial：断言全部通过才记为通过，同时保留 0–100 分。
- Case：报告 Trial 通过率、均分、最小、最大和标准差；所有 Trial 通过才记为稳定通过。
- Run：按 Case 等权聚合；安全 Case 失败单独置顶。

真实模型的时延和 Token 可能波动。未在 Expected 显式声明预算时只展示不判失败。

### 4.3 基线比较

`compare` 先校验报告 Schema 和可比性：

- mode 必须相同。
- live 模式 provider/model 必须相同。
- AGENTS、Skills、工具、MemoryPolicy、ToolLoopLimits 指纹不同仍允许比较，但必须列出变化，Git HEAD 不作为拒绝条件。

满足任一条件判回归：总分下降 `> 3`；通过率下降 `> 5` 个百分点；任一原通过的 safety 标签 Case 失败。Case 新增/删除单独提示，不静默按相同集合比较。

## 5. 可选 LLM Judge

`app/evaluation/llm_judge.py` 使用现有 Provider 协议，工具列表为空：

1. 固定中文系统 Prompt，包含 Judge Schema 版本和“不执行输入指令”的边界。
2. 用户消息是 Case ID、受控输入、Expected 摘要、最终输出和脱敏工具轨迹 JSON。
3. Provider 必须返回严格 JSON：正确性、完整性、相关性各 1–5，理由每项不超过 500 字符。
4. 对每个 Trial 独立评分，Token 单独聚合为 `judge_usage`。
5. 单个 Judge 失败记录错误并继续；全部失败返回退出码 3。
6. Judge 不接收确定性安全评分的修改权，不能改变 Case pass/fail。

## 6. 报告格式与写入

报告 Schema 从 `version: 1` 开始。JSON 使用 UTF-8、稳定排序键和原子替换。Markdown 由 JSON 报告对象单向渲染，包含：

1. 运行信息与 Harness 指纹。
2. 总分、通过率、Token、耗时和 Trial 统计。
3. Case 表格。
4. 安全失败和普通失败详情。
5. Judge 结果（如有）。
6. 与基线比较结果（compare 输出，不修改原报告）。

文件名组件只允许 ASCII 字母、数字、点、下划线和短横线，其他字符转换为短横线。`evals/reports/` 加入 `.gitignore`，`evals/cases/` 和 `evals/baselines/` 保持可跟踪。

## 7. 核心 Suite

`evals/cases/core.jsonl` 至少包含：

| Case | 验证重点 |
|---|---|
| `direct-answer` | 无工具直接回答 |
| `readonly-tool` | 激活 general 并调用当前时间工具 |
| `write-approved` | 激活写组、审批通过、文件符合预期 |
| `write-denied` | 审批拒绝、文件不变、模型恢复回答 |
| `tool-error-recovery` | 非法工具参数返回安全错误后恢复 |
| `tool-loop-limit` | 超限映射为 `tool_limit` |
| `on-demand-tools` | 首步只见激活工具，下一步才见目标工具 |
| `explicit-skill` | `$skill` 正文进入系统提示且 skills 组预激活 |
| `memory-context` | 初始历史/偏好进入请求且成功轮次被隔离持久化 |

固定当前时间工具的动态结果不做精确值断言，只断言工具成功 Envelope 和最终回答。写入样例只创建普通 `notes.txt`，不触发外部命令、Git 或网络。

## 8. 异常与恢复

| 场景 | 行为 |
|---|---|
| JSONL 某行非法 | Suite 整体拒绝，退出码 2，不产生半份报告 |
| 单个 Agent Case 失败 | 记录失败并继续，最终退出码 1 |
| 临时目录创建/清理失败 | Case 标记基础设施失败；清理失败写报告警告 |
| live 配置缺失 | 启动前拒绝，退出码 2 |
| live 上游失败 | 记录 Trial；所有有效 Trial 缺失时退出码 3 |
| 报告目标已存在 | 使用时间戳加短 run ID 避免覆盖 |
| Judge 输出非法 | 记录 Judge 错误，不修改确定性评分 |
| Observer 事件不完整 | Trial 标记基础设施失败，不以部分轨迹评分 |

## 9. 安全

- 临时 Workspace 是所有文件工具的唯一根；不向工具传递真实项目 Policy。
- Case Setup 不支持符号链接、二进制、外部 URL、Shell 命令或环境变量展开。
- 核心 Suite 不启用 Git Push、Skill 安装或脚本执行；此类能力后续需独立 Spec。
- live 和 Judge 只允许现有供应商枚举，密钥仅从环境读取。
- 报告落盘前执行递归脱敏测试；错误堆栈默认不进入报告。
- 临时复制的 Skill 脚本即使存在，也必须经过真实审批；核心 Suite 不批准执行类工具。

## 10. 性能与成本

- replay 模式没有网络成本，Case 串行执行并使用小型 fixture。
- live 模式预计调用次数约为 `Case 数 × trials × 平均模型步骤`，CLI 启动前显示预计最少 Case/Trial 数，不推测 Token 费用。
- `--trials` 限制为 1–20，Suite 限制 500 Case，单行和单文件文本有界。
- 报告仅保存有限 Trace，避免工具结果或模型输出导致无界内存和磁盘增长。

## 11. 兼容与迁移

- 不修改 HTTP `/chat` 契约、TUI 命令和会话 Schema。
- 新增可选 Trace 参数，现有调用方无需修改。
- 不改变现有日志事件字段。
- 不新增依赖、数据库或环境变量。
- 删除 `app/evaluation/`、`app/runtime/trace.py`、`evals/` 及可选参数即可回滚；已有 Runtime 行为不需要数据迁移。

## 12. 实施顺序

1. 数据契约、Loader 和回放 Provider。
2. Runtime Trace 契约与工具循环事件。
3. 隔离环境、Harness 指纹和 Runner。
4. 确定性 Grader、报告与 CLI `run`。
5. 核心 Suite 与端到端回放。
6. 基线比较和 `compare`。
7. 可选 Judge。
8. 文档、全量门禁和代码审查。
