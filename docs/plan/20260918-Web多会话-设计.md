# Web 多会话设计

状态：已完成（2026-09-18）

对应需求：[Web 多会话需求](../spec/20260918-Web多会话-需求.md)

## 1. 架构

```text
Web 页面
  └─ /ui/api/sessions/*
      └─ WebUiService（并发门禁与页面 DTO）
          ├─ WebSessionCatalog（索引、选择、标题、迁移）
          │   ├─ data/web-sessions/index.json
          │   └─ data/web-sessions/sessions/<id>.json
          └─ ChatSession Cache
              └─ SessionStore（消息、摘要、偏好）
```

`WebSessionCatalog` 只管理元数据，不复制 Runtime 的对话逻辑。`WebUiService` 使用工厂按 ID 延迟装配 `ChatSession`，切换会话时复用缓存；切换模型后同步替换已缓存会话的 Provider，后续新会话从项目级模型选择装配。

## 2. 数据结构

索引版本为 1，包含 `current_session_id` 和带 `id`、`title`、`created_at`、`updated_at` 的会话数组。

- ID 只能由服务端 `uuid4().hex` 生成，所有入口重新校验。
- 标题去除首尾空白，长度为 1–80；自动标题取首条输入前 30 个字符。
- 索引使用同目录临时文件、`fsync` 与 `os.replace` 原子提交，权限 `0600`；目录权限 `0700`。
- 会话文件由现有 `SessionStore` 管理；索引最多接受 1000 条，API 返回最近 50 条。

## 3. 生命周期

1. 索引存在：严格解码并恢复当前会话。
2. 索引不存在且旧 `web-session.json` 存在：读取旧状态、生成“历史对话”、写新会话文件，再写索引。
3. 两者都不存在：创建一个“新对话”元数据；空会话文件延迟到首次消息。
4. 成功发送后更新 `updated_at`；默认标题在首轮成功后自动生成。
5. 删除先写入不含目标的新索引，再删除目标会话文件；残留孤儿文件不影响索引安全。

## 4. 并发与模型

- `WebUiService` 保留一个全局 `asyncio.Lock`；请求期间所有会话结构操作返回 409。
- 流开始时捕获会话 ID 与对象，成功、失败或取消事件都归属该 ID。
- 模型选择仍写 `data/model-selection.json`。成功切换当前会话后，清除其他会话对象缓存；以后通过恢复后的 Provider 装配。
- `/chat`、TUI 和 Workspace 权限不变。

## 5. 页面

- `state.sessions` 与 `state.currentSessionId` 是页面会话元数据唯一来源。
- 会话列表通过 DOM API 和 `textContent` 构造，不使用 `innerHTML`。
- 新建、切换、重命名、清空和删除成功后统一应用服务端返回的当前会话 DTO。
- 流完成事件携带更新后的会话元数据，用于自动标题和排序。
- 删除与清空使用确认框；重命名使用受后端再次校验的文本输入。

## 6. 风险与恢复

| 风险 | 处理 |
|---|---|
| 索引损坏导致会话串线 | 启动失败并返回稳定 503，不猜测磁盘文件 |
| 旧文件迁移中断 | 索引最后写入；重启可从旧文件重新迁移 |
| 删除过程中断 | 先提交索引，孤儿文件不被加载 |
| 模型切换后旧对象仍持有 Provider | 只保留当前对象，其他缓存失效 |
| 页面快速点击产生竞态 | 后端全局门禁，页面 busy 状态禁用操作 |
