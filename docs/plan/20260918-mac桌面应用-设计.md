# Web UI 与 macOS 桌面应用设计

> 后续状态：Web 工作区写入与逐次审批采用 [20260919-Web工作区写入设计](20260919-Web工作区写入-设计.md)；本文的只读 Registry 仅记录第一阶段方案。

状态：Web UI 第一阶段已完成（2026-09-18）；macOS 壳待后续确认

对应需求：[macOS 桌面应用需求](../spec/20260918-mac桌面应用-需求.md)

## 1. 设计原则

- 桌面端是新的 Presentation Adapter，不是第二套 Agent Runtime。
- 复用真实 Session、工具组、审批、Skill、模型与日志边界。
- Host 拥有权威状态，浏览器只维护渲染状态。
- 先完成可测试、可打包的本地单机版本，再考虑系统集成能力。

## 2. 总体架构

第一阶段直接挂载到现有 FastAPI：

```text
Browser → /ui + /ui/api/* → WebUiService → ChatSession → Runtime
                               ├─ WebSessionCatalog → data/web-sessions/
                               └─ 只读 Workspace Registry
```

`/chat` 保持无状态聚合接口；Web UI 使用独立会话、流式 NDJSON 和只读工具。生产 Service 延迟到首次 Web API 请求才装配，Web 会话损坏或配置错误不会影响 `/chat`、Swagger 或应用模块导入。

第二阶段才增加桌面壳：

```text
Tsi Desktop.app
  └─ app.desktop.__main__
      ├─ DesktopHost（窗口和进程生命周期）
      ├─ LoopbackServer（127.0.0.1:随机端口 + 启动令牌）
      │   ├─ Desktop API
      │   ├─ 静态 Web UI
      │   └─ DesktopSessionService
      │       └─ ChatSession → Chat Runtime → Provider / Tools / Skills
      └─ WKWebView（pywebview）
          └─ 左栏 / 对话 / 右栏 / 审批层
```

`app/application.py` 的公开 HTTP 应用保持原样。桌面端使用独立 `create_desktop_app()` 组装静态资源和桌面专属 API，避免 `/chat` 获得会话、模型或写工具权限。

## 4. 页面状态与布局

桌面根布局使用 CSS Grid：

```text
┌──────────────┬────────────────────────────┬──────────────────┐
│ 工作区/会话  │ 会话标题 / 模型 / 状态     │ 文件 / 活动      │
│              ├────────────────────────────┤                  │
│ + 新会话     │ 消息与流式输出             │ 文件树或工具轨迹 │
│ 历史列表     │                            │ 审批详情         │
│              ├────────────────────────────┤                  │
│ 设置         │ 多行输入 / 发送 / 停止      │                  │
└──────────────┴────────────────────────────┴──────────────────┘
```

- 默认宽度建议 1280×820，最小 760×560。
- 左栏 238px，可收起；右栏 308px，可收起；中栏最小 420px；窄屏首次加载默认收起两侧面板。
- 消息正文使用 DOM 文本和受限 Markdown 渲染，代码块提供复制按钮。
- 新建、设置、会话操作、侧栏、文件和活动等功能入口使用本地图标按钮，并保留 `aria-label` 与悬停提示；标题、模型、会话名和状态数据保留必要文字。
- 活动记录按本轮请求归组，只展示有界参数/结果摘要，不替代本地完整日志。
- 设置使用原生 `dialog`；界面偏好以带白名单校验的单一 JSON 保存在 `localStorage`，无效或损坏值回退默认。模型切换仍调用 `/ui/api/model`，不新增通用设置写接口。

## 5. Web API 契约

第一阶段所有 `/ui` 与 `/ui/api/*` 请求必须来自 loopback 客户端。接口不提供写能力；桌面阶段再增加进程启动令牌交换。

主要接口：

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/ui/api/bootstrap` | 工作区、稳定消息、当前模型、候选和能力 |
| POST | `/ui/api/chat` | 启动一次 NDJSON 流式请求 |
| POST | `/ui/api/cancel` | 取消当前请求 |
| POST | `/ui/api/clear` | 清空当前 Web 会话 |
| POST | `/ui/api/sessions` | 创建并切换到空会话 |
| POST | `/ui/api/sessions/{id}/select` | 切换会话 |
| PATCH | `/ui/api/sessions/{id}` | 重命名会话 |
| DELETE | `/ui/api/sessions/{id}` | 删除会话并返回有效当前项 |
| POST | `/ui/api/model` | 切换并保存模型 |
| GET | `/ui/api/files` | 读取安全浅层文件树 |
| GET | `/ui/api/files/preview` | 预览安全 UTF-8 文本 |

流事件统一为一行一个 JSON：`request_started`、`text_delta`、`text_reset`、`tool_started`、`approval_required`、`tool_finished`、`usage`、`completed`、`failed`、`cancelled`。每行包含 `request_id` 和单调递增 `sequence`；页面忽略重复或旧序号。

## 6. 第一阶段会话与持久化

```text
data/web-sessions/index.json
data/web-sessions/sessions/<id>.json
```

- Web 多会话复用现有 `SessionStore` schema 和记忆策略，元数据由 `WebSessionCatalog` 原子维护。
- 每次只允许一个 Web 请求运行，避免模型上下文竞态。
- TUI 的 `data/chat-session.json` 不迁移、不共享；模型选择继续复用安全的 `data/model-selection.json`。
- 旧 `data/web-session.json` 在新索引不存在时迁移为“历史对话”，索引最后写入以支持中断恢复。

## 7. Runtime 与权限

- `DesktopSessionService` 按会话创建现有 `ChatSession`，加载相同 AGENTS、Skill Catalog、Workspace Policy 和请求级工具组。
- `on_text_delta`、`on_text_reset`、`on_tool_result` 转换为流事件。
- 第一阶段 Registry 只包含 `general` 与 `workspace_read`，从工具定义层面排除所有需审批能力。
- 写审批 Broker 在桌面阶段单独实现，不能用页面确认框代替 Host 权威审批状态。

## 8. 文件与模型

- 文件树和预览调用与 Workspace 工具相同的 Policy 和大小边界，不直接使用 `Path.read_text()` 绕过策略。
- 文件预览只返回 UTF-8 文本、相对路径、哈希和截断标记。
- 模型列表复用 `ModelCatalog`；切换复用 `select_chat_model` 和 `ModelSelectionStore`。
- Bootstrap 只返回 Provider、模型、是否配置密钥，不返回密钥值、环境变量或上游 Header。

## 9. macOS Host 与打包

- Host 使用 socket 预绑定获得随机 loopback 端口，待 Uvicorn 健康检查通过后创建窗口。
- WebView 仅允许本地应用 URL；外链交给系统浏览器前必须由明确用户操作触发。
- 窗口关闭后先取消活动请求和审批，再请求 Uvicorn 停止；设置有界等待，超时仍退出。
- PyInstaller spec 收集 `app/desktop/static`；应用名称为 `Tsi 助手`，Bundle ID 暂定 `com.tsi.assistant`。
- `build/`、`dist/` 和生成的 `.app` 忽略；第一版产物未签名，不宣称可直接分发给其他用户。

## 10. 异常、性能与可观测性

- Host 启动失败显示原生错误窗口，不打开空白 WebView。
- 流断开不把半截 Assistant 消息写入会话；可重新打开会话查看最后一次稳定状态。
- 页面事件和预览均设置大小上限；会话列表默认加载最近 50 条，消息按需加载。
- 桌面生命周期日志与模型日志分离，默认记录启动、端口、退出、会话 ID、请求 ID 和有限错误分类，不记录消息、密钥或完整文件内容。
- 首版目标是本地交互稳定，不建立响应时间或内存硬门槛；测试确保空闲时无轮询请求。

## 11. 风险与回滚

| 风险 | 缓解 |
|---|---|
| pywebview/macOS WebKit 版本差异 | 延迟导入、固定最低 macOS、Host 与页面契约测试 |
| 浏览器页面扩大本地攻击面 | loopback、随机令牌、Cookie 交换、Origin/Host 校验 |
| 审批等待造成悬挂 | 有界超时、取消传播、断开即拒绝 |
| 多会话引入状态竞态 | 单并发、独立 Store、原子 Index |
| 打包遗漏静态资源 | PyInstaller 冒烟测试和资源存在性测试 |

回滚时删除 `app/desktop/`、桌面测试、打包脚本和新增依赖即可；现有 HTTP/TUI 数据和契约不迁移。
