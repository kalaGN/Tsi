# 移除 HTTP 对话接口设计

状态：已完成（2026-09-19）

对应需求：[移除 HTTP 对话接口需求](../spec/20260919-移除HTTP对话接口-需求.md)

## 方案

删除 `app/routers/` 整个包，并从 `app/application.py` 移除 `chat_router` 的导入与 `include_router` 调用。FastAPI 应用、根路由和 Web UI Router 保持不变，Uvicorn 启动方式、端口和静态资源挂载均不变。

`app/runtime/chat.py` 保留：`run_chat_messages` 是 Web UI 与 TUI 共用的 Runtime 入口，`get_chat_runtime_info` 仍被 Web UI 服务与 TUI bootstrap 使用。HTTP 专属的错误到状态码映射随路由一并删除；上游失败改由 Web UI 的流内 `failed` 事件表达，不再映射为 HTTP 状态码。`create_default_registry` 目前只作为 Runtime 与评测的默认值，本次不动。

## 安全与可靠性

- 对外攻击面减少一个无状态接口；Web UI 的 loopback 限制、审批绑定、Workspace 路径边界和工具白名单不变。
- 日志配置不变：Web 服务仍向 stderr 和本地文件双写，TUI 只写本地文件。
- 不涉及持久化格式变更，`data/chat-session.json` 与 `data/web-sessions/` 无需迁移，也不受影响。

## 验证

`tests/test_application.py` 覆盖 main 导出、`create_app` 注入日志配置、根路由、OpenAPI 标题和已移除端点；完整测试确认没有其他模块依赖被删除的模块。

## 回滚

从 Git 恢复 `app/routers/`、`app/application.py` 与 `tests/test_chat.py` 即可；没有数据迁移或配置变更。
