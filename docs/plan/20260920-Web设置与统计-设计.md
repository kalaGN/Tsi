# Web 设置与统计设计

状态：已完成（2026-09-20）

对应需求：[Web 设置与统计需求](../spec/20260920-Web设置与统计-需求.md)

## 1. 现状

- `/ui` 由 `app/webui/static/index.html`、`app.css` 和 `app.js` 构成，不使用前端框架和构建工具。
- 设置内容位于 `settings-dialog`，主题、密度和发送快捷键保存在浏览器 `localStorage`；模型切换调用现有 `/ui/api/model`。
- `WebUiService.stream_message()` 已统一产生 `request_started`、`completed`、`failed` 和 `cancelled` 事件；完成事件包含单次 Token 与耗时。
- Web 请求由一个 `asyncio.Lock` 串行执行，但没有跨请求统计，也没有统计持久化文件。
- Web Router 已统一执行 loopback 检查，生产 Service 采用延迟装配。

## 2. 总体架构

```text
/ui 单页应用
├─ #/chat
│  └─ 现有三栏对话视图
└─ #/settings/*
   ├─ general
   ├─ model
   └─ statistics ── GET /ui/api/statistics
                         │
                         ▼
                    WebUiService
                         │
                         ▼
                 WebStatisticsStore
                         │
                         ▼
                data/web-statistics.json

WebUiService.stream_message()
  └─ 请求终态 ── WebStatisticsStore.record()
```

依赖方向保持为：页面 → Router → Service → Store。Router 不解析统计文件，页面不从日志推导统计，Store 不依赖 FastAPI、会话或 Provider 实现。

## 4. 页面路由与状态

### 4.1 Hash 路由

前端只识别以下规范路由：

| Hash | 页面 |
|---|---|
| 空 Hash、`#/chat` | 对话页 |
| `#/settings/general` | 通用设置 |
| `#/settings/model` | 模型设置 |
| `#/settings/statistics` | 统计页 |

未知 Hash 通过 `history.replaceState` 规范化为 `#/chat`，避免产生额外历史项。点击设置入口写入 `#/settings/general`；点击设置菜单写入对应 Hash；“返回对话”写入 `#/chat`。浏览器前进、后退由 `hashchange` 统一驱动。

### 4.2 DOM 边界

`body` 下保留两个互斥顶层视图：

```html
<main id="chat-view">...</main>
<section id="settings-view" hidden>
  <aside class="settings-sidebar">...</aside>
  <main class="settings-content">...</main>
</section>
```

工具审批 `dialog`、Toast 等跨页面浮层位于两个视图之外。设置切换只修改 `hidden`、`aria-current` 和面板焦点，不重建对话 DOM，因此消息、滚动状态、右侧面板和输入草稿不会丢失。

### 4.3 统计加载

- 首次进入统计页时请求 `GET /ui/api/statistics`。
- 每次重新进入统计页时刷新一次；同一次页面停留不轮询。
- 请求期间展示骨架/加载态；失败显示局部错误和重试按钮，不影响其他设置页。
- 所有 Provider、模型、日期和错误文本均通过 `textContent` 写入，不使用 `innerHTML`。

趋势区域提供两组选项：

- 时间范围：“近 7 天”“近 30 天”，默认近 7 天；
- 指标：“请求数”“Token”“平均耗时”，默认请求数。

页面从接口返回的 30 个连续日桶中截取对应范围，并使用原生 SVG 绘制单指标波形图：

- 折线表示每日值，半透明面积填充用于强化趋势；
- X 轴显示日期，Y 轴根据当前指标自动缩放；全零数据使用稳定的零基线；
- 请求数使用整数，Token 使用紧凑数字格式，平均耗时统一换算为秒；
- 每个数据点使用可聚焦的 SVG 元素，并通过 `aria-label` 提供“日期 + 指标 + 数值”；图表下方保留当前范围的最小值、最大值和合计/均值文本摘要；
- 切换范围或指标只重绘图表，不重新请求接口；重新进入统计页才刷新数据；
- SVG 节点和属性由固定代码创建，不接受服务端提供的 SVG/HTML 片段，也不加载第三方图表代码。

## 5. 统计数据模型

### 5.1 文件结构

```json
{
  "version": 1,
  "updated_at": "2026-09-20T12:00:00+08:00",
  "totals": {
    "requests": 12,
    "completed": 10,
    "failed": 1,
    "cancelled": 1,
    "usage_known": 9,
    "input_tokens": 8000,
    "output_tokens": 2400,
    "total_tokens": 10400,
    "completed_elapsed_ms": 45600.0
  },
  "days": {
    "2026-09-20": {
      "requests": 12,
      "completed": 10,
      "failed": 1,
      "cancelled": 1,
      "usage_known": 9,
      "input_tokens": 8000,
      "output_tokens": 2400,
      "total_tokens": 10400,
      "completed_elapsed_ms": 45600.0
    }
  },
  "models": [
    {
      "provider": "deepseek",
      "model": "deepseek-v4-flash",
      "last_used_on": "2026-09-20",
      "metrics": {}
    }
  ]
}
```

`metrics` 复用统一计数结构。平均耗时不直接持久化，由 `completed_elapsed_ms / completed` 计算，避免累计舍入误差。Token 全部使用非负整数，耗时使用有限非负浮点数。

### 5.2 事件输入

Store 只接受一个不可变的终态记录：

```python
@dataclass(frozen=True)
class WebRequestStatistic:
    outcome: Literal["completed", "failed", "cancelled"]
    provider: str
    model: str
    elapsed_ms: float
    token_usage: TokenUsage | None = None
```

Provider 和模型在请求开始时从 `runtime_info` 捕获，避免请求结束后模型切换造成归属错误。标识去除首尾空白并限制长度，不接收控制字符。

### 5.3 聚合与边界

- 每个终态同时更新 `totals`、当天 `days` 和对应 `models`。
- `requests` 每次加一；按 outcome 只增加一个分类计数。
- 仅 `completed` 累加 `completed_elapsed_ms`；只有真实 `token_usage` 才增加 `usage_known` 和 Token。
- 写入前按本地日期保留最近 30 个日桶。
- 模型明细最多保留 100 项；超过时把最久未使用项合并到“其他模型”，保留总量但不继续保留标识。
- 所有载入数据均验证 `requests == completed + failed + cancelled`、Token 非负以及模型标识长度；不接受部分损坏数据。

## 6. 请求生命周期接入

### 6.1 唯一记录点

`WebUiService.stream_message()` 创建请求后捕获：

- `started_at = time.monotonic()`；
- 当前 Provider 和模型；
- 一个仅在 `run()` 内使用的终态记录函数。

流程调整为：

```text
Runtime 返回/抛错/被取消
  → 计算 outcome、elapsed、usage
  → 尽力写统计一次
  → 发送 completed/failed/cancelled 终态事件
```

统计在终态事件入队前写入，因此页面收到终态后立即访问统计接口能看到本轮数据。Store 写入异常只记录服务端错误日志，终态事件仍按原契约发送。

### 6.2 计数边界

- API Key 未配置、参数校验失败、Busy 409 等尚未进入 Runtime 的请求不计数。
- 成功、`ChatRuntimeError`、未知异常和主动取消计数。
- 客户端在流中途断开时，Generator 的 `finally` 取消 Runner；Runner 将其记录为取消。
- 终态记录函数使用局部布尔门禁，避免取消与异常清理路径重复计数。
- 会话索引 `touch()` 失败但模型结果已成功时，仍按成功计数。

## 7. Store 持久化

### 7.1 装配

`WebUiService` 构造函数新增 `statistics: WebStatisticsStore`。生产装配使用 `DATA_ROOT / "web-statistics.json"`；测试显式注入临时路径，避免写入真实 `data/`。

### 7.2 原子写入

写入过程复用项目现有 Store 风格：

1. 创建父目录并设置 `0700`；
2. 在同目录创建 `0600` 临时文件；
3. 写紧凑 UTF-8 JSON、flush、`fsync`；
4. `os.replace` 原子替换目标；
5. 尽力 `fsync` 父目录；
6. 异常时清理临时文件并抛出稳定的 `WebStatisticsStoreError`。

Store 使用进程内 `threading.RLock` 保护读取和更新。当前 Web UI 是本机单进程应用，不支持多个 Uvicorn Worker 同时更新该文件；文档不提供多 Worker 启动方式。

### 7.3 损坏恢复

统计是可重建的辅助数据，不应像会话数据一样阻断启动：

- 文件缺失：返回空统计，首次终态时创建。
- 文件版本未知或内容损坏：尝试原子改名为 `web-statistics.corrupt-<时间>.json`，记录不含原文的错误日志，并从空统计继续。
- 隔离失败：仍在内存从空统计继续；后续写入失败继续只记录日志。
- 不读取旧日志或会话文件回填。

## 8. API 契约

新增：

```http
GET /ui/api/statistics
```

响应示例：

```json
{
  "generated_at": "2026-09-20T12:01:00+08:00",
  "period_days": 30,
  "totals": {
    "requests": 12,
    "completed": 10,
    "failed": 1,
    "cancelled": 1,
    "success_rate": 83.3,
    "usage_coverage": 75.0,
    "input_tokens": 8000,
    "output_tokens": 2400,
    "total_tokens": 10400,
    "average_elapsed_ms": 4560.0
  },
  "days": [],
  "models": []
}
```

- `days` 始终补齐最近 30 个自然日，无数据日期返回零值，页面无需推导日期。
- 每个日桶同时返回请求数、总 Token 和成功请求平均耗时，供页面在近 7 天与近 30 天之间切片并切换波形指标。
- `models` 按请求数、最近使用日期和名称稳定排序。
- 空统计返回 200 和全零 DTO。
- Store 查询异常由 Service 降级为空统计并记录日志，不向页面泄露路径或原始 JSON。

## 9. 异常、日志与隐私

- 新增结构化事件仅记录统计读取/写入/隔离是否成功、异常类型和文件逻辑名，不记录统计文件原文。
- 页面错误只显示“统计暂时不可用”，详细异常留在服务端日志。
- 统计文件和 API 永远不包含消息、Session ID、请求 ID、工具参数、文件路径、密钥或错误正文。
- 统计写入不改变模型请求的成功/失败结果，不延长上游超时。

## 10. 性能

- 单次终态只读取内存快照并原子写入一个小型有界 JSON 文件。
- 日桶最多 30 个，模型桶最多 100 个，文件大小保持有界。
- 统计页只在进入时请求一次，不轮询、不阻塞首屏 Bootstrap。
- 近 7 天/近 30 天及指标切换只在浏览器重绘至多 30 个 SVG 数据点，不产生额外 API 请求。
- 不从模型日志聚合，避免随日志规模线性增长。

- Store 写失败不改变原终态事件；

## 12. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 请求取消路径重复计数 | 只在 Runner 的唯一终态函数记录，并设置幂等门禁 |
| 统计写失败拖垮对话 | Service 捕获 Store 错误，记录日志后继续发送原终态 |
| 文件损坏导致 Web 无法启动 | 隔离损坏文件并降级为空统计 |
| 模型维度无限增长 | 限制 100 项并把旧项合并为“其他模型” |
| Hash 导航丢失聊天状态 | 只隐藏顶层视图，不重建 Chat DOM 或重新 Bootstrap |
| 图表量纲混淆或不可访问 | 同时只展示一个指标，提供单位、可聚焦数据点和文本摘要 |
| 窄屏左侧菜单占用过大 | 在窄屏将侧栏收窄或改为横向可滚动菜单 |
| 多 Worker 丢失更新 | 明确限制本机单进程运行，不提供多 Worker 配置 |

## 13. 回滚

- 页面可恢复原设置 Dialog 和监听器，不影响工具审批 Dialog。
- 删除统计路由、Service 注入和 Store 后，现有对话事件契约仍可继续工作。
- `data/web-statistics.json` 是独立辅助文件，回滚无需迁移会话或模型选择数据；遗留文件可安全忽略。
- 本次不修改 Provider、Session、Tool Registry 或 TUI，回滚不涉及其数据。

## 14. 设计确认项

- 已确认统计落在独立 `app/webui/statistics.py`，不复用或解析日志。
- 已确认请求统计在终态事件发送前同步原子写入；写失败不影响对话。
- 已确认本地 Web UI 继续采用单进程更新模型，不支持多 Worker 共享统计文件。
- 已确认最近 30 天、最多 100 个模型明细的有界数据结构。
- 已确认原生 SVG 单指标波形图，支持近 7 天/近 30 天和请求数/Token/平均耗时切换，默认近 7 天请求数。
