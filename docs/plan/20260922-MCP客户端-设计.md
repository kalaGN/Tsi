# MCP 客户端设计

对应[需求](../spec/20260922-MCP客户端-需求.md)。

## 接入路径

配置加载器读取 `data/mcp-servers.json` 并校验服务器名、传输和引用的环境变量。请求开始时由 MCP 适配层连接已启用服务器，完成初始化与分页工具发现，把工具冻结为本轮快照；请求结束、失败或取消时统一关闭。未配置时不创建 MCP 客户端。

MCP 适配层将合格的工具 Schema 变成 `ToolDefinition`，工具名使用 `mcp_<server>_<tool>`，并在 `GroupedToolRegistry` 中注册 `mcp` 组。各工具的 `preview()` 生成独立 MCP 审批请求；Web/TUI 用现有逐次审批通道显示服务器、工具、参数和风险。批准后才调用 Server；结果提取文本并做长度与类型限制。

## 分层与顺序

1. 新增配置解析、SDK 连接生命周期和工具适配，保持 `tools/` 不依赖 UI 或具体 LLM Provider。
2. 扩展审批契约、Registry 校验、Web/TUI 审批展示和工具日志/轨迹的 MCP 脱敏，确保所有 MCP 调用默认拒绝。
3. 将请求级 MCP 快照接入 Web 与 TUI 的 Registry 工厂；连接失败不改变本地工具组。
4. 增加协议假服务测试及文档；运行仓库要求的完整门禁。

## 风险与处理

- 外部工具可以有副作用，服务器的只读声明不作为免审批依据；所有调用一律逐次审批。
- 服务端描述、Schema、结果及错误均不可信，校验名称、大小和类型；超限工具不披露，异常映射为固定错误。
- stdio 启动可执行程序，配置仅由本地用户编辑；调用审批展示该服务器的本机执行风险。子进程使用隔离环境，并在取消时关闭。
- HTTP 连接可能带凭据，配置只保存环境变量名；对 MCP 的工具调用日志和轨迹只记录服务器名、工具名、状态、大小和时长，不记录参数或响应正文。

## 验证节点

先用假 Server 验证发现、命名与 Schema；再验证 Web/TUI 审批拒绝和批准调用；最后验证超时、断连、取消、重复名称与清理。所有外部行为在测试中本地模拟。
