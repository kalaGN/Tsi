# 通用 Agent 首版 P0：设计

对应需求：[通用 Agent 首版 P0 需求](../spec/20260923-通用Agent首版P0-需求.md)。

## 最小架构

`TaskRun` 是独立于会话的本机任务记录，包含任务 ID、会话 ID、项目 ID、目标、验收条件、状态、修订号、尝试次数和脱敏状态说明；`TaskRunStore` 在私有 `data/task-runs/` 原子写入。对话仍由 `ChatSession` 持久化，不复制模型消息。每次任务执行只调用一次现有会话请求，成功返回后再运行确定性验收。

任务状态为 `ready → running → verifying → completed | needs_review | failed | cancelled`；审批期间是 `awaiting_approval`。启动时把遗留 `running/awaiting_approval/verifying` 标记为 `needs_review`，绝不自动重放工具。恢复需重新检查会话和文件状态，用户确认后从下一个完整步骤继续。任务状态文件不是会话/工具副作用的跨文件事务：崩溃窗口一律要求人工检查，不能承诺 exactly-once。

`tools/policy.py` 集中记录 Web/TUI 的能力与现有 `ToolEffect` 风险等级；Registry 创建只从固定策略投影工具组。组激活不改变工具的执行权限。Web 不因本需求获得 TUI 的 Git/Skill 脚本；未知 MCP 效果继续逐次审批。

验收器只读取允许的工作区路径并复用固定项目检查；它输出结构化 pass/fail/unknown 与无秘密证据。失败后进入 `needs_review`，由用户检查后显式继续；写操作不进行宿主级自动重试。缺失可验证条件、证据不明或检查失败时不能标记完成。

## 入口与资源

Web 增加任务创建/读取/继续/取消接口和简洁状态区；TUI 增加任务创建与状态/继续命令，不引入独立页面。两入口复用同一任务领域逻辑，但保留不同工具目录和审批 UI。首版继续单活动请求，不增加队列、后台定时器或跨进程并发执行。

## 风险

- 任务文件与会话文件无法原子提交：启动恢复对不确定步骤标记 `needs_review`，人工检查，不自动重放。
- 长任务成本：每任务最多 3 次显式执行，Web 单轮执行最多 10 分钟；模型请求继续受既有上下文与工具调用预算约束。首版不做跨轮 Token 累计配额。
- 工具权限回归：策略抽取先做行为等价测试，再接任务入口。
- 验收器误报：仅固定、确定性检查；未知一律等待人工，不用 LLM Judge 作硬门禁。
