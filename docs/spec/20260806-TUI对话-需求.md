# 需求：TUI 对话入口

## 背景

当前项目只通过 FastAPI `POST /chat` 提供单轮模型调用。开发者若要在终端中连续试用模型，需要手工启动 HTTP 服务并执行 curl，交互成本较高。

参考 Reasonix 的“多个交互界面共用同一运行内核、界面保持轻薄”原则，为项目增加本地全屏 TUI。只复用适合当前项目的分层思想，不复制 Reasonix 尚无对应运行能力的工具审批、Sandbox、Plan、多 Agent、MCP 或持久化会话功能。

参考资料：

- [Reasonix Engineering Spec](https://github.com/esengine/DeepSeek-Reasonix/blob/main-v2/docs/SPEC.md)
- [Reasonix 官方文档](https://reasonix.io/docs/)

## 目标

- 开发者可以执行 `python3 -m app.tui` 打开全屏终端对话界面。
- TUI 和现有 HTTP API 共用与界面无关的 Chat Runtime。
- 保持现有 `/chat` 公开契约和错误映射不变。
- TUI 能明确展示消息、运行状态和安全错误，不暴露 API Key 或内部堆栈。
- 保持当前项目轻量，只增加首期实际需要的模块和依赖。

## 用户与使用场景

目标用户是本地学习、开发和调试当前 FastAPI/模型集成项目的开发者。

核心场景：

1. 在项目根目录启动 TUI。
2. 输入一段非空文本并提交。
3. 界面显示用户消息和 `Thinking` 状态。
4. 请求完成后显示模型响应，状态恢复为 `Ready`。
5. 请求失败时显示安全、可理解的错误，界面仍可继续使用。
6. 使用命令清空界面或退出。

## 功能范围

### 1. 启动入口

```bash
python3 -m app.tui
```

- 从项目根目录运行。
- 默认读取项目根目录 `.env`。
- 从 `DASHSCOPE_API_KEY` 获取上游密钥。
- 缺少密钥时不启动模型请求，并在界面中显示配置错误。
- 不要求先启动 Uvicorn；TUI 直接复用项目运行内核。

### 2. 界面区域

首期界面包含：

- 顶部标题：项目名称。
- 对话记录区：按顺序显示用户消息、模型响应和错误消息。
- 输入区：输入提示词，支持直接输入中文。
- 底部状态栏：显示 Provider、模型和运行状态。

运行状态限定为：

- `Ready`：可以提交输入。
- `Thinking`：正在等待模型响应。
- `Error`：最近一次请求失败，仍允许继续输入。

### 3. 交互行为

- 非空文本提交后立即出现在对话记录区。
- 请求执行期间禁止重复提交，避免同一界面并发发起多个模型调用。
- 输入为空或全为空白时不发起请求，并给出校验提示。
- 请求不得阻塞 TUI 事件循环；等待期间界面仍能重绘和响应取消。
- 成功响应以可读 JSON 或从上游响应中提取的可显示文本呈现；具体展示策略在设计阶段基于真实响应契约确定。
- 请求错误不得导致 TUI 退出。
- 从用户按 `Enter` 提交有效输入开始，到成功响应或错误完成为止统计耗时，并在对应结果后显示 `耗时：x.xx 秒`。
- 耗时使用单调时钟计算并保留两位小数；空白输入、本地命令、重复提交和 `Esc` 取消不显示耗时。

### 4. 命令与快捷键

- `/clear`：清空当前界面的对话记录，不修改外部数据。
- `/quit`：退出 TUI。
- `Enter`：提交输入内容。
- `Esc`：第一次按下时取消运行中请求并提示；1.5 秒内再次按下才退出 TUI，超时后重新计数。

TUI 不提供 `/help` 或 `/chat` 命令。普通非命令输入直接作为模型请求提交。

### 5. 配置

已确认配置：

- Provider：阿里云 OpenAI 兼容 Responses API。
- 模型：`qwen3-max`。
- API Key：`DASHSCOPE_API_KEY`。
- 环境文件：项目根目录 `.env`。

状态栏只显示 Provider 名称、模型名和密钥是否配置，不显示密钥内容。

## 非目标

首期不实现：

- 启动、停止或管理 Uvicorn。
- 流式 Token 输出。
- 多轮上下文发送给模型。
- 会话持久化、恢复或历史搜索。
- 工具调用、文件修改、Shell、权限审批或 Sandbox。
- Plan、Ask、Auto、YOLO 等 Agent 模式。
- MCP、Skills、Plugin 或多 Agent 协作。
- 模型和 Provider 切换。
- 鼠标选择、系统剪贴板、Markdown 富文本或语法高亮。
- 远程访问、WebSocket 或浏览器 UI。

界面可以连续显示多次单轮调用，但显示历史不等于模型拥有多轮记忆。

## 技术栈与依赖

保留当前 Python 3.11、FastAPI、Pydantic、HTTPX、Uvicorn 和 Pytest。

批准新增：

- `textual`：全屏终端界面、组件、事件循环和异步 Worker。
- `python-dotenv`：独立 TUI 入口加载现有 `.env`。

依赖版本在设计和实现阶段基于当前 Python 3.11 兼容性确定，并固定到 `requirements.txt`。不得借本需求升级现有依赖。

## 目标结构

```text
app/
├── application.py                 # FastAPI 组装
├── routers/
│   └── chat.py                    # HTTP 适配
├── runtime/
│   ├── __init__.py
│   └── chat.py                    # 界面无关的单轮对话执行入口
├── services/
│   └── aliyun_responses.py        # 上游 Provider 调用
└── tui/
    ├── __init__.py
    ├── __main__.py                # python3 -m app.tui
    ├── application.py             # Textual 应用和事件处理
    └── state.py                   # 消息及 Ready/Thinking/Error 状态

tests/
├── test_chat.py                   # 现有 HTTP 契约测试
├── test_chat_runtime.py           # Runtime 行为和错误测试
└── test_tui.py                    # TUI 状态、命令和提交行为测试
```

最终文件边界可以在设计阶段小幅收敛，但不得增加没有实际职责的空壳层。

## 架构约束

目标依赖方向：

```text
FastAPI Router ─┐
                ├──> Chat Runtime ──> Aliyun Responses Service
Textual TUI ────┘
```

- HTTP Router 和 TUI 不能相互依赖。
- Runtime 不依赖 FastAPI、Textual 或具体界面组件。
- 上游 Service 不依赖 Router、Runtime UI 或 Textual。
- FastAPI `HTTPException` 的创建和 HTTP 状态转换应留在 HTTP 适配边界；共享 Runtime 使用界面无关的结果或异常。
- TUI 只负责输入、呈现、状态和取消，不复制上游请求逻辑。
- 保持 `main.py → app.application` 现有 HTTP 启动入口不变。

## 错误与安全要求

- 缺少 API Key、连接失败、超时、鉴权失败、上游状态错误和无效 JSON 都必须映射为 TUI 可读错误。
- HTTP API 的现有状态码和 `{"detail": "..."}` 结构保持不变。
- TUI 不显示 Authorization Header、API Key、`.env` 内容或 Python 堆栈。
- 自动化测试只使用假密钥和 MockTransport，不访问真实阿里云接口。
- 取消请求后状态恢复为 `Ready`，不得遗留后台任务继续运行。
- `.env` 继续由 `.gitignore` 排除。

## 性能与可靠性要求

- 沿用当前上游 10 秒连接超时和 60 秒总超时；本需求不调整超时策略。
- 单个 TUI 实例同时最多存在一个模型请求。
- 不增加自动重试，避免未知幂等性、费用和延迟放大。
- TUI 启动和本地组件交互不得依赖真实网络。
- 当前没有性能基线，本需求不声明启动时延或渲染帧率阈值。

## 测试策略

### Runtime 测试

- 成功响应。
- 缺少密钥。
- 连接失败、超时、鉴权、其他上游状态和非 JSON。
- 共享异常不依赖 FastAPI 或 Textual。

### HTTP 回归测试

- 现有 17 个测试继续通过。
- `/chat` 请求、成功响应和全部错误映射不变。

### TUI 测试

使用 Textual 测试能力和 Mock Runtime 验证：

- 初始状态为 `Ready`。
- 空输入不发起请求。
- 提交后进入 `Thinking`，重复提交被阻止。
- 成功消息写入记录区并回到 `Ready`。
- 失败显示安全错误并进入 `Error`，下一次输入仍可提交。
- `/clear`、`/quit` 行为。
- 取消运行中请求后不再更新已取消结果。
- 状态栏不包含 API Key。

当前不设置覆盖率百分比门槛。

## 边界

### Always

- 保持 HTTP 公开契约不变。
- TUI 和 HTTP 复用同一 Runtime。
- 使用 Mock 测试全部模型调用。
- 在依赖变更后运行全量测试和依赖检查。
- 对终端退出、请求取消和错误恢复进行自动化验证。

### Ask First

- 增加本需求之外的依赖。

- 修改模型、Provider、URL、超时或 HTTP 契约。
- 增加配置文件格式、用户级配置目录或凭证存储。

### Never

- 在 TUI 中显示或保存真实密钥。
- 为 TUI 复制一套上游调用逻辑。
- 在测试中调用真实模型。
- 将 Reasonix 尚未实现到当前项目的能力写成已具备功能。
- 未经确认创建 Git Commit。

## 已确认设计决策

- 响应展示依次尝试顶层 `output_text`、`output[*].text`、`output[*].content[*].text`，无法提取时降级为格式化 JSON。
- `Enter` 提交，1.5 秒内连续两次 `Esc` 退出。
- 启动入口在导入 Textual 前关闭 Kitty 扩展键盘协议，输入框可直接接收 macOS 中文输入法完成的文本。
- 固定使用 Textual 8.2.8 和 python-dotenv 1.2.2。
- Runtime 使用 `ChatResult`、`ChatRuntimeError` 和 `ChatErrorCode`；HTTP/TUI 在各自边界呈现错误。
