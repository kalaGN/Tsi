# 当前对话上下文需求

状态：已完成（2026-08-08）

## 1. 背景

当前 TUI 可以连续展示多次调用，但每次只向模型发送当前输入，模型无法理解“刚才的回答”或“继续”。

本次参考 Reasonix 的两个基础原则：

1. `Session` 持有有序的消息列表，前端不自行拼接 Provider 请求。
2. 对话能力属于共享 Runtime/内核，TUI 只负责输入、清空和展示。

- `/Users/wangfei/GolandProjects/DeepSeek-Reasonix/ARCHITECTURE-v2.md`，重点为第二、六、十、十二和十三节。
- [Reasonix Engineering Spec](https://github.com/esengine/DeepSeek-Reasonix/blob/main-v2/docs/SPEC.md)。
- [阿里云 Responses API 输入契约](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-responses)：`input` 支持按对话顺序排列的消息数组。

## 2. 目标

- TUI 保留当前对话中成功的 user/assistant 轮次，并在每个成功轮次后持久化。
- TUI 重新启动时自动恢复上次保存的界面历史和模型上下文。
- 后续输入会连同先前成功历史一起发给当前 Provider。
- DeepSeek 和阿里云使用同一组 Provider 中立消息，由 Adapter 映射为各自协议。
- `/clear` 同时清空 TUI 显示和当前模型上下文。
- 保持现有 HTTP `/chat` 为无状态单轮接口，请求、响应和 Header 契约不变。

## 3. 默认假设

1. “当前对话”指 TUI 使用的唯一本地会话，可跨 TUI 进程重启恢复。
2. 只有成功的 user/assistant 完整对才进入上下文。Provider 失败或用户取消不修改历史。
3. 退出 TUI 不删除历史；下次启动自动加载上次成功持久化的完整轮次。
4. 本期不为 HTTP 增加全局共享 Session，避免并发请求在没有 session ID 时串话。
5. 本期不做 Token 计数、裁剪或摘要；超长对话由上游上下文限制报错，后续变更再增加 Reasonix 式 compaction。
6. 模型输入输出日志继续只记录本轮完整输入/输出，不每轮重复记录全部历史。
7. 本期只管理一个当前会话，不增加会话列表、命名、切换、分叉或搜索。

## 4. 核心数据契约

Provider 中立消息：

```python
class ChatRole(str, Enum):
    USER = "user"
    ASSISTANT = "assistant"


@dataclass(frozen=True)
class ChatMessage:
    role: ChatRole
    content: str
```

当前不增加 system、developer、tool、reasoning 或多模态字段，避免把未实现的 Agent 能力预先塞入契约。

Provider 契约从单文本改为有序消息：

```python
async def generate(messages: Sequence[ChatMessage]) -> ProviderResult: ...
```

- DeepSeek Adapter 将消息映射为 `messages` JSON 数组。
- 阿里云 Adapter 对单个 user 消息继续使用原 `input: string`，保持现有单轮线路；有历史时改用 `input: [{role, content}, ...]`。
- Provider 拒绝空消息列表、空内容或非 user 结尾的请求，不访问网络。

## 5. Session 行为

新增最小 `ChatSession`，属于 `app/runtime/`，不属于 TUI：

```python
class ChatSession:
    @classmethod
    def load(cls, store: "SessionStore", ...) -> "ChatSession": ...
    async def send(self, input_text: str) -> ChatResult: ...
    def clear(self) -> None: ...
    @property
    def messages(self) -> tuple[ChatMessage, ...]: ...
```

`send()` 原子语义：

1. 校验当前输入。
2. 以 `已提交历史 + 当前 user` 构造候选消息序列。
3. 调用 Provider，不先修改已提交历史。
4. 成功后将“旧历史 + 当前 user/assistant”原子写入会话文件。
5. 持久化成功后再一次性更新内存历史并返回 `ChatResult`。
6. Provider 失败、持久化失败或取消时不追加任何消息，不展示不可恢复的半个轮次。

Session 同一时间最多允许一个 `send()`；TUI 已经阻止重复提交，Session 仍使用 `asyncio.Lock` 守住自身不变式，避免未来其他边界并发调用导致顺序错乱。

## 6. HTTP 与 TUI 边界

### HTTP

- `/chat` 继续调用无状态 `run_chat()`，Runtime 内部将单个输入包装为一条 user 消息。
- 不增加 session ID、Cookie、Header、新路由或进程全局历史。
- 当前请求 `{"input":"..."}`、成功 `{"output_text":"..."}` 和错误映射保持不变。

### TUI

- 每个 `ChatTuiApp` 默认拥有一个 `ChatSession`，将 `session.send` 作为运行时 Chat Runner。
- TUI 启动时自动读取会话文件，按原顺序恢复界面消息和 Session 上下文。
- 测试仍可注入假 `chat_runner`，不调用真实 Provider。
- `/clear` 在清空界面前调用 Session clear 能力，并删除已持久化的当前会话。
- `/help` 和 `/chat` 继续作为普通模型输入，不恢复为本地命令。
- 回车发送、双击 Esc、中文输入、取消和耗时显示保持不变。

## 7. 持久化与恢复

- 默认文件为项目根目录 `data/chat-session.json`，`data/` 必须被 Git 忽略。
- 文件使用 UTF-8 JSON，只保存 schema 版本和有序 `role/content` 消息，不保存 API Key、Provider 原始响应或异常对象。
- 保存采用“同目录临时文件 + `os.replace`”，避免进程中断留下半个 JSON；尽可能将文件权限限制为当前用户读写。
- 恢复时必须校验 schema 版本、角色、非空内容和 user/assistant 成对顺序。
- 文件不存在时从空会话启动。文件损坏或 schema 不支持时不静默覆盖；TUI 显示可操作错误，用户可执行 `/clear` 删除损坏历史并回到空会话。
- 本期不引入数据库、多文件会话索引、锁服务或第三方存储依赖。

## 8. 安全、隐私与性能

- 对话内容会以明文持久化到本地；README 必须说明位置、隐私影响和清理方式。
- Session 不持有 API Key、Provider 原始响应或异常对象。
- 现有模型日志仍会按已确认规则明文持久化每轮输入和输出；这与 Session 内存是两个独立的数据边界。
- 每轮上游请求会重发全部已提交历史，输入 Token、耗时和费用随对话长度增长。
- 本期不设长度上限，因此超长会话可被上游拒绝；不将“无界内存”描述为可生产的长会话方案。

## 10. 测试策略

- Provider 合同测试：两种 Adapter 正确映射单轮和多轮消息，并拒绝非法序列。
- Session 单元测试：首轮、第二轮历史、成功原子提交、失败/取消回滚、clear、并发守卫。
- Store 单元测试：文件不存在、UTF-8 中文往返、原子替换、写入失败、损坏 JSON、未知版本和非法消息顺序。
- Runtime 回归：HTTP 无状态调用仍只发一条 user 消息，日志仍只记录当前轮原文。
- TUI headless 回归：第二次输入能看到第一次成功轮次，重启后恢复界面和模型上下文，`/clear` 后恢复空上下文，取消不污染历史。
- 自动化测试只使用假 Provider 和 HTTPX MockTransport，不调用真实模型。

## 12. 可测试验收标准

1. TUI 第二次模型请求包含第一轮 user 和 assistant 消息，且角色顺序正确。
2. `/clear` 后下一次请求只包含新 user 消息。
3. Provider 失败或请求取消不会把半个轮次留在 Session。
4. 阿里云和 DeepSeek 均能正确发送多轮消息数组，单轮 HTTP `/chat` 行为保持兼容。
5. HTTP `/chat` 仍为无状态，两次 HTTP 请求不共享历史。
6. 成功对话后生成 Git 忽略的 UTF-8 Session 文件，TUI 重启后恢复相同历史和消息顺序。
7. Provider 或持久化失败都不会将半轮消息留在内存或 Session 文件中。
8. 损坏的 Session 文件不被静默覆盖，错误可见，`/clear` 可恢复为空会话。
9. 现有中文输入、回车发送、双击 Esc、取消、耗时、HTTP 错误映射和模型日志测试全部通过。
10. 不新增第三方依赖。
