# 模型输入输出日志需求

状态：已完成（2026-08-07）

## 1. 背景

当前 HTTP 与 TUI 在发起模型请求前记录一条脱敏 `llm_request`，只包含输入字符数。用户现在明确要求增加输入和输出正文，便于本地回看真实模型交互。

这会降低日志隐私等级：用户提问和模型回答将以明文进入 stderr 和本地日志文件。

## 2. 目标

- 发起模型调用前记录 `llm_request`，包含完整 `input_text`。
- 模型调用成功且已完成统一文本提取后记录 `llm_response`，包含完整 `output_text`。
- 请求与响应使用同一 request ID、Provider 和模型，可在本地日志中关联。
- 保留 stderr 和 `logs/model-calls.log` 双写、10 MiB 转储和 5 个备份。
- 不改变 HTTP、TUI 和 Provider 的对外契约。

## 3. 事件契约

### 3.1 `llm_request`

`INFO` 级别，在 `provider.generate()` 之前记录：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `timestamp` | string | UTC ISO 8601 毫秒时间 |
| `level` | string | `INFO` |
| `event` | string | `llm_request` |
| `request_id` | string | Runtime 生成的 UUID hex |
| `provider` | string | 实际 Provider |
| `model` | string | 实际模型 |
| `input_chars` | integer | 输入字符数 |
| `input_text` | string | 完整用户输入 |

### 3.2 `llm_response`

`INFO` 级别，Provider 返回统一 `output_text` 后记录：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `timestamp` | string | UTC ISO 8601 毫秒时间 |
| `level` | string | `INFO` |
| `event` | string | `llm_response` |
| `request_id` | string | 与请求事件一致 |
| `provider` | string | 实际 Provider |
| `model` | string | 实际模型 |
| `output_chars` | integer | 输出字符数 |
| `output_text` | string | 完整统一模型回答 |

JSON 保持单行；输入或输出内的换行、引号和控制字符由 JSON 编码转义。

## 4. 错误边界

- 空输入或 Provider 创建失败时不会发起模型请求，不写任何日志事件。
- Provider 调用失败时已写入 `llm_request`，但不写 `llm_response`。
- 本期不增加失败或取消事件，不记录异常消息、Traceback、上游状态码或原始响应。

## 5. 安全与留存

- 输入和输出为明文，不做脱敏、截断、Hash 或加密。
- 仍禁止记录环境变量 API Key、Authorization、上游请求对象、原始响应或异常对象。
- 如用户在提问中主动输入敏感信息，该内容会作为 `input_text` 进入日志；项目无法可靠自动识别和删除所有敏感文本。
- `logs/` 继续被 Git 忽略，但本地具有文件读取权限的进程或用户可以读取内容。
- 转储限制仅约束历史文件数量。由于正文不截断，单条超大记录可令当前日志文件暂时超过 10 MiB。

## 6. 非目标

- 不记录耗时、成功标记、失败分类、取消或上游状态码。
- 不增加 HTTP `X-Request-ID`，不向上游传递 request ID。
- 不修改 `LlmProvider.generate()` 或共享 HTTP 客户端签名。
- 不增加内容开关、内容截断、过滤器、指标、Trace、告警或远程日志。

## 7. 验收标准

1. 成功调用产生一条 `llm_request` 和一条 `llm_response`，两者 request ID 一致。
2. 请求日志完整包含输入，响应日志完整包含统一输出，中文和换行可正确还原。
3. Provider 失败只产生请求日志，不产生伪响应。
4. API Key、Authorization、原始 Provider 响应和异常原文不会因本次改动进入日志。
5. stderr 与本地转储文件保持幂等双写，`logs/` 不进入 Git。
6. HTTP JSON/Header、Provider 契约和 TUI 交互保持不变。
7. 全量门禁通过。

## 8. 已确认决策

1. 输入和成功输出以明文、完整内容同时进入 stderr 和本地文件。
2. Provider 失败时只保留已写入的请求事件，不记录异常或失败事件。
3. 不增加脱敏、截断或显式开关。
