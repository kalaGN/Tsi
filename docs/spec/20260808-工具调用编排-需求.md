# 工具调用编排需求

状态：已完成（2026-08-08）

## 1. 前置假设

本需求先按以下假设设计，确认前不进入技术方案和编码：

1. “工具调用”指模型 Function Calling：模型选择已注册工具并生成参数，应用执行工具，再把结果回传模型，直到得到最终文本。
2. HTTP `/chat` 与 TUI 共用同一套工具调用能力，公开请求和成功响应保持不变。
3. 第一版只允许应用内显式注册的只读工具，不支持 Shell、文件写入、数据库写入、外部 MCP 或动态插件。
4. 第一版内置一个可实际使用的 `get_current_time` 工具，接收 IANA 时区名；其他工具通过相同注册接口后续增加。
5. 工具调用过程只在当前请求内存在；TUI 会话仍只持久化最终的 `user/assistant` 完整轮次，不持久化中间工具轨迹。
6. 工具按模型返回顺序串行执行；即使模型一次返回多个调用，也暂不并行。
7. 工具系统放在仓库根目录的 `tools/` Python 包中，不放入 `app/`；Runtime 可以依赖 `tools`，`tools` 不反向依赖 Runtime、Router、TUI 或具体 Provider。

## 2. 背景与目标

当前 Runtime 只能把文本消息交给 Provider 并取得最终文本。即使上游模型支持 Function Calling，Provider 也会把没有文本的工具调用响应视为非法响应，应用不能使用当前时间、业务查询或其他外部能力。

本次目标是在不破坏现有 HTTP/TUI 契约和多模型边界的前提下，增加一个受控工具循环：

```text
用户问题
  -> 模型判断直接回答或请求工具
  -> Runtime 校验调用轮数与数量
  -> Registry 按名称查找并执行白名单工具
  -> Provider 按各自协议回传工具结果
  -> 模型继续调用工具或输出最终文本
```

成功标准是：同一个中立工具能被 DeepSeek Chat Completions 和阿里云 Responses 使用，模型协议差异不进入 Router、TUI 或具体工具实现。

## 3. 功能范围

### 3.1 中立工具契约

每个工具必须显式提供：

- 唯一名称、用途描述和 JSON Schema 参数说明。
- 异步执行入口，接收已解析的 JSON object。
- UTF-8 文本结果；成功和可恢复失败都能作为工具结果回传模型。
- 工具实现自行执行语义校验，不信任模型生成的参数。

建议的中立数据对象：

```python
ToolDefinition(name, description, parameters)
ToolCall(call_id, name, arguments_json)
ToolResult(call_id, output, is_error)
ModelStep(output_text, tool_calls, continuation)
```

`continuation` 只由产生它的 Provider 解释，Runtime 仅原样交还同一个 Provider，避免公共层依赖 DeepSeek `tool_calls` 或阿里云 `function_call` 的私有结构。

### 3.2 工具注册与执行

- Registry 在应用启动时由代码显式组装，拒绝重名或非法名称。
- 模型只能调用当前 Registry 已暴露的工具；未知名称绝不执行。
- `arguments` 必须是合法 JSON object，解析失败、未知工具和参数错误转换为有限、安全的错误结果，允许模型修正后继续。
- 工具抛出的内部异常不得把类名、堆栈、本地路径、凭据或原始异常文本回传模型、HTTP 或 TUI。
- 第一版 `get_current_time` 使用 Python 标准库 `zoneinfo`，返回指定时区的 ISO 8601 时间；未知时区返回安全的参数错误。

### 3.3 有界工具循环

为避免模型无限循环和成本放大，第一版采用固定上限：

- 每个用户请求最多 5 个模型步骤（首次请求也计入）。
- 每个步骤最多执行 4 个工具调用。
- 单次工具参数 JSON 的 UTF-8 编码最多 8 KiB。
- 单次工具结果的 UTF-8 编码最多 32 KiB；超限结果不回传原文，改为安全的超限错误。
- 多个工具调用严格串行，顺序与模型响应一致。

达到任一上限时停止调用模型，并返回新的中立 `tool_limit` 错误；HTTP 建议映射为 502，TUI 展示固定安全文案。

### 3.4 Provider 协议适配

根据两家官方协议：

- DeepSeek 请求携带 `tools`；响应从 `choices[0].message.tool_calls` 提取调用。续接请求必须追加原 assistant 工具调用消息，再追加 `role=tool`、对应 `tool_call_id` 的结果消息。
- 阿里云 Responses 请求携带 `tools`；响应从 `output[type=function_call]` 提取调用。续接请求必须按顺序追加 `function_call` 和紧随其后的 `function_call_output`，并保持同一 `call_id`。
- 无工具调用时，两家 Provider 都必须返回统一的非空 `output_text`。
- 单次用户请求内所有模型步骤继续使用同一个 Runtime `request_id`，每个实际 HTTP 请求仍产生现有 HTTP 请求/响应日志。

协议依据：

- [DeepSeek Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)
- [DeepSeek Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion)
- [阿里云 Responses API 自定义 Function Call](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-responses)

### 3.5 HTTP、TUI 与会话

- `POST /chat` 继续接收 `{"input":"..."}`，成功仍返回 `{"output_text":"..."}`。
- HTTP 每次请求无状态，但允许在单次请求内部完成多步模型/工具循环。
- TUI 只展示最终回答和现有总耗时，不新增 `/help`、`/chat` 或工具命令。
- TUI 发送成功后仍只保存用户输入和最终 assistant 文本；任何模型步骤、工具参数和工具结果失败时，本轮不写入会话文件。
- `/clear`、Esc 取消和双 Esc 退出语义保持不变；取消应传播到当前模型请求或工具执行，不提交陈旧结果。

## 4. 可观测性与安全

- 新增 `llm_tool_call` 与 `llm_tool_result` 结构化事件，使用当前 `request_id` 和上游 `call_id` 关联。
- 工具事件记录工具名、结果状态、耗时和参数/结果字符数；第一版不在专用工具事件中重复记录完整参数与结果。
- 现有 `llm_http_request.request_body` 会记录真实上游 JSON，因此续接请求中出现的工具调用和工具结果仍会按现有明文日志策略落盘。
- 不记录工具异常对象、Traceback、环境变量、API Key、Authorization 或未经白名单选择的 Header。
- 工具定义只能来自代码注册，用户输入或模型输出不能覆盖工具名称、Handler 或 Schema。
- 第一版禁止任何有副作用的工具；未来增加写操作前必须另建 Spec，定义权限、确认、幂等、审计和回滚。

## 5. 技术栈、目录与代码风格

不增加第三方依赖，继续使用 Python 3.11、FastAPI、HTTPX、Textual 和 Pytest。

建议新增职责：

```text
tools/__init__.py            # 根目录工具包的稳定导出
tools/contracts.py           # 中立定义、调用、结果和工具异常
tools/registry.py            # 白名单注册、查找、参数边界和安全执行
tools/builtin.py             # get_current_time
app/runtime/tool_loop.py     # 有界模型步骤与工具执行编排
tests/test_tools.py          # Registry 与内置工具测试
tests/test_tool_loop.py      # Provider 中立循环测试
```

`tools/` 是项目源码的一部分，不是脚本杂项目录；其中不得导入 FastAPI、Textual、Runtime 或具体 Provider。Provider 适配仍位于 `app/services/llm/`。示例风格：

```python
async def execute(self, call: ToolCall) -> ToolResult:
    """只执行已注册工具，并把可恢复失败转换为安全结果。"""
    tool = self._tools.get(call.name)
    if tool is None:
        return ToolResult.error(call.call_id, "Tool is not available")
    return await tool.invoke(call)
```

代码使用明确类型和冻结数据对象；注释解释协议边界、安全取舍和循环上限，不逐行复述实现。

## 6. 测试策略与命令

测试必须全部使用 Fake Provider、可控时钟和 HTTPX MockTransport，不调用真实付费模型或外部工具。

至少覆盖：

- 模型直接返回文本，不执行工具。
- 单次工具调用后返回最终文本。
- 连续多步调用与单步多个调用，验证串行顺序和同一 request ID。
- DeepSeek 和阿里云首次请求、调用提取、结果续接的精确 JSON 结构。
- 非法 JSON、非 object 参数、未知工具、参数错误、工具异常和结果超限。
- 模型步数、每步调用数、参数长度和结果长度四类上限。
- HTTP/TUI 成功契约、错误映射、取消、会话提交/回滚和完整日志回归。

验证命令：

```bash
.venv/bin/python -m compileall -q main.py app tests
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -m pytest -q
.venv/bin/python -m pip check
git diff --check
```

仓库没有 Formatter、Lint、类型检查或 CI，不增加虚构门禁。

## 7. 边界

### Always

- 工具必须显式注册、参数必须在执行边界校验、循环必须受限。
- 工具定义和实现统一放入根目录 `tools/` 包，并保持对应用入口与 Provider 的单向依赖边界。
- Provider 私有消息结构只存在于 Provider 适配和不透明续接状态。
- 工具失败与模型失败不能提交不完整的 TUI 会话轮次。
- 新功能同步更新测试、架构 Knowledge、README 和本 Spec 状态。

### Ask First

- 增加任何会修改文件、数据库、远端资源或系统状态的工具。
- 接入 MCP、动态发现、外部工具服务、人工审批 UI 或新依赖。
- 修改 `/chat` 公开契约、会话存储 Schema、日志明文策略或循环上限。

### Never

- 执行模型提供的任意 Python、Shell、模块名、URL 或文件路径。
- 将未知工具名回退为反射调用、`eval`、`exec` 或动态 import。
- 把密钥、Authorization、内部异常或堆栈作为工具结果交给模型。
- 自动化测试调用真实模型或产生外部副作用。

## 8. 非目标

- MCP Client/Server、远程插件市场、动态工具加载或多 Agent。
- 并行工具调用、流式输出、重试、退避、熔断或 Provider 故障转移。
- 写操作审批、认证授权、租户隔离、限流或生产沙箱。
- 持久化工具轨迹、模型 reasoning、Provider 原始响应或独立 Agent Memory。
- 阿里云内置联网搜索、代码解释器、文件搜索等服务端工具。

## 9. 可测试验收标准

1. 不需要工具的问题只发起一次模型请求，HTTP/TUI 输出与当前行为一致。
2. 需要工具的问题可完成“模型调用 → 白名单工具执行 → 工具结果回传 → 最终文本”，两家 Provider 均可使用同一个工具定义和 Handler。
3. DeepSeek 和阿里云的工具请求、调用提取和结果续接严格符合各自官方字段与顺序，协议字段不泄漏到 Router、TUI 或工具代码。
4. 未注册工具、非法参数和工具内部失败不会执行任意代码，也不会暴露内部异常；模型可收到有限错误结果并在剩余步数内修正。
5. 5 个模型步骤、每步 4 次调用、8 KiB 参数和 32 KiB 结果上限均有确定性测试，超限后不会继续调用模型或工具。
6. 单个用户请求的模型和工具事件共用 request ID，工具事件可关联 call ID，且日志不出现假密钥或异常原文。
7. TUI 只有取得最终文本并成功持久化后才提交完整轮次；失败、取消或超限不污染历史。
8. 现有 `/chat` 成功响应、错误映射、TUI 操作、会话恢复和模型日志测试全部回归通过。

## 10. 待确认决策

1. **已确认**：第一版只开放只读工具，并以内置 `get_current_time(timezone)` 作为端到端样例。
2. **已确认**：固定上限为最多 5 个模型步骤、每步 4 个调用、8 KiB 参数、32 KiB 结果；KiB 按 UTF-8 编码字节数计算。
3. **已确认**：工具轨迹仅在当前请求内使用，TUI 历史只保存用户输入和最终回答。
4. **已确认**：工具事件只记录元数据，但真实续接 JSON 仍按现有模型 HTTP 请求日志完整落盘。
5. **已确认**：HTTP/TUI 完全自动执行只读工具，不增加逐次确认界面。
6. **已确认**：工具代码统一放在根目录 `tools/` Python 包，后续新增工具也遵循该目录边界。
