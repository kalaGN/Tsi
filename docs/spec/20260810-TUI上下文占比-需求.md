# TUI 上下文占比需求

状态：待确认

## 1. 背景

当前 Textual TUI 会持久化唯一当前会话，并在后续请求中重发已经成功提交的
user/assistant 历史。状态栏只展示 Provider、模型、密钥状态和运行状态，用户无法直观看到
会话历史相对上下文预算的增长情况。

Provider 当前没有向 Session 暴露可跨重启恢复的精确 token usage，项目也没有安装与
DeepSeek、Qwen 完全一致的 tokenizer。因此第一版不能把本地统计描述为模型服务端的精确值。

## 2. 目标

- 在 TUI 底部状态栏最右侧持续显示当前会话上下文已使用占比。
- 显示文本明确标识为估算值，例如 `Context: ~12.3%`，避免误导为上游精确计费数据。
- TUI 启动恢复历史、成功完成一轮对话和执行 `/clear` 后，占比与当前已提交历史保持一致。
- 保持 HTTP `/chat` 请求、响应和错误映射不变。
- 不新增第三方 tokenizer 依赖，不调用外部服务完成统计。

## 3. 默认假设

1. “上下文”只指 `ChatSession.messages` 中已经成功提交并持久化的 user/assistant 消息。
2. 正在输入、请求中尚未提交的 user 消息、失败或取消的轮次，以及工具循环临时消息不计入占比。
3. 第一版使用确定性的本地估算算法，而不是 Provider 返回的 usage；状态栏使用 `~` 标识这一边界。
4. 上下文预算默认使用 `128000 tokens`，可通过 `TUI_CONTEXT_WINDOW_TOKENS` 配置正整数覆盖。
5. 自定义模型的真实窗口可能不同，部署者负责让该配置与实际模型保持一致。
6. 占比保留一位小数；空会话显示 `Context: ~0.0%`，超过预算时允许显示大于 `100.0%` 的结果，不静默截断。
7. “右侧”指在终端宽度足够时右对齐；窄终端下优先保证文本可见，不依赖手工填充空格定位。

## 4. 功能范围

### 4.1 状态栏

状态栏拆成左右两个展示区域：

```text
DeepSeek | deepseek-v4-flash | Key: configured | Ready    Context: ~12.3%
```

- 左侧继续显示现有 Provider、模型、密钥配置状态和运行状态。
- 右侧显示上下文估算占比。
- `Ready`、`Thinking`、`Error` 切换不能覆盖或隐藏右侧占比。

### 4.2 更新时机

- 启动空会话：显示 `Context: ~0.0%`。
- 启动并恢复历史：挂载时根据恢复后的 `ChatSession.messages` 计算。
- 成功完成一轮：Session 成功持久化后更新。
- Provider 失败、持久化失败或用户取消：保持提交前占比。
- `/clear` 成功：更新为 `Context: ~0.0%`。
- `/clear` 失败：保留原占比。

### 4.3 本地估算口径

估算器只接收 Provider 中立的 `ChatMessage` 序列，不读取密钥或 Provider 原始响应。

建议的无依赖确定性算法：

```python
def estimate_message_tokens(messages: Sequence[ChatMessage]) -> int:
    # 每条消息预留少量角色和结构开销；文本按 ASCII 与非 ASCII 分别估算。
    ...
```

设计阶段需固定以下细节并用测试锁定：

- 每条消息的固定结构开销。
- ASCII 文本的字符/token 换算。
- 中文及其他非 ASCII 字符的字符/token 换算。
- 空序列、换行、混合中英文和超预算输入的处理。

算法必须稳定、线性扫描，不能声称与任一上游 tokenizer 完全一致。

## 5. 配置与错误边界

- `TUI_CONTEXT_WINDOW_TOKENS` 仅影响 TUI 展示，不改变发送给 Provider 的消息，也不执行裁剪、摘要或拒绝请求。
- 未设置时使用默认值 `128000`。
- 空白、非整数、零或负数属于配置错误；TUI 使用安全错误状态提示，不以除零或未知异常崩溃。
- 配置值不是密钥，可以写入 README 示例；不得在日志中增加对话内容或密钥。
- 本次不新增 `/chat` 字段、响应字段、环境级 Provider 选择规则或 Session 文件字段。

## 7. 代码风格

- Python 3.11，使用明确类型标注和语义化名称。
- 只为非显而易见的估算口径、失败回滚和布局取舍增加必要注释。
- 统计逻辑与 Textual Widget 查询分离，使估算器可直接单元测试。
- 不在 TUI 中解析 DeepSeek 或阿里云原始响应。

## 8. 测试策略

- 估算单元测试：空历史、纯 ASCII、中文、混合文本、多轮、超预算和非法预算。
- TUI headless 测试：初始值、恢复历史、成功发送后更新、失败/取消不变、`/clear` 归零。
- 布局回归：左侧现有 Provider、模型、Key 和运行状态仍可见，右侧出现上下文占比。
- 自动化测试使用假 Runner/Provider，不调用真实模型服务。

## 9. 边界

### 必须做到

- 使用已提交 Session 历史计算，失败和取消不得虚增占比。
- 状态栏明确显示估算符号 `~`。
- 配置输入在边界校验，避免除零和负百分比。
- 同步测试、README、Spec/Plan/Tasks 和受影响 Knowledge。

### 实施前确认

- 将默认预算从 `128000` 改为其他数值。
- 改为依赖第三方 tokenizer 或使用 Provider usage。
- 增加自动裁剪、摘要、阻止发送或告警阈值。

### 禁止

- 把估算结果描述为精确 token 或计费数据。
- 修改 HTTP `/chat` 公开契约。
- 将工具临时轨迹写入当前 Session 历史。
- 为统计调用真实模型或新增外部服务。

## 10. 非目标

- 不实现上下文压缩、摘要、滑动窗口或自动清理。
- 不在达到某个比例时阻止用户发送。
- 不展示 prompt/completion/cache token 明细或费用。
- 不持久化统计快照，不修改现有 Session JSON schema。
- 不为 HTTP `/chat` 增加上下文占比。
- 不保证本地估算与 DeepSeek/Qwen tokenizer 精确一致。

## 11. 可测试验收标准

1. TUI 状态栏右侧显示 `Context: ~x.x%`，左侧原有信息保持可见。
2. 空会话显示 `Context: ~0.0%`，恢复历史后显示由相同算法计算出的稳定非负值。
3. 成功轮次持久化后占比更新；Provider 失败、存储失败或取消后占比不变。
4. `/clear` 成功后占比归零，清理失败时不伪造归零状态。
5. `TUI_CONTEXT_WINDOW_TOKENS` 可覆盖默认预算；非法值产生可理解的安全错误，不导致 TUI 未处理异常。
6. 超过预算时结果可大于 `100.0%`，不截断、不触发自动裁剪。
7. HTTP `/chat` 契约、TUI 中文输入、回车发送、双 Esc 退出、耗时和历史恢复行为不回归。
8. 不新增第三方依赖，全部自动化测试不访问真实模型服务。
9. 项目全部真实质量门禁通过。

## 12. 待确认决策

1. 接受第一版显示本地估算值，并用 `~` 明示不是上游精确 token usage。
2. 接受默认上下文预算 `128000 tokens`，并允许 `TUI_CONTEXT_WINDOW_TOKENS` 覆盖。
3. 只统计已成功提交的 user/assistant 历史，不统计未提交输入和工具临时轨迹。
4. 占比保留一位小数且不截断到 100%。
5. 本期只展示，不做压缩、告警或阻止发送。
