# TUI 输入交互需求

状态：已完成（2026-08-10）

## 1. 背景

当前 TUI 使用 `TextArea` 接收输入，回车发送，双 Esc 退出。用户发送后，现有底部状态栏只把
`Ready` 切换为 `Thinking`，没有位于输入框附近的 Claude 风格活动提示，也不会实时展示已经等待的时间。

输入框当前也没有命令行式历史浏览；重复或微调先前问题时只能重新输入或粘贴。

## 2. 目标

- 在输入框正上方增加独立活动状态栏。
- 模型请求进行期间显示动画、中文“思考中”、实时耗时和 Esc 取消提示。
- 使用上下方向键浏览已经发送的历史输入，并能恢复浏览前尚未发送的草稿。
- 保持现有 Provider 状态栏、最终耗时记录、会话持久化、快捷键和 HTTP 契约不变。
- 不新增第三方依赖，不调用真实模型完成状态或历史管理。

## 3. 默认假设

1. 新活动栏位于 transcript 与输入框之间；现有 Provider/模型/Key/RunStatus 状态栏仍保留在输入框下方。
2. 空闲时活动栏保留一行高度但不显示重复的“就绪”；请求开始后显示类似 `⠋ 思考中 · 1.2 秒 · Esc 取消`。
3. 活动耗时使用单调时钟，显示一位小数，约每 100 ms 刷新；不把 UI 刷新次数写入日志。
4. 成功、已知错误、未知错误或取消后立即停止动画并清空活动栏；最终耗时仍按现有逻辑写入 transcript，取消仍不写最终耗时。
5. 输入历史只包含通过非空校验并真正启动请求的普通输入，不包含 `/clear`、`/quit` 或空白输入。
6. 当前进程内，失败或取消的已发送输入仍可通过上下键找回；进程重启后只能从既有 Session 中恢复成功持久化的 user 消息。
7. 相同输入按发送次数保留，不自动去重或排序。
8. `↑` 从最新向更早浏览，`↓` 向更新方向浏览；越过最新记录时恢复第一次按 `↑` 前的输入框草稿。
9. 到达最早或最新边界时继续按相同方向不循环。
10. 上下键总是用于输入历史，不再承担多行 `TextArea` 的垂直光标移动；粘贴的多行文本仍可发送。
11. `/clear` 成功后同时清空 transcript、Session 和当前进程输入历史；清理失败时三者均保持原状态。

## 4. 活动状态栏行为

### 4.1 布局

```text
┌──────────────── transcript ────────────────┐
│ You / Assistant ...                        │
└────────────────────────────────────────────┘
  ⠋ 思考中 · 1.2 秒 · Esc 取消                 <- 新活动栏
┌──────────────── prompt ────────────────────┐
│                                            │
└────────────────────────────────────────────┘
DeepSeek | model | Key: configured | Thinking <- 现有状态栏
```

- 新栏使用固定一行高度，避免请求开始或结束时界面上下跳动。
- 窄终端优先保留“思考中”和耗时；不使用手工空格对齐。
- 动画只在请求存活时运行，空闲时不触发周期刷新。

### 4.2 生命周期

1. 普通非空输入被接受时记录 `started_at`，清空输入框并启动 Worker。
2. 同步显示初始活动文本，启动周期 Timer。
3. 每次 tick 使用 `clock() - started_at` 更新动画帧和耗时。
4. 成功或异常处理完成后停止 Timer、清空活动栏、恢复输入焦点。
5. 第一次 Esc 取消请求时同样停止 Timer、清空活动栏，并保留现有“再次按 Esc 退出”提示。
6. 请求代次守卫继续阻止已取消 Worker 的延迟结果或延迟 Timer 写回。

活动栏不是模型 reasoning 展示，不显示思维链、Provider 原始状态、Token 或工具内部轨迹。

## 5. 历史输入行为

### 5.1 数据来源

- TUI 构造时从 `ChatSession.messages` 按顺序提取 `role=user` 的原始内容，作为可跨重启恢复的历史。
- 没有 Session 的注入式测试/调用从空历史开始。
- 每个通过校验且启动 Worker 的普通输入立即追加到进程内历史；因此即使请求失败或被取消，也能在本次进程中找回。
- 不新增历史文件，不修改 `data/chat-session.json` schema，也不把失败/取消轮次写入 Session。

### 5.2 导航状态

TUI 维护：

```python
input_history: list[str]
history_index: int | None
history_draft: str
```

- 第一次按 `↑` 时保存当前输入框文本为 `history_draft`，加载最后一条历史。
- 后续按 `↑` 向更早移动，到第一条后停留。
- 按 `↓` 向更新移动；越过最后一条后恢复 `history_draft` 并退出浏览状态。
- 未处于浏览状态时按 `↓` 不修改输入框。
- 加载历史后光标移动到文本末尾，便于直接补充或修改。
- 浏览期间对召回文本的编辑不回写历史；再次导航会加载相邻原始记录。
- 成功启动新请求或 `/clear` 后退出浏览状态并清空草稿。

## 6. 项目结构

预计修改：

```text
app/tui/application.py   # 活动栏布局、Timer 生命周期、上下键历史状态
tests/test_tui.py        # 无头交互、计时、取消、恢复与历史边界测试
README.md                # 新状态栏和快捷键说明
docs/knowledge/          # 同步 TUI 当前事实
docs/spec|plan|tasks/    # SDD 文档和索引
```

不修改 Runtime、Provider、工具、Router、Session Store 或 HTTP 模型。

## 7. 代码风格

- Python 3.11，所有新增方法提供简洁中文 docstring。
- 活动栏渲染、Timer 清理、历史导航分别保持单一职责，不把全部逻辑堆入 `action_submit_prompt()`。
- 对 Timer/Worker 代次和草稿恢复等非显而易见边界增加必要注释。
- 不增加仅为未来扩展服务的 Manager、Repository 或抽象基类。

建议接口形态：

```python
def action_previous_input(self) -> None: ...
def action_next_input(self) -> None: ...
def _start_activity(self, started_at: float, generation: int) -> None: ...
def _stop_activity(self) -> None: ...
```

具体 Timer 类型和停止 API 在设计阶段依据当前 Textual 8.2.8 的实际接口确认。

## 8. 测试策略

### 活动栏

- 空闲时为空，输入框上方占位存在。
- 请求开始立即显示思考中、初始耗时和取消提示。
- 可控时钟推进后，耗时文本更新且动画帧变化。
- 成功、错误和取消均停止 Timer、清空活动栏。
- 取消后晚返回结果不能重新显示活动状态或写入回答。

### 输入历史

- 空历史上下键不改变草稿。
- 多次发送后，`↑`/`↓` 按顺序浏览并在边界停留。
- 浏览前非空草稿在向下越过最新记录时恢复。
- 恢复 Session 后可浏览历史 user 消息，assistant 消息不会进入输入历史。
- 失败/取消输入在当前进程可浏览，但不改变 Session 持久化语义。
- `/clear` 成功清空历史，失败保留历史。
- 中文、多行和重复输入原样召回，加载后光标位于末尾。

自动化测试使用假 Runner、可控 Clock 和 Textual headless Pilot，不调用真实模型。

## 9. 边界

### 必须做到

- Timer 在所有终止路径清理，不能空闲时继续刷新或引用已结束请求。
- 历史召回使用原始文本，不修改 Session 或模型上下文。
- 保持 Enter、双 Esc、中文输入、Markdown 输出、`/clear`、`/quit` 和最终耗时行为。
- 新增方法包含必要注释和对应行为测试。

### 实施前确认

- 将失败/取消输入持久化。
- 改变 Session JSON schema、增加独立历史文件或设置历史条数上限。
- 移除 transcript 中的最终耗时。
- 将上下键恢复为多行光标移动，或改成仅在首行/末行触发历史。

### 禁止

- 展示或推断模型思维链。
- 为动画或历史管理新增第三方依赖或外部服务。
- 修改 HTTP `/chat` 契约、Provider 请求或工具执行行为。
- 让周期 Timer 在空闲状态持续运行。

## 10. 非目标

- 不展示 reasoning 内容、Token、费用、工具调用详情或流式响应。
- 不增加历史搜索、模糊匹配、删除单条、收藏、分页或独立历史面板。
- 不跨设备同步，不新增数据库或额外持久化文件。
- 不增加多会话管理或上下文压缩。
- 不模仿 Claude 的品牌、颜色或完整视觉，只参考“请求中动画 + 实时耗时 + 取消提示”的交互模式。

## 11. 可测试验收标准

1. 输入框正上方存在固定一行活动栏，现有底部状态栏仍在且内容不回归。
2. 普通输入发送后立即显示 `思考中`、实时一位小数耗时和 `Esc 取消`，等待期间持续更新。
3. 成功、错误或取消后活动栏清空，Timer 不再运行；现有最终耗时规则保持不变。
4. `↑` 从最新输入向前浏览，`↓` 向后浏览，边界不循环，并能恢复浏览前草稿。
5. 历史支持中文、多行和重复输入；召回后光标位于末尾。
6. 重启恢复的成功 user 消息可浏览；assistant、命令、空白不进入历史。
7. 当前进程中失败/取消的已发送输入可浏览，但 Session 文件仍只保存完整成功轮次。
8. `/clear` 成功清空 Session、transcript 和输入历史，失败时不伪造清空。
9. HTTP、Provider、工具、Session schema 和依赖声明无变化。
10. 全量自动化测试和项目真实门禁通过，测试不访问真实模型服务。
