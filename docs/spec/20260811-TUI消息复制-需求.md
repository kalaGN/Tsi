# TUI 消息复制需求

状态：已完成（2026-08-11）  
创建日期：2026-08-11

## 1. Objective

让本地 Textual TUI 中已经展示的消息可以像普通终端文本一样选择和复制，解决当前
`RichLog` 虽能渲染 Markdown、但不能向 Textual 选择系统提供文本的问题。

目标用户是在 macOS 或其他现代终端中使用 `.venv/bin/python -m app.tui` 的开发者。

## 2. 已确认事实与默认假设

- 当前最终对话记录和流式临时回答均使用 Textual 8.2.8 的 `RichLog`。
- `RichLog` 没有实现消息文本提取和选择高亮，Textual 内置的
  `Cmd+C` / `Ctrl+C` 因此无法复制其中内容。
- 默认支持鼠标拖选任意一段消息，而不是只提供“复制最后一条回答”。
- 最终 transcript 和正在生成的临时文本都支持选择；输入框继续使用 `TextArea` 自身的
  选择、复制和粘贴行为。
- 复制的是屏幕渲染后的可见纯文本，不包含 Markdown 源标记，不改变 Session 中保存的原文。
- 继续使用 Textual 内置剪贴板和 OSC 52 通道；本次不执行 `pbcopy`、Shell 或第三方剪贴板命令。

## 4. Project Structure and Code Style

- 选择能力放在 `app/tui/` 的专用 Widget 中，不修改 `.venv` 内的 Textual 源码。
- `app/tui/application.py` 只负责组装可选择的消息组件。
- 无头交互与文本提取测试放在 `tests/test_tui.py` 或对应 Widget 测试文件。
- 使用明确类型和必要中文注释，只解释 RichLog 兼容边界与选择坐标等非显而易见逻辑。

## 5. Testing Strategy

- 先写失败测试证明现有 RichLog 无法提取选择内容。
- 覆盖单行、多行、中文、Markdown 渲染结果和流式临时文本。
- 验证选择后执行 Textual 内置复制动作，`app.clipboard` 得到准确可见文本。
- 回归输入框中文、Enter、上下历史、Esc、Markdown、流式输出和 `/clear`。
- 自动化测试不调用真实模型、不访问系统剪贴板或外部进程。

## 6. Boundaries

Always：

- 复制内容必须来自当前可见消息，保留中文和换行。
- 保持 `/chat`、Session schema、模型请求、日志和 Markdown 持久化原文不变。
- 复用 Textual 现有选择与复制快捷键，不新增依赖。

Ask first：

- 增加“复制整条消息”按钮、快捷键或上下文菜单。
- 调用 `pbcopy`、`xclip` 等系统命令以绕过终端剪贴板能力。
- 改用其他消息展示 Widget 或取消 Markdown 渲染。

Never：

- 修改虚拟环境中的第三方 Textual 源码。
- 为复制功能执行任意 Shell 或把消息写入临时文件。
- 复制未选择的隐藏历史、Provider 原始响应或 reasoning 内容。

## 7. Success Criteria

1. 鼠标可在最终 transcript 中选择任意单行或多行文本，并有可见选择高亮。
2. `Cmd+C` / `Ctrl+C` 可复制选中文本，中文和换行保持正确。
3. 流式临时回答也可选择和复制；完成后的最终消息仍只出现一次。
4. 复制的是 Markdown 渲染后的可见文本，不含 `**`、标题井号或代码围栏等源标记。
5. 输入框及现有 TUI 快捷键、会话、流式、取消和清理行为不变。
6. 全量项目门禁通过，且不增加依赖。
