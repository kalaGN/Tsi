# TUI 项目自修改需求

状态：已实现（2026-08-12）
创建日期：2026-08-11
基线版本：`v0.1.0`（`a743f8d`）

## 1. 背景

当前项目已经具备多轮 TUI、系统提示词、流式模型调用和自动只读工具编排，但默认 Registry
只注册 `get_current_time`。模型无法读取启动目录中的源码、生成受控变更、运行项目检查或撤销
自己刚完成的修改，因此还不具备完整的本地 Coding Agent 闭环。

用户要求让当前项目具有修改自身项目代码的能力，并明确本期不考虑 `/chat`。该能力会改变现有
“工具只能无副作用自动执行”的安全边界，必须把工作区隔离、写入审批、命令白名单、并发冲突、
审计和恢复语义写成宿主程序不可由模型绕过的约束。

## 2. 目标

为本地 Textual TUI 增加一个绑定启动目录的 Workspace 工具集，使用户可以通过自然语言让模型：

1. 检查项目目录、搜索并分段读取相关源码。
2. 查看 Git 工作区状态和差异，识别用户已有修改。
3. 生成结构化文件变更，在 TUI 展示 Diff 并得到用户明确确认后应用。
4. 使用项目现有白名单命令验证修改，根据结果继续修正或安全撤销本轮变更。
5. 最终向用户汇总修改文件、检查结果和剩余风险，但不自动提交、推送或发布。

成功意味着模型能够在一次 TUI 请求内完成“理解 → 修改 → 验证 → 汇报”的闭环，同时不能读取
敏感文件、越过启动目录、运行任意命令或在未经确认时改变项目文件。

## 3. 已确认范围

以下内容已由用户确认，按此范围进入设计：

1. 仅 `python -m app.tui` 获得 Workspace 工具；FastAPI、Router 和 `/chat` 的 Registry、契约与行为完全不变。
2. Workspace 根目录是 TUI 启动时捕获的 `Path.cwd()`，运行期间固定，不跟随进程目录变化。
3. 只读工具继续自动执行；创建、修改或撤销文件前必须展示变更并等待本地用户确认。
4. 第一版不支持删除、移动、重命名文件，不支持任意 Shell/Python、依赖安装、Git Commit/Tag/Push 或外部发布。
5. 修改的是磁盘上的项目代码；当前运行中的 TUI、Registry 和系统提示词不热加载，重启后才使用新代码。
6. 工具执行失败、用户拒绝或模型请求失败时，不得把不完整 assistant 消息写入 Session。
7. 当前明文模型请求日志策略保持不变；允许读取的源码、工具参数和工具结果可能随 Provider 续轮进入本地日志。

## 4. 功能范围

### 4.1 Workspace 上下文

- TUI 启动入口创建不可变的 Workspace Context，保存解析后的启动目录。
- TUI 为 `ChatSession` 注入专用 Workspace Registry；HTTP 继续使用原有默认只读 Registry。
- 所有路径参数都使用相对 Workspace 根目录的 POSIX 风格路径。
- 工具结果返回稳定、Provider 中立且有大小边界的 JSON 数据，不返回 Python 对象表示或内部异常。

### 4.2 第一版工具清单

#### `list_workspace_files`

- 输入：相对目录、可选深度和结果游标。
- 输出：排序后的相对路径、类型和下一页游标。
- 不递归进入受保护目录，不跟随符号链接。

#### `search_workspace_text`

- 输入：非空字面量、相对目录、可选 glob 和结果游标。
- 输出：按路径和行号稳定排序的有限匹配结果。
- 使用项目现有系统能力或标准库实现，但参数不能拼接成 Shell 字符串。

#### `read_workspace_file`

- 输入：相对文件、起始行和最大行数。
- 输出：文件哈希、总行数、实际行区间和原始 UTF-8 文本。
- 仅允许有界 UTF-8 普通文件；二进制、超大、受保护或不可读文件返回安全错误。

#### `get_workspace_git_status`

- 无模型可控命令参数。
- 输出当前 Workspace 的 Porcelain 状态；非 Git 仓库返回明确的安全错误。

#### `get_workspace_git_diff`

- 输入：可选的已允许相对路径和分页参数。
- 输出有界的未暂存及已暂存文本差异，不启用外部 diff 驱动。

#### `apply_workspace_edits`

- 输入一个有界批次，支持创建 UTF-8 文本文件和对现有文件执行精确文本替换。
- 修改现有文件必须携带最近一次读取获得的 SHA-256；哈希变化时拒绝覆盖。
- 精确替换要求旧文本在目标文件中只出现一次；零次或多次均拒绝。
- 宿主先在内存中验证完整批次并生成统一 Diff，TUI 展示后等待用户确认。
- 用户确认后才执行；所有目标使用同目录临时文件和原子替换，批次中途失败时恢复已替换文件。
- 返回 `change_id`、变更文件和摘要，不把无界完整文件再次放入工具结果。

#### `run_project_check`

- 输入只能从 `compile`、`test_all`、`pip_check`、`diff_check` 中选择。
- 分别映射到 `AGENTS.md` 已记录的固定 argv，不通过 Shell 解释字符串。
- 每次执行有超时、输出字节和并发上限；退出码、有限 stdout/stderr 和耗时返回模型。
- 检查失败属于可观察结果，不伪装为工具执行异常，模型可以据此继续修正。

#### `undo_workspace_change`

- 只能撤销当前 TUI 进程由 `apply_workspace_edits` 产生的最近未撤销 `change_id`。
- 撤销前检查当前文件哈希仍等于该变更结果，避免覆盖用户后续编辑。
- TUI 展示反向 Diff 并确认后执行；重启后不恢复撤销日志。

### 4.3 TUI 审批体验

- 写工具进入等待状态时停止继续调用模型，不占用新的 Provider 步骤。
- TUI 展示工具名、变更文件数、每个相对路径和有界统一 Diff。
- 用户可以明确选择“应用”或“拒绝”；默认焦点和关闭行为必须是拒绝。
- `Esc` 在审批界面表示拒绝本次写入，不触发主界面的双 Esc 退出。
- 拒绝后工具向模型返回稳定的 `approval_denied`，模型可解释结果但不得重复自动弹出同一变更。
- 审批期间不允许提交第二个聊天请求；退出 TUI 前不会遗留待应用变更。

### 4.4 修改、验证与恢复闭环

- 模型应先使用只读工具理解目标文件和现有差异，再请求写工具。
- 写入成功后模型可以调用一个或多个白名单检查，并根据失败输出生成后续新变更。
- 每次新写入都需要独立审批；读取和检查不需要逐次确认。
- 工具循环需要 TUI 专属的总步骤和调用预算，不能直接放大全局 `/chat` 上限。
- 达到预算、取消或 Provider 失败时保留用户已经确认并成功写入的文件，同时明确汇报未完成状态；用户可要求撤销。
- 系统不自动 Git Commit；Commit 继续只响应用户明确命令。

## 5. 安全边界

### 5.1 路径隔离

所有文件工具必须：

- 先规范化并解析路径，再验证结果位于固定 Workspace 根目录内。
- 拒绝绝对路径、`..` 越界、NUL、符号链接及非普通文件。
- 不依赖 glob 展开后的偶然结果实现安全校验。

第一版禁止读取和修改：

- `.env` 及所有 `.env.*`
- `.git/`、`.venv/`、`data/`、`logs/`
- `__pycache__/`、`.pytest_cache/` 和其他生成缓存

第一版额外禁止修改：

- `AGENTS.md`
- `docs/rules/`
- `.gitignore`、`requirements.txt`
- Workspace Tool、Registry、审批和路径策略自身的实现文件

受保护路径由宿主代码判断，不能由模型参数、`AGENTS.md` 或项目配置关闭。

### 5.2 命令边界

- 不注册 `run_shell`、`run_python` 或任意命令工具。
- 固定命令使用 `asyncio.create_subprocess_exec` 风格的 argv 调用，`cwd` 固定为 Workspace 根目录，禁止 `shell=True`。
- 子进程继承最小必要环境；工具结果和日志不得包含 API Key 或完整环境变量。
- 检查超时后终止对应进程并返回安全的 `check_timeout`。

### 5.3 写入和并发边界

- 单文件、单批次、单次工具参数和 Diff 预览均设置独立 UTF-8 字节上限。
- 同一 `ChatSession` 继续串行发送；Workspace 写入额外使用进程内锁。
- 哈希前置条件、精确替换唯一性和原子替换共同防止静默覆盖。
- 自动测试不得操作真实用户仓库、调用真实模型或执行非测试白名单命令。

## 6. 非目标

- 修改 `/chat`、增加远程 Agent API 或通过 HTTP 写文件。
- 多 Workspace、多 Agent、后台任务、任务队列或跨进程锁。
- 任意 Shell、脚本执行、网络访问、MCP、数据库或浏览器工具。
- 删除、移动、重命名文件或修改文件权限。
- 自动安装或升级依赖。
- 自动提交、创建分支、Tag、推送或创建 PR。
- 热更新当前 TUI、动态加载刚修改的工具或自我提升权限。
- 跨重启保存 Change Journal 或自动恢复未完成任务。
- 绕过用户审批实现无人值守写入。

## 7. 项目结构约束

预计职责仍遵循当前依赖方向：

```text
app.tui -> ChatSession -> Runtime -> ToolLoop -> ToolRegistry -> tools/
```

- Workspace 路径策略、只读/写入工具和固定检查实现放在根目录 `tools/`。
- Tool 风险元数据和审批所需的中立契约放在 `tools/contracts.py`，不得依赖 Textual。
- Tool Loop 只负责预算、审批回调和执行顺序，不理解文件或 Git 细节。
- TUI 负责渲染审批界面和收集本地决定，不实现文件写入。
- `ChatSession` 只负责注入 TUI 专属 Registry/策略并维持成功轮次提交语义。
- HTTP/Application/Router 不引入 Workspace 依赖。
- 测试继续位于 `tests/`，文档保持现有 `docs/spec`、`docs/plan`、`docs/tasks` 和 `docs/knowledge` 结构。

## 8. 代码风格

- Python 3.11，使用现有 dataclass、Protocol、明确类型和异步边界。
- 工具名称、参数和错误码稳定且语义明确；不暴露内部异常或绝对路径。
- 注释只解释路径安全、原子性、审批和兼容等非显而易见意图。
- 优先标准库和现有依赖，不新增 Patch、Git 或 Shell SDK。
- 不创建空壳 Repository、Manager 或通用插件系统。

契约风格示意：

```python
@dataclass(frozen=True)
class ToolDefinition:
    name: str
    description: str
    parameters: Mapping[str, object]
    effect: ToolEffect = ToolEffect.READ_ONLY
```

风险字段只由宿主注册代码定义，不能接受模型覆盖。

## 9. 测试策略

### 9.1 Workspace 工具

- 临时目录验证分页列举、文本搜索、行范围读取、稳定排序和 UTF-8 中文。
- 覆盖绝对路径、`..`、符号链接、受保护目录、二进制、超限和权限错误。
- Git 工具在临时仓库验证 clean、tracked、untracked、staged 和非仓库结果，不读取真实项目 Git 状态。
- 写工具覆盖创建、精确替换、哈希冲突、重复旧文本、批次失败恢复、拒绝审批和撤销冲突。
- 检查工具 Mock 子进程边界，验证固定 argv、cwd、超时、输出限制和退出码；测试不执行生产外部服务。

### 9.2 Runtime 与 Session

- 只读工具继续自动执行；写工具在审批前没有文件变化。
- 应用、拒绝、撤销、取消、预算耗尽和检查失败都返回稳定结果。
- TUI Session 注入 Workspace Registry；未注入的 Runtime 和 HTTP 仍只看到 `get_current_time`。
- 工具过程不进入会话文件，只有完整 user/assistant 轮次成功后提交。

### 9.3 TUI

- 审批界面展示有界 Diff，默认拒绝，应用/拒绝/Esc 行为可测试。
- 审批期间输入锁定，取消后没有陈旧回调或待写入变更。
- 修改完成后最终 Markdown 汇总、临时流清理、耗时和上下文状态保持现有行为。

### 9.4 全量门禁

```bash
.venv/bin/python --version
.venv/bin/python -m compileall -q main.py app tools tests
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -m pytest -q
.venv/bin/python -m pip check
git diff --check
```

仓库仍不虚构 Formatter、Lint、类型检查、打包或 CI 门禁。

## 10. 验收标准

1. 从任意测试 Workspace 启动 TUI 后，模型只能列举、搜索和读取该目录内允许的 UTF-8 普通文件。
2. `/chat` 请求体、响应、错误映射和默认工具列表与 `v0.1.0` 保持一致，不出现任何 Workspace Tool。
3. 模型提出结构化文件修改时，用户确认前磁盘零变化；拒绝或 Esc 后所有目标内容和 Git 状态不变。
4. 用户确认后，合法创建/精确替换按批次完成并返回可撤销的 `change_id`；哈希冲突或批次失败不会留下部分修改。
5. 越界、符号链接、受保护路径、删除/移动意图和超限载荷均被宿主拒绝，错误不泄漏绝对路径、文件正文或内部堆栈。
6. 模型只能运行四种既有项目检查，不能通过参数执行额外命令；结果包含退出码、耗时和有界输出。
7. 撤销只作用于当前进程最近且未被后续编辑改变的 Agent 变更，执行前同样获得用户确认。
8. 修改和工具轨迹不写入 Session；完整最终回答仍可持久化和恢复，失败/取消不产生半轮记录。
9. 中文路径、中文源码和中文 Diff 可以正确读取、展示、修改与验证。
10. 语法、全量测试、依赖检查和 `git diff --check` 全部通过，README、架构、故障排查、Spec、设计和任务与实现一致。
