# 模型流式输出需求

状态：已完成（2026-08-11）  
创建日期：2026-08-11

## 1. 背景

当前阿里云与 DeepSeek Provider 都等待上游完整 JSON 响应后，才把统一的
`output_text` 返回给 Runtime。TUI 因此只能在完整响应结束后一次性展示回答，
长回答期间只能显示“思考中”和耗时，无法让用户尽早看到已经生成的文本。

本次改造让两家上游都使用其官方流式协议，并让 TUI 实时展示最终回答文本。
FastAPI `/chat` 继续聚合完整文本后返回现有 JSON，以避免本次同时引入公开 HTTP
破坏性变更。

## 2. 已确认的上游协议事实

### 2.1 DeepSeek Chat Completions

- 请求体使用 `"stream": true`。
- 响应 Content-Type 为 `text/event-stream`。
- 文本增量来自 SSE `data:` JSON 中的 `choices[0].delta.content`。
- `data: [DONE]` 表示流结束。
- `reasoning_content` 不属于最终回答，不向 TUI 展示或写入 Session。

官方参考：[DeepSeek Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)

### 2.2 阿里云兼容 Responses API

- 请求体使用 `"stream": true`。
- `response.output_text.delta` 事件的 `delta` 是最终文本增量。
- `response.completed` 表示响应完整结束，并携带完整 Response 对象。
- reasoning summary 和其他内置工具状态事件不属于最终回答，不向 TUI 展示或写入 Session。

官方参考：[阿里云 Responses API](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-responses)

## 3. 目标

1. 阿里云与 DeepSeek 的真实上游模型请求默认使用流式响应。
2. Provider 把不同 SSE 事件转换为 Provider 中立的文本增量和最终 `ModelStep`。
3. TUI 在上游产生最终回答文本时增量展示，而不是等待完整回答。
4. 一轮成功结束后，仍以完整原文记录模型输出日志并持久化唯一完整 user/assistant 轮次。
5. HTTP `/chat` 复用同一流式上游链路，但在服务端聚合后继续返回
   `{"output_text":"..."}`。
6. 保持现有自动只读工具调用、取消、耗时、Markdown 最终展示和安全错误映射。

## 4. 用户可观察行为

### 4.1 TUI

1. 用户按 Enter 后，输入框上方继续显示“思考中”和实时耗时。
2. 收到首个最终文本增量后，TUI 出现临时 Assistant 输出区域并持续追加内容。
3. 流式生成期间按纯文本展示原文，避免半截 Markdown 导致布局持续跳动。
4. 流成功完成后，临时区域被清空，完整原文按现有 Rich Markdown 规则一次性写入对话记录。
5. 成功后显示最终耗时，并把完整回答写入 Session。
6. 流式过程中按 Esc 取消时，立即停止读取上游、清空临时输出，不写入不完整回答和用户轮次。
7. 流开始后发生超时、连接中断或非法事件时，清空临时输出，显示现有中立错误；不持久化半轮会话。
8. 恢复历史时只恢复已经完整提交的回答，不恢复临时流式内容。

### 4.2 HTTP

1. `POST /chat` 请求仍为 `{"input":"非空字符串"}`。
2. 成功仍为 `200` 和 `{"output_text":"完整模型回答"}`。
3. HTTP 客户端不会收到上游 SSE、增量事件、Provider 原始结构或工具轨迹。
4. 现有错误状态码与 `{"detail":"..."}` 结构保持不变。

## 5. 工具调用行为

1. 根目录 `tools/` 的显式白名单和只读限制保持不变。
2. 每个模型步骤都允许通过流式事件产生文本或工具调用。
3. Runtime 只把没有工具调用的最终步骤作为最终回答。
4. 如果某个步骤最终包含工具调用，已经展示的该步骤临时文本必须撤销，然后自动执行工具并继续下一模型步骤。
5. 工具调用参数增量只能在 Provider 内部组装；参数完整且通过现有 Registry 校验后才允许执行。
6. 工具步骤数、每步工具数和载荷上限保持现有值，不因流式改造放宽。
7. 工具调用和工具结果仍不进入 Session；Session 只保存最终 user/assistant 文本。

## 6. 中立流式契约

具体类型名称在设计阶段确认，但职责必须满足：

```python
TextDeltaHandler = Callable[[str], None]
TextResetHandler = Callable[[], None]

async def run_chat_messages(
    messages: Sequence[ChatMessage],
    *,
    on_text_delta: TextDeltaHandler | None = None,
    on_text_reset: TextResetHandler | None = None,
) -> ChatResult:
    ...
```

- Provider 负责解析 SSE、组装完整文本和工具调用参数。
- Tool Loop 负责判定当前步骤是否为最终步骤；遇到工具步骤时通知展示层撤销临时文本。
- Runtime 负责最终完整文本日志和中立错误。
- HTTP 不传展示回调，因此只得到聚合后的 `ChatResult`。
- TUI 只消费中立文本事件，不解析 DeepSeek 或阿里云 SSE。
- 回调不得包含 reasoning、上游事件对象、密钥、Header 或 Provider 私有字段。

## 7. 项目结构

预计影响范围如下，设计确认前不新增目录：

```text
app/services/llm/http_client.py  # 安全 SSE 请求、状态与网络错误边界
app/services/llm/contracts.py    # Provider 中立流式回调契约
app/services/llm/deepseek.py     # DeepSeek SSE 与工具参数增量组装

app/runtime/session.py           # 成功完成后原子提交完整轮次

```

## 8. 代码风格

- Python 3.11，使用异步迭代器和明确类型，不引入 OpenAI SDK 或新的 SSE 依赖。
- SSE 解码、Provider 事件解析、Runtime 编排和 Textual 展示分层实现，不把协议判断写进 TUI。
- 对流结束、工具参数拼接、取消清理和完整轮次提交等非显而易见边界增加必要中文注释。
- 不逐 Token 记录日志，不在日志中记录原始 SSE 事件或不完整工具参数。

示意：

```python
async for event in stream_events:
    delta = extract_text_delta(event)
    if delta:
        full_text.append(delta)
        if on_text_delta is not None:
            on_text_delta(delta)
```

## 9. 错误、取消与数据一致性

1. HTTP 建连超时、读取超时、连接失败、401/403 和其他非成功状态继续映射为现有错误类型。
2. SSE 行不是合法 UTF-8、`data:` JSON 非法、缺少完成标记、最终文本为空或工具参数不完整时，视为非法上游响应。
3. 60 秒现有请求超时边界不得因持续收到小数据块而无限延长；具体整体超时实现由设计明确。
4. 取消必须关闭 HTTP 流和 Textual Worker，陈旧增量不得写回新请求界面。
5. 只有上游完整结束、工具循环完成、完整输出日志写入并且 Session 保存成功后，内存历史才提交新轮次。
6. 流式中断不得把部分回答写入 `data/chat-session.json`。

## 10. 日志与安全

1. `llm_http_request.request_body` 记录真实流式请求体，其中 `stream` 为 `true`；Authorization 继续固定脱敏。
2. 每次外部 HTTP 流完成后记录一次 `llm_http_response`，不为每个 Chunk 生成日志。
3. 一轮最终成功后只记录一次现有 `llm_response`，内容为拼接后的完整 `output_text`。
4. 失败或取消时不记录伪造的完整 `llm_response`，也不把部分文本写入新的日志字段。
5. 上游错误体、原始 SSE、Cookie、密钥和完整工具参数不得新增到日志。
6. 对单个事件、单轮累计文本和工具参数设置有界校验；具体上限在设计阶段基于现有工具边界确定。

## 11. 性能与展示约束

1. 流式目标是降低首段文本可见延迟，不承诺尚未测量的具体毫秒指标。
2. TUI 不允许每个极小 Chunk 都重排完整 Markdown；流中只更新一个临时纯文本区域。
3. 完整 Markdown 仅在成功结束时构造一次。
4. 更新频率可在设计中做轻量合并，但不得明显吞掉或重排文本。
5. 不新增后台队列、数据库、缓存、重试、连接池或并发基础设施。

## 12. 测试策略

### 12.1 Provider 与 HTTP Client

- 使用 HTTPX `MockTransport` 或自定义异步字节流，不访问真实外部服务。
- DeepSeek：多段中文/英文 `delta.content`、`[DONE]`、空心跳、非法 JSON、缺少结束标记、流中断。
- 阿里云：多段及空字符串 `response.output_text.delta`、`response.completed`、无关事件、非法事件、缺少完成标记；空字符串 Delta 按无内容事件忽略，非字符串 Delta 仍视为非法。
- 两家 Provider：工具调用参数跨多个 Chunk 拼接、多个工具调用、重复或缺失 ID、空最终文本。
- 验证请求体真实包含 `stream: true`，Header 不泄密。

### 12.2 Runtime、工具和 Session

- 无工具时按原顺序收到增量，最终 `ChatResult.output_text` 与拼接结果一致。
- 工具步骤撤销临时文本，工具执行完成后的最终回答重新流式展示。
- 达到工具上限、Provider 失败或取消时不生成成功日志。
- Session 只在完整成功后保存，失败与取消后磁盘和内存历史不变。
- HTTP `/chat` 继续返回唯一 `output_text` 字段。

### 12.3 TUI

- 首个增量出现后临时输出可见，后续增量顺序追加。
- 完成后临时输出清空，最终 Markdown 进入 transcript，原文进入 Session。
- 工具步骤 reset、Esc 取消、网络错误和陈旧请求不会留下临时内容。
- 中文、多行文本和 Markdown 半成品在流中保持可读。

## 14. 边界

### 必须执行

- 两家 Provider 都使用官方流式事件格式并通过 Mock 测试。
- 保持 Provider → Runtime → TUI 的依赖方向。
- 保持完整输出日志、Session 原子提交和取消代次保护。
- 更新受影响的 README、架构 Knowledge、Spec、设计和任务。

### 实施前确认

- 将 `/chat` 改为 SSE、NDJSON 或 WebSocket。
- 改变 60 秒超时策略、增加重试或连接池。
- 新增第三方 SSE/OpenAI SDK 依赖。
- 展示 reasoning、工具轨迹或部分失败回答。

### 禁止

- 向 HTTP 客户端透传 Provider 原始 SSE。
- 持久化不完整 assistant 回答。
- 执行未注册工具、写操作工具、动态 import、Shell 或文件写入工具。
- 在测试中调用真实付费接口。
- 把密钥、Authorization、上游错误体或 Cookie 写入日志和 Git。

## 15. 验收标准

1. DeepSeek Mock 流依次发送 `你`、`好` 时，TUI 在完成前按顺序显示 `你好`，最终记录只保留一条完整 Assistant 回答。
2. 阿里云 Mock 流依次发送两个 `response.output_text.delta` 并以 `response.completed` 结束时，行为与 DeepSeek 一致。
3. 两家上游请求 Body 均包含 `stream: true`。
4. HTTP `/chat` 仍通过同一流式 Provider 路径返回 `{"output_text":"完整文本"}`，Schema 和错误映射不变。
5. 工具调用参数跨 Chunk 时能完整组装并仅执行显式注册的只读工具；工具步骤临时文本不会残留。
6. 流中断、非法事件、缺少完成标记、空回答和超时均返回现有中立错误，Session 不产生半轮记录。
7. Esc 取消后 HTTP 流关闭，临时输出清空，延迟 Chunk 不再更新界面。
8. 成功只记录一次完整 `llm_response`；不产生逐 Chunk 日志，不泄漏密钥或上游原始事件。
9. 全量测试、语法检查、依赖检查和 `git diff --check` 全部通过。

## 16. 非目标

- 不把 FastAPI `/chat` 改为面向客户端的流式接口。
- 不增加新的 `/chat/stream` 路由。
- 不展示或持久化 reasoning 内容。
- 不实现多会话、上下文压缩、多 Agent、MCP、写操作工具或流式语音/图片。
- 不新增 Token 用量展示、重试、断点续传或断线重连。
