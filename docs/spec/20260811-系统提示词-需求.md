# 系统提示词需求

状态：已完成（2026-08-11）
创建日期：2026-08-11

## 1. Objective

为当前模型调用架构增加 Provider 中立的系统提示词能力。第一版由本地 TUI 在启动时读取
启动目录直属的 `AGENTS.md`，并把正文作为每轮请求的第一条 `system` 消息，使阿里云和
DeepSeek 都能遵循项目级约束。

系统提示词属于运行时上下文，不属于用户对话历史，不应显示在终端对话区或写入
`data/chat-session.json`。

## 2. Assumptions to Confirm

1. 本期系统提示词唯一来源是 TUI 启动时 `Path.cwd()` 直属、大小写精确的 `AGENTS.md`。
2. 文件只在 TUI 启动时读取一次；修改后重启 TUI 才生效。
3. 文件缺失或全为空白时不发送 system 消息，保持当前行为。
4. 文件必须是可读取的 UTF-8 普通文件，最大 32 KiB；非法文件明确报错并禁止发起模型请求。
5. HTTP `/chat` 本期不自动读取宿主机文件，也不增加公开请求字段。
6. 现有详细上游请求日志记录完整请求 body，因此会包含实际发送的系统提示词；
   `AGENTS.md` 不得包含密钥、Token 或其他不应发给模型的内容。

## 3. Scope

### In scope

- 中立消息契约支持最多一条位于首位的 `system` 消息。
- `run_chat_messages` 和 `ChatSession` 支持独立、可选的 `system_prompt`。
- Session 每轮请求在历史之前添加一次系统提示词，但只持久化原有 `user/assistant` 完整轮次。
- TUI 启动入口读取并校验启动目录的 `AGENTS.md`，装配到 Session。
- TUI 状态栏或启动消息只显示系统提示词是否加载，不展示正文。
- 阿里云 Responses `input` 与 DeepSeek Chat Completions `messages` 使用标准
  `{"role": "system", "content": "..."}`。

### Out of scope

- Codex CLI 式 Git 根目录到当前目录的分层发现。
- `AGENTS.override.md`、fallback 文件名、多文件合并和运行中热重载。
- HTTP 请求级自定义系统提示词。
- 将系统提示词写入 Session、允许用户在 TUI 中编辑，或增加新的配置依赖。
- 解析或执行 `AGENTS.md` 中的命令、链接和其他文件引用。

## 5. Project Structure and Code Style

- `app/services/llm/contracts.py`：定义 system 角色和统一消息序列校验。
- `app/runtime/`：读取项目系统提示词，并保持提示词与持久化会话隔离。
- `app/tui/__main__.py`：捕获启动目录并装配系统提示词。
- `app/tui/application.py`：展示是否加载，不解析或修改正文。
- `tests/`：使用 `tmp_path` 和假 Provider，禁止调用真实外部模型。
- 新代码使用明确类型和必要中文注释，只解释提示词优先级、文件边界和持久化隔离等关键意图。

## 6. Testing Strategy

- 文件读取：中文 UTF-8 正常读取；缺失和空白返回无提示词。
- 文件边界：恰好 32 KiB 可用；超限、非 UTF-8、目录冒充文件和读取失败返回安全错误。
- Runtime：有提示词时消息首位唯一出现 system，无提示词时保持原序列。
- Session：首轮、多轮、恢复和 `/clear` 后继续使用系统提示词，但磁盘只保存 user/assistant。
- Provider：阿里云与 DeepSeek 请求体准确包含 system 首位消息。
- 回归：HTTP `/chat`、工具循环、流式输出、日志和 TUI 现有交互不变。

## 7. Boundaries

Always：

- 系统提示词与用户输入、Assistant 输出和持久化历史分别建模。
- 在网络请求前完成类型、编码、空白和大小校验。
- Provider 收到的 system 消息最多一条且只能位于首位。
- 保持 HTTP `/chat` 的请求、响应和错误契约不变。

Ask first：

- 支持父目录递归、override、多文件合并或热重载。
- 允许 HTTP 客户端提交自定义系统提示词。
- 修改现有完整模型请求日志的记录或脱敏策略。

Never：

- 把系统提示词拼进用户原文或 Assistant 历史。
- 静默截断或忽略非法 `AGENTS.md`。
- 执行 `AGENTS.md` 中出现的代码、Shell 或工具调用。
- 在测试、文档或代码中写入真实密钥。

## 8. Success Criteria

1. 从包含有效 `AGENTS.md` 的目录启动 TUI 后，每次阿里云或 DeepSeek 请求都只在首位发送
   一条内容完全一致的 system 消息。
2. 模型返回、工具调用、流式展示、多轮恢复和 `/clear` 均不重复或持久化系统提示词。
3. 缺失或空白文件没有行为回归；非法文件在网络调用前给出稳定且不泄露正文的错误。
4. HTTP `/chat` 不读取 `AGENTS.md`，公开 JSON 契约不变。
5. 全量测试、语法、依赖和差异检查通过，不增加第三方依赖。

## 9. Confirmed Decisions

1. 第一版只读取启动目录直属 `AGENTS.md`，暂不实现 Codex 的分层发现。
2. 启动时读取一次，要求 UTF-8，采用 32 KiB 上限，非法文件阻止请求。
3. 系统提示词进入现有完整上游请求日志。
