# TUI 双击复制单行需求

状态：已实现（2026-08-12）
创建日期：2026-08-12

## 1. 目标

在 TUI 对话记录区域双击任意可见文本行时，立即把该行的可见文字复制到 Textual 剪贴板，
减少“鼠标拖选 → Ctrl/Cmd+C”的操作成本，同时保留现有任意范围选择复制能力。

## 2. 已知事实与假设

- `#transcript` 当前使用 `SelectableRichLog`，已经支持鼠标拖选、选择高亮和
  `Ctrl/Cmd+C`。
- Textual 的 `Click.chain == 2` 可稳定识别双击；其默认行为是选择整个 RichLog，不能满足
  单行复制。
- 本需求中的“单行”按 RichLog 当前渲染后的可见行定义；Markdown 标记不会重新加入复制内容。
- 双击只作用于左键和 `#transcript`；流式临时输出及审批 Diff 暂不增加该快捷行为。
- 双击空白、边框、内边距或不存在的行时不改变剪贴板。

## 3. 技术栈与结构

- Python 3.11、Textual，依赖版本保持 `requirements.txt` 不变。
- 行定位和复制行为放在 `app/tui/widgets.py` 的 `SelectableRichLog`。
- `app/tui/application.py` 只为 `#transcript` 启用该行为，避免扩散到其他日志组件。
- 自动化测试放在 `tests/test_tui.py`。

## 4. 行为约束

### 必须

- 使用点击内容坐标加滚动偏移定位当前渲染行，支持滚动后的中文行。
- 通过 Textual `app.copy_to_clipboard()` 复制，不执行 `pbcopy`、Shell 或第三方命令。
- 双击后不得触发 RichLog 默认的“全选全部对话记录”。
- 保留现有鼠标拖选、多行复制、Markdown 展示、流式输出和输入快捷键行为。

### 需要另行确认

- 将相同行为扩展到流式输出或审批 Diff。
- 增加复制成功 Toast、状态栏提示或系统消息。

### 禁止

- 复制整段消息、Session 原文、Markdown 源码或屏幕外其他行。
- 因复制操作修改 Session、对话记录或输入框。

## 5. 代码风格

事件处理保持在组件边界，并用注释说明坐标转换原因：

```python
content_offset = event.get_content_offset(self)
line_index = self.scroll_offset.y + content_offset.y
```

不把复制逻辑放入 `ChatTuiApp` 的业务方法中。

## 6. 测试与命令

- 双击普通中文行，只复制该行。
- 滚动后双击，复制滚动偏移对应行。
- 双击空白区域，不覆盖已有剪贴板。
- 单击和拖选复制保持原行为；其他 `SelectableRichLog` 默认不启用双击复制。

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -m pytest -q tests/test_tui.py
.venv/bin/python -m compileall -q main.py app tools tests
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -m pytest -q
.venv/bin/python -m pip check
git diff --check
```

## 7. 验收标准

1. 双击 `#transcript` 某一可见非空行，剪贴板内容精确等于该渲染行文字。
2. 中文、空格和 Markdown 渲染后的行文字保持正确。
3. 双击不会选择或复制整个 transcript。
4. 空白区域不复制，现有剪贴板内容不变。
5. 流式输出和审批 Diff 仍维持现有拖选复制语义。
6. 定向测试、全量测试、语法、依赖和差异检查通过。
