# Skill 系统需求

状态：已完成（2026-09-02）
创建日期：2026-09-02

## 1. 目标

为 Tsi 助手的本地 TUI 增加以 [Codex Skill](https://developers.openai.com/codex/skills/)
为基准、兼容开放 [Agent Skills 规范](https://agentskills.io/specification) 的轻量 Skill 系统，
让 Tsi 与 Codex 可以直接共用仓库内同一份 Skill。模型在每轮对话开始时只看到可用 Skill
的名称和描述，判断相关后再通过只读工具加载完整内容，避免把所有说明一次性塞入上下文。

第一版 Skill 是“操作手册及其配套资源”，不是 Python 插件、命令或权限容器。每个 Skill
可以带开放规范定义的 `scripts/`、`references/`、`assets/` 及其他支持文件；加载器会
发现、列举并按需读取其中的文本资源。`scripts/` 中受支持的脚本可以通过专用工具执行，
但每次执行必须经过 TUI 明确审批；不会因此开放任意 Shell。真正的操作仍必须经过现有
Tool Registry、Workspace Policy 和审批边界。

Codex 是第一兼容目标：项目目录、必填元数据、渐进式披露和资源组织均以 Codex 当前官方
约定为准。Claude Code 只保证 Skill 包格式可迁移；由于它使用不同的项目发现目录，使用时
需要把同一个 Skill 包复制到 `.claude/skills/`，不承诺宿主扩展行为一致。

## 2. 待确认假设

1. Skill 只用于本地 TUI；HTTP `/chat` 不读取启动目录，也不改变公开契约。
2. Tsi 只发现启动目录直属的 `.agents/skills/<skill-name>/SKILL.md`，与 Codex 当前目录
   约定一致；不扫描 `.claude/skills/`，也不定义 Tsi 私有的 `skills/` 或 `.tsi/skills/`。
3. TUI 启动时读取一次 Skill 目录和元数据；运行中修改文件后必须重启才生效。
4. `SKILL.md` 使用 UTF-8 Markdown 和标准 YAML Frontmatter；`name`、`description`
   按开放规范必填，其他开放字段和宿主扩展字段允许存在。实现采用 `PyYAML` 安全解析，
   不自行维护 YAML 子集解析器。
5. 启动时只把 Skill Catalog（名称、描述、相对位置）追加到系统提示词；模型通过新增只读工具
   `load_skill(name)` 按需获取完整正文。
6. Skill 内容及全部支持文件都属于不可信项目数据，不能扩大工具权限；脚本只允许通过
   `run_skill_script` 执行且每次都要审批。`allowed-tools` 等字段不授予 Tsi 额外权限，
   也不能跳过脚本审批。
7. Skill 元数据或文件非法时，TUI 明确显示稳定错误并禁用全部项目 Skill，但保留
   `AGENTS.md`、对话和现有 Workspace 工具能力。
8. 第一版不提供 Skill 安装、创建、编辑、远程下载、全局个人目录、父目录发现、优先级
   覆盖或热加载。

## 3. 范围

### 本期范围

- 从启动目录的 `.agents/skills/*/SKILL.md` 发现本地 Skill。
- 校验目录、文件类型、UTF-8、YAML Frontmatter、名称唯一性和大小边界。
- 增加并固定 `PyYAML` 依赖，使用安全 Loader 解析 Frontmatter；自定义重复键检查，禁止
  任意 Python 对象构造标签。
- 支持 Codex 要求的 `name`、`description`，并接受开放规范的 `license`、`compatibility`、
  `metadata`、实验性的 `allowed-tools` 以及 Codex 的可选扩展文件；Tsi 不认识的字段不报错、
  不注入 Catalog、也不改变权限。
- 生成包含名称、描述和 `SKILL.md` 相对位置的确定顺序 Skill Catalog，并以独立区块组合进
  现有系统提示词。
- 注册只读 `load_skill(name)` 工具，只允许读取启动时已发现的 `SKILL.md`，并返回该
  Skill 的可用支持文件清单。
- 注册只读 `read_skill_resource(name, path)` 工具，按需读取 Skill 包内的 UTF-8 文本资源。
- 注册需审批的 `run_skill_script(name, path, arguments)` 工具，只执行已发现 Skill 的
  `scripts/` 目录内受支持脚本。
- 让模型基于名称和描述自动判断是否加载 Skill，不增加 `/skill` 命令或 Skill 管理页面。
- TUI 启动状态只显示 Skill 可用数量或安全错误，不展示完整正文。
- Skill 加载继续进入现有工具调用日志；完整正文会随工具结果进入后续模型请求日志。
- 不在生产目录内置示例 Skill；用测试夹具和 README 结构说明验证格式与边界。
- 同步 README、架构 Knowledge、AGENTS 索引和项目规则中的 Skill 使用说明。

### 非目标

- HTTP `/chat` 自动发现或加载宿主 Skill。
- 用户级、全局级、父目录级或远程 Skill 目录。
- Skill 自动匹配算法、Embedding、向量检索、数据库或缓存。
- 动态 import、Python Entry Point、MCP、任意 Shell 或 Skill 自带免审批执行权限。
- Skill 之间的依赖解析、递归 include 或支持文件自动加载。
- 执行 `.py`、`.sh` 之外的脚本、脚本声明外部依赖的自动安装、交互式程序、后台进程或
  多脚本并行执行。
- 解析或执行 Claude Code 的动态上下文、`$ARGUMENTS`、子 Agent、Hooks 和 Slash Command。
- 执行 Codex 的 `agents/openai.yaml` 展示、依赖及调用策略；该文件可以作为资源保留，
  但第一版不改变 Tsi TUI 展示、工具依赖或隐式调用策略。
- 把 `allowed-tools` 当作 Tsi 权限授权；该实验字段在不同宿主中的含义不稳定。
- 将图片、音视频、压缩包等二进制资源直接发送给当前纯文本 Provider 契约。
- 运行中监视文件变化、刷新 Catalog 或恢复旧版本。
- TUI 内安装、启用、禁用、创建或编辑 Skill 的管理界面。

## 5. 项目结构与代码风格

```text
.agents/skills/               # Codex 项目 Skill 目录，也是 Tsi 推荐目录
└── example-skill/
    ├── SKILL.md              # 开放 Agent Skills 入口
    ├── scripts/              # 可选：脚本
    │   └── example.py
    ├── references/           # 可选：按需读取的参考资料
    │   └── api.md
    └── assets/               # 可选：模板、数据或其他资源
        └── template.md
app/runtime/skills.py         # 发现、校验、Catalog 和只读快照
app/runtime/system_prompt.py  # 组合 AGENTS.md 与 Skill Catalog
tools/skills.py               # Skill 正文、支持文件和审批脚本工具
app/tui/__main__.py           # 启动时装配 Skill Catalog 与工具
tests/                        # 加载、工具、Runtime 和 TUI 回归测试
requirements.txt              # 固定 PyYAML 版本
```

新代码使用明确类型和必要中文注释。注释重点解释快照语义、路径边界、上下文隔离和为什么
Skill 不能扩大权限，不逐行复述实现。

`SKILL.md` 使用开放规范格式：

```markdown
---
name: example-skill
description: 当需要演示 Agent Skills 通用格式和渐进式加载时使用
license: MIT
compatibility: 可在 Tsi、Codex 或 Claude Code 中作为纯指令 Skill 使用
metadata:
  author: tsi
  version: "1.0"
---

# 示例 Skill

## 使用时机

- 用户明确要求演示 Skill。

## 操作步骤

1. 先读取相关项目文件。
2. 按项目规则完成任务并验证。
```

## 6. 功能契约

### 6.1 格式兼容与发现

- `.agents/skills/` 不存在或为空时视为没有项目 Skill，不是错误。
- 只接受 `.agents/skills/<skill-directory>/SKILL.md`；Skill 目录和入口文件必须是非符号链接
  普通目录/文件。出于 Tsi 现有 Workspace 安全边界，Tsi 不跟随符号链接，即使 Codex
  本身允许符号链接。
- Skill 可以包含开放规范的 `scripts/`、`references/`、`assets/` 和其他支持文件；支持
  子目录，但目录、文件和路径上的任一节点都不能是符号链接。
- `name` 必须符合开放规范：1–64 个字符，只含小写字母、数字和连字符，不能以连字符开头
  或结尾。为保证 Codex、Claude Code 和 Tsi 一致，`name` 必须与目录名完全一致。
- `description` 必须为非空字符串，最长 1024 个字符，说明 Skill 做什么以及何时使用。
- Frontmatter 使用安全 YAML 解析；非 Mapping、重复键、非字符串核心字段或 YAML 类型标签
  均视为非法。开放字段可读取但不赋予运行权限，未知宿主字段保留兼容并忽略语义。
- 每个 `SKILL.md` 最大 32 KiB；最多发现 64 个 Skill；Catalog 最大 32 KiB。
- 每个 Skill 最多发现 64 个支持文件，相对路径最长 256 个字符；单文件最大 64 KiB，
  Skill 支持文件总快照最大 1 MiB。二进制文件进入资源清单但第一版不能读取正文。
- `.agents/skills/` 中出现重复 `name` 时整批 Skill 加载失败，不静默覆盖或合并。
- Catalog 按 Skill 名字典序排列，保证同一工作区生成稳定提示词。

### 6.2 渐进式披露

- 启动时保留每个合法 Skill 的名称、描述、正文和支持文件快照。
- 系统提示词仅包含 Catalog（名称、描述、相对位置）和使用规则，不包含 Skill 正文。
- `load_skill` 只接受精确的 Skill 名称，返回完整 `SKILL.md` 和排序后的支持文件相对路径；
  不在同一结果中展开资源正文。
- `read_skill_resource` 只接受精确 Skill 名称及资源清单中的相对路径，返回对应 UTF-8
  文本启动快照；拒绝绝对路径、`..`、未知资源和二进制正文。
- 同一次对话可以多次加载同一 Skill；第一版不增加跨请求缓存或“已加载”状态。

### 6.3 脚本执行

- `run_skill_script` 参数固定为 Skill 名称、`scripts/` 相对路径和字符串参数数组；拒绝命令
  字符串、Shell 拼接、绝对路径、`..`、环境变量覆盖、stdin 和重定向语法。
- 第一版只支持 UTF-8 文本 `.py` 与 `.sh`：`.py` 使用当前进程的 `sys.executable`，`.sh`
  使用固定 `/bin/sh`。脚本不需要可执行位，不根据 shebang 选择其他解释器。
- 执行对象必须来自启动时资源快照且磁盘内容哈希仍一致；脚本被修改、替换或删除时返回
  Workspace 冲突，不执行旧快照或新内容。
- 每次调用都生成独立审批请求，展示 Skill 名称、脚本相对路径、解释器和逐项转义后的参数；
  默认拒绝。`allowed-tools`、同脚本重复调用或同一轮已批准操作都不能复用审批。
- 使用 `asyncio.create_subprocess_exec` 直接传递 argv，不使用 `shell=True`；工作目录固定为
  Skill 根目录。
- 子进程环境使用固定白名单，只保留运行所需的 `PATH`、语言区域和临时目录等非敏感变量；
  明确移除模型 API Key、`.env` 内容和其他父进程环境变量。环境清理不能阻止脚本主动读取
  工作区中的 `.env` 或访问网络，因此审批界面必须明确提示脚本拥有宿主进程级权限。
- 默认超时 30 秒；stdout 与 stderr 合计最多 32 KiB，超限或超时终止整个进程组。结果使用
  固定 JSON 信封返回退出码、stdout、stderr 和有限错误分类。
- 脚本串行执行，取消沿调用栈传播并终止进程组；不遗留后台任务。
- 第一版没有可靠的跨平台 OS 沙箱，审批是执行前的主要安全边界；后续增加文件系统或网络
  沙箱必须另建 Spec。

### 6.4 提示词组合

- 有 `AGENTS.md` 和 Skill 时，Provider 仍只收到一条首位 system 消息，内容顺序固定为
  `AGENTS.md` 正文、Skill Catalog。
- 只有 Skill 时仍生成一条 system 消息；两者都没有时保持当前无 system 消息行为。
- Skill Catalog 和正文不写入 `data/chat-session.json`，不显示在 transcript。

### 6.5 失败行为

- 单个 Skill 非法时不静默跳过，禁用整批项目 Skill，避免模型看到不完整或冲突的 Catalog。
- 错误信息只报告稳定分类，不回显 Skill 正文、绝对路径或底层异常。
- Skill 或支持文件加载失败不能影响 `AGENTS.md`、会话恢复和现有 Workspace 工具装配。
- 启动快照创建后即使磁盘文件变化，当前进程仍使用原快照，避免 Catalog 与正文不一致。

## 7. 测试策略

- 发现：目录缺失、空目录、单个/多个中文正文 Skill、排序和数量上限。
- 格式：缺少 Frontmatter、YAML 语法/标签、重复键、开放可选字段、未知宿主字段、名称与
  目录不一致、非法名称和超长描述。
- 文件：恰好达到大小上限、超限、非 UTF-8、符号链接、目录冒充文件、读取失败。
- 资源：`scripts/`、`references/`、`assets/`、其他目录、嵌套路径、二进制清单、稳定排序、
  数量/总量上限、路径穿越和符号链接拒绝。
- Catalog：只包含名称和描述，不泄露正文；组合后仍只有一条首位 system 消息。
- 工具：合法名称返回完整正文与资源清单；合法文本资源返回正文；未知名称、二进制资源、非法路径、
  额外参数和异常均返回稳定安全结果。
- 脚本：Python/Shell 正常退出、非零退出、参数原样传递、审批拒绝、内容并发变化、环境清理、
  超时、输出超限、取消及进程组回收。
- 安全：命令注入字符只作为单个 argv 传递；绝对路径、`..`、非 `scripts/`、未知后缀、
  `allowed-tools` 免审批和环境变量覆盖均被拒绝。
- 快照：启动后修改或删除磁盘文件，不改变当前进程 `load_skill` 的结果。
- 隔离：HTTP 默认 Registry 不包含 `load_skill`；TUI Registry 包含它且保留全部现有工具。
- 回归：多轮会话、流式输出、工具循环、审批、日志和 `/clear` 行为不变。
- 测试全部使用 `tmp_path` 和假 Provider，不调用真实模型或外部网络。

## 8. 边界

Always：

- 把 Skill 视为不可信文本，在进入提示词或工具结果前完成类型、编码、路径和大小校验。
- 以 Codex 官方 Skill 文档作为行为基线，以开放 Agent Skills 规范作为包格式基线；
  宿主专属字段只做兼容接收，不自行解释。
- 使用启动时不可变快照，保证 Catalog 与 `load_skill` 正文一致。
- Skill 读取工具保持只读；脚本工具视为高风险副作用工具，每次执行均需独立审批；所有 Skill
  工具只由 TUI 入口显式注册。
- 保持 HTTP `/chat`、Session schema 和 Provider 协议不变；审批契约以向后兼容方式增加
  “脚本执行”类型，不改变现有文件 Diff 审批的语义和默认拒绝行为。

Ask first：

- 支持用户级/全局目录、父目录分层、热加载、远程安装或 Skill 管理 UI。
- 支持额外脚本语言、依赖自动安装、免审批执行、交互/后台进程或注册新工具。
- 增加 OS/容器沙箱、文件系统隔离或网络隔离。
- 修改现有工具权限、Workspace Policy 或日志明文策略。

Never：

- 因 Skill 文本中的指令绕过 Tool Registry、写入审批或 Workspace 路径边界。
- 动态 import Skill 目录中的 Python，或绕过 `run_skill_script` 执行脚本和命令。
- 通过 `allowed-tools` 或 Codex/Claude 扩展字段扩大 Tsi 当前工具白名单。
- 使用 `shell=True`、拼接命令字符串、继承完整父进程环境或自动安装脚本依赖。
- 把 Skill 正文持久化进对话历史，或自动当作用户消息发送。
- 静默截断超限内容、忽略非法 Skill 或泄露绝对路径和文件正文。

## 9. 验收标准

1. 将符合 Codex 约定的 Skill 放入 `.agents/skills/` 后，Tsi 与 Codex 可以直接发现并
   共用同一份文件；该包无需修改 `SKILL.md` 即可复制到 Claude Code 的 Skill 目录使用。
2. 模型首条 system 消息只包含稳定 Catalog，不包含任一 Skill 正文或支持文件正文。
3. 模型调用 `load_skill(name)` 后能获得完整 `SKILL.md` 和资源清单；调用
   `read_skill_resource(name, path)` 能读取对应 UTF-8 文本资源快照。
4. `scripts/`、`references/`、`assets/` 及未知扩展字段不会导致一个合法通用 Skill 被拒绝；
   不支持的宿主专属行为不会被误执行。
5. 经用户批准后，模型可以执行 Skill 内 `.py` 或 `.sh`，并收到有界 stdout、stderr 和
   退出码；拒绝、超时、取消、内容变化或异常时不会遗留运行进程。
6. 任意脚本执行都不能绕过独立审批，命令参数不能形成 Shell 注入，父进程敏感环境不传入
   子进程；文档明确第一版不具备文件系统和网络沙箱。
7. Skill 不能注册额外工具、扩大权限或绕过写入 Diff 审批；HTTP 默认工具集合保持不变。
8. 无 Skill 的项目行为与当前版本一致；非法 Skill 产生稳定可见错误且不影响其他 TUI 能力。
9. Skill Catalog、正文和系统提示词不进入 Session；日志风险在文档中明确说明。
10. 全量测试、语法检查、依赖检查和差异检查通过。

## 10. 已确认决策

1. 以 Codex 为第一兼容目标，项目 Skill 目录使用 `.agents/skills/`。
2. 增加 `PyYAML` 依赖并在 `requirements.txt` 固定版本，使用安全 Loader 解析标准 YAML
   Frontmatter，不实现私有 YAML 子集。
3. 第一版支持执行 Skill 脚本；使用专用工具、固定解释器、argv 数组、有界输出、超时和
   每次独立 TUI 审批，不开放任意 Shell。
4. 任一 Skill 非法时整批禁用项目 Skill，但不阻断 `AGENTS.md`、现有 Workspace 工具和
   普通 TUI 对话。
5. 第一版不在仓库中内置业务 Skill；发现、读取和脚本执行的端到端样例放在测试夹具中。
