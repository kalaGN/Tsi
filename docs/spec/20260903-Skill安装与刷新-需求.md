# Skill 安装与刷新需求

状态：已完成（2026-09-04）
创建日期：2026-09-03
前置需求：[Skill 系统需求](20260902-Skill系统-需求.md)

## 1. 目标

为 Tsi 助手本地 TUI 增加受控 `install_skill` 工具，让模型在用户逐次审批后，可以把公开
GitHub URL 或本机 `~/.codex/skills` 中的 Codex Skill 安装到当前启动项目的
`.agents/skills/`。安装成功后无需重启 TUI，从下一次用户请求开始使用新的 Skill Catalog、
正文、资源和脚本。

该能力面向在本地 TUI 中维护当前项目的开发者。成功标准是：安装来源和目标明确可见，下载或
外部目录读取发生前必须审批，非法包不会污染项目目录，安装完成后下一轮可以发现并使用 Skill，
同时保持 HTTP `/chat`、已有 Skill 执行审批和 Session 持久化契约不变。

## 2. 已确认决策

已确认：

1. 第一版安装源支持 GitHub URL。
2. 第一版安装源支持本机 `~/.codex/skills`。
3. 热加载只由 `install_skill` 成功触发，不持续监控 `.agents/skills/` 的手动文件变化。

1. `install_skill` 只注册到本地 TUI；HTTP `/chat` 不安装、下载、读取个人 Skill 或热刷新。
2. GitHub 第一版只支持公开仓库的 `https://github.com/...` URL，不读取 GitHub Token、SSH
   Agent、Credential Helper 或私有仓库凭据。
3. GitHub URL 必须精确定位一个包含 `SKILL.md` 的目录；不根据仓库内容猜测 Skill 路径，
   不支持网页搜索、市场检索或任意下载 URL。
4. 本机来源只接受 `~/.codex/skills` 直属 Skill 目录名，不接受任意绝对路径、`..`、用户输入的
   `~` 展开或其他用户目录。
5. 目标固定为 TUI 启动目录 `.agents/skills/<skill-name>`。目标已存在时拒绝，不覆盖、不合并、
   不自动升级，也不增加卸载工具。
6. 安装前在隔离临时目录完整获取候选包，并复用现有 Skill YAML、编码、文件类型、符号链接、
   数量和大小边界验证。只有整包合法时才原子移动到目标目录。
7. GitHub 下载、本机 Codex 目录读取和目标写入都属于高风险副作用；每次调用先展示来源、目标、
   是否访问网络及固定风险警告，默认拒绝，批准不能复用。
8. 安装成功不会改变正在执行的 Provider Turn。当前请求返回安装结果后结束；下一次用户请求使用
   新 Catalog 和新 Registry 快照，避免同一请求内系统提示词、工具定义和内容版本不一致。
9. 手动增删改 `.agents/skills/`、修改 `~/.codex/skills` 或 GitHub 远端内容不会触发刷新；需要
   再次安装或重启 TUI。

## 3. 范围

### 本期范围

- 增加 TUI 专属 `install_skill` 工具及明确的安装来源类型。
- 支持从公开 GitHub HTTPS URL 获取单个 Skill 目录。
- 支持从当前用户 `~/.codex/skills/<source-directory>` 复制单个 Skill。
- 在任何外部读取、网络请求或项目写入前展示安装审批 Modal。
- 在临时目录中执行完整候选包验证，拒绝非法 YAML、名称不一致、符号链接、特殊文件、超限文件、
  超限资源及目录穿越。
- 使用临时目录和同一文件系统内原子重命名提交安装；失败时不留下半成品目标。
- 安装成功后更新进程内 Skill 状态，使下一次用户请求使用新的 Catalog 和工具快照。
- TUI 状态栏更新 Skill 数量；安全错误只显示稳定分类，不泄露绝对路径、凭据或底层异常。
- 继续记录现有工具调用、参数和结果日志，并在文档中明确 GitHub URL、个人 Skill 名称及安装结果
  会明文落盘。
- 更新 README、AGENTS、项目 Rules、架构 Knowledge、故障排查和本变更 Spec/Plan/Tasks。

### 非目标

- HTTP `/chat` 安装或刷新 Skill。
- 私有 GitHub 仓库、GitHub Enterprise、GitLab、Gitee、压缩包 URL 或任意 HTTP 地址。
- GitHub 搜索、Skill 市场浏览、版本推荐、依赖解析或可信度评分。
- 覆盖、升级、降级、合并、卸载、启用、禁用或回滚已安装 Skill。
- 监控本地或远端文件变化、定时更新、后台轮询或自动同步。
- 从任意本地路径、父目录、`.claude/skills` 或其他用户目录安装。
- 自动安装 Skill 声明的 Python、Node、系统或其他第三方依赖。
- 在当前 Provider Turn 中立即注入新 system prompt 或执行刚安装的脚本。
- 为 Skill 脚本增加文件系统或网络沙箱；现有逐次脚本审批规则保持不变。

## 4. 工具契约

模型工具名固定为 `install_skill`，参数使用显式来源类型，禁止把 URL 和路径解释混在一个自由文本
字段中：

```json
{
  "source_type": "github | codex_home",
  "source": "GitHub URL 或 ~/.codex/skills 下的直属目录名",
  "expected_name": "目标 Skill 的 metadata name"
}
```

规则：

- `source_type=github` 时，`source` 必须是允许的 GitHub HTTPS Skill 目录 URL。
- `source_type=codex_home` 时，`source` 必须是单个直属目录名，不允许斜杠、绝对路径和 `..`。
- `expected_name` 必须符合现有 Skill 名称规则，并与候选 `SKILL.md` 的 `name` 完全一致；目标目录
  使用该名称，避免来源目录名与 metadata 名称不同导致静默改名。
- 不接受额外字段、环境变量、Header、Token、Git 参数、目标路径、覆盖开关或安装后命令。
- 每次调用都生成独立安装审批；没有审批回调、用户拒绝或审批内容失配时不访问来源、不写项目。
- 成功结果只返回安装名称、项目相对目标、来源类型、刷新状态和下一轮生效提示。
- 参数错误、目标冲突、来源不可用、下载超时、包非法和提交冲突使用固定安全错误码与消息。

## 5. 热刷新契约

- TUI 启动时创建持有当前不可变 `SkillCatalog` 的进程内 Skill Runtime。
- 一次用户请求开始时固定读取 Catalog、系统提示词和 Registry 版本；请求执行期间不替换。
- `install_skill` 成功后构建包含全部项目 Skill 的新 Catalog；只有全量加载成功才原子替换 Runtime
  当前版本。
- 当前请求的 Provider Turn 和 system 消息保持原版本；工具结果明确提示“下一次请求生效”。
- 下一次用户发送消息时，Chat Session 使用新 Catalog prompt 和对应 Registry。
- 刷新失败时回滚刚安装目录并保留旧 Runtime，不能出现磁盘已安装但运行时 Catalog 部分更新。
- 不启动 watchdog、轮询 Timer、后台线程或文件系统事件监听器。

## 6. 安装流程

```text
模型提出 install_skill
  -> Registry 校验有界参数
  -> TUI 展示来源、目标、网络/外部读取和写入风险
  -> 用户明确批准
  -> 创建项目内临时安装目录
  -> GitHub 获取或 ~/.codex/skills 安全复制候选包
  -> 复用现有完整 Skill 校验生成候选快照
  -> 校验 expected_name 且目标仍不存在
  -> 原子重命名到 .agents/skills/<name>
  -> 全量重建项目 Catalog
  -> 成功：发布新 Runtime 版本，下一次请求生效
  -> 失败：删除临时内容/回滚目标，保留旧 Runtime
```

GitHub 获取必须使用参数数组和固定可执行程序或受限标准库 HTTP，不使用 `shell=True`，不继承模型
API Key。连接、总耗时、下载体积、文件数量和输出均设置显式上限。网络重定向不能离开允许的
GitHub 官方下载域名集合。

本机复制必须逐个使用无跟随文件操作，不调用 `cp -R` 跟随未知链接。来源根固定为进程启动时
解析的当前用户 Codex Skill 目录；审批和日志只展示 `~/.codex/skills/<directory>`，不展示真实
Home 绝对路径。

## 7. 项目结构与依赖方向

预计结构：

```text
tools/skills.py                 # 既有 Catalog、读取和脚本能力
tools/skill_installation.py     # 来源解析、审批预览、临时获取、验证和原子安装
app/runtime/skill_runtime.py    # 请求边界上的 Catalog/Registry 版本发布
app/runtime/system_prompt.py    # 基于当前版本组合 system prompt
app/tui/__main__.py             # 创建 Skill Runtime 并只向 TUI 注册安装工具
app/tui/application.py          # 下一请求读取新版本、状态栏和安装审批
app/tui/approval.py             # 安装来源与风险预览
tests/                          # 安装、回滚、刷新、隔离和 TUI 回归
```

依赖方向保持：

```text
TUI -> runtime skill state -> root tools
HTTP -> default registry
root tools -X-> TUI / Provider / Router
```

安装 Tool 不直接操作 Textual；它通过既有审批契约获取决定，并通过窄接口发布验证后的 Catalog。
HTTP Runtime 不导入安装模块，不读取 Home 或项目 Skill 目录。

## 8. 代码风格

- Python 3.11，使用明确 dataclass、Enum、Protocol 和类型标注表达来源、候选包和发布结果。
- 路径、URL、网络和文件复制分别使用短小验证函数，不把整个安装流程堆在一个方法。
- 必要中文注释解释审批前无副作用、无跟随复制、原子提交和请求级版本快照，不逐行复述代码。
- 对外异常只使用固定分类；底层 Git、HTTP、文件系统、YAML 和绝对路径异常不得进入 ToolResult。

示例风格：

```python
candidate = await source.fetch_into(staging_directory)
snapshot = validate_skill_candidate(candidate, expected_name)
installed = commit_candidate(snapshot, destination)
runtime.publish(reload_project_catalog())
```

每一步先完成验证再改变下一层状态；发布失败必须撤销 `installed` 并保留旧 Runtime。

## 10. 安全、可靠性与性能边界

必须：

- 审批发生在任何 GitHub 网络访问、Home 目录读取或项目写入之前。
- 只安装通过现有完整 Skill 校验的有限普通文件，不跟随任何符号链接。
- 网络请求和子进程使用最小环境，不读取或记录 API Key、GitHub Token、SSH Key 和凭据配置。
- 目标提交与 Runtime 发布形成可恢复流程，任一步失败都不能留下半安装或部分热刷新状态。
- 日志继续使用固定字段，并明确记录的 URL、目录名和 ToolResult 是明文数据。
- 每次安装串行执行；同时到达的同名安装只有一个成功，其余返回稳定冲突。

需先确认：

- 支持私有仓库、GitHub Enterprise、认证 Header、SSH URL 或 Credential Helper。
- 增加覆盖、升级、卸载、回滚、自动同步或文件监控。
- 引入新的网络、Git、归档、watchdog 或沙箱依赖。
- 修改 HTTP、Session 文件格式、Provider 协议或现有脚本审批语义。

禁止：

- 把模型提供的 URL 交给 Shell，执行仓库 Hook、安装脚本、依赖安装或候选包内代码。
- 写入 `.agents/skills/` 之外的目标，或使用候选包名称决定未经验证的路径。
- 安装失败后静默保留文件，刷新失败后使用磁盘与内存不一致的 Catalog。
- 把安装批准当作后续 `run_skill_script` 的执行批准。

性能边界：安装不属于请求热路径，但必须有界。第一版不定义吞吐指标；目标是单次安装不阻塞 TUI
事件循环，网络和文件操作在异步边界执行，Catalog 重建保持现有 64 个 Skill、每 Skill 1 MiB
资源快照上限。

## 11. 验收标准

1. TUI 模型工具列表始终包含 `install_skill`；HTTP 默认 Registry 仍只包含
   `get_current_time`。
2. 经一次明确审批后，可以从假 GitHub Skill URL 安装合法包到
   `.agents/skills/<expected_name>`；未审批时无网络和磁盘副作用。
3. 经一次明确审批后，可以从假 `~/.codex/skills/<directory>` 安装合法包；不能读取其他本地
   路径或跟随符号链接。
4. 目标已存在、名称不匹配、非法 URL、包校验失败、超时、超限或并发冲突均返回稳定安全错误，
   项目目录不留半成品。
5. 安装成功后的当前请求保持旧 system prompt；下一次用户请求看到新 Catalog 并能调用
   `load_skill`，无需重启 TUI。
6. 手动修改 Skill 目录不会自动刷新；重启或下一次成功安装才重新构建 Catalog。
7. 安装刷新失败会删除本次目标、清理临时文件并继续使用旧 Catalog。
8. 安装审批与脚本审批完全独立；安装成功不会免除任何脚本执行审批。
9. Session 仍只保存 user/assistant 最终轮次，不持久化 Catalog、安装轨迹或工具消息。
10. README、AGENTS、Rules、架构 Knowledge 和故障排查与代码一致，明确公开 GitHub、无监控、
    明文日志和无脚本沙箱边界。
11. 语法检查、全量测试、依赖检查和差异检查全部通过。

## 12. 已确认边界

1. 第一版仅支持公开 `github.com` HTTPS Skill 目录，不支持任何私有仓库凭据。
2. 目标同名时直接拒绝，后续另行设计升级和覆盖。
3. 安装完成后从下一次用户请求生效，不在当前模型工具循环中立即使用。
