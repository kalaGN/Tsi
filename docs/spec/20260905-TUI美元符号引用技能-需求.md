# TUI 美元符号引用技能需求

状态：已完成（2026-09-05）
创建日期：2026-09-05

## 1. 背景与目标

TUI 已能通过 `/skills` 查看当前 Catalog，也允许模型自行调用 `load_skill`，但用户无法在输入时明确选择本轮必须使用的 Skill。本需求增加与 Codex 习惯一致的 `$技能名` 引用：输入 `$` 可查看候选，补全后发送，本轮在调用模型前加载所选 Skill 的完整 `SKILL.md`。

成功标准是用户能够只使用键盘发现、选择并显式引用当前运行时已发布的 Skill，同时保持现有会话原文、工具权限和 HTTP 行为不变。

## 2. 交互与输入契约

- `$` 仅在输入开头或空白字符之后开始技能引用，避免把金额、环境变量和普通正文中的 `$` 误判为技能。
- 候选来自 `SkillRuntime` 当前已发布的内存 Catalog，按名称稳定排序，不重新扫描磁盘。
- `$` 后输入字符时按 Skill 名称前缀过滤；候选展示名称和简短描述。
- Up/Down 循环选择，Tab 或 Enter 只完成当前候选；再次按 Enter 才发送整段输入。
- 补全时只替换光标所在的 `$前缀`，写入 `$完整技能名` 和一个空格，保留输入框其他内容与光标之后的文本。
- Esc 优先关闭技能候选；候选关闭后再次按 Esc 才沿用现有输入清理和双击退出行为。
- 一条输入允许引用多个不同 Skill；重复引用按首次出现顺序去重。
- 完整且存在的 `$技能名` 才属于显式引用。未知名称继续作为普通用户文本发送，不阻断请求。

## 3. 执行语义

- 发送前从同一次 `SkillRuntime` 执行快照解析引用，避免候选展示与请求执行读取不同 Catalog 版本。
- 每个显式引用加载对应 `SKILL.md` 完整正文和资源路径索引，不自动加载资源正文，不自动执行脚本。
- 显式 Skill 内容只对当前请求生效，不写入 `data/chat-session.json`；持久化和恢复的用户消息仍保留用户输入的 `$技能名` 原文。
- 已引用 Skill 仍不能注册工具、扩大 Workspace、跳过写入或脚本审批，也不能改变系统安全边界。
- 单轮最多加载 3 个显式 Skill；超过上限时在 TUI 显示稳定错误且不调用模型，防止上下文无界增长。
- Skill 安装成功仍只影响下一次请求；正在执行的请求使用开始时固定的 Catalog、Registry 和系统提示词。

## 4. 技术栈与项目结构

- Python 3.11、Textual、现有 `SkillRuntime`、`ChatSession` 和 `SkillCatalog`，不增加第三方依赖。
- `app/tui/skill_palette.py`：技能候选定位、过滤、选择、补全和展示。
- `app/tui/application.py`：协调候选按键优先级、输入框替换和请求启动。
- `app/runtime/skill_runtime.py`：基于本轮输入和固定 Catalog 生成显式 Skill 执行快照。
- `app/runtime/session.py`：把当前用户原文传给执行快照提供者，仍只持久化原始 user/assistant 消息。
- 测试分别位于 `tests/test_tui.py`、`tests/test_skill_runtime.py` 和 `tests/test_chat_session.py`。

## 5. 实现与代码风格

- 候选解析使用纯函数或小型状态组件，不在 `ChatTuiApp` 中复制 Skill 目录规则。
- Skill 名称沿用 Catalog 已验证的 `[a-z0-9]+(?:-[a-z0-9]+)*`，不新增另一套宽松校验。
- UI 组件只接收 `AvailableSkill` 摘要，不直接读取 `SKILL.md` 或文件系统。
- 对不明显的光标边界、快照一致性和权限隔离增加中文注释。

示意接口：

```python
snapshot = skill_runtime.snapshot_for_input(input_text)
references = resolve_skill_references(input_text, catalog)
```

## 6. 测试策略

- 单元测试：引用边界、前缀过滤、重复去重、未知名称、多引用和 3 个上限。
- 组件测试：候选出现/关闭、Up/Down、Tab/Enter 补全、光标中间替换和中文输入共存。
- 集成测试：显式 Skill 正文仅进入当前请求快照，安装刷新后下一请求可引用，Session 仅保存用户原文。
- 回归测试：命令候选、输入历史、Esc、流式输出、工具审批及 `/skills` 行为不变。

## 7. 边界

### 必须做到

- 使用请求开始时的 Skill 快照，保持候选元数据与实际加载内容一致。
- 只加载明确存在的完整名称，限制单轮引用数量。
- 保留原始用户消息和现有逐次审批边界。

### 实施前确认

- 修改本文定义的触发边界、补全按键、最大引用数量或未知名称行为。
- 改变 Session schema、Skill 安装规则或引入新依赖。

### 禁止

- 因 `$技能名` 自动执行脚本、批准工具或授予额外权限。
- 从磁盘临时重载候选，或让 Skill 内容覆盖宿主安全规则。
- 修改 HTTP `/chat` 请求、响应或工具集合。

## 8. 验收标准

1. 输入框在引用边界键入 `$` 后展示当前可用 Skill，输入前缀可过滤。
2. Up/Down、Tab、Enter 和 Esc 与现有命令候选、输入历史和退出手势无冲突。
3. 补全只替换当前引用片段，支持一条输入引用最多 3 个不同 Skill。
4. 请求使用固定 Catalog 加载所选完整 `SKILL.md`，不加载资源正文、不自动执行脚本。
5. Session 和日志中的用户输入保持原文，显式 Skill 正文不进入会话文件。
6. 未知 `$名称` 作为普通文本；超出引用上限时不调用模型并显示安全错误。
7. `/chat`、普通 TUI 请求、`/skills`、安装热刷新和审批流程回归通过。

## 9. 已确认决策

- 引用只在输入开头或空白后触发。
- 未知技能按普通文本发送。
- 单轮最多显式引用 3 个不同 Skill。
