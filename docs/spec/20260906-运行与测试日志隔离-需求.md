# 运行与测试日志隔离需求

状态：已完成（2026-09-06）
创建日期：2026-09-06

## 1. 背景

当前模型事件默认写入 `logs/model-calls.log`。FastAPI 应用在模块导入时初始化该文件 Handler，测试导入应用或使用默认日志配置时也可能写入同一文件，导致真实使用记录与自动化测试记录混合，排障时无法可靠区分来源。

## 2. 目标

在不改变现有日志事件、正文格式、脱敏策略和 stderr 行为的前提下，将默认文件日志按用途固定隔离：

```text
logs/
├── runtime/model-calls.log  # HTTP 与 TUI 的真实使用日志
└── tests/model-calls.log    # Pytest 测试日志
```

运维或开发者应仅凭路径即可判断日志来源；运行完整测试不得创建或追加真实使用日志。

## 3. 当前假设

1. “真实使用日志”包括正常启动的 FastAPI HTTP 服务和 TUI，两者继续共享一个 `runtime` 文件。
2. “测试日志”指通过项目约定 Pytest 命令执行时产生的模型日志；显式传入临时 `log_path` 的单元测试继续使用该临时路径。
3. 现有 `logs/model-calls.log` 作为历史文件保留，不自动移动、合并或删除；新版本只向新目录写入。
4. 测试与运行日志使用相同的中文分块格式、10 MiB 轮转阈值和 5 个备份。

## 4. 范围

- 为模型日志定义固定的运行目录和测试目录。
- 提供仅接受有限用途值的默认日志路径选择机制，禁止把任意环境变量解释为文件路径。
- 在 Pytest 初始化阶段显式选择测试日志用途，确保选择发生在应用模块导入之前。
- 覆盖默认路径、显式路径优先级、HTTP/TUI 入口和测试隔离的自动化测试。
- 更新 README、架构知识和故障排查文档中的日志路径说明。

## 5. 非目标

- 不改变事件字段、请求 ID、日志级别或日志正文内容。
- 不拆分 HTTP 与 TUI 日志，不按 Provider 或会话继续分文件。
- 不引入远程日志、指标、Trace、日志清理任务或新增依赖。
- 不迁移或删除历史 `logs/model-calls.log*` 文件。
- 不允许测试调用真实付费模型服务。

## 6. 可观测性问题

本功能需要直接回答以下问题：

1. 当前文件中的事件来自真实运行还是自动化测试？通过父目录判断。
2. 执行测试是否污染真实运行日志？比较测试前后 `logs/runtime/` 文件状态并由自动化测试验证默认目标。
3. 显式诊断日志是否仍可写入调用方指定的临时位置？保留并回归 `log_path` 覆盖能力。

## 7. 安全与边界

- `Authorization` 继续只记录固定脱敏值，不因目录拆分扩大日志内容。
- 用途选择只允许 `runtime` 和 `tests`，不得接受绝对路径、`..` 或用户输入路径。
- `logs/` 继续整体由 Git 忽略，Workspace 工具继续禁止读取和修改。
- TUI 继续只写文件而不写 stderr；HTTP 继续使用 stderr JSON 与本地文件双写。

## 8. 验收标准

1. 默认启动 HTTP 或 TUI 时，文件日志目标为 `logs/runtime/model-calls.log`。
2. 使用项目约定 Pytest 命令时，默认文件日志目标为 `logs/tests/model-calls.log`。
3. 测试初始化发生在应用导入前，测试套件不会创建或追加 `logs/runtime/model-calls.log`。
4. 调用 `configure_model_logging(log_path=...)` 时，显式路径优先于用途默认值。
5. 两类日志保持现有格式、脱敏、轮转和错误隔离行为。
6. 现有 `logs/model-calls.log` 不被代码自动修改。
7. 全量测试、语法检查、依赖检查和 `git diff --check` 通过。

## 9. 已确认决策

- 使用固定目录名 `runtime` 与 `tests`。
- 保留旧日志文件，不自动迁移。
