# TUI 安全 Git 写工具需求

状态：已完成（2026-09-08）

创建日期：2026-09-07

## 1. 目标

为 Tsi 助手的本地 TUI 增加受控 Git 交付能力，使模型能够在用户明确批准后暂存指定文件、创建中文提交并把当前分支推送到既有上游。

本功能用于补齐现有“读取、修改、检查”之后的本地交付闭环，不提供任意 Git 或 Shell 执行能力，不改变 HTTP `/chat`。

## 2. 已采用假设

1. 第一版只支持 `git_stage`、`git_commit`、`git_push`。
2. 三项工具仅装配到 TUI，并归入独立的 `git_write` 意图工具组。
3. 每次调用都属于有副作用的执行操作，必须先显示预览并获得本地用户批准。
4. Stage 只接受模型明确列出的 Workspace 相对路径，不接受 `.`、glob、pathspec 魔法或 `-A`。
5. Commit 只提交当前已暂存内容，信息必须符合 `type: 中文描述`。
6. Push 不接受远程地址、分支、force、Tag 或删除参数，只能把当前分支推送到已经配置的上游分支。
7. Git 子进程禁用仓库 hooks；不实现签名提交、凭据管理或自动设置上游。

## 3. 功能范围

### 3.1 `git_stage`

输入：

```json
{"paths":["tools/git.py","tests/test_git_tools.py"]}
```

约束：

- `paths` 为 1 至 20 个不重复的 Workspace 相对文件路径。
- 拒绝绝对路径、`..`、NUL、目录、符号链接、受保护路径、Git pathspec 魔法和以 `-` 开头的值。
- 允许已跟踪文件和普通未跟踪文件；第一版不支持通过 Stage 删除文件。
- 宿主使用临时 Git Index 计算“批准后将形成的完整 staged diff”，预览阶段不得改变真实 Index。
- 用户批准后重新计算预览指纹；工作区或 Index 已变化时返回冲突，不静默覆盖。
- 成功结果返回已暂存相对路径和有界摘要，不返回绝对路径。

### 3.2 `git_commit`

输入：

```json
{"message":"feat: 增加安全Git写工具"}
```

约束：

- `message` 为单行 UTF-8 文本，长度 6 至 200 个字符。
- 格式固定为 `type: 中文描述`；`type` 仅允许 `feat`、`fix`、`refactor`、`docs`、`test`、`chore`、`perf`、`build`、`ci`、`revert`。
- 冒号后必须包含至少一个中文字符，不接受空白描述、换行或控制字符。
- 只提交调用时已暂存内容；没有 staged diff 时拒绝。
- 预览展示当前分支、提交信息、文件列表和完整有界 staged diff。
- 批准后再次验证 HEAD、Index 和 staged diff 指纹；变化时返回冲突。
- Git hooks 和 GPG 签名关闭，避免仓库配置在提交过程中执行额外程序或阻塞 TUI。
- 成功结果只返回新提交短哈希、分支和提交信息。

### 3.3 `git_push`

输入：

```json
{}
```

约束：

- 当前必须是命名分支，且已配置形如 `<remote>/<branch>` 的上游。
- 不接受模型提供 remote、URL、refspec 或额外参数。
- 只允许非强制地把当前 `HEAD` 推送到精确的既有上游分支。
- 没有待推送提交、HEAD 已变化、上游配置变化或远端 URL 不安全时拒绝。
- 预览展示远程名称、安全脱敏后的目标、当前分支以及待推送提交的有界列表。
- 允许既有 HTTPS 或 SSH Git 远端；日志和工具结果不得包含凭据、Home 路径或 SSH 命令正文。
- Git hooks 关闭；用户批准后才允许网络访问。
- 成功结果返回远程名称、分支和已推送提交数量，不回传 Git/SSH 原始输出。

## 4. 工具组与执行流程

新增 `git_write` 组：

```text
git_write
├─ git_stage
├─ git_commit
└─ git_push
```

- TUI 每轮初始仍只披露 `activate_tool_groups`。
- 模型只有激活 `git_write` 后才能看到三项 Git 工具。
- 激活工具组不代表批准操作；每次 Stage、Commit、Push 都独立审批。
- 工具调用继续计入当前 Tool Loop 的模型步骤和总调用预算。
- 工具组与审批状态只存在于当前请求，不跨请求持久化。

## 5. 项目结构

```text
tools/git.py                    Git 状态快照、预览和三个专用工具
tools/contracts.py              如需要，扩展 Git 审批的中立契约
tools/workspace.py              将 Git 工具装配到 TUI Catalog
tools/groups.py                 增加固定 git_write 组名
app/tui/approval.py             展示 Git 预览和风险说明
tests/test_git_tools.py         临时仓库单元测试
tests/test_tool_groups.py       工具组可见性与审批回归
tests/test_tui.py               TUI 审批交互回归
```

不得在 Router、HTTP Application 或 Provider 适配器中实现 Git 逻辑。

## 6. 代码风格

- 使用 Python 3.11、标准库异步子进程、dataclass 和现有 Tool/Registry 契约。
- 所有 Git 命令使用固定 argv 和 `asyncio.create_subprocess_exec`，禁止 `shell=True`。
- 模型只能提供结构化业务参数，不能提供 Git flags、环境变量、cwd 或命令片段。
- 必要注释解释临时 Index、竞态校验、远端脱敏和 hooks 禁用边界。
- 工具错误只返回固定安全错误码，不回显 Git stderr、绝对路径或凭据。
- 不新增 GitPython、dulwich 或其他依赖。

## 7. 测试策略

测试只操作 Pytest 临时 Git 仓库，并为测试仓库设置本地身份；不得修改当前项目、访问真实远程或调用真实模型。

必须覆盖：

- Stage 已跟踪和未跟踪文件、多个路径、重复路径和非法路径。
- Stage 预览零副作用、拒绝零变化、批准后真实 Index 变化。
- Stage 删除、符号链接、受保护文件和 Index/工作区竞态拒绝。
- Commit 中文格式、无 staged 内容、预览、拒绝、竞态和成功结果。
- Commit 不执行测试仓库 hooks，不启用 GPG 签名。
- Push 使用本地 bare 远端验证成功、无上游、无待推送提交和竞态。
- Push 测试不使用互联网；force、Tag、删除和模型自定义目标从 Schema 上不可表达。
- `git_write` 未激活时三项工具返回 `unknown_tool`，激活后仍需要审批。
- HTTP 默认 Registry 和 `/chat` 测试保持不变。

验证命令：

```bash
.venv/bin/python -m compileall -q main.py app tools tests
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -m pytest -q
.venv/bin/python -m pip check
git diff --check
```

## 8. 安全边界

始终执行：

- 固定 Workspace cwd、固定 Git argv、关闭 hooks、限制输入和输出大小。
- 预览零副作用；批准后重新校验关键状态。
- 所有 Git 写操作均记录现有工具调用、结果和审批日志。
- Push 只在批准后产生网络访问。

必须先询问：

- 每次 Stage、Commit、Push。
- 未来增加分支创建、Tag、设置上游、PR 或远端选择能力。

绝不执行：

- 任意 Git 参数、任意 Shell、force push、删除远端 ref、改写历史。
- 自动暂存整个仓库、自动包含未指定文件、自动提交用户已有改动。
- 读取或修改 `.git/` 文件实现操作、写入凭据或记录认证信息。
- HTTP 自动执行 Git 写操作。

## 9. 验收标准

1. TUI 模型可按需激活独立 `git_write` 组，并看到且只能看到三项专用 Git 写工具。
2. 用户可以通过连续的明确审批完成“指定文件 Stage → 中文 Commit → 推送既有上游”。
3. 任一审批拒绝、状态竞态、非法参数或 Git 失败都不会执行后续隐式操作。
4. 模型无法表达 force、Tag、删除、任意远端、任意分支、任意 Git flag 或 Shell 命令。
5. Git hooks、GPG 签名和外部 diff 不会在工具流程中被启用。
6. HTTP `/chat` 的工具集合、响应和安全边界不变。
7. 全量测试、编译、依赖和 Diff 检查通过，且没有真实网络或模型调用。

## 10. 非目标

- `git restore`、`git reset`、`git clean`、merge、rebase、cherry-pick 或 stash。
- 创建、切换或删除分支。
- 创建或推送 Tag。
- 设置、修改或删除 remote/upstream。
- force push、`--force-with-lease` 或任何历史改写。
- 自动生成提交信息、自动批准、后台 Push、重试或凭据管理。
- GitHub/GitLab PR、Issue、Release 或 CI/CD 接入。

## 11. 已确认决策

- 第一版采用上述范围与安全限制。
- Push 只能使用当前分支已经存在的上游，不提供首次 `--set-upstream`。
