# TUI 意图工具组需求

状态：已完成（2026-09-07）

创建日期：2026-09-07

## 1. 背景

当前 TUI 每个模型步骤都会携带完整 Workspace、Skill 和安装工具定义。正式日志显示全部 34 次上游请求都发送了 13 个工具；其中一轮复杂请求执行 21 个模型步骤、24 次工具调用，累计输入 368,193 Token。对普通问答、只读分析和单一 Skill 请求而言，固定发送全部工具会增加 Token、干扰工具选择，并扩大高风险工具的暴露范围。

本需求为 TUI 增加请求级渐进式工具披露：模型先根据用户意图选择必要工具组，后续模型步骤只携带已经激活的工具。该机制优化工具上下文，不改变工具本身的参数、安全、审批和执行语义。

## 2. 目标

1. 普通问答不再携带全部 13 个业务工具定义。
2. 模型能根据自然语言意图激活时间、Workspace 只读、Workspace 修改、Skill 使用或 Skill 安装工具。
3. 一个请求可组合多个工具组，并在有限次数内追加能力。
4. 工具激活只影响当前用户请求，下一次发送重新从最小工具集开始。
5. 写文件、撤销、脚本执行和 Skill 安装继续逐次审批，激活工具组不能绕过安全边界。
6. HTTP `/chat`、现有模型 Provider、会话持久化和 `/model` 行为保持兼容。

## 3. 已知现状

当前依赖链为：

```text
TUI -> ChatSession -> run_chat_messages -> Provider Turn
                                 |-> ToolRegistry -> tools/
```

- `SkillRuntime.snapshot(input_text)` 在每次发送前创建包含全部可用工具的固定 Registry。
- `run_chat_messages` 在创建 Provider Turn 时一次传入 `registry.definitions`。
- Provider Turn 在工具续轮中重复使用同一组工具定义。
- `ToolRegistry` 是冻结白名单；副作用工具必须实现审批预览。
- HTTP 未注入 Workspace Registry，继续使用只含 `get_current_time` 的默认 Registry。

## 4. 功能范围

### 4.1 初始最小工具集

TUI 每次用户发送开始时，Provider 只收到 `activate_tool_groups` 元工具，以及请求边界已明确预激活的工具。

`activate_tool_groups`：

- 输入一个非空、去重、有界的工具组名称数组。
- 描述中明确每个组的用途，让模型根据用户意图选择。
- 只改变当前请求内存中的可见工具定义，不访问网络、不读取或修改项目文件。
- 自动执行，不弹出审批。
- 返回已激活组、当前可用工具名称和是否发生新增。
- 自身始终保留在可见工具中，允许模型在后续阶段申请补充工具组。

### 4.2 工具组

| 工具组 | 包含能力 | 典型意图 |
|---|---|---|
| `general` | `get_current_time` | 查询日期、时间和时区 |
| `workspace_read` | 文件列表、文本搜索、分段读取、Git 状态和 Diff | 理解、分析、审查、定位代码 |
| `workspace_write` | `workspace_read` 全部能力，以及应用编辑、项目检查、撤销 | 开发、修复、重构、修改文档 |
| `skills` | 加载 Skill、读取 Skill 资源、执行 Skill 脚本 | 使用 `$技能名` 或领域 Skill |
| `skill_install` | 安装 Skill | 从 GitHub 或 Codex Home 安装 Skill |

规则：

- `workspace_write` 自动包含 `workspace_read`，避免重复声明。
- `skills` 只在当前 Catalog 非空时可用；脚本仍必须审批。
- `skill_install` 只在安装工具已配置时可用；每次安装仍必须审批。
- 不存在或当前运行时不可用的组返回固定安全错误，不泄漏路径、配置或内部异常。
- 一次请求最多成功追加激活两次；一次调用可选择多个组。达到上限后不扩大能力。

### 4.3 意图选择

- 普通自然语言由模型读取 `activate_tool_groups` 的组说明后自行决定，不增加本地关键词表或第二个路由模型。
- 模型可以直接回答无需工具的问题，无需先调用激活工具。
- 输入显式引用已发布 `$技能名` 时，`SkillRuntime` 在请求快照中预激活 `skills`，并继续注入现有显式 Skill 指令。
- 未显式引用 Skill 时，不预加载 Skill 工具；模型可按需激活。
- 激活失败作为工具结果返回模型；不得自动退化为全部工具。

### 4.4 请求内动态更新

- Registry 激活后，Tool Loop 在下一次 Provider 调用前刷新 Turn 使用的工具定义。
- 工具调用与结果的续接顺序保持不变；不得为切换工具组重新创建会话、丢失待续接的 `call_id` 或重复执行工具。
- DeepSeek Chat Completions 和阿里云 Responses Provider 使用相同的中立刷新契约。
- 工具列表只能从请求开始时已经构造和验证的宿主白名单中选择；模型不能定义新工具、修改风险等级或扩大参数上限。

### 4.5 可观测性

- 现有工具调用/结果日志记录 `activate_tool_groups` 的请求和结果，能够按 `request_id` 还原选择过程。
- 不在日志中增加系统提示词、Skill 正文或路径之外的新敏感内容。
- HTTP 请求日志中的工具数组应体现当前步骤真实可见工具，而不是完整 Catalog。
- 测试应证明普通请求、只读请求和写请求发送的工具集合不同。

## 5. 非目标

- 不修改 HTTP `/chat` 的工具策略或成功响应契约。
- 不引入新的模型、分类服务、Embedding、数据库或第三方依赖。
- 不使用中英文关键词、正则或文件扩展名猜测自然语言意图。
- 不根据模型名称维护不同工具组。
- 不取消现有写操作、脚本和安装审批。
- 不修改工具参数 Schema、工具调用总预算或日志正文策略。
- 不持久化已激活工具组，不在下一轮自动继承。
- 不允许 AGENTS.md、Skill 或模型输出注册未被宿主白名单提供的工具。

## 6. 项目结构

预计职责边界：

```text
app/runtime/                 请求快照、工具循环和中立动态刷新契约
app/services/llm/            两个 Provider Turn 应用新的工具定义
tools/                       工具组 Catalog、激活工具和受限 Registry
tests/                       Registry、Tool Loop、Provider、Session 和 TUI 回归测试
docs/spec|plan|tasks/        需求、设计与执行清单
docs/knowledge/              完成后更新架构和故障排查
```

不得把工具分组判断放进 Textual Widget，也不得让 Provider 直接理解 Workspace 或 Skill 类型。

## 7. 代码风格

- Python 3.11，沿用不可变 dataclass、Protocol 和显式 tuple 快照。
- 组名使用稳定的小写 snake_case；模型可见错误使用固定安全文本。
- 注释只解释请求隔离、能力升级和审批不变量。
- 不新增通用 DI 容器、插件框架或配置语言。

中立契约示意：

```python
class ToolDefinitionUpdater(Protocol):
    def replace_tools(self, tools: tuple[ToolDefinition, ...]) -> None:
        ...
```

最终设计可以调整名称，但必须保持 Provider 中立且只允许使用已验证定义。

## 8. 测试策略

### 8.1 工具组与 Registry

- 初始仅发布激活工具和明确预激活工具。
- 激活单组、多组、包含关系、重复激活和最多两次追加。
- 拒绝未知组、空数组、重复/超限名称和当前运行时不可用组。
- 激活写组后，写工具仍走原有审批；拒绝审批不写盘。

### 8.2 Tool Loop 与 Provider

- 激活结果先返回模型，下一模型步骤才使用更新后的定义。
- DeepSeek 和阿里云请求体中的工具列表与 Registry 当前快照一致。
- 动态更新不丢失 Function Call 与 Tool Result 配对。
- 普通最终文本不调用激活工具，也不触发额外模型步骤。
- 激活调用计入现有模型步骤和工具调用预算。

### 8.3 Session、Skill 与兼容性

- 每次 `ChatSession.send` 使用独立激活状态；上一轮工具不泄漏到下一轮。
- `$技能名` 预激活 `skills`，未知或超限引用继续使用现有错误语义。
- `/model` 切换前后意图工具组行为一致。
- HTTP `/chat` 现有测试保持不变。
- 测试不访问真实模型、网络或用户文件。

## 10. 边界

### 始终执行

- 工具只能来自请求开始时宿主创建的白名单 Catalog。
- 动态激活后仍执行现有参数、载荷、路径、审批和日志约束。
- 新增行为必须覆盖 DeepSeek、阿里云和无真实网络测试。
- 完成后同步架构、项目概览和排障文档。

### 必须先确认

- 修改本需求定义的组名、包含关系或最大激活次数。
- 将意图选择扩展到 HTTP。
- 增加依赖、配置项或第二个模型路由调用。
- 改变写操作、脚本或安装审批规则。

### 永不执行

- 根据模型提供的 Schema 动态创建任意工具。
- 激活工具组时自动执行组内工具。
- 因激活写组而跳过本地用户审批。
- 把 API Key、环境变量、完整系统提示词写入新增日志字段或测试。

## 11. 验收标准

1. TUI 普通问答的首个上游请求只携带 `activate_tool_groups`，不再携带全部 13 个工具。
2. 模型激活 `workspace_read` 后，下一步只能看到激活工具和五个只读 Workspace 工具。
3. 激活 `workspace_write` 后可完成现有“读取 → 审批修改 → 检查 → 汇报”闭环，所有副作用审批保持不变。
4. `$技能名` 请求首步可见 Skill 使用工具，但不自动暴露 Skill 安装工具。
5. 多组激活、最多两次追加和请求间重置均有自动化测试。
6. DeepSeek 与阿里云都能在不丢失工具续接状态的情况下刷新下一步工具定义。
7. HTTP `/chat`、TUI `/model`、会话持久化以及所有既有测试通过。
8. 正式日志可按 `request_id` 看出激活组及每一步真实工具集合，且没有新增敏感字段。
