# TUI 模型切换需求

状态：已完成（2026-09-07）

## 背景与目标

Tsi 助手当前只在启动时读取 `LLM_PROVIDER` 及对应模型变量，运行中的 TUI 无法切换模型。需要参考 Codex 的 `/model` 交互增加本地模型选择器，让用户从可选列表中通过键盘切换供应商和模型，同时不退出应用、不修改 `.env`、不影响 HTTP `/chat`。

## 交互契约

- 用户输入完整 `/model` 并回车后打开模型候选列表，不调用大模型。
- 列表中的每个可选项同时显示供应商品牌和模型名，并标识当前项。
- 打开列表时默认选中当前供应商和模型；当前项不在目录时仍加入并选中。
- `Up` / `Down` 在可选模型间循环移动，`Enter` 确认当前选项，`Esc` 关闭且不切换。
- 确认成功后关闭列表、立即刷新底部状态栏，并写入一条 System 消息说明当前供应商和模型。
- `/model` 继续参与现有 `/` 命令预览；不支持 `/model` 后追加供应商或模型参数。
- 模型选择期间保持输入框焦点，但方向键、回车和 Esc 优先由模型列表消费。

## 模型目录

- 当前仅支持 `deepseek` 与 `aliyun`，不联网请求供应商模型目录。
- 新增可选环境变量 `DEEPSEEK_MODELS`、`ALIYUN_MODELS`，值为英文逗号分隔的模型名列表。
- 每家供应商合法的 `DEEPSEEK_MODEL` / `ALIYUN_MODEL` 当前配置和项目默认模型必须自动加入候选，即使对应 `*_MODELS` 未配置。
- 候选按供应商固定顺序和环境列表原顺序展示；重复模型按供应商内首次出现去重；每项环境列表最多读取 8 KiB，超限时忽略该列表并保留当前/默认候选。
- 模型名去除首尾空白后必须非空、不得包含控制字符或英文逗号，长度不超过 128 个字符；非法目录配置使该条候选失效，但不得泄漏环境内容或阻止 TUI 启动。
- 如果某供应商的 API Key 缺失，其候选仍展示为不可用并标明 Key 缺失；不可用项可以选中查看，但回车不得切换。

示例配置：

```dotenv
DEEPSEEK_MODELS=deepseek-v4-flash,deepseek-v4-pro
ALIYUN_MODELS=qwen3-max,qwen-plus
```

示例仅说明格式，不承诺模型在上游真实存在；实际名称由项目使用者配置。

## 行为范围

- 切换只影响当前 TUI 进程中切换成功后的请求，不写入 `.env`、环境变量或会话文件。
- 重启 TUI 后重新以 `.env` 和 Shell 环境为准。
- 切换保留当前已持久化会话；下一轮请求将既有历史发送给新模型。
- `/model`、候选浏览和切换结果不进入输入历史、模型上下文或会话持久化。
- 仅允许空闲时打开选择器；请求执行或工具审批期间不更换当前 Provider。
- Key 缺失、候选配置非法或 Provider 创建失败时保持原配置和会话。
- 本功能不试调用模型；配置了不存在或无权限的模型时，由下一次正常请求按现有错误语义报告。

## 项目结构

- `app/tui/commands.py`：注册完整 `/model` 本地命令及候选说明。
- `app/tui/model_palette.py`：维护不可变候选、当前选择、循环导航、确认/关闭和纯文本展示，不创建 Provider。
- `app/tui/application.py`：协调打开选择器、按键优先级、Provider 切换、System 消息和状态栏刷新。
- `app/runtime/session.py`：在无活动发送时替换当前 Provider，同时保留消息和存储。
- `app/services/llm/factory.py`：解析模型目录，并基于明确候选创建 Provider；继续集中处理默认模型和 API Key。
- `tests/`：分别覆盖目录解析、Session 切换、选择器状态与 TUI 无头交互。

## 代码风格

- 使用不可变候选/配置对象、明确类型标注和 Provider 中立接口，不让 Textual 组件实例化具体 Provider。
- 模型目录解析不依赖 Textual；选择器不读取环境变量、不操作 Session，应用层只协调这些边界。
- 复用现有命令候选的键盘优先级和渲染习惯，不把模型状态塞入通用命令枚举。
- 注释只解释目录降级、切换时机和并发边界，不逐行复述代码。

示例目标接口：

```python
catalog = resolve_model_catalog()
selection = palette.take_selection()
provider = create_provider_for_model(selection.provider, selection.model)
session.replace_provider(provider)
```

具体名称可在设计阶段按现有模块语义调整，但职责边界不得改变。

## 测试策略

- Pytest 单元测试覆盖模型目录缺失、单项、多项、空白、重复、控制字符、超长值及当前模型自动补入。
- Provider 工厂测试覆盖两家候选创建、对应 Key 读取、默认模型与显式模型，且不改变原环境配置。
- Session 测试验证切换后下一轮使用新 Provider、历史保持，以及发送期间拒绝替换。
- 选择器测试覆盖当前项默认选中、上下循环、确认、Esc 关闭、不可用项和空目录降级。
- Textual 无头测试验证 `/model` 预览、打开列表、上下键、回车确认、Esc 取消、状态栏刷新、System 消息，以及命令不调用模型且不进入历史。
- 完成后运行：

```bash
.venv/bin/python -m compileall -q main.py app tools tests
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -m pytest -q
.venv/bin/python -m pip check
git diff --check
```

## 边界

- 始终：打开时展示稳定快照；切换前完整校验；切换成功后 Provider、状态栏和后续请求保持一致。
- 先确认：持久化模型选择、联网获取模型目录、修改 HTTP 契约、增加依赖或新增供应商。
- 禁止：写回 `.env`、记录 API Key、把 `/model` 发给模型、在活动请求中替换 Provider、清空或改写既有会话。

## 验收标准

1. 输入 `/model` 回车后出现同时包含供应商和模型名的候选列表，当前模型默认选中，模型调用次数为零。
2. `Up` / `Down` 能循环移动，`Enter` 确认并关闭，`Esc` 关闭且保持原配置。
3. `DEEPSEEK_MODELS` 与 `ALIYUN_MODELS` 中的合法候选按稳定顺序展示，合法的当前模型和默认模型不会遗漏或重复。
4. 确认可用候选后，状态栏和 System 消息立即显示相同配置，下一轮请求使用新 Provider 和模型。
5. 缺少 Key 的候选明确标为不可用且无法确认；非法目录项安全忽略，原配置和会话不改变。
6. `/model` 和选择行为不进入输入历史、持久化会话或上游请求，重启后仍使用环境初始配置。
7. 切换后继续发送切换前的已提交历史，`/clear` 行为保持不变。
8. HTTP `/chat` 的请求、响应、Provider 选择和错误映射完全不变。
9. 全量自动化测试与四项质量门禁通过。

## 非目标

- 不支持 `/model <供应商> <模型>` 直接参数切换。
- 不联网发现、校验或排序模型，不承诺示例模型可用。
- 不持久化选择，不修改 `.env`。
- 不增加请求级模型字段，不改变 HTTP `/chat`。
- 不支持自定义 Base URL、新供应商、自动降级或并行多模型。
