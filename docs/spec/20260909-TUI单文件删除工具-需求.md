# TUI 单文件删除工具需求

## 背景

Tsi 助手已经能在启动工作区内读取、创建和精确修改文件，但模型无法删除已经确认不再需要的文件。现有项目规则明确禁止文件删除，因此本需求属于安全边界变更，必须先确认契约，再开放一个受限、可审批、可恢复的单文件删除能力。

## 目标

在根目录 `tools/` 中增加 `delete_workspace_file` 工具，使 TUI 中的模型能够请求删除启动工作区内的一个普通文件，并在真正删除前向用户展示明确预览、获得逐次审批。删除结果应进入现有 Workspace 变更记录，使用户可以通过 `undo_workspace_change` 恢复最近一次删除。

## 使用者与成功条件

- 使用者：通过本地 Textual TUI 操作当前项目的开发者。
- 成功条件：模型可以删除一个符合策略的文件，但不能删除目录、链接、受保护路径或工作区外内容；未审批时磁盘不发生变化；审批与执行之间内容变化时拒绝删除；成功删除后可以撤销恢复。

## 工具契约

工具名：`delete_workspace_file`

参数：

```json
{
  "path": "docs/obsolete.md",
  "expected_sha256": "待删除文件当前内容的 SHA-256"
}
```

- `path` 必须是相对启动工作区的单个文件路径，不接受绝对路径、目录、glob、路径列表或 `..`。
- `expected_sha256` 必须是 64 位小写十六进制摘要，由模型先通过 `read_workspace_file` 获取。
- 工具定义为 `ToolEffect.MUTATING`，必须实现无副作用的 `preview()`。
- 审批预览显示规范化相对路径和有界删除 Diff；不显示工作区绝对路径。
- 成功结果只返回删除路径、原内容摘要和 `change_id`，不回传已删除文件全文。

## 范围

### 包含

1. 在 `tools/workspace.py` 中实现单文件删除工具并复用 `WorkspacePolicy`、审批指纹、Journal 和撤销边界。
2. 在 TUI Workspace 工具注册表和“文件写入”意图工具组中显式注册工具。
3. 每次执行前展示删除 Diff 并由本地用户批准；HTTP 注册表不开放该工具。
4. 审批后再次校验路径、文件类型和 SHA-256，防止 TOCTOU 与误删。
5. 删除记录可以由现有 `undo_workspace_change` 恢复；恢复时仍执行冲突检查和审批。
6. 增加正常、拒绝、越界、保护路径、目录、符号链接、哈希冲突、审批缺失与撤销恢复测试。
7. 更新 README、架构知识与长期安全规则，明确删除工具是原“禁止删除”的唯一例外。

### 不包含

- 批量删除、目录删除、递归删除、glob 删除。
- 移动、重命名、修改权限、清空文件或回收站集成。
- 删除 `.git`、`.venv`、`.env*`、`data`、`logs`、缓存目录、项目保护文件或 `docs/rules/**`。
- 通过 HTTP 自动执行删除。
- 绕过审批、永久授权、模型自行批准或 Skill 脚本代替本工具执行删除。
- 删除超过现有 Journal 安全容量、非 UTF-8 或包含 NUL 的文件；第一版只支持现有结构化编辑边界内的文本文件。

## 安全边界

### 始终执行

- 使用 `WorkspacePolicy` 做逐组件路径和符号链接校验。
- 使用调用方提供的 `expected_sha256` 做乐观并发控制，并在审批后重新读取验证。
- 删除前生成完整且有界的删除 Diff；超限时在审批前拒绝。
- 写入 Journal 成功后再删除；删除失败时不得留下可误用的成功记录。

### 必须询问

- 每一次删除都必须通过 TUI 本地审批。
- 未来若要支持批量、目录、二进制、大文件或无审批删除，必须创建新 Spec。

### 永不执行

- 不跟随符号链接，不执行 Shell `rm`，不接受模型提供的绝对路径。
- 不删除受保护路径，不在 HTTP 注册表中暴露该写工具。
- 不把已删除正文、绝对路径或底层异常写入模型可见错误。

## 验收标准

1. TUI 工具定义中包含 `delete_workspace_file`，HTTP 默认工具定义中不包含它。
2. 合法文本文件在用户批准且摘要一致时被删除，并返回可用于审计的有限结构化结果。
3. 没有审批处理器、用户拒绝、参数非法、目标不存在、目标为目录/符号链接、路径越界或受保护时，文件保持不变。
4. 文件在预览后发生变化时返回 `workspace_conflict`，不得删除新内容。
5. 成功删除产生 `change_id`，随后调用 `undo_workspace_change` 并批准后可按原字节恢复文件。
6. 已有创建、替换、撤销、Git、Skill、HTTP 和 TUI 测试不回归。
7. 文档不再笼统声称“工具系统禁止任何文件删除”，而是准确描述唯一受限例外。

## 兼容与回滚

- 这是新增工具，不改变现有工具参数和 HTTP 契约。
- 回滚代码后该工具从模型白名单消失；已经删除但尚未撤销的文件不会因代码回滚自动恢复，应在回滚前使用 `undo_workspace_change` 或 Git 恢复。
