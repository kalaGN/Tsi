# TUI 应用职责收敛需求

状态：已完成（2026-09-09）

## 1. 背景

`app/tui/application.py` 已增长到约 1000 行，同时承担 TUI 组件组装、启动配置恢复、Session 创建、模型恢复与切换、输入与命令协调、Worker 生命周期、流式输出、工具审批、取消代次、状态投影和错误展示。继续增加功能会扩大变更影响面，也使大量测试必须构造完整 Textual App。

项目已组件化 Palette、Transcript、ActivityBar、InputHistory 和 WorkspaceChanges；本轮不继续机械拆分展示组件，而是收敛已实际形成的启动装配、请求生命周期和模型选择三个边界。

## 2. 目标

1. 将 TUI 启动期的配置、模型恢复、Memory Policy 解析、Session 恢复和启动诊断从 `ChatTuiApp` 构造函数移出。
2. 将单次请求的 Worker、Timer、generation、流式输出、审批、取消和收尾语义收敛到 TUI 专属请求协调器。
3. 将模型候选、已保存选择恢复、Provider 创建、Session Provider 替换和选择持久化收敛到 Runtime 用例。
4. 保持现有扁平 TUI 目录，不引入通用 DI 框架、Controller 目录、State 目录或空壳抽象。
5. 保持所有 HTTP、TUI、Provider、Session、Workspace、Skill 和审批安全语义不变。

## 3. 范围

### 3.2 `bootstrap.py`

- 提供一个明确的 TUI 启动装配入口。
- 解析有界模型候选，恢复可用的已保存模型或安全回退环境默认模型。
- 解析 Memory Policy，创建或恢复 `ChatSession`。
- 保留损坏会话文件，只允许用户通过 `/clear` 显式处理。
- 以结构化结果返回 Session、RuntimeInfo、SkillRuntime、Workspace 启用状态和启动诊断。
- 不导入 Textual，不查询或修改 Widget。

### 3.3 `request.py`

- 保留可注入的 `ChatRunner` 协议和单调时钟。
- 拥有活动 Worker、请求 generation、Timer、开始时间和流式输出 generation。
- 统一处理成功、`ChatRuntimeError`、未知异常、取消和陈旧结果。
- 在 Workspace 启用时提供工具审批和工具结果观察回调。
- 保持 100 ms 流式合并、成功统计、失败耗时、已落盘变更提醒和最终聚焦输入框语义。
- 该模块是 TUI 专属协调器，允许使用 Textual `Worker` 和 `Timer`；不为追求形式纯净额外引入 Port/Adapter 层。

### 3.4 `runtime/model_selection.py`

- 对 TUI 暴露 Provider 中立的候选快照、恢复结果和切换结果。
- 内部调用 LLM Factory 创建 Provider，并通过 `ChatSession.replace_provider()` 完成会话替换。
- 只在 Provider 完整创建且 Session 替换成功后保存选择。
- Store 写入失败不回滚已生效的进程内模型，返回稳定非阻断警告。
- TUI 不再直接导入 `app.services.llm.factory`、`LlmProviderError` 或 `ModelSelectionStoreError`。

### 3.5 `application.py`

- 继续拥有 `compose()`、Textual 事件入口、Widget 查询、Palette 优先级、输入历史展示、本地命令分发、Transcript 和 StatusBar 投影。
- 继续拥有 Esc 的输入清空、Palette 关闭和双击退出优先级。
- 不再创建 Session、SessionStore、Provider 或解析 Memory Policy。
- 不再直接拥有 Worker、Timer 和请求 generation 状态。
- 不追求人为行数门槛；验收以职责边界和行为兼容为准。

## 4. 行为兼容

1. `python -m app.tui` 启动命令、环境加载和 Workspace 绑定目录不变。
2. 恢复对话、损坏历史、`/clear`、`/memory`、`/memory clear`、`/skills`、`/model` 和 `/quit` 语义不变。
3. Enter、Tab、Up、Down 和 Esc 的处理优先级不变。
4. TUI 仍只允许同时一个请求，旧 Worker、Delta 或审批结果不得写回新请求。
5. 工具审批默认拒绝，取消请求后的陈旧审批结果必须失效。
6. 成功请求显示耗时和 Token 统计；失败显示耗时；取消和陈旧请求不显示统计。
7. 模型切换后保留当前会话，继续使用安全候选，不向 Session 或日志写入 API Key。
8. HTTP `/chat` 响应、Runtime 工具循环和 Provider 网络语义不变。

## 5. 代码约定

- 新增类和函数按职责命名，不使用泛化 `Manager` 或 `Utils`。
- 跨模块状态优先使用 `@dataclass` 的有限快照，不传递无界字典。
- 安全错误消息保留现有稳定文案，未知异常不向 TUI 暴露堆栈、密钥或内部路径。
- 新边界不反向导入 `app.tui.application`，Runtime 不导入 Textual。
- 不通过复制已有逻辑实现拆分；旧实现迁移后必须从 `application.py` 删除。

## 6. 测试策略

- `tests/test_tui_bootstrap.py`：模型恢复、Memory Policy 失败、Session 恢复和损坏历史降级。
- `tests/test_tui_request.py`：成功、Runtime 错误、未知错误、取消、陈旧请求、Delta/reset、审批和已落盘变更提醒。
- `tests/test_model_selection.py`：候选解析、有效恢复、无效恢复、切换成功、Provider 创建失败和 Store 保存失败。
- `tests/test_tui.py`：保留黑盒键盘、Palette、Modal、状态栏和完整请求集成回归；可在独立单元测试覆盖对应边界后删除重复用例，不得删除行为覆盖。
- 所有测试使用假 Runner、假 Provider 或临时存储，禁止访问真实付费服务。

## 7. 边界

### 始终执行

- 保留现有公开响应、错误文案、键盘优先级、审批和取消语义。
- 使用显式、可注入且可独立测试的边界。
- 同步架构 Knowledge 与故障排查中受影响的事实描述。

### 需要另行确认

- 改变 HTTP 契约、Session Schema、模型选择文件 Schema 或工具审批策略。
- 引入新依赖、通用 DI 框架或新持久化文件。
- 将现有扁平 TUI 组件迁入多层子目录。

### 禁止

- 通过删除或弱化测试使重构通过。
- 调用真实模型、真实付费服务或扩大 Workspace/Skill 执行范围。
- 向日志、文档、测试或 Git 写入密钥。

## 8. 验收标准

1. `ChatTuiApp` 不再创建 SessionStore、ChatSession 或 Provider，不再解析 Memory Policy。
2. `ChatTuiApp` 不直接导入 LLM Factory 和模型选择 Store 异常。
3. 请求活动字段和主要生命周期逻辑不再定义在 `application.py`。
4. 使用已保存模型、环境默认模型、显式测试 Runner 和显式测试 Session 的构造路径均可用。
5. 全部现有 TUI 行为和安全回归通过，HTTP 契约不变。
6. 新增边界有独立单元测试，完整质量门禁通过。
7. 架构 Knowledge 与实现一致，旧“TUI 主应用保留请求生命周期”说明被明确更新。

## 9. 非目标

- 不修改 HTTP `/chat` 契约或引入 HTTP 流式输出。
- 不修改 Session、Memory、Skill、Tool 或模型选择的持久化 Schema。
- 不新增命令、模型、Provider、工具或 TUI 可见功能。
- 不将所有 UI 交互抽象成框架无关状态机。
- 不拆分现有扁平 Widget 文件，不增加 `controllers/`、`state/` 或 `widgets/` 子目录。
- 不为达成特定行数指标进行无语义拆分。
