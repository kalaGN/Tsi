# TUI 模型选择持久化需求

状态：已完成（2026-09-09）

## 背景与目标

Tsi 助手已经支持在 TUI 中通过 `/model` 切换供应商和模型，但选择仅在当前进程内有效。每次重新启动都会重新采用 `.env` 中的默认配置，用户需要重复切换。

本需求为 TUI 增加本机模型选择持久化：每次成功切换后立即保存当前供应商与模型，下一次启动优先恢复这组选择；持久化状态不可用时安全回退到 `.env` 默认配置。

## 假设与已采用建议

1. “上次退出时的模型”按“最近一次成功切换并生效的模型”处理；切换成功即保存，不依赖正常退出钩子，以覆盖崩溃、强制关闭等场景。
2. 模型偏好属于 TUI 本机设置，独立保存到 `data/model-selection.json`，不写入 `.env`，也不与聊天记录 `data/chat-session.json` 耦合。
3. 只恢复当前模型目录中仍存在、名称合法且 API Key 已配置的选项；否则回退 `.env` 默认配置。
4. `/clear`、`/memory clear` 和会话文件清理不删除模型偏好。
5. 本需求只影响 TUI；HTTP `/chat` 继续完全按环境配置创建 Provider。

## 用户行为

- 用户通过 `/model` 选择可用候选并确认后，当前会话立即切换模型，同时保存该选择。
- 下次运行 `.venv/bin/python -m app.tui` 时，启动流程先解析环境候选，再尝试恢复最后选择。
- 恢复成功后，底部状态栏、模型候选中的“当前”标识和下一次请求都使用恢复的供应商与模型。
- 偏好文件缺失时保持现有启动行为。
- 偏好文件损坏、版本不支持、字段非法、候选已移除或 API Key 缺失时，TUI 仍可启动并回退环境默认模型，同时显示不含路径、密钥和底层异常的安全提示。
- 如果运行中模型已切换成功但偏好保存失败，继续使用新模型，并提示“模型已切换，但无法保存启动选择”；不得为了持久化失败回滚正在使用的 Provider。

## 持久化契约

文件位置：启动项目根目录下的 `data/model-selection.json`。

第一版格式：

```json
{
  "version": 1,
  "provider": "deepseek",
  "model": "deepseek-v4-flash"
}
```

- `version` 固定为整数 `1`。
- `provider` 只接受当前支持的 `deepseek` 或 `aliyun`。
- `model` 必须通过现有模型名校验，并且与当前 `resolve_model_options()` 目录中的同供应商候选完全匹配。
- 文件使用 UTF-8 JSON、`0600` 权限、同目录临时文件和原子替换写入。
- 文件设置合理大小上限；超限、非普通文件、符号链接、结构错误或未知字段类型均视为不可恢复状态。
- 不保存 API Key、Base URL、聊天内容、系统提示词或其他环境变量。
- 无效文件不在启动时自动覆盖，避免掩盖故障；之后用户成功切换模型时可用新的合法状态原子替换。

## 项目结构

- `app/runtime/model_selection_store.py`：负责模型选择的严格解析、原子保存和安全错误，不依赖 Textual。
- `app/tui/__main__.py`：在创建 TUI 应用前加载偏好，校验候选与 Key，并构造恢复后的初始 Provider。
- `app/tui/application.py`：模型切换成功后调用存储；展示恢复或保存失败提示。
- `app/services/llm/factory.py`：继续集中负责候选解析和 Provider 创建，不承担磁盘持久化。
- `tests/`：覆盖存储、启动恢复及 TUI 切换保存行为。
- `docs/`：实现完成后同步启动行为、架构知识和原模型切换文档中“重启不持久化”的历史描述。

## 代码风格

- Python 3.11，使用显式类型、不可变模型选择值和小型单一职责函数。
- 存储层只处理数据契约；恢复策略由启动编排层决定；Textual 组件不直接解析 JSON。
- 错误分为可向用户展示的安全描述与内部异常，不把绝对路径、环境内容或密钥带入界面。
- 必要注释只解释原子替换、候选复验和失败降级等非显而易见的边界。

示例目标接口：

```python
selection = store.load()
option = select_restorable_model(selection, resolve_model_options())
provider = create_provider_for_model(option.provider, option.model)
```

具体命名可在设计阶段按现有模块语义调整，但职责边界不得改变。

## 测试策略

- 存储单元测试：文件缺失、合法读写、权限、原子替换、损坏 JSON、超限、符号链接、版本和字段校验。
- 恢复策略测试：候选存在、候选移除、Key 缺失、供应商非法、模型非法以及环境默认回退。
- TUI 无头测试：成功切换触发保存，保存失败不回滚 Provider且显示提示，恢复后状态栏与候选当前项一致。
- HTTP 回归测试：模型偏好文件不改变 `/chat` 的环境 Provider 选择。
- 自动化测试只使用临时目录和假 Provider，不请求真实模型。

## 边界

### 始终执行

- 成功切换后立即持久化，启动恢复前重新验证供应商、模型候选和 API Key。
- 任何恢复失败都安全回退环境默认值，不阻止 TUI 启动。
- 保持模型选择、聊天会话、长期记忆三类状态相互独立。

### 必须询问

- 修改 `.env`、增加新的配置依赖、跨设备同步、保存 API Key，或让 HTTP 读取本地偏好。
- 增加清除模型偏好的新命令，或改变无效偏好文件的处理策略。

### 永不执行

- 不在偏好文件、日志或界面中保存或显示密钥。
- 不因偏好文件故障清空聊天记录、长期偏好或其他运行数据。
- 不恢复当前目录中已不存在或当前密钥不可用的模型。

## 验收标准

1. 用户成功切换到任一可用模型后，关闭并重新启动 TUI，状态栏和下一次模型请求仍使用该供应商与模型。
2. 保存发生在切换成功时，因此普通退出、双 Esc 退出和非正常终止后的下一次启动均可恢复最后一次已保存选择。
3. `data/model-selection.json` 仅包含版本、供应商和模型，权限为 `0600`，更新使用同目录原子替换。
4. 文件缺失时保持环境默认模型；文件损坏、超限、非法、候选移除或 Key 缺失时回退环境默认模型且 TUI 可继续使用。
5. 模型切换成功但保存失败时，当前进程仍使用新模型，并显示有限的持久化失败提示。
6. `/clear`、`/memory clear` 不删除或重置模型选择；聊天历史、摘要和长期偏好契约不变。
7. HTTP `/chat` 不读取该文件，其 Provider 选择和公开契约不变。
8. 原模型选择、会话恢复、工具调用、流式输出及全量质量门禁全部通过。

## 非目标

- 不记录“最后一次模型请求成功”的模型；只记录用户最后一次成功切换的选择。
- 不自动编辑 `.env`，不增加 `/model reset` 或模型偏好管理界面。
- 不跨工作区、跨机器或跨用户同步。
- 不联网校验模型是否真实存在，也不提供启动时自动请求探测。
- 不改变聊天会话文件版本或 HTTP 请求参数。
