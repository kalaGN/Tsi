# TUI 记忆管理需求

状态：已完成（2026-09-09）

## 1. 目标

为当前单会话 TUI 增加可持续运行的三层记忆：自动滚动摘要、超出上下文预算时的成对淘汰，以及跨 `/clear` 保留的用户长期偏好。完整对话仍用于本地恢复和界面展示，模型请求只携带受预算控制的上下文。

## 2. 已确认行为

1. 使用稳定的本地 Token 估算，不引入第三方 tokenizer；默认窗口为 128000 Token。
2. 上下文估算达到窗口 70% 时触发压缩，压缩后以 50% 为目标。
3. 正常压缩至少保留最近 6 个完整 user/assistant 轮次和当前输入。
4. 旧轮次由当前模型生成滚动摘要；摘要请求不提供任何工具。
5. 摘要失败时不阻断正常对话，按完整轮次从旧到新淘汰模型上下文；完整 Transcript 不删除。
6. 摘要后仍超过目标时继续成对淘汰最旧轮次；单条当前输入自身超过硬预算时返回安全错误。
7. 长期偏好仅从用户明确表达的“请记住”“以后请/以后使用”“我的偏好是”“我习惯”等语句提取，不推断隐含属性。
8. 密钥、Token、密码、Cookie 等敏感内容不得进入长期偏好。
9. `/clear` 清理对话和摘要，但保留长期偏好；`/memory` 查看偏好，`/memory clear` 明确清除偏好。
10. v1 `chat-session.json` 可直接恢复；下一次成功写入时升级为 v2。

## 3. 持久化契约

v2 会话保持一个原子 JSON 文件：

```json
{
  "version": 2,
  "messages": [],
  "context": {
    "summary": null,
    "summarized_message_count": 0
  },
  "preferences": [
    {
      "id": "稳定标识",
      "content": "使用中文回复",
      "source": "explicit",
      "updated_at": "UTC ISO-8601"
    }
  ]
}
```

- `messages` 保存完整成功轮次，供界面恢复，不受压缩删除。
- `summarized_message_count` 必须为不超过消息总数的偶数，只标记模型上下文边界。
- 摘要只覆盖边界之前的完整轮次。
- 偏好最多 50 条，每条正文不超过 500 字符，相同正文更新而不重复。

## 4. 请求上下文

每次发送给模型的顺序为：

```text
AGENTS.md + Skill 提示
+ 长期偏好
+ 历史滚动摘要
+ 未摘要的最近完整轮次
+ 当前用户输入
```

系统提示、Skill 正文、工具临时调用和工具结果仍不写入会话历史。摘要模型调用也不出现在 Transcript 中。

## 5. 安全与失败语义

- 本地文件继续使用临时文件、`fsync`、`0600` 和原子替换。
- 损坏的 v1/v2 文件不得静默覆盖，仍由用户明确处理。
- 摘要失败只触发本轮确定性淘汰，不伪造摘要。
- 偏好作为低优先级用户上下文，不能覆盖当前请求、项目规则或工具审批。
- `/memory` 不调用模型，不读取日志，不显示会话摘要正文。
- HTTP `/chat` 保持无状态，公开响应不变。

## 6. 测试策略

- Token 估算：空值、中英文、结构开销和超预算。
- v1/v2 存储：迁移、约束、原子保存、损坏文件和偏好保留。
- Session：触发摘要、保留最近轮次、摘要合并、失败淘汰、超长当前输入、成功提交与失败回滚。
- 偏好：显式提取、去重、数量上限、敏感内容拒绝、注入请求及清理语义。
- TUI：`/memory`、`/memory clear`、`/clear` 保留偏好和既有交互回归。
- 所有自动化测试使用假 Provider，不访问真实模型。

## 7. 验收标准

1. 长会话达到阈值后，下一次业务请求只携带摘要和受控最近轮次。
2. 摘要失败或摘要后仍超预算时，模型上下文按完整轮次淘汰且不会破坏角色交替。
3. 完整 Transcript 在压缩后仍可恢复。
4. 明确偏好能跨重启、跨 `/clear` 生效，并可查看和单独清除。
5. v1 会话无需人工迁移即可恢复。
6. HTTP、工具审批、Skill 热加载、模型切换和流式输出行为不回归。
7. 完整质量门禁通过，无真实网络或付费调用。

## 8. 非目标

- 多会话、向量数据库、Embedding、跨设备同步和自动事实推断。
- 精确复刻 DeepSeek/Qwen tokenizer。
- 将工具调用轨迹写入长期会话。
- 修改 HTTP `/chat` 为有状态接口。
