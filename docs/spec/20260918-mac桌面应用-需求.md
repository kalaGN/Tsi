# Web UI 与 macOS 桌面应用需求

> 后续状态：Web 工作区写入与逐次审批已由 [20260919-Web工作区写入需求](20260919-Web工作区写入-需求.md) 补充实现；本文的“第一阶段只读”仅记录当时边界。

状态：Web UI 第一阶段已完成（2026-09-18）；macOS 壳待后续确认

## 1. 背景

Tsi 助手当前提供 FastAPI HTTP 和 Textual TUI，核心对话、模型、工具、Skill、记忆与日志能力已集中在共享 Runtime。项目需要增加可分发的 macOS 桌面入口，并参考 DeepSeek Harness（DSH）Web UI 的信息架构和交互方式，降低终端使用门槛。

本项目只借鉴 DSH 的布局和产品能力，不复制其源码、品牌、图标或文案。官方 DSH 仍处于开发者预览，本项目不能依赖其内部接口。

## 2. 实施顺序

第一阶段先在现有 FastAPI 中交付 `/ui` Web UI，验证页面布局、流式协议和共享 Runtime 边界；第二阶段再使用 WKWebView 包装已稳定的本地 Web UI。第一阶段不引入桌面依赖或打包链。

## 3. 目标

- 增加可直接在本机浏览器启动的 Web UI，并为后续 macOS 桌面壳提供稳定页面。
- Web UI、后续桌面端和 TUI 共享同一套 Agent Runtime。
- 提供 DSH 风格的三栏工作区：左侧工作区与会话、中间对话、右侧文件与活动详情。
- 支持持久化多会话、流式 Markdown、停止生成、模型切换、上下文占比、Token 与耗时展示。
- 在桌面端继续执行现有工具白名单、Workspace 隔离和逐次审批，不降低安全边界。
- 提供开发启动命令和 `.app` 构建命令，生成物不进入 Git。

## 4. 用户场景

1. 用户从项目目录启动 Tsi Desktop，应用自动打开当前目录工作区。
2. 用户可新建、切换和删除本地会话，重启应用后恢复会话列表与最后打开项。
3. 用户输入中文问题后看到流式回答；Markdown、代码块、列表和表格可阅读、选择和复制。
4. 模型请求触发工具时，右侧活动区显示工具名、状态和有限摘要；写操作与 Skill 脚本弹出审批卡片。
5. 用户可在标题区切换已配置的 Provider/模型，并在下次启动时恢复。
6. 用户可从右侧文件树打开工作区内允许读取的文本文件，但不能借此绕过工具路径策略。

## 5. 范围

### 5.1 Web UI 第一阶段

- 由现有 FastAPI 在 `/ui` 提供本地页面、静态资源和 `/ui/api/*` 接口。
- 提供 DSH 风格三栏响应式布局、持久化 Web 多会话、流式对话、停止生成、模型切换、上下文/Token/耗时展示，以及安全文件树和文本预览。
- 提供设置面板；主题、界面密度和发送快捷键仅保存在浏览器，模型选择复用现有后端持久化，页面不读写 API Key。
- Web 会话保存到 `data/web-sessions/`，与 TUI 的 `data/chat-session.json` 隔离；“新对话”创建独立会话，旧 `data/web-session.json` 首次启动时迁移。
- 模型只可调用时间和 Workspace 只读工具；写工具、Skill 和 Git 写能力在具备 Web 审批 Broker 前不得注册。
- Web UI 仅允许 loopback 客户端访问，即使 Uvicorn 被误绑定到非本机地址也拒绝远程页面和 API。

### 5.2 后续桌面壳

- macOS 13 及以上。
- 使用系统 WKWebView 承载本地页面；桌面壳负责窗口生命周期、本地服务启动、随机端口和退出清理。
- 默认单实例、单窗口；关闭窗口即退出第一版应用。
- 开发模式可从命令行启动，发布模式可构建 `.app`。

### 5.3 页面布局

- 顶部：工作区名称、连接状态、当前 Provider/模型、设置入口。
- 左栏：新建会话、当前工作区、会话列表及删除操作。
- 中栏：欢迎态、消息流、流式临时回答、活动状态、底部多行输入框和发送/停止按钮。
- 右栏：可折叠的文件与活动标签页；展示安全文件树、文本预览、工具调用、审批结果和错误摘要。
- 窗口较窄时右栏折叠，左栏可收起；支持浅色、深色和跟随系统主题。

### 5.4 完整功能

- 复用现有模型 Provider、Session、记忆压缩、Skill Catalog、意图工具组、日志和模型选择能力。
- Web 与桌面状态不与 TUI 的唯一会话文件互相覆盖。
- 新建会话时绑定当前工作区；第一版运行期间不切换到其他目录。
- 支持发送、流式展示、取消、失败恢复和会话清空。
- 支持安全读取文件以及现有工具调用；写操作、删除、Skill 安装/脚本和 Git 写保持逐次审批。
- 模型候选只来自现有环境配置；桌面设置页不显示、编辑或回传 API Key。

## 6. 第一阶段非目标

- 不复制或嵌入 DSH 官方 Web UI，不使用 DeepSeek 商标冒充官方产品。
- 不实现 Windows/Linux、菜单栏常驻、系统托盘、开机自启、自动更新、通知和多窗口。
- 不实现应用内 API Key 保存；后续如需支持，必须单独设计 macOS Keychain。
- 不新增任意 Shell、浏览器、网络或文件系统权限。
- 不在第一版制作签名、Apple Developer ID、公证或 DMG 发布流水线。
- 不改变现有 `/chat` 响应契约和 TUI 行为。
- 不在第一阶段实现写工具审批、Skill 操作或桌面壳。

## 7. 假设与决策

- 第一阶段页面使用项目内原生 HTML、CSS、JavaScript，不引入前端构建工具；第二阶段拟采用 `pywebview + WKWebView + 本机 FastAPI`。
- 桌面本地服务只绑定 `127.0.0.1` 随机端口，并为当前进程生成不可预测的会话令牌。
- 页面与服务通过同源 JSON、流式 NDJSON 和审批接口通信，不把 Python 对象直接暴露给页面。
- 第一版以 Apple Silicon 开发环境验收；代码不主动限制 Intel，但 Universal Binary 属于后续发布工作。

## 8. 安全与隐私

- 所有桌面 API 必须校验启动令牌和同源请求；禁止绑定公网地址。
- 文件树、预览和写入统一复用 Workspace Policy；页面不能提交任意绝对路径。
- 审批默认拒绝，超时或窗口退出视为拒绝；模型不能伪造审批结果。
- API Key 不进入页面、URL、桌面状态、会话文件或桌面生命周期日志。
- 模型输入输出仍按现有项目策略写入本地模型日志，README 必须继续提示明文风险。
- 页面 Markdown 禁止原始 HTML、远程图片、脚本和任意外链自动加载。

## 9. Web UI 第一阶段验收标准

1. 启动现有 Uvicorn 后访问 `http://127.0.0.1:8000/ui` 可打开 Tsi 助手页面。
2. 页面具备响应式三栏布局、中文输入、流式输出、安全 Markdown、停止生成、模型切换，以及 Web 多会话的新建、切换、重命名、清空、删除和恢复。
3. 右栏可浏览及预览 Workspace Policy 允许的 UTF-8 文本，不能读取保护路径、符号链接、二进制或超限文件。
4. 模型只看到按需激活的只读工具，不存在编辑、删除、脚本、安装或 Git 写工具。
5. Web 会话与 TUI 会话隔离；`/chat` 契约和 TUI 回归测试保持通过。
6. Web 页面与 API 拒绝非 loopback 客户端；页面不加载远程脚本、样式、图片或字体。
7. 设置面板支持跟随系统/浅色/深色主题、舒适/紧凑密度、Enter 或 Cmd/Ctrl+Enter 发送，并可恢复默认值。

## 10. 后续桌面验收标准

1. `.venv/bin/python -m app.desktop` 能在 macOS 打开名为“ Tsi 助手”的窗口，退出后本地服务停止。
2. 桌面页面具有可收折的三栏布局，并在 900px 以下保持对话区可用。
3. 可新建、切换、删除和恢复至少 20 个会话；不同会话上下文互不串线。
4. 中文输入、流式回答、Markdown、取消、错误、耗时、Token 和上下文占比展示正确。
5. 已配置模型可切换并持久化；页面永远拿不到 API Key。
6. 只读工具自动执行；每个写操作独立审批，拒绝后磁盘不变，批准后结果和活动记录一致。
7. 文件树和预览拒绝越界、保护路径、符号链接、二进制与超限文件。
8. 浏览器直接访问无令牌桌面 API 返回 401/403；服务只监听 loopback 随机端口。
9. `scripts/build_macos_app.sh` 可生成未签名 `.app`；构建目录被 Git 忽略。
10. 原有 HTTP、TUI 和离线评测无回归，自动化测试不调用真实模型或外部网络。
