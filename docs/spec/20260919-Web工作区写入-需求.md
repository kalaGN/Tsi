# Web 工作区写入需求

状态：已完成（2026-09-19）

## 1. 目标

让仅限本机访问的 Web UI 具备与 TUI 一致的安全文件修改闭环。模型可按意图加载工作区写工具，提出创建、精确替换或删除单个文件的操作；页面必须先展示完整、有界的变更预览，只有用户针对本次操作明确批准后才允许执行。

成功标准是用户能够在 Web 对话中要求修改当前启动目录内的项目文件，审查 Diff 后批准或拒绝，并在同一条流式对话中看到执行结果与模型最终回答，同时不削弱现有 Workspace 路径、哈希、大小和审批约束。

## 2. 已确认范围

1. Web UI 开放现有 `workspace_write` 工具组，启动目录仍是唯一 Workspace 根目录。
2. 开放 `apply_workspace_edits`、`delete_workspace_file`、`run_project_check` 和 `undo_workspace_change`；工作区读取工具继续可用。
3. `apply_workspace_edits` 和 `delete_workspace_file` 等有副作用操作必须逐次审批，页面显示工具名称、文件列表与纯文本完整 Diff。
4. 每个审批只对关联请求中的一次工具调用有效，不提供“永久允许”或批量授权。
5. 本次不开放 Git 写工具、Skill 安装、Skill 脚本执行或任意 Shell 命令。
6. 请求等待审批时保持忙碌状态，禁止发送新消息、切换或变更会话、切换模型及清空历史；用户仍可取消当前请求。

## 3. 页面与接口行为

- 模型产生待审批写操作后，当前 NDJSON 对话流发送 `tool_approval_required` 事件，包含请求 ID、审批 ID、工具名、标题、相对路径列表和纯文本预览。
- 页面打开模态审批框，默认焦点为“拒绝”；用户可滚动、选择和复制 Diff。
- 页面通过独立的本机 API 提交一次 `approve` 或 `reject` 决策。审批 ID 必须由服务端生成，客户端不能指定工具参数、路径、Diff 或指纹。
- 服务端只接受当前活动请求的当前待审批项；未知、过期、重复或跨请求审批必须失败关闭。
- 批准后原工具继续执行；拒绝后向模型返回现有拒绝结果，由模型继续给出最终说明。
- 取消、浏览器断开、模型失败或请求结束时，所有待审批状态立即失效，不能在后续请求中复用。
- 页面能力字段把 `workspace_write` 标记为可用，并在文件区和审批区域使用简洁图标与短标签，不增加冗长说明。

## 4. 技术栈与项目结构

- Python 3.11、FastAPI、现有 `ChatSession`、`ToolLoop`、`WorkspacePolicy` 与 `ToolApprovalRequest`。
- 页面保持原生 HTML/CSS/JavaScript，不增加前端构建工具或第三方依赖。
- `app/webui/service.py`：请求级写工具 Registry、待审批状态和决策协调。
- `app/webui/router.py`：严格校验审批决策 API。
- `app/webui/static/`：审批模态框、事件处理和忙碌状态。
- `tests/test_webui.py`：Service、API、安全边界和静态页面契约。

## 5. 代码风格

沿用现有领域命名和稳定错误映射，注释只解释并发、生命周期和安全边界。例如：

```python
async def resolve_tool_approval(self, approval_id: str, approved: bool) -> None:
    """只完成当前请求尚未决策的审批，拒绝过期或重复提交。"""
```

审批 DTO 只暴露页面渲染所需白名单字段，不序列化内部 Fingerprint，也不接受客户端回传 Diff。

## 6. 测试策略

- Service 单测：写工具组可见、批准执行、拒绝不落盘、取消清理、重复/过期/错误审批 ID。
- API 测试：仅 loopback、严格布尔决策、404/409/422 映射、审批期间会话与模型操作冲突。
- UI 静态契约：审批事件、模态框、批准/拒绝按钮、默认拒绝、纯文本渲染和忙碌状态。
- 回归测试：Web 多会话、只读文件预览、TUI 审批、HTTP `/chat` 及全部工具测试不得退化。

## 7. 边界

- 必须：复用现有 Workspace Policy、结构化编辑、SHA-256 并发校验、Diff 上限、变更日志和逐次审批；所有状态绑定请求 ID。
- 需另行确认：Git 写入、Skill 安装/执行、目录级删除、直接编辑器、自动批准、远程访问和多请求并发。
- 禁止：客户端提交或修改工具参数、绕过审批回调、审批后重新生成 Diff、接受过期决策、把绝对路径或内部异常暴露给页面。

## 8. 非目标

- 不把 Web UI 改造成通用 IDE，不提供文件直接保存、拖拽上传或终端。
- 不修改 TUI、HTTP `/chat` 的工具权限与交互。
- 不新增鉴权体系；Web UI 继续只允许 loopback 来源。
- 不持久化未完成审批，刷新页面等同拒绝并取消当前请求。

## 9. 验收标准

1. Web 对话能按意图激活 `workspace_write`，读工具和四个工作区写闭环工具对模型可见。
2. 未收到明确批准前，创建、修改和删除操作不会改变磁盘。
3. 页面完整显示有界纯文本 Diff 和目标相对路径；批准后执行，拒绝后文件保持不变。
4. 一个审批决定只能消费一次，错误、过期、重复或跨请求 ID 不能执行工具。
5. 取消请求、断开流或内部失败都会解除等待，并使之后提交的旧审批无效。
6. 审批等待期间所有会话和模型变更保持现有 409 门禁，页面不会并发发起第二条消息。
7. Web 能力声明准确反映写入能力，TUI 和 HTTP `/chat` 行为不变。
8. 定向测试、完整测试、编译、依赖和 Diff 检查全部通过。
