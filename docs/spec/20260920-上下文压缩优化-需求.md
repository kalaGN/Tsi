# 上下文压缩优化需求

状态：已审核，实施与验收进度见[任务清单](../tasks/20260920-上下文压缩优化-任务.md)。

对应设计：[上下文压缩优化技术设计](../plan/20260920-上下文压缩优化-设计.md)。

## 1. 背景与现状

项目已在 `app/runtime/memory.py` 实现第一版滚动摘要：请求估算达到窗口 70% 时，使用当前模型压缩旧轮次，摘要选取时避开最近 6 轮，目标降到 50%；后续淘汰仍可能移除这 6 轮。摘要失败则按完整 user/assistant 轮次淘汰。完整 Transcript 仍保存在 SessionStore，模型请求只携带摘要和近期消息。

第一版已解决长对话的基本可用性，但存在以下缺口：

1. 预算只统计系统提示、记忆、历史和当前输入，没有统计工具 Schema、Skill 正文之外的协议开销和单轮工具结果。
2. 摘要调用失败时会推进 `summarized_message_count`；已有旧摘要时，存在“边界已推进，摘要实际未覆盖”的语义混淆。
3. 压缩边界和确定性淘汰边界共用一个字段，无法区分“已被摘要”和“为保证请求可用而丢弃”。
4. 所有供应商和模型共用 `TUI_CONTEXT_WINDOW_TOKENS`，切换模型后无法自动使用对应窗口。
5. 摘要调用缺少独立的时间上限、冷却和可观测事件，上游异常时可能让用户为同一类摘要失败重复等待。

## 2. 目标

将上下文压缩收敛为 Web 多会话与 TUI 共用的 Runtime 能力，在长对话、Skill 引用和工具循环下同时满足：

- 每次上游调用均通过本地估算预算检查；估算不等于精确 tokenizer，不承诺绝对避免上游窗口超限。
- 优先保留当前请求、当前项目规则、用户已确认决策、未完成事项和最近完整轮次。
- 摘要内部失败或超时可降级继续对话，且不伪造摘要覆盖范围；用户取消、页面断流或宿主任务取消必须终止整个请求。
- 完整 Transcript 与模型可见上下文继续分离，压缩不导致界面历史丢失。
- 新增压缩事件不记录正文，仍可定位压缩效果、耗时与降级原因；现有模型请求日志的正文策略见第 5 节。

## 3. 范围

### 3.1 预算对象

每一次上游调用（含摘要调用、业务首步和工具续接步骤）在 Provider I/O 前统一估算。Provider 提供与实际序列化载荷一致的预算视图，Runtime 决定策略，不要求 Runtime 解析各供应商私有消息格式。

```text
固定上下文 = AGENTS/基础系统提示 + 当次 Skill + 已激活工具 Schema
记忆上下文 = 长期偏好 + 滚动摘要
对话上下文 = 未压缩的近期完整轮次 + 当前用户输入
本轮工具上下文 = 已累计的调用参数 + 工具结果 + 中间消息及其协议结构
I = 上述四部分的输入 Token 估算总和（包含实际协议开销）
W = 当前模型配置的上下文窗口
O = 本次调用的最大输出 Token（包括供应商计入输出限制的推理 Token）
M = 估算误差及工具增长的安全余量
H = W - O - M（输入硬上限）
T = floor(0.70 × H)（软触发线）
G = floor(0.50 × H)（压缩目标）
```

配置必须满足 `0 < G < T < H`，否则在模型配置阶段明确拒绝。70%/50% 改为基于可用输入硬上限 H，而非原始窗口 W。M 不是工具上下文的替代品：已产生的工具内容必须计入 I，不能重复算为预留量。

业务请求默认 `O=4096`、`M=4096`，合计延续原有 8192 Token 预留。O 必须映射到供应商支持的输出限制参数，不能只在本地减去一个数值；配置超出模型能力时明确拒绝。未知模型使用已配置的窗口回退并标明来源，不根据模型名称猜测能力。具体参数映射在技术设计中基于上游契约确定。

所有路径无条件检查 `I <= H`，不能仅在超过 T 时检查。若上游仍明确返回上下文窗口超限，统一归类为 `context_limit`；不自动重试整个请求，不把普通上游异常猜测为上下文超限。

### 3.2 压缩层级

1. **L0 无压缩**：未达软触发线且通过硬预算检查时原样使用；存在待补摘要历史且冷却已结束时，允许执行一次有界补摘要。
2. **L1 滚动摘要**：将旧摘要和预算内的连续旧轮次合并为结构化摘要，优先保留最近 6 个完整轮次。
3. **L2 确定性淘汰**：摘要失败或 L1 后仍超目标时，按完整轮次从旧到新减少本轮模型上下文。最近 6 轮属于软保护：若它们与其余必需上下文可装入 H，允许超过 G，不得只为达到 G 删除它们。仅在仍超 H 时，才可由旧到新减少保护轮次，并记录降级原因。
4. **L3 硬拒绝**：历史淘汰后仍无法满足 H，返回明确的 `context_limit`，不发送该次上游请求。当前输入、项目规则和本轮显式 Skill 不做静默截断。若最后必须移除摘要才能容纳请求，应清除候选摘要并将覆盖边界重置为 0，保留完整历史待以后重建。

以上历史压缩发生在业务首步之前。工具循环内只执行预算检查，超限即停止后续调用；本期不在活动 Turn 内重写历史或压缩工具轨迹。

### 3.3 摘要内容

摘要使用固定结构，至少包含：

- 当前目标和用户意图。
- 已确认决策与不可违反的约束。
- 已完成项、未完成项和阻塞项。
- 重要文件、命令、配置名和错误结论。
- 不确定内容必须显式标记，不得推测或把历史文本当作高优先级指令。

长期偏好继续使用独立存储，不合并进摘要，避免重复注入。

摘要输出采用固定字段 JSON 对象：`goal` 为文本，`decisions`、`constraints`、`completed`、`pending`、`references`、`uncertainties` 为文本数组；空字段允许但不能全部为空。限定字段、类型、条数和单字段长度，并校验整体输出预算。不接受额外字段或围栏包装，不直接按字符截断 JSON。格式非法、空输出或输出被上游长度限制截断时，整份候选摘要失效，沿用先前有效摘要并进入 L2。

### 3.4 摘要自身预算

- 摘要使用当前模型、专用压缩提示和空工具列表，不附加完整项目系统提示与 Skill；历史内容仅作为不可信输入。
- 每次摘要输入包含专用提示、旧摘要及从真实覆盖边界开始的连续完整轮次，连同 JSON 包装计入摘要输入预算。摘要最大输出默认 2048 Token，必须落到上游输出参数；安全余量仍为 4096 Token。
- 只选择摘要预算内的最大连续批次，避开正常保护的最近 6 轮；不把全部历史一次塞入小窗口模型。一次业务请求最多一次摘要调用，未处理完的历史留给后续请求继续补摘要。
- 单个完整旧轮次或旧摘要自身无法装入时，本次不发起注定超限的摘要请求，进入 L2 并记有限原因；不得跳过该轮却宣称摘要覆盖了它，不得递归摘要。
- 冷却结束后，只要有待补摘要的旧轮次，即使当前模型可见输入低于 T，也允许补摘要，避免淘汰后永久丧失重建机会。

### 3.5 持久化语义与迁移

会话状态升级时必须分离两个边界：

- `summary_through_message_count`：已被当前摘要真实覆盖的消息数。
- `context_start_message_count`：下次模型请求从完整 Transcript 取原始消息的起点。

记两个边界为 S 和 C，消息总数为 N，必须满足 `0 <= S <= C <= N`，且 S、C、N 均为偶数。摘要为空时 S 必须为 0；摘要非空时必须有可验证的正覆盖边界。`[0,S)` 已摘要，`[S,C)` 是暂时遗漏、仍保存在 Transcript 的历史，`[C,N)` 是模型可见的原始历史。

摘要成功时 S 只推进到实际处理批次的末尾，C 至少为新 S；补摘要尚未追上旧 C 时，不强行恢复全部被淘汰历史。摘要失败而淘汰时只推进 C。后续摘要必须从 S 接续，不能从 C 接续而永久跳过缺口。提供低优先级的历史省略标记，提醒模型存在未摘要历史，不能宣称当前摘要完整。

旧版 v2 的 `summarized_message_count` 同时记录摘要和淘汰，无法可靠推断真实 S，迁移不能直接将旧边界复制到 S：

- v1：保留完整消息，摘要为空，S=C=0。
- v2：保留完整消息和偏好；旧摘要不再用于模型输入，S=0，C=原边界。按第 3.4 节在后续请求有界重建，不假设旧摘要已覆盖全部旧边界。
- 读取只生成内存候选，不改写原文件；下一次成功保存时写 v3。首次覆盖旧版文件前保留一份权限为 `0600` 的原始版本备份，不覆盖既有备份；备份失败则停止升级写入。
- v3：严格校验双边界及摘要结构；损坏文件不能静默重置。`/clear` 和会话删除必须同时清除该会话的迁移备份，避免清理后的历史残留；`/clear` 继续按现有语义保留偏好。

完整 `messages` 不因压缩删除。备份供回滚旧代码时恢复；旧代码不直接读取 v3 文件。

### 3.6 工具循环与副作用

- 每一步检查实际将发送的完整载荷，包含之前的 assistant 中间内容、全部工具调用及对应结果，以及最新激活的工具定义；累计内容不得只用上一轮 usage 或固定余量代替。
- 原始工具调用与结果保持成组、按 call ID 对应，不单独删除或截断其中一项。预算视图不得改变实际工具输入、审批 Diff 或执行结果。
- 已知下一步载荷必然无法容纳时，不执行剩余工具；实际结果大小只能在执行后确定时，执行后、下次上游 I/O 前再次检查。
- 超限后关闭 Turn 并返回 `context_limit`，不重试、不重放工具，也不自动撤销已批准的写入。TUI/Web 必须保留并展示本轮已完成的文件修改等副作用，不能让“会话状态未提交”被理解为“文件未修改”。

### 3.7 模型配置与界面占比

- 窗口按精确的 `provider/model` 查找页面覆盖，再查模型环境默认，未命中时回退 `TUI_CONTEXT_WINDOW_TOKENS`，再回退现有 128000 默认值；配置值只表示本地预算依据，不宣称经过上游能力验证。模型切换时一并更新预算，在同一次请求期间冻结 Provider 与预算快照。
- Web/TUI 展示 Runtime 提供的活动输入估算 `I/H`，标明“上下文估算”，不再使用完整 Transcript 大小计算。未提交草稿不计入；发送、压缩、工具续接和模型切换后更新快照。恢复会话时以持久化摘要、有效历史、当前规则和初始工具估算，无须调用模型。
- 分别提供输入估算、硬上限、模型窗口与估算来源；上下文占用和本轮/累计真实 Token 消耗分开展示，缺失 usage 不能用估算冒充。
- 摘要阶段显示“正在整理上下文”并保持计时和取消可用；无可压缩内容、摘要降级和历史省略采用简短中文提示，不展示摘要正文或内部异常。

### 3.8 页面设置

- 在现有独立设置页中增加“上下文”，左侧菜单顺序为“通用、模型、上下文、统计”；使用 `#/settings/context`，支持刷新和前进/后退。
- “模型”页在当前模型选择下增加“模型预算”：上下文窗口、最大回复 Token；折叠的高级选项包含摘要最大 Token 和安全余量。配置按精确 provider/model 保存，编辑预算本身不切换模型。
- “上下文”页管理全项目压缩策略：触发占比（默认 70%）、压缩后目标（50%）、最近保留轮数（6）；高级选项包含摘要超时（30 秒）和失败冷却（10 分钟）。这些数值成为可校验配置，正文中的对应默认值不再表示不可调整常量。
- 页面以数字控件、必要单位和简短说明呈现；高级项默认折叠。提供保存、放弃修改、恢复继承/默认按钮，恢复只改草稿、保存后生效，不在每次输入时自动保存。
- 后端保存到项目数据目录 `data/context-settings.json`，不使用浏览器 localStorage 保存运行参数，不编辑 `.env`，不显示或回传 API Key。
- 字段级优先级为页面覆盖值 → 模型环境默认 → 旧窗口环境变量 → 内置默认。模型页恢复继承只清除该模型覆盖，上下文页恢复默认只清除全局策略覆盖；不影响对话、偏好或统计。
- 保存通过后从下一次请求生效，活动请求保持原配置快照；Web 请求中禁止提交保存。独立运行的 TUI 在下一次发送时读取同一持久化配置，空闲时不承诺即时刷新。
- 前后端都验证单字段范围和完整预算关系；新增读写接口必须处理版本冲突、配置损坏和存储失败，失败不能假装保存成功。保存不触发摘要或真实模型调用。

## 4. 异常与降级

- 每次业务请求最多发起一次摘要调用，不递归摘要。
- 摘要调用从发起到完整消费使用独立 30 秒超时，不开放工具，不流式展示，不写入 Transcript；正常完成、失败和取消都必须关闭摘要 Turn 的连接。
- 摘要内部超时、上游错误、空结果或非法结构均进入 L2；业务请求只有通过最终硬预算检查才继续。
- 用户取消、页面断流或宿主任务取消必须传播取消信号并结束整个请求；不得作为摘要失败吞掉，不再发起业务请求或工具执行。
- 同一会话摘要失败或批次无法装入后进入 10 分钟内存冷却，使用单调时钟；冷却期内超软阈值时直接 L2，低于阈值则复用有效上下文。业务失败不回滚冷却状态，避免下次重复等待；用户取消不触发失败冷却。重启、清空会话或切换模型清除冷却。
- 业务回答失败或取消时，候选摘要、边界和偏好都不提交。

## 5. 安全与隐私

- 摘要、历史和工具结果都是不可信数据，不能覆盖项目规则、当前用户请求或工具审批。
- 不在新的压缩事件日志中记录摘要正文、对话正文、工具参数或工具结果。
- 新增压缩事件只记录估算 Token、实际 Usage（如有）、边界、耗时、策略层级和有限失败分类，并可关联本次业务与摘要请求。
- 现有 `llm_http_request.request_body` 等模型日志继续遵循既有正文记录策略，可能包含旧摘要、摘要输入历史及业务请求中的摘要；本需求不承诺所有日志无正文，也不修改既有模型日志开关。秘密信息仍受现有脱敏和禁止记录规则约束。
- 摘要不提取或持久化新的长期用户偏好，偏好仍只来自明确表达。

## 6. 项目结构与实现边界

- `app/runtime/memory.py`：保留长期偏好与低优先级记忆提示构造。
- `app/runtime/context_compaction.py`：拟新增，放置预算估算、压缩计划、边界与降级策略。
- `app/runtime/context_settings_store.py`：拟新增，持久化页面模型预算和压缩策略覆盖，供 Web/TUI 共用。
- `app/runtime/session.py`：只负责一次发送事务的编排和候选状态提交。
- `app/runtime/session_store.py`：负责 v1/v2/v3 兼容、备份、严格验证和原子持久化。
- `app/runtime/tool_loop.py`：编排每步预算检查与工具生命周期，不绕过审批或重放副作用。
- `app/services/llm/`：提供实际序列化载荷的预算视图、输出限制、模型标识和 Usage，不承担会话记忆策略，不反向依赖 Runtime。
- `app/webui/`、`app/tui/`：消费统一上下文快照与压缩阶段事件，展示估算占比、取消状态和已执行副作用。
- `tests/`：使用假 Provider 和临时存储，禁止调用真实付费模型。

代码继续使用不可变 dataclass、显式类型和中文必要注释，不引入第三方 tokenizer 依赖。

## 7. 测试策略

1. 预算单元测试覆盖完整输入、工具累计载荷和预留量；专门覆盖 H 低于旧版 70% 窗口阈值的小窗口案例，证明硬检查不会被软阈值跳过。
2. 压缩测试覆盖 L0/L1/L2/L3、最近 6 轮软保护、摘要独立预算、一次有界批次、跨请求补摘要、非法 JSON、输出超限与冷却。
3. 持久化测试覆盖 v1/v2 迁移、旧摘要覆盖未知、v3 双边界偶数及顺序约束、迁移备份失败、损坏文件、原子替换和清理备份。
4. Session 测试证明只在业务回答成功时提交压缩结果，完整 Transcript 不变。
5. Web 多会话与 TUI 回归测试证明各会话独立压缩，模型切换、工具调用、流式输出、取消和 `/clear` 语义不变。
6. 固定评测样本为目标、决策、未完成项和路径标注必须保留事实；离线回放验证结构、保留标记和边界，明确它不证明真实模型语义质量。真实摘要质量评测仅在另行授权付费调用时执行，报告遗漏与错误新增事实，不用 Token 减少替代质量结论。
7. 两家 Provider 的 MockTransport 验证每步真实载荷预算与输出参数；动态工具激活和大结果后超限时，断言不发生下一次 HTTP 调用、不重放工具、已执行修改仍被提示。
8. 在摘要中途模拟用户取消与断流，断言连接关闭、业务 Provider 未调用、存储未提交；仅内部摘要超时才降级。
9. 界面测试验证压缩后占比随有效上下文变化而非随完整历史增长，模型切换更新分母，Token 消耗仍按实际 usage 展示。
10. 日志测试区分无正文的新增压缩事件与维持原策略的模型请求事件，不用检查一种事件来宣称所有日志无正文。
11. 设置测试覆盖四菜单导航、字段范围与组合校验、按模型隔离、继承优先级、恢复默认、版本冲突、保存失败和重启恢复；验证保存不调用模型，活动请求使用旧版本、后续 Web/TUI 请求使用新版本。

## 8. 边界

### 必须做

- 保留完整 Transcript，按完整轮次处理原始历史。
- 在 Provider 请求前完成确定性预算检查。
- 摘要无工具、不进入界面 Transcript，失败可降级。
- 会话文件迁移可恢复，读取 v1/v2 时不立即改盘。

### 技术设计必须落实

- 模型预算目录的环境配置格式、类型校验、数量上限及 Provider 输出参数映射。
- Provider 中立预算视图、摘要结构大小限制、事件字段和请求快照的接口。
- v3 编解码、迁移备份和回滚操作、界面占比与副作用展示的验证方式。

以上是本需求范围内的设计细化，按第 11 节默认决策推进；只有新增依赖、外部服务或扩大权限等范围变化才另行确认。

### 不得做

- 不删除用户可见完整历史来节省模型 Token。
- 不让摘要或历史内容提升为高优先级指令。
- 不为压缩引入向量库、Embedding 服务、外部数据库或新的网络依赖。
- 不用删除或弱化既有测试解决迁移问题。

## 9. 验收标准

1. 业务首步、摘要请求及每次工具续接都检查实际待发送载荷的本地预算，输出限制与 O 一致；小窗口下未达软阈值也不能绕过硬检查。
2. 摘要只覆盖实际处理的连续完整轮次；失败、分批补摘要和淘汰后都满足双边界约束，不虚报覆盖，不永久跳过缺口。
3. 不为达到 G 删除本可装入 H 的最近 6 轮；只有硬预算要求才缩减它们，完整 Transcript 保持可恢复。
4. 每次业务请求最多一次摘要调用，30 秒超时后可降级；10 分钟冷却内不重复发起摘要。用户取消在摘要阶段也立即终止整轮且不发起业务调用。
5. 超过本地预算时不发送该次上游请求，不提交候选记忆；若之前已执行写工具，Web/TUI 显示已执行修改，且不会自动重放或撤销。
6. 新增压缩事件无正文并能观察触发、结果、降级、耗时和输入估算变化；不将既有明文模型日志误称为无正文日志。
7. v1/v2 无需手工处理即可恢复，未知覆盖的旧摘要失效并有界重建，首次成功升级保留备份；损坏状态不能静默覆盖。
8. Web/TUI 的上下文占比来自活动输入估算和当前 H，压缩与切换模型后更新；真实 Token 消耗不使用估算替代。
9. 摘要结构错误或超出限额时不截断接受；固定离线样本验证事实标记保留与边界，真实模型质量仍需独立评测。
10. 完整质量门禁通过，测试不访问真实付费或生产服务。
11. 所有预算与压缩配置可在相应页面设置中查看、修改和持久化；可识别配置来源，恢复继承不删除会话，非法值或冲突不改变有效状态。

## 10. 非目标

- 语义检索、向量化长期记忆和跨会话自动关联。
- 完全精确复制每家模型的私有 tokenizer。
- 在 Transcript 中持久化工具调用过程或摘要内部请求。
- 同一会话并发发送多个模型请求。

## 11. 本轮采用的默认决策

1. **范围**：Web 多会话和 TUI 使用共享 Runtime 压缩，已有 `/chat` 不恢复。
2. **会话 Schema**：升级为 v3，分开摘要覆盖边界和原始上下文起点；v2 旧摘要失效、完整历史与偏好保留，并有界重建。
3. **模型窗口**：按 `provider/model` 配置，页面覆盖优先于模型环境默认，保留 `TUI_CONTEXT_WINDOW_TOKENS` 和现有默认窗口作为兼容回退。
4. **预算**：业务输出上限 4096、摘要输出上限 2048、安全余量 4096 Token；压缩阈值为 H 的 70%，目标为 H 的 50%，模型配置不满足约束时拒绝。
5. **摘要等待**：独立 30 秒超时，失败后内存冷却 10 分钟；用户取消终止整轮。
6. **工具超预算**：返回明确的 `context_limit`，保留副作用提示，不自动二次摘要或重放工具结果；工具专用精简契约留待后续需求。
7. **日志**：新增压缩事件不含正文，现有模型请求日志维持既有策略。
8. **交互**：显示“正在整理上下文”和有效上下文估算占比；保留取消、流式输出和多会话隔离。
9. **配置入口**：模型相关预算位于“设置 → 模型”，全项目策略位于“设置 → 上下文”；后端持久化页面覆盖，保存后下一次请求生效，环境配置继续提供默认值。
