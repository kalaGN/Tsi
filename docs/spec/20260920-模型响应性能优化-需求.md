# 模型响应性能优化需求

状态：已完成（2026-09-20）

## 目标

降低工具型任务中重复建连和逐文件读取造成的等待，并让正式日志能够区分响应头、首个 SSE 事件、首个可展示文本和完整流耗时。

## 配置与命令

- 定向测试：`PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -m pytest -q tests/test_llm_providers.py tests/test_model_logging.py tests/test_workspace_tools.py tests/test_tool_loop.py`
- 完整测试：`PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -m pytest -q`
- 编译：`.venv/bin/python -m compileall -q main.py app tools tests`

## 项目结构

- `app/services/llm/`：单次用户请求内复用 HTTP 客户端并采集流式里程碑。
- `app/observability/`：输出有界、可关联的模型性能字段。
- `tools/workspace.py`：增加一次读取最多四个文本片段的只读工具。
- `tests/`：只使用内存 Transport 和临时工作区验证，不访问真实模型。

## 代码风格

继续使用 Provider 中立契约和显式白名单；仅为非显而易见的生命周期、安全上限和计时语义增加中文注释。

## 测试策略

- 验证同一 Turn 的多个模型步骤复用一个客户端，并在成功、失败、取消或工具上限后关闭。
- 使用可控单调时钟验证响应头、首事件、首文本和完整流耗时。
- 验证批量读取保持现有路径、编码、大小和保护目录边界。

## 边界

- 始终：请求结束关闭连接；计时字段使用同一单调时钟；批量读取总输出有界。
- 另行确认：跨用户请求共享全局连接池、改变模型或增加并行写操作。
- 禁止：记录密钥；放宽 Workspace 路径；用真实付费接口做测试；删除或弱化既有测试。

## 验收标准

1. 一个用户请求内的所有模型步骤只创建一个 `AsyncClient`，请求结束可靠关闭。
2. `llm_http_response` 和 `llm_http_error` 能记录已有里程碑耗时；无首文本的工具步骤使用空值而非伪造数据。
3. Workspace 只读组提供一次最多四个文件片段的批量读取工具，并复用单文件读取的安全语义。
4. 现有 Web UI、TUI、Provider、审批和会话行为不变，完整门禁通过。
