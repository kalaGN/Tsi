# MCP 客户端需求

## 目标

让 Tsi 助手在 Web UI 与 TUI 对话中连接用户明确配置的外部 MCP Server，发现并调用其工具。首版只接入 MCP Tools；Resources、Prompts、服务器管理界面和 OAuth 不在本次范围内。

## 技术与配置

- Python 3.11，复用现有 `app/runtime/` 工具循环、`tools/` 注册层和本地审批界面；使用官方 Python MCP SDK，并在 `requirements.txt` 固定版本。
- 支持本机 stdio 与 Streamable HTTP。服务器配置保存在现有 Git 忽略的 `data/` 目录，包含显式服务器名、传输类型，以及 stdio 命令与参数或 HTTP URL。密钥只通过环境变量引用，不在配置、日志和文档中保存明文。
- 只连接用户在配置中显式启用的服务器；每轮请求固定一份工具快照。连接、发现或调用失败时返回安全错误，不能影响本地工具可用性。

## 行为与安全

- MCP 工具名称带服务器前缀，避免与内置工具或其他服务器重名。将工具描述和 JSON Schema 转换为现有 Provider 中立的 `ToolDefinition`；拒绝不支持或超出大小限制的定义。
- MCP 工具按需作为独立工具组披露。每次工具调用均经现有本地审批，展示服务器、工具名、参数和可能的本机执行或网络访问风险；拒绝时不发送调用。服务器返回的内容视为不可信数据，限制长度，不把异常、密钥和原始协议报文展示给模型或 UI。
- stdio 子进程使用参数数组启动，仅传入允许的环境变量；请求结束或取消时关闭连接和子进程。HTTP 限制为明确配置的 HTTP(S) URL，设置连接与调用超时，不自动跟随跨源重定向。
- Web UI 保留 loopback 限制；MCP 不绕过现有模型步骤、调用次数和审批上限。
- MCP 参数和结果可能含敏感内容；现有工具循环会记录完整参数与结果，因此 MCP 调用必须在正式日志与轨迹中脱敏，只保留服务器、工具、状态、大小和耗时等元数据。

## 目录、风格与验证

- 实现放在 `tools/` 的 MCP 适配与配置模块，Runtime 只依赖现有工具协议；Web/TUI 入口负责请求级装配。测试放在 `tests/`，用本地假 MCP Server 或 MockTransport，不调用真实外部服务。
- 复用现有明确类型标注、异步 I/O、有界错误与中文文档风格。覆盖 stdio 和 HTTP 发现、调用、拒绝审批、重名、错误、取消及资源清理。
- 开发验证：`.venv/bin/python -m pytest -q tests/test_mcp.py`。跨模块变更完成后执行 `.venv/bin/python -m compileall -q main.py app tools tests`、`PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -m pytest -q`、`.venv/bin/python -m pip check`、`git diff --check`。

## 完成标准

1. 用户按文档配置并启用一个 MCP Server 后，Web 与 TUI 都能在下一轮对话中发现其工具；未配置时行为与现有版本一致。
2. 模型只能调用当前已披露且本轮发现的 MCP 工具；每次调用经本地审批，拒绝后服务器不会收到调用。
3. 服务器不可达、响应非法、超时或取消时，连接得到清理，模型和界面只收到有界安全错误。
4. README、架构知识文档和 Spec 索引准确描述配置、风险与支持范围。

## 实施边界

- 始终：显式配置、逐次审批、限制输入输出、清理连接、测试使用假服务。
- 需先确认：增加 MCP SDK 依赖及上述公开功能和审批方式。
- 禁止：将密钥写入仓库、让模型指定任意服务器或命令、绕过审批、真实付费服务测试。

## 确认范围

- 首版按上述范围同时支持 stdio 和 Streamable HTTP，并在 Web 与 TUI 都启用。
