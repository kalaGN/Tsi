# TUI 应用职责收敛任务

状态：已完成（2026-09-09）

## 概览

按已确认的需求和设计，测试先行建立启动健康状态、Runtime 模型选择用例、TUI 启动装配和请求协调器，再一次性将生产入口与 ChatTuiApp 切到新边界，最后同步文档并执行全量门禁。

## 架构决策

- 保持 TUI 目录扁平，只新增 bootstrap.py、request.py 和 runtime/model_selection.py。
- ChatTuiApp 只接收单个 TuiDependencies，生产与测试通过两个明确工厂获得依赖。
- RequestCoordinator 独占 Worker、Timer、generation 和流式生命周期；App 只查询活动状态和发起操作。
- Runtime ModelSelectionService 封装 LLM Factory、Session Provider 替换和 Store 持久化顺序。
- 所有用户可见行为、错误文案、安全审批和持久化 Schema 保持不变。

## 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 旧构造签名被大量测试使用 | 迁移噪声大 | 先建立统一注入工厂，再机械迁移构造点 |
| 生命周期双重所有权 | 取消竞态与 Timer 泄漏 | 接入时一次性删除 App 旧字段和方法 |
| 启动错误被重新分类 | 可发送语义变化 | 每种 issue 独立测试 severity 与 blocks_prompt |
| 模型切换顺序改变 | 内存、状态栏和磁盘分叉 | 有序假对象验证先替换后保存 |

## 并行说明

健康状态、模型用例、bootstrap、请求协调器和 App 都共享核心契约，且用户未要求子 Agent 并行工作，因此按依赖顺序串行实施。
