# TUI 模型选择持久化任务

## 概览

按已确认的[需求](../spec/20260909-TUI模型选择持久化-需求.md)和[设计](../plan/20260909-TUI模型选择持久化-设计.md)，测试先行实现独立模型选择 Store，再接入 TUI 启动恢复与运行中切换保存，最后同步文档并执行全量门禁。

## 架构决策

- 模型选择、聊天会话和长期记忆使用独立状态文件，互不清理。
- Store 只负责严格、安全、原子的 JSON 读写；TUI 应用层负责候选、Key 和 Provider 恢复策略。
- 保存发生在 Provider 成功切换之后；保存失败不回滚当前模型。
- HTTP 不实例化 Store，继续完全由环境选择 Provider。

## 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 状态栏与真实 Provider 分叉 | 高 | 同一恢复 Provider 同时注入 Session 与 RuntimeInfo |
| 测试污染真实偏好 | 高 | 仅生产默认装配创建 Store，测试显式注入临时 Store |
| 损坏状态阻止启动 | 中 | 非阻断警告并回退环境默认 |
| 保存失败造成误解 | 中 | 保持当前切换并立即显示保存警告 |
| HTTP 意外读取偏好 | 中 | Store 只从 TUI 应用层引用并增加 HTTP 回归检查 |

## 并行说明

Store 契约、TUI 装配和文档依次依赖前一层真实行为，且会共同修改 `application.py` 与测试文件，因此按顺序实施，不并行修改共享边界。
